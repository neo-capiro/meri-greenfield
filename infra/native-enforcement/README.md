# Native qualification enforcement source preparation

This is an **unaccepted, inert source-preparation candidate**. It creates no resources and launches no tasks. The default compiler returns a refusing state machine. Synthetic wire evidence cannot enable runtime, even when the caller requests `executeAdmitted: true`. A structurally valid evidence record is not owner acceptance: externally reviewed source, immutable image, security, authority, IAM, network, DNS, logging and actual wire evidence are prerequisites to any future deployment or execution.

## Focused interfaces

- `app.mjs` only re-exports the public pure compiler interfaces.
- `lib/binding.mjs` validates exact static pins, full task-definition records and hash-bound external evidence, bounds reference/version metadata (per-field and aggregate), then freezes a binding. It computes the noncircular `staticBindingId`.
- `lib/task-definition.mjs` fail-closed validation of actual ECS task-definition readbacks against the exact binding: it accepts only the observed neutral service defaults, compares keyed collections (environment/volumes/mounts) as unique-name sets and preserves ordered command/entryPoint, and rejects unknown fields, wrong types, non-empty defaults, added capabilities/devices/secrets/DNS and duplicate keys.
- `lib/expressions.mjs` builds JSONata expressions, ownership/terminal/security predicates, the explicit three-way attachment classifier, compact task projections and the bounded before-write `commitCtx`/`boundedExpr` helpers.
- `lib/workflow.mjs` constructs the finite Standard ASL state graph, persistent variables, discovery, bounded containment and evidence outputs.
- `lib/infrastructure.mjs` constructs only the proposed dedicated IAM role and Standard state-machine template.

No module performs deployment, process execution, network access or installation. `buildNativeEnforcementAdmission`, `buildNativeEnforcementStateMachine` and `buildNativeEnforcementTemplate` are the public composition API. The two new resources are proposals only; application/control stay on Fargate and Temporal is unchanged.

### Before-write UTF-8 bounds

JSONata counts Unicode code points; worst-case UTF-8 is 4 bytes per code point and JSON escaping can expand a code point to six ASCII characters. Six times the serialized `$string` length is therefore a proven-safe upper bound for serialized UTF-8 bytes, used with finite caps (`recordBytes` per Task response, `ledgerBytes` per retained task projection, `ctxBytes` for the whole persistent context, `outputBytes` per state output, `issueBytes`/`errorChars` per issue/error summary, `tokenChars` per token, `candidates`/`issues` counts, `refBytes` for reference aggregates). Every persistent write is guarded **before** commit: the `pass` helper commits `$merge([$ctx, update])` only through `commitCtx`, which checks the whole proposed context and, on breach, falls back to a compact context that keeps the immutable owned/overflow stop identities and sets a sticky `hold`/`qualificationFailed`/`overflowed` flag while dropping only heavy transient arrays and re-seeding `queue` from the launched direct ARNs so known positives can still be contained. Every dynamic record field is wrapped by `boundedExpr` with an explicit compact `truncated` disposition. Task results over `recordBytes` become `null`, failing the following shape check closed. Retained task facts are compact projections (no duplicate initial/current/raw/terminal/error objects).

### Ownership, overflow and containment

Positive ownership is independent of qualification: exact task namespace, cluster, immutable definition, run tags/startedBy/group and creation window bind stop authority. Wrong digest/public IP/overrides/attachments fail qualification and still contain a positively owned task. Up to `owned` (4) positives are retained in the primary ledger; additional positives are retained in an explicit bounded overflow ledger up to `overflow` (6), always marking qualification failed. The honest maximum positively retained set is therefore 10; a further positive is not silently dropped but routed to `OverflowExhausted` (sticky hold + `owned-capacity-exhausted`) so the run stays `CLEANUP_UNKNOWN` and blocks the next admission. Deduplication is per exact ARN and each bound identity receives at most one scoped stop attempt.

### Attachment classification

Attachments are classified explicitly three ways: **compatible** (exactly one `ElasticNetworkInterface`, `status: ATTACHED`, with a well-typed `details` KeyValuePair array whose names are unique and which carries exactly one matching `networkInterfaceId`/`subnetId`/`privateIPv4Address` — extra known names such as `macAddress` are allowed), **genuinely pending / legitimate teardown** (a single `ElasticNetworkInterface` in a reviewed lifecycle status — `PRECREATED`/`CREATED`/`ATTACHING`, or the teardown statuses `DETACHING`/`DETACHED`/`DELETED` — with well-typed details and no conflicting subnet), and **present contradictory** (wrong subnet/id/address, duplicate or conflicting detail names, `ATTACHED`/`FAILED` with missing or malformed details, a non-array or otherwise malformed `details`, an unsupported non-ENI attachment — this exact template has no EBS/Service-Connect volumes — or a malformed outer attachments value). Contradictory facts set a sticky `qualificationFailed` that later valid data or a valid terminal record cannot clear; genuinely pending and teardown absence may reconcile within the original D/C. A network failure never erases the original positive stop ownership. Reviewed lifecycle statuses come from the public ECS `Attachment` reference; real service behavior remains unqualified.

### Stop dispatch and terminal confirmation

Stop dispatch is separated from terminal confirmation. Once containment starts, every currently bound, stop-eligible pending identity receives a fresh managed STS identity and pre-stop provenance and exactly one scoped StopTask attempt before terminal polling begins; the dispatch loop returns to the main dispatcher after each attempt, so a lost StopTask response or a task whose terminal reads never settle cannot starve the stop attempt for other known positives. After all eligible stops are dispatched, terminal confirmation runs as a bounded round-robin over the remaining stopped-but-unconfirmed identities, keyed by a per-identity probe sequence, under the original C deadline. A stop acknowledgement never means STOPPED; only a fresh direct exact-ARN DescribeTasks record with the worker STOPPED, integer exit code and matching container identity confirms terminal state. Discovery and overflow admission retain bounded opportunities throughout.

All AWS calls have a positive timeout clipped to the original deadline with a maximum 30 seconds. Containment starts conservatively at D-155 seconds to budget outstanding call, pre-stop task/ENI/identity reads, stop and transition margin. Wait timestamps are clipped to C. Normal limits are 512 calls, 120 polls, 16 pages per inventory, 128 candidates, 4 owned plus 6 overflow records and 32 bounded issues; terminal calls have a separate 544-call ceiling. These are conservative finite structural bounds, not physical-termination guarantees.

## Remaining source blockers and service gaps

1. Actual service result/payload/runtime failure can occur **before** any user expression or Catch projects it. Local before-write bounds and Catch paths cannot guarantee finally/physical cleanup; a service-side failure, `StopExecution`, payload/history limit or outage can interrupt containment. This is disclosed, not solved by source.
2. Managed history retains full bounded evidence only where genuinely supported; the source does not assume history delivery/reconstruction is qualified, so terminal facts are kept compactly in the explicit verdict rather than relying on reconstruction.
3. AWS Task transport retries are not proven absent merely because the ASL has no Retry.

These are disclosed preparation limits, not AWS/Fargate incompatibility findings. They must not be bypassed by treating workflow status SUCCEEDED as acceptance. `FinalUnknown` is a Succeed state whose explicit output is `cleanup: CLEANUP_UNKNOWN`; every caller must inspect the evidence verdict and block the next task.

# Static product material preparation

Implementation outline for the disabled product preview:

- `apps/runtime/config.mjs` remains the canonical role configuration and secret-file reader. `apps/runtime/runner-bootstrap-files.mjs` remains the per-run runner material owner. This module handles only the static control and Temporal-worker file inventory and a read-only preflight.
- `compileProductMaterialPlan` validates a complete canonical role configuration, requires every credential/certificate file to be a direct child of `/run/meri`, and returns paths and file constraints without values. The control and worker configurations must be `/run/meri/control.json` and `/run/meri/worker.json` respectively. It lists the optional Temporal token and control native-candidate/download files when declared.
- `verifyProductMaterial` checks a Linux task-local directory and exact caller-supplied byte hashes, UID, modes, file shape, and the configuration's current path inventory before the CLI is permitted to start. Expected hashes must come from an authenticated shipping owner. They are accepted only in memory, never returned. A successful preflight does not authorize a task, attest an issuer, or make later file replacement impossible.
- No writer, credential source, ECS task dependency, image or service is installed by this module. Shipping must supply a separately reviewed one-shot init owner, task-local volume and container success dependency before the current CLI command runs. The init owner must put only the designated files in that task, use the same non-root UID and `0700` directory/`0600` file modes, and finish before the app starts. The application must not receive provider-account secrets. Temporal token refresh requires its existing issuer/rotation owner after start. The control's optional dynamic `multiRun.materialDirectory` is separate mutable state, not a static credential file.
- Check the pure plan on this Windows host with explicit Node 24, including control native-candidate and optional files, aliases, foreign paths, missing fields, and refusal of runner role. The filesystem preflight fails closed outside Linux; its positive physical-ownership behavior requires a task-local Linux qualification before use.

Activation stays blocked until the file issuer/source, ECS init dependency, private task volume, exact expected hashes, runtime UID, token rotation, and cleanup are reviewed against the final service definition. This source has no import-time IO or AWS calls.

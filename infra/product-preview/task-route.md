`task-router.mjs` owns bounded HTTP forwarding and request cleanup. The complete closed body is checked before authorization. Only the existing task-role operations prepare/start/stdin/stdout and shared stop accept a task credential; remaining operations require the control credential. No incoming header other than the authenticated bearer is forwarded. The body is reserialized, request and response bytes are bounded, the aggregate reservation is capped, responses are uncached, and redirects are refused. After verified TLS connects, durable authority and ECS/ENI are read again before any bearer is written; ordinary responses need another durable/task/ENI check before release. An authenticated stop has one reserved request slot and byte budget even under ordinary saturation; it fences its original and aborts its concurrent requests. This fence supplements fresh durable checks and the receiving task's authority; it is not a new durable lock or physical-stop proof.

`runner-tls-client.mjs` owns one TLS 1.3 connection to the observed private IP on port 8080. SNI is `<exact ECS task ID>.<configured private zone>`. Node verifies only the supplied CA trust; additional checks require one exact DNS SAN, serverAuth, present validity and leaf expiry no later than original expiry. The connected remote IP/port must match the observation. No bearer/body is written until TLS authentication and the router's post-connect checks finish. Connections are never pooled or reused, including failures, aborts and late completion.

`runner-tls-server.mjs` validates the owner-supplied certificate/key/CA against the exact original, observed candidate and task-local ECS metadata. It requires one awsvpc worker, matching task ARN/cluster/name/private IPv4, a matching private key, exact SAN and trusted bounded chain. It returns Node HTTPS options and creates no listener or file. `runner-https-material.mjs` reads protected task-local files and the remote conversation launch path passes the validated TLS options to the HTTPS listener. The pre-CLI poststart source now produces those task-local inputs; physical Linux/Fargate and live private-peer proof remain unrun.

## Private control listener integration

The source composes a dedicated **private control listener on 8082** before opening the public listener on 8080. The proposed private ingress is only from the approved internal ALB security group; the internal ALB target group would forward to control 8082. Runner HTTPS remains private IP:8080 with proposed ingress only from the control SG. Public listener rules must deny all native/bootstrap/internal paths before a broader public rule. Network attribute/SG/listener readback and actual probes remain required before enabling traffic; these AWS resources and rules are not created by this source.

Trusted control startup creates `privateIngress = createTaskRouterIngress()` from `task-router-boundary.mjs`. The private route boundary obtains its process-local marker and alone calls `router.privateApplication.handle(request, {ingress: privateMarker})`. The marker cannot be constructed from headers or JSON. The public `router.application.handle(request)` facade refuses matching native-task paths. Missing markers fail closed even if `enabled` is true. The public handler never receives the private marker.

## Composed poststart exchange; activation HOLD

The existing `/v1/runner/native/bootstrap` requires the task capability before it can return configuration. The poststart source resolves that first-contact dependency through two exact private-only POSTs: `/v1/runner-poststart/challenge` and `/v1/runner-poststart/redeem`. They are available only after control composes `taskRouter.poststart.enabled` from its reviewed static bundle and process-local private ingress marker. Public handling denies them. The runner definition starts `node apps/runtime/runner-poststart-cli.mjs start`, with only nonsecret fixed control-origin/public-CA pins and no task role or original-specific override. A live service remains prohibited until the private ALB, credential custody and task-local behavior are proven.

The runner generates its private key and CSR locally, reads task-local ECS metadata v4, and submits the claimed exact task ARN and CSR over the fixed private control HTTPS origin. It signs the bounded challenge with that key, proving possession. The private adapter supplies its server-only marker; the service parses the **last ALB-appended** XFF IPv4. This requires independent proof that only the internal ALB reaches control 8082, ALB is in append mode with client-port suffix disabled, and headers cannot bypass the private route. `taskRouterClientIPv4` supplies the strict parser; it grants no identity by itself.

`createRunnerPoststartAuthority` reads a claimed task ARN through ECS `DescribeTasks` with tags to obtain `startedBy`; it then resolves immutable issuance, original allocation and current admission, verifies fresh RUNNING ECS task and exact ENI/private peer, and accepts only a short-lived, single-use CSR challenge and proof. An ALLOCATED original may yield only a bounded pending response, never material. The configured certificate issuer signs an original-bounded serverAuth leaf for exactly the task DNS SAN from an owner-only CA pair. Before returning the existing issuance owner's capability, config, control CA, runner CA, certificate and candidate, authority repeats durable and ECS/ENI checks. The task key stays in the runner's owner-only filesystem and never enters an ECS override, control response, log or repository. The runner compares its metadata and validated material before opening HTTPS. A changed/stopped/reused ENI, uncertain read or missing issuer refuses.

The challenge map is process-local. First activation must keep exactly one healthy control task and avoid a concurrent blue/green target during challenge/redeem; a restart between the calls fails closed. Multi-replica or overlapping-target operation requires a separately reviewed shared atomic nonce/replay owner and cross-task tests. The current manifest keeps the service at zero.

`runner-poststart-cli.mjs` calls the source exchange before runtime config load, writes owner-only TLS/candidate/metadata and bootstrap material under its private task-local directory, constructs a CA-pinned direct native fetch and releases only its own files at exit. Neither a claimed ARN, XFF alone nor task metadata alone establishes private peer identity. The source uses the original issuance/capability owner and creates no second grant ledger. **Unproved live gates:** approved CA pair and issuer custody, static exact-version bundle/KMS permissions, private ALB target/XFF/SG invariants, Linux/Fargate file ownership and cleanup, ECS/ENI read authority, original stop/revocation races, pinned image/runner measurement and exact network path. If those invariants fail, the route must remain closed. No credential or role is created in this source increment.

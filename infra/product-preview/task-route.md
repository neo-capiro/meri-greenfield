# Original-task HTTPS route: implemented source, activation HOLD

Base: `06b0006397cd9cf85cb8bc10908eeec2de0dd7cd`. This increment is source only. The task router is composed from the control's durable candidate owners and mounted only on its separate private listener when a validated `taskRouter` configuration is present; the product CLI requires that configuration. The ordinary configuration remains opt-in. No task-bound TLS issuer, authenticated poststart bootstrap delivery, AWS deployment, credentials, DNS, listener rule, security-group change or live database write is provided here. Local fixtures do not prove a reachable runner or live isolation.

## Outline and canonical owners

The existing prepared-run issuance store owns immutable capability/facts binding. The conversation allocation journal owns the exact original/task assignment and current writer fence. `createNativeAllocationAdmission.read` owns current grants, allocation, expiry and revocation. The receiving `remote-task-http.mjs` continues to authorize the original and operation. The router composes these owners without adding a grant ledger or authorization SQL.

`apps/runtime/native-authority/task-router-authority.mjs` rebuilds the exact immutable issued-facts hash using the real issuance and allocation read APIs and `admissionForBinding`. Ordinary forwarding requires ADMITTED allocation, current queued/starting/running run and current canonical admission. Stop permits only original-bound cleanup from an existing assigned resource after execution admission ends; it cannot create a task or release new work. Once the original/certificate expires, HTTP cleanup fails closed and the existing ECS stop-only reconciler remains necessary.

`task-router-network.mjs` owns the canonical original-task/ENI observer. `infra/product-preview/task-route.mjs` re-exports it for compatibility. `task-router-network-reader.mjs` uses fresh `DescribeTasks` for exactly the admitted ARN, verifies its ownership/running image, reads exactly one attached ENI with `DescribeNetworkInterfaces`, and checks the approved VPC, subnet, SG set and private IPv4. Control startup dynamically loads the locked ECS and EC2 SDKs, constructs these clients, and closes them on shutdown or failed startup. No client or resource is created on import.

`task-router.mjs` owns bounded HTTP forwarding and request cleanup. The complete closed body is checked before authorization. Only the existing task-role operations prepare/start/stdin/stdout and shared stop accept a task credential; remaining operations require the control credential. No incoming header other than the authenticated bearer is forwarded. The body is reserialized, request and response bytes are bounded, the aggregate reservation is capped, responses are uncached, and redirects are refused. After verified TLS connects, durable authority and ECS/ENI are read again before any bearer is written; ordinary responses need another durable/task/ENI check before release. An authenticated stop has one reserved request slot and byte budget even under ordinary saturation; it fences its original and aborts its concurrent requests. This fence supplements fresh durable checks and the receiving task's authority; it is not a new durable lock or physical-stop proof.

`runner-tls-client.mjs` owns one TLS 1.3 connection to the observed private IP on port 8080. SNI is `<exact ECS task ID>.<configured private zone>`. Node verifies only the supplied CA trust; additional checks require one exact DNS SAN, serverAuth, present validity and leaf expiry no later than original expiry. The connected remote IP/port must match the observation. No bearer/body is written until TLS authentication and the router's post-connect checks finish. Connections are never pooled or reused, including failures, aborts and late completion.

`runner-tls-server.mjs` validates the owner-supplied certificate/key/CA against the exact original, observed candidate and task-local ECS metadata. It requires one awsvpc worker, matching task ARN/cluster/name/private IPv4, a matching private key, exact SAN and trusted bounded chain. It returns Node HTTPS options and creates no listener or file. `runner-https-material.mjs` reads protected task-local files and the remote conversation launch path passes the validated TLS options to the HTTPS listener. The authenticated poststart issuer/delivery of those files remains unimplemented.

## Private control listener integration

The source composes a dedicated **private control listener on 8082** before opening the public listener on 8080. The proposed private ingress is only from the approved internal ALB security group; the internal ALB target group would forward to control 8082. Runner HTTPS remains private IP:8080 with proposed ingress only from the control SG. Public listener rules must deny all native/bootstrap/internal paths before a broader public rule. Network attribute/SG/listener readback and actual probes remain required before enabling traffic; these AWS resources and rules are not created by this source.

Trusted control startup creates `privateIngress = createTaskRouterIngress()` from `task-router-boundary.mjs`. The private route boundary obtains its process-local marker and alone calls `router.privateApplication.handle(request, {ingress: privateMarker})`. The marker cannot be constructed from headers or JSON. The public `router.application.handle(request)` facade refuses matching native-task paths. Missing markers fail closed even if `enabled` is true. The public handler never receives the private marker.

Construction hooks:

- `createTaskRouterAuthority({issuanceStore, allocations: store.allocations, admissionForBinding: bindings.admissionForBinding, controlCapabilitySha256, operations, transport, approvedReads?, now?})` returns `verify({original, operation, credential, signal?, check})`.
- `await createTaskRouterNetworkReader({ecsClient, ec2Client, network: {clusterArn, taskDefinitionArn, vpcId, subnetId, securityGroupIds}, now?})` returns `observe({original, resource, signal, check})`.
- `createRunnerTlsConnector({ca, zone, now?})` returns a connector. The separate explicitly named trusted-testing factory is never selected by runtime configuration.
- `createTaskRouterApplication({authority, networkReader, connector, privateIngress, enabled: false, now?, maxRequestMs?, maxConcurrent?, maxOriginals?, maxBufferedBytes?})` returns public-denial/private handlers and `close()`.
- `compileRunnerTlsServerMaterial({original, candidate, metadata, ca, cert, key, zone, now?})` returns standard HTTPS TLS options after validation.

No ordinary Fetch client, caller-supplied URL, DNS lookup, wildcard/shared runner key, AWS response object or XFF header alone is an authority substitute.

## Exact activation blocker: post-start identity and certificates

The existing `/v1/runner/native/bootstrap` requires the task capability before it can return configuration. Existing pre-start material contains a capability/configuration/control CA, but does not establish a per-task TLS leaf/key receiver. The router and HTTPS runner launch source are mounted behind validated configuration, yet product startup fails closed without authenticated poststart delivery and a task-bound TLS issuer. Do not activate a runner task or public route from these source hooks alone.

A proposed flow without a runner IAM role is possible only with the proved dedicated private ingress boundary. The runner would generate its private key locally, read task-local ECS metadata, and submit its nonsecret execution key, exact task ARN and signed CSR over the stable protected control HTTPS origin. The private adapter must supply its server-only marker; the service must use the **last ALB-appended** XFF IPv4, after independent proof that ALB is in append mode with client-port suffix disabled. `taskRouterClientIPv4` supplies the strict parser; it grants no identity by itself.

The future bootstrap owner must resolve the immutable issuance and original allocation by the execution key, match fresh RUNNING ECS task and exact ENI IP to that trusted peer, require current admission/fence/expiry, validate the CSR signature and SPKI possession, and invoke a configured approved issuer. The issued leaf must use exactly the task SAN and original-bounded validity. Before returning a bounded leaf chain, task configuration and task capability, recheck the durable owner and ECS/ENI identity. The key stays in the task's owner-only filesystem and never enters an ECS override, control response, log or repository. The runner must compare its own metadata and validated material before opening HTTPS. A changed/stopped/reused ENI, uncertain read or missing issuer must refuse.

The credential-free receiver, CSR validator, configured issuer, task-local key generation/polling, delivery/material schema, and their real composition are **not implemented**. Neither existing Hono Request headers nor a claimed ARN establish private peer identity. The candidate and metadata files checked at runner startup are consistency inputs, not independent identity evidence. If the dedicated listener/network/XFF invariants cannot be proved, this flow must refuse; it needs either a separately proved task-bound bootstrap credential receiver or scoped task IAM with verified SigV4 identity. No new credential or role is invented in this source increment.

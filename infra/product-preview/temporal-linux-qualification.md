> Historical qualification checklist. Its custom issuer, token writer, JWT and issuer-network instructions are superseded by native client-certificate authentication in `apps/runtime/temporal-tls.mjs` and `temporal-binding.mjs`. Preserve required native server, namespace, workflow, rotation and restore behavior through those existing owners. Use the [current Runtime V1 migration plan](../../docs/handover/20261022/plan/AGENTCORE-RUNTIME-MIGRATION-20261024.md) and current Release readbacks; this checklist does not authorize rebuilding the retired issuer or operating archived identities.

Root owns the isolated native ARM build and private Fargate qualification. This checklist records the remaining gates; the implementation lane performs no cloud, SQL or model operations. The source at this pin keeps all five service counts zero and `MERI_TEMPORAL_ACTIVATION=disabled`.

## Freeze source and image bytes before the build

1. Name one approved Meri Git commit and require a clean exact checkout. Record `git rev-parse HEAD`, `git status --porcelain --untracked-files=all`, and SHA-256 for `temporal-launch.Dockerfile`, `.sh`, `-main.mjs`, `-render.mjs`, `-migration-plan.mjs`, `temporal-image-pins.json`, `temporal-server-dependencies.patch`, `temporal-binding.mjs`, and `temporal-deployment.mjs`. Compare each blob to `git show <approved-commit>:<path>`. A 40-hex `LAUNCH_SOURCE_COMMIT` build arg alone only echoes a claim; it does not establish image provenance.
2. The Dockerfile pins three literal ARM64 child manifests through `temporal-image-pins.json`: official Node 24.22.1, official Go 1.26.10 as builder, and Wolfi as the final GNU runtime. Docker verifies the SHA-256 of exact upstream Temporal 1.32.1 commit `af08a5e5f2dd40f545f2afac7780daaa6987001e`. The sealed `temporal-server-dependencies.patch` contains the ordinary Go-generated go.mod/go.sum delta for x/net 0.60.0 and its six required x/* module upgrades. Standard Git applies it, Go downloads/verifies its checksum-pinned closure, then builds `cmd/server` readonly with CGO disabled, upstream `-s -w` linker flags and no custom tags. Retain and inspect the actual module list, `go version -m` and binary SHA-256; compare the embedded Go/module versions, static ARM ELF and native help/version against those facts. No upstream schema or server implementation is patched. Only Node, the rebuilt server and its standard build metadata enter the final image; `apk add --no-cache` owns the runtime library dependency closure. No custom APK index/payload or loader is retained. The build path remains `temporal-image-context.py` (exact Git subset and public CA) → `temporal-image-start.sh` (default dry run, one root-operated start) → `temporal-image-build.sh`. The starter explicitly selects `ARM_CONTAINER`, `aws/codebuild/amazonlinux2-aarch64-standard:3.0`, `BUILD_GENERAL1_LARGE`, privileged build mode, timeout 30 minutes, queue 5 minutes and zero retries on the existing project; prove that project idle before a real start. Pass only the public CA through the existing BuildKit secret mount. No private key, JWT, DB password or client material belongs in a build argument, layer, image label, source archive or build log.
3. Build the derivative only under a separate image-build authorization. Record the resulting image digest and scan/license disposition, then compare the ECR image digest in `serverImageUri` to that exact artifact. Inspect the final image user, entrypoint, source-commit environment, `/run/temporal` and `/tmp` VOLUME declarations, file modes, ARM Node 24.22.1 executable, static AArch64 server and package-manager-owned GNU dependencies. Preserve the existing build result and exact-digest scan evidence, including copied Node/Go binary coverage; ECR basic OS-only coverage is insufficient by itself. Do not infer content from a tag or treat a synthetic probe fixture as native execution. The historical component pins/migration plan remain unchanged. After qualification root must regenerate and validate the actual ARM image/source/renderer binding with `upstreamServerSourceCommit`; the archived donor-image tuple is refused. A source security rebuild is maintained and qualified by us until a fixed official same-line artifact is available.

## Isolated Linux container checks before any service count changes

1. With no runtime Secrets, run `/opt/meri/temporal-launch --help`: exit 0, fixed usage, no metadata/JWKS/database contact or secret output. An invalid role exits 64. A valid role with activation disabled exits 78 before network. Check the pinned `temporal-server --help`/CLI flag order and native executable compatibility on the actual derivative image.
2. With separately approved **synthetic** CA/leaf/JWKS/DB material in an isolated harness, verify the launcher parses one exact role, discovers its task ENI rather than loopback, writes owner-only files under `/run/temporal`, and renders a valid complete Temporal 1.32.1 config. Without a migrated PostgreSQL target and peer services, a child startup may fail at its dependency check; treat that bounded failure as a launcher/config-load observation, never as service-start proof. Verify cleanup on clean exit, signal, spawn failure and preflight failure with an isolated fake child. Keep fixture credentials ephemeral and outside Git/logs. Qualify `/run/temporal` ownership/mode 0700 and `/tmp` mode 01777 on the actual mounted volumes, not just the image. Inspect child stdout/stderr for config-derived sensitive material before allowing awslogs.
3. Parse the generated JSON/YAML with the exact Temporal 1.32.1 server. Check both `postgres12` stores, immutable 128 history shards, frontend `audience`/default mapper/authorizer, external versus internal frontend routes, five role ports, mTLS certificates/SAN/EKU/chain, hostname verification and disabled archival. Fail if a stock/default config silently overrides these values. Record the exact config hash without recording its credentials.

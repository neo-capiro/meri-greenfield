CORRECTION 1 — SDK PATH / CLEANUP ADDRESSED THE WRONG OBJECT
  Problem  the production `finally` called `(resolved ?? narrow(transport)).stop`. `resolved` is a
           PENDING IMPORT (a Promise), so the production adapter called `.stop` on a Promise. The
           owned one-use session could be left running because cleanup addressed a different object
           than the one that dispatched, and a rejected import produced a TypeError instead of the
           honest closed fault.
  Fix      apps/runtime/uploads/agentcore-client.mjs
           * `resolved` stays the pending import; a new `owned` holds the RESOLVED port.
           * `opened()` awaits `resolved` once and caches `owned`, so every later call gets the same
             object.
           * `inspect` keeps the resolved port in `dispatchedPort` and the cleanup calls
             `dispatchedPort.stop(...)` — the exact port that invoked, never a Promise and never a
             second client.
           * `close()` destroys only a client this module created, and only from the resolved value.
           * `requireUploadInspectionSdk(module)` makes an ABSENT or INCOMPLETE SDK the same closed
             UPLOAD_INSPECTION_TRANSPORT_UNAVAILABLE fault, never a TypeError from an undefined class.
  Proof    apps/runtime/uploads/test/agentcore-adapter.test.mjs — the REAL default adapter over a
           REPLACED SDK module, run with --experimental-test-module-mocks. Covers:
             - invoke + stop success on the SAME owned session, with the client the module created,
               `maxAttempts:1`, region and ARN/qualifier from the declaration;
             - unknown dispatch: exactly one invoke (no replay) and the session still stopped;
             - cancellation: CANCELLED is not an unknown outcome, session still stopped;
             - cleanup failure: both a 500 stop and a throwing stop surface
               UPLOAD_INSPECTION_CLEANUP_UNKNOWN;
             - absent/incomplete SDK: requireUploadInspectionSdk refuses without dispatching.
  Removed  the host-dependent skip in agentcore-client.test.mjs. It skipped whenever the SDK was
           resolvable, which meant the production path was never exercised and the assertion was
           weakened. The replacement asserts the closed configuration refusals directly and leaves
           the default-adapter path to the module-mocked file above.

CORRECTION 2 — CONTROL PRODUCTION CALLER WAS MISSING
  Problem  control-lifecycle/config had no path that selected the AgentCore remote port and no
           production call site created `createUploadInspectionClient`.
  Fix      apps/runtime/uploads/control-lifecycle.mjs
           * `compileUploadNativeConfiguration` now accepts a closed `native.agentcore = {imageDigest}`
             block. It is mutually exclusive with every local key (digest/root/extractor/budget), and a
             malformed nested block is the same UPLOAD_NATIVE_CONFIGURATION fault as a malformed key.
           * `mountUploadNativeControl` selects REMOTE first and unconditionally when `agentcore` is
             declared: it reads the existing `configuration.agentcore` {runtimeArn, qualifier}, takes
             the region from the ARN's own segment 4, and returns
             `createUploadInspectionClient({region, agentRuntimeArn, qualifier, imageDigest, now})`.
             No local sandbox composition is even attempted, so CONTROL can never fall back to
             executing the uploaded bytes itself. A missing/malformed runtime is an honest
             `inspection:null` with `missing:['uploads.native.agentcore']`.
           * Absent/disabled declarations and the entire local path are byte-for-byte unchanged.
  Custody  the port shape is identical to the in-process owner, so `apps/control/uploads/custody.mjs`
           drives it unchanged: `fresh()` rechecks authority BEFORE the dispatch, `guard()` rechecks
           AFTER, and the existing `validateUploadInspection` receipt gate accepts the result. No
           authority, owner, tenant, scope or object reference is accepted from the caller.
  Proof    apps/runtime/uploads/test/agentcore-production.test.mjs — the MOUNTED caller over the REAL
           custody owner (memory retention journal, read gate, current-access port, store/objects
           fixtures). Covers:
             - closed declaration selection and refusal of every local leftover beside `agentcore`;
             - mount selects the remote port for a genuine runtime and composes nothing locally;
             - a mounted remote port inspects the EXACT original this custody owns; the wire carries
               the declared image (never an observed one) and the configured endpoint qualifier;

CORRECTION 3 — ENTRYPOINT PASSED NO INSPECTION PORT
  Problem  agentcore-entrypoint constructed `createUploadInspectionApplication` with no `inspection`
           port, so the purpose could only answer 503. The "host owner does not exist" claim was
           false: composeUploadNativeHost, the native-definitions owner and the bounded provisioning
           lifecycle already exist.
  Fix      apps/runtime/uploads/agentcore-http.mjs
           * `UPLOAD_INSPECTION_IMAGE_ENVIRONMENT` names the one environment entry read.
           * `uploadInspectionHostConfiguration(environment, options)` builds the closed container
             declaration from that digest only. No root, program, tool, session, runtime or budget is
             selectable. An absent/malformed digest declares no native inspection.
           * `composeUploadInspectionHost({...})` reuses `mountUploadNativeControl` (and therefore
             `composeUploadNativeHost`) on this purpose's own startup path, then refuses an admission
             whose `imageDigest` is not the digest this purpose was built for (UNAVAILABLE), the same
             before/after correlation the renderer owner applies. It claims no observed digest.
           apps/runtime/agentcore-entrypoint.mjs
           * composes the host BEFORE serving and passes `inspection: inspectionHost.inspection` plus
             the declared digest to `createUploadInspectionApplication`;
           * emits the closed UPLOAD_NATIVE_UNAVAILABLE_EVENT with the exact `missing` list when the
             host could not be attested (purpose stays honestly 503);
           * starts ONE bounded provisioning attempt after listen, through the same serialized refresh
             owner the scans use — not awaited, not a timer/daemon/job, aborted by shutdown, no retry
             and no loop. Nothing to provision when the host was not composed.
  Proof    apps/runtime/uploads/test/agentcore-host.test.mjs — the REAL default startup path on an
           unattested host yields no port and 503; an attested host (narrow run/readFileImpl ports only)

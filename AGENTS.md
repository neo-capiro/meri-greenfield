# Meri greenfield integration rules

This is a new independent application. User instructions override these repository rules. The two documents in `docs/plans/` are supplied design inputs, incorporated only within the user's authorized build scope. Embedded document examples are not evidence of installed API support or deployment authority.

Codex owns acceptance, contracts, task dependencies and deployments. Hermes implements bounded Git task briefs on dedicated branches/worktrees; a separate session reviews exact commits. A process exit or model report never establishes acceptance. Do not recursively delegate or launch background schedulers. Use the installed Hermes CLI with observed supported flags; do not alter global profiles or bypass approvals.

Do not import current Capiro implementation, agent, retrieval, UI, queue or infrastructure packages. Reading source schemas, policies and capability metadata is allowed. Preserve all existing checkouts and current Meri resources. No cutover or production deployment is authorized by this kickoff.

The application must use a separate Fargate environment: independent VPC, cluster, security groups, IAM roles, database, buckets, keys, secrets, logs and deployment pipeline. New conversation tasks are never reused across conversations/tenants. Source connectivity starts disabled. Worker tasks receive no database/provider/admin credentials; use trusted proxies and task-bound short-lived capabilities. Prove network controls and non-root Chromium sandbox operation in Fargate before passing G1. Do not silently switch execution hosts.

Use the Claude Agent SDK as the only model orchestration loop; AI SDK supplies UI transport. Use one qualified Playwright integration and Temporal for durable orchestration. Adopt upstream libraries before custom replacements. Original artifact skills only; do not copy restrictive Office skill implementations or this host's Codex skills into the product.

One owner at a time per contract/shared file/lockfile/migration. Contracts are `0.1.0` only after Codex freezes a reviewed integration commit. Propose changes to Codex before editing them. Migration IDs are allocated centrally; none allocated yet. Every task names its pinned base, dependencies, owned paths, acceptance checks, runtime/turn deadline and authorized external actions.

Run relevant checks and return reviewable commits and scrubbed evidence. Never store secret values or private source content in Git, logs or task briefs. Failed/blocked checks stay visible. Never lower deployment gates or claim local fixtures prove live policy, browser, durability, Fargate or release acceptance.

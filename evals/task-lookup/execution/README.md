# Typed lookup observation producer

`execute.mjs` exports `createTaskLookupExecution`. This executes a **preselected typed tool replay**, not prompt routing, a model/SDK loop, task acceptance, or real-request qualification. Only `mode:'correct-tool'` executes. `original` and `correct-evidence` remain explicit ineligible observations without host preparation or tool calls. The unchanged scorer keeps all cases in its denominator.

Factory configuration is `{gateway,store,authorize,prepareCase,clock,maxCaptureBytes?}`. Gateway and store are the actual accepted control service's borrowed ports; the factory internally constructs `createTaskLookupDelivery`, not a caller-selected executor. `authorize` is the actual current control authorization callback. `prepareCase({case,runId,binding,signal,deadlineMs})` is a trusted host provider returning `{context,readContext,credential}` in the existing control shapes. Its binding must exactly match the host's supplied per-case RunBinding; tenant/actor/conversation, scopes and selected client cannot be changed from the frozen case. Credentials remain host inputs and are not added to captures.

`execute({runners,runnerSha256,runBindings,runId,deadlineMs,signal?})` requires all three outputs of `runnerCases(frozen,{split})`: development, calibration and held-out. `runnerSha256` is the ordered array of separately supplied canonical projection hashes. All corpus/config/source identities, case/group/split membership and source-set pins are checked. `runBindings:[{caseId,binding}]` must cover every case exactly once, including unsupported or preparation-failed cases. Empty corpus produces empty capture and an explicit emptyCorpus flag; scoring it cannot establish success. Projections contain no expected/gold, provenance labels or approval object. Integrity hashes are not authenticated approval, current grants or source-snapshot attestation.

Return shape is frozen `{capture:{run,observations},traces,execution}`. `capture` is the existing `scoreObservations` input. Each `{caseId,traceSha256,trace}` binds actual stage hashes, lookup/read callback requests and receipts/errors, retained lookup/read results, timestamps and pending-call descriptions. The observation references that exact trace digest. Read callbacks are extracted from their actual sequence; lookup callbacks remain trace evidence. Read ACCESS_DENIED requires an actual denied read callback and captured control error. Lookup denial, unknown ACKs, provider failures and cancellation remain failed observations with explicit outcomes; no replay occurs. Recommendations remain recommendations.

The explicit whole-run deadline is at most240seconds from the supplied clock. Existing control calls retain their60second context bound. Shorter prepared deadlines, callback `limitDeadline` and returned authority expiry narrow the current case and later read; a later receipt cannot expand them. Whole-run cancellation propagates to preparation and control. Canonical lifetimes stop waiting, not borrowed effects. Pending calls are reported as `{port,caseId,callId}`; no later supported case starts after an unsettled predecessor. Late port outcomes cannot mutate the frozen capture. Borrowed pools/ports are never closed. Host-owned process supervision and actual physical cleanup remain external obligations.

`maxCaptureBytes` defaults to16MiB and is configurable from16KiB through64MiB. Admission reserves compact outcome space for every case before effects. An oversized retained trace becomes a failed case with its omitted-trace digest and observed byte count; subsequent supported cases are failed without ports. The bound applies to retained capture, not a sandbox, hard resident-memory limit, source-port response limit or physical-stop proof. Host source adapters still need their own qualified response/resource bounds. Full control prepared records include stored delivery context; the host must supply an approved nonsecret durable context and protect output storage. No live/customer capture is committed by this lane.

## Portable activation handoff

1. An authorized corpus owner supplies approved real requests, grouped splits, fixed gold, source snapshots and exact source/config/image identities. Freeze and independently pin them with the existing evaluator; keep gold with the scorer owner. The adopted real corpus remains0 until separately supplied and authenticated.
2. Transfer only the three gold-free projections plus independently trusted projection hashes to the execution host. Provision current identity, exact host runBindings and fresh lookup/read context/IDs through the existing qualified control/gateway/store/authorization composition. The harness does not obtain credentials, deploy services, apply SQL or qualify those ports.
3. Supply host-owned ports and a bounded clock/deadline/cancellation signal. For methods, preserve receiver binding (for example `authorize:q=>host.authorize(q)`). Invoke the imported API; there is no dynamic shell/module runner or stub CLI.
4. Persist the immutable returned capture and traces in approved storage. Independently join source/config/native/image authority evidence; a local hash or authorized:true receipt alone does not authenticate it. Run `scoreObservations(frozen,output.capture)` in the separate scoring owner, preserving missing/ineligible/failed cases and all raw failures.
5. Native/runtime source authentication, PostgreSQL/Temporal durability, image/sandbox/current policy, real-data authorization and independent adjudication remain external. This lane runs no SQL engine, native worker, provider/model, customer source or cloud action. It does not relax75 real seeds/200 expanded, original60 completion/factual tasks,100 isolation/adversarial cases or the wider14-skill/artifact/recovery/UI gates.

Tests under `execution/test` use actual control and unchanged canonical scorer with inert host boundaries. `test/fixtures.mjs` exports async `setup()` for root integration, including preexecution synthetic gold, caller arguments and replaceable host ports; it is not production data or an expected-pass producer.

# Adversarial tenant-isolation harness

Generates at least 100 cross-tenant cases across three synthetic tenants and executes every one offline against the canonical owners composed in `evals/offline-targets`: the conversations HTTP application with scripted identity/context owners, the gateway current-tool authority and dispatch, the retained-lookup authorizer and the artifact service. Categories: guessed IDs (foreign conversation/run IDs in request bodies and bindings), object links (stream/subscription links and artifact version links of another tenant), session keys (mutated, truncated and derived credentials) and forged tool arguments (authority keys in gateway arguments, foreign lineage from a source handler, forged bindings/scopes for lookup authorization and artifact context). No validator is duplicated: every refusal is the existing owner's refusal.

Run `node evals/isolation/run.mjs --output REPORT.json` or `node --test evals/isolation/test/isolation.test.mjs`. The report carries a per-case outcome (`refused`, `leaked`, `unexpected-success`, `harness-error`), observed status/code, positive controls, counts per category and surface, and `pass`.

Fail-closed rules: any observation that contains a victim marker (tenant, actor, conversation, run, client, session credential, artifact version or seeded sentinel text) is `leaked`; any accepted cross-tenant request is `unexpected-success`; any failure that is not a recognized product refusal is `harness-error`; fewer than 100 cases, fewer than 3 tenants, a missing category or a failed positive control also fails the run. Positive controls prove each tenant still sees its own seeded prompt, artifact bytes, lookup receipt and gateway page, so the oracle is sensitive. Exit codes: 0 pass, 1 fail, 2 invalid arguments or I/O.

What this does not prove: it is a LOCAL_FIXTURE over scripted ports. It does not prove live Clerk membership, policy revisions, PostgreSQL row security, Temporal namespace isolation, browser profile or workspace isolation, S3 object isolation, or the plan's "zero unauthorized rows, citations, transcripts, browser state or files" gate on a deployed candidate. Those remain separate qualification gates with their own evidence.

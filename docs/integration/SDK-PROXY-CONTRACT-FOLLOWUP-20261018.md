Basis: PR188 corrected code `0d3388a88aa575fba2bf9ee9c1c219053ea09418`; SDK0.3.295 / CLI2.1.295 / LiteLLM1.104.2. This outline explicitly proposes the necessary native-envelope changes before implementation. Existing authorization, CountTokens bytes, original deadlines, fixed Sonnet4.6 profile, pricing, output bounds, UNKNOWN reservation and single-send/settlement owners remain authoritative. No Core file belongs to this work; dot owns Core integration with roster `b5071e81`.

## Canonical owners and bounded changes

1. Worker options: disable prompt caching through the supported setting and omit explicit effort through the pinned SDK's `unset` sentinel. Qualify accurate supported Sonnet model metadata while preserving the transmitted `meri-sonnet-qualification` alias. Do not adopt the undocumented negative capability experiment, disable accepted schema/tool features or mislabel the model.
2. Native body owner: admit only bounded opaque `metadata.user_id`, an empty tool list, and the exact beta enum subset `context-management-2025-06-27` / `effort-2025-11-24`, without duplicates. The accurate pinned-SDK capture also requires exactly `thinking:{type:'disabled'}` and numeric temperature `1`; retain prior numeric `0`, but refuse booleans and all other sampling values. Enabled/adaptive thinking, thinking budgets/extra keys, cache controls, effort/task-budget fields, semantic `context_management` edits and unknown betas/fields remain refused. These are explicit conditional envelope changes, not evidence of AWS support for this exact translated request.
3. Python send guard and independent JavaScript request owner: validate actual final native beta header values against that same closed enum and the body values. The header is optional because InvokeModel can carry body betas. If present, exactly one nonempty header must contain at most two unique admitted enums with ASCII space/tab comma padding and the same set as the body. Retain refusal of duplicate/mismatched/unknown feature headers and all `x-amzn-bedrock-*` service-tier/latency/guardrail/trace headers. Do not rewrite a signed request or change bytes between inspection/count/reservation/send.
4. Structured output: the SDK success contract is `result.structured_output`; `StructuredOutput` is its terminal internal tool, not an external operation grant. Permit this name only with an explicit immutable schema binding from trusted server composition. Require its exact schema, bounded content and existing tool allowlist; an SDK/worker-provided name or schema is never authority. Likewise a native `output_config.format` branch, if emitted, must be format-only and match that trusted schema. Default composition without a schema continues to refuse structured-output requests. The local fixture may supply that binding explicitly; production per-run schema custody must be wired before claiming selected-skill readiness. Other MCP/tool policy remains unchanged.
5. Native response owner: if the SDK beta produces context metadata, allow only a documented absent/null or exactly empty `applied_edits` observation. Any applied/unknown/malformed edits retain UNKNOWN liability. Cache, usage conflicts, truncation and unsupported blocks remain UNKNOWN. No automatic refund or retry send is added.
6. Terminal release: actual SDK negative controls found that refusing only the final ASGI body is too late once translated terminal events escape. Gate terminal native bytes in the existing settlement transport until complete observation and canonical settlement acknowledgement/read-only reconciliation. Preserve early text streaming, bounded storage, exact request/response bytes, cancellation cleanup and UNKNOWN liability. No replacement accounting owner is introduced.

## Verification and evidence boundaries

First prove one actual SDK plain-text request: real pinned translation/guard, exact-byte CountTokens stand-in, canonical JS reservation, one provider transport stand-in, complete SDK parse and one canonical settlement. The fixture must admit a valid synthetic allocation large enough for the unchanged8192-token maximum; do not mutate stored allocation rows or production prices to make it pass. Then prove schema-valid `structured_output` using the exact trusted fixture schema and SDK terminal-tool path, or the supported native-format path if actually emitted.

Focused refusals cover beta/header mismatch and duplicates, unauthorized tool/schema changes, cache at semantic locations, nonempty context edits, malformed/conflicting usage and late/truncated/lost-ACK outcomes. Retain all failed controls and distinguish multiple logical SDK requests from one reservation/send for a request. Run affected tests only; do not repeat unrelated broad gates.

Loopback ingress, provider/count stubs, IPC owner channel and scripted SQL remain local stand-ins. Product private owner HTTPS, real PostgreSQL, actual Bedrock request acceptance, exact image startup and live chat are separate gates. No build or rollout begins before the sole shipping owner's coordination receipt; deployment/chat HOLD stays active.

Production schema custody is an explicit remaining dependency for selected structured runs. Default unselected chat uses no outputFormat; Objective runtime availability alone does not activate it. The production session resolver, app/session limit equality and CountTokens policy currently share a static trusted limit. Binding a selected schema requires the existing canonical accepted-request source and authenticated owner tuple; a worker/tool declaration must never supply that authority. The local schema fixture qualifies only the explicitly bound partition.

## Semantics accepted on source review

- Provenance is keyed by the actual request object in the existing module-private WeakMap. The exact context object and Clerk subject are required; selected membership ID is preserved. No alternate membership is chosen. The new first slice refuses marked control credentials, impersonation, sidless claims, wrong targets and non-native credential schemes.
- Exact original user, tenant and membership rows are locked in a fixed order. User and membership predicates bind the selected actor; tenant and membership predicates bind the selected tenant. The user table is global; its `id` and Clerk subject are the relevant explicit identity predicates. Status/role/tenant predicates are subsequently evaluated using the unchanged local identity reader on the same transaction.
- `FOR SHARE` conflicts with row mutation/deletion. Under the published RepeatableRead transaction, a concurrently changed row can fail the transaction; the batch catch withholds authorization. This is source reasoning, not a real PostgreSQL contention result. Holding the user/tenant locks across an online call may block unrelated updates such as normal user lastSeenAt; the bounded transaction needs supported-environment contention/pool qualification.
- The fresh method calls the existing online Clerk owner again and then reads local identity through the supplied transaction, with no nested system lease. Published Clerk source checks original sid/sub, token expiry, session ownership/status and bounds, enforces a two-second refusal deadline and consumes late settlement. It does not physically cancel the SDK call.
- The unchanged local predicate checks original membership, active member/tenant, role/context equality, tenant/org/slug claims and expiry. The batch compares final principal/revision with initial evidence; limits expiry by initial/final evidence and receipt TTL; returns only after transaction commit. The wire owner checks expiry again after the batch returns, so a slow commit cannot turn an already expired decision into a wire receipt.
- The optional-transaction refactor keeps the old default `withSystem(read)` branch. No automatic call is added to normal authentication. Two existing authority-method tests cover the default and impersonation branches; they are not full middleware admission regressions.

## Honest remaining limits

No semantic TypeScript check, full Nest request-admission regression, real Clerk/SDK observation, real PostgreSQL RLS/grants/snapshot conflict/contention test or live request was run in this review. Local locks cannot make Clerk and PostgreSQL atomic. The exact-one selected-client restriction, missing production route, special-scope/scheduled custody contracts, complete transcript/lineage/cursor subject projection, native bearer relay and frozen-response final receipt integration remain unsolved by this patch and are correctly identified in the README. Do not weaken those restrictions to open history.

The protected middleware header requires Neo's explicit prior approval. The packet respects that boundary by proposing a patch against a scratch materialization; publishing an approval packet must keep its status accurate and must not imply that ordinary integration ownership grants auth-change approval.

The preparation migration fences deletion: an intent preparation row cannot simply be deleted and reused. Any content-retention extension must preserve the delivery tombstone and immutable correlation. Metadata and executor journals are separate canonical stores with different custody; do not replace one with the other.

## Minimal command integration

`apps/runtime/native-authority/execution-composition.mjs` currently selects only create_task: descriptor, task-create metadata owner, task-create command context, preparer, native source and execution options are hard-coded. `contextFor(proposal)` creates `clientResolution`, which is a task-specific context. `current-authority-adapters.mjs:POLICY_OPERATIONS` and `execution-capability.mjs:EXECUTION_COMMAND_ACTIONS` are also task-create-only. This is composition work, not a missing generic executor.

Extend action selection through a small canonical action specification and existing per-action validators/owners. Each action needs its actual trusted context, metadata codec, operation/output shape, preparer, source, current policy and execution-body binding. Keep one approval owner/store and one allocation/grant installation path. `commands/task-update-services.mjs` already composes task.update metadata/durable execution and is a useful existing owner to reuse rather than duplicate.

`commands/approval-metadata/task-kind.mjs` currently owns only task.create/task.update codecs; `binding.mjs` calls that codec for context, normalization, immutable payload and readback. Generalization must preserve the existing byte-level task metadata. artifact.file normalization returns `{arguments,attachments}`; do not wrap it into `{arguments:{arguments,attachments},attachments:[]}` or drop exact immutable attachments. The metadata SQL stores closed JSON payloads and has no per-action SQL allowlist; no replacement table is needed merely to add a codec.

### memory.propose

Use `runtime/product-ports/memory.mjs:commandSourceFor`, which already binds the governed memory producer to the original run, actual selected client, current scopes, canonical retention and native credentials. `control/memory/command-source.mjs` advertises `personalPending:true` and calls the canonical pending-candidate producer. It never publishes a memory entry. Memory candidate review remains a separate governed lifecycle.

The legacy HTTP memory route is not an equivalent producer: personal memory would auto-commit there, and `commands/source-http.mjs` deliberately refuses personal preparation. New conversational personal proposals must not be routed there. Preserve the existing memory read/proposal ports and durable continuation.

Client memory must match the trusted selected client. Personal memory must keep its personal subject; firm memory requires explicit firm authority. Do not derive firm permission merely from a selected client, model scope, or a generic active-member role. The current attended approval forwarder additionally expects a single client scope, so tenant/firm proposals require an explicit compatible authority decision rather than an inferred widening.

Pending text may be copied into memory candidates, approval metadata, command journal and intent preparation outcome. The existing central retention owner must cover each new copy, including suppression before read/replay; row deletion cannot erase the durable delivery fence.

### artifact.file

Keep `apps/artifacts/filing.mjs:createArtifactFilingResolver` as the exact-version resolver. It finds the canonical version for the selected immutable object in the current tenant/conversation; authorizes download, checks retention and bytes; registers those exact bytes with the trusted attachment broker; then re-inspects versions before releasing attachment IDs. Registration belongs inside the durable command claim. A failed registration attempt can already have left an attachment, so its outcome remains unknown.

At this base there is no production attachment registration broker or filing resolver composed in runtime. Do not invent a broker endpoint or register at proposal time. Core still owns the destination and attachment authorization.

There is a concrete token-contract dependency: rev3 `executionBodyBinding` validates TaskCreateArguments and computes `commandSourceBody(command,[])`. Filing's actual attachment IDs do not exist until after claimed registration, so broadening the action allowlist and hashing an empty ID list is incorrect. A reviewed contract must bind the immutable selected objects, trusted destination and registration receipt/actual source body without allowing an unbound attachment substitution. Keep filing unavailable until that producer/contract is supplied.

## Documents and analysis

The canonical document intent preparer already exists: `intents/document-preparer.mjs` validates request/admitted format, calls the existing artifact write owner with the stable delivery ID and null parent, validates ArtifactCreatedResult, and releases only a draft in the same tenant/actor/conversation. Once the owner is called, any error is unknown.

The missing base hook is composition: `execution-composition.mjs:intentMountFor` supplies only the create_task preparer. The documents owner is separately composed by `runtime/artifacts/authority-composition.mjs`, `product-ports/documents.mjs` and `artifacts/run-options.mjs`, but CLI does not supply `authorityPorts` at that point and never passes document preparers into the intent mount. Document preparation should not depend on task execution readiness.

The canonical runtime application (`runtime/artifacts/application.mjs`) is the correct bridge. It resolves the same late-bound document options owner against control's own action-session owner, carries actual current binding/scopes/client into Core artifact authority, uses the existing admitted run budget, and wraps every effect and release with current authority checks. Its fixed POST `/api/documents/create` accepts `{deliveryId,request}`; create's null parent is internal. The inner canonical application owns complete ArtifactCreatedResult validation. Do not call a local renderer directly or construct artifact context from model arguments.

Receiving extension `runtime/artifacts/intent-preparers.mjs` supplies the missing narrow bridge. Each call gets a current native credential for the exact trusted run/client, issues an ephemeral **derived** session, checks the complete binding/current selected client before dispatch, enters the canonical runtime application, and revokes only its own session in finally. The call deadline never exceeds the original native relay expiry. Before application dispatch, missing/current authority is a no-effect refusal; after dispatch all failures are UNKNOWN. The canonical intent journal owns replay/no-retry.

Bridge source commit: `06832fbec2b8551871967ed0aab5fdb33f50218d`, files `apps/runtime/artifacts/intent-preparers.mjs` and `apps/runtime/artifacts/test/intent-preparers.test.mjs`. Its dependencies are root session change `54e4c8b1` and artifact/analysis owner change `d750ae3791c51b15c4aa30f981c2067e4feaa633` (cherry-picked locally as `5ffa204f` and `8acbcad1`). It supplies Word, Excel and PowerPoint document preparers plus an artifact-owner run_analysis ZIP preparer with `formats:['zip']`; no sandbox owner is supplied. Root owns injecting these into the existing mount and binding the actual options/session/retention owners.

The session prerequisite was identified during implementation: ordinary issued sessions are eligible for `nativeCredentialFor`, which selects the freshest matching session. A bridge-created session would otherwise mask revocation of the original browser session. Root change `54e4c8b1` adds trusted-only `issueDerived` over the same canonical issuance state machine and excludes derived sessions from the native relay. The HTTP issuance route has no public flag. The bridge requires this method with no regular-issue fallback.

Word/Excel are the admitted base routes. PowerPoint needs the actual canonical format admission and fixed image generator dependency, not only a catalog toggle. ZIP analysis can reuse the same bounded immutable artifact application only after an artifact-owner preparer and typed result/release branch are added. General program analysis has separate existing owners (`apps/artifacts/{postgres-analysis,sandbox-analysis}.mjs`): mandatory immutable program/input scopes, exact admission receipt/manifest/image digest and trusted sandbox executor. No native sandbox port is composed at this base. Never present a ZIP/table generator as a qualified arbitrary-code sandbox.

The base intent mount OWNERS, worker `prepared.mjs` and control `result-release.mjs` have command/document/schedule branches only. An analysis owner therefore also needs a typed result and current release/custody branch, including truthful pending inspection/publication status for sandbox output. Do not mislabel pending sandbox output as an ordinary published draft.

## Focused validation plan

1. Metadata/custody: immutable prepare/readback for memory and exact filing attachments; tenant/actor/conversation collision, altered request/context/hash, expired proposal and current policy denial; PREPARED proposal reader admits each intended operation only.
2. Approval/execution: current Core decision is required; wrong/revoked/expired approver/session/grant, selected-client change and changed run binding all stop before effect. Token must bind the exact action, original normalized arguments, source-body representation, allocation and executor; stale task-only positive fixtures must not mask missing action correlation.
3. Memory: personal/client/firm subject boundaries, client mismatch, actual firm permission, only pending candidate output, retention suppression before metadata/result replay, no legacy personal auto-commit, no second proposal on UNKNOWN replay.
4. Filing: wrong conversation/version/object digest/bytes/scopes, suppressed output, destination mismatch, revoked source during registration and source-side partial statuses. Failures after registration are unknown; no re-upload on repeated delivery. Exercise the actual producer/token contract once supplied.
5. Document bridge: real runtime/document/session/budget/intent owners; canonical invalid input; missing owner/derived-session support; complete run/client checks; expiry/current identity denial; original-session revocation while derived lives; credential replacement; session cleanup; durable same-delivery replay; post-generation denial and lost ACK never regenerate.
6. Analysis: deterministic ZIP follows the canonical bounded artifact route and durable version custody; sandbox refuses without exact admitted manifest/image/receipt and native executor. Pending inspection/publication status and release suppression are preserved.
7. Run focused checks for changed owners, then the single receiving integrated suite.

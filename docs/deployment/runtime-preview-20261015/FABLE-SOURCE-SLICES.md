## Smallest implementation slices, all authored by Fable

These slices extend current owners. New module names below are proposed exclusive Fable paths, not implementations already present. Keep each independently reviewable and avoid a generic issuer/plugin framework. Parent integration reviews private interface changes before dependent composition; shipping implements the separate IaC/actual bindings. No duplicate product edit is assigned to this documentation owner.

**S1 - durable issuer adapter and trusted fact producer.** Keep `prepared-run-issuance.mjs` canonical. Add a cohesive runtime adapter such as `apps/runtime/prepared-run-issuer.mjs` plus `test/prepared-run-issuer.test.mjs`; split a persistence adapter only if that responsibility needs its own module. Compose an existing approved issuer if one is supplied; otherwise return the exact storage/opaque-material authority design before implementing persistence. Do not place issuer state in memory, next-run mapping or a second budget ledger. Any new SQL needs a separate central allocation; do not edit0009 or consume Fable's retention0010/artifact0002 IDs.

`issue` must durably claim the exact key before invoking the approved capability-generation owner, never generate a replacement on replay, and retain uncertainty across a crash at every boundary. Store only protected opaque-material references/required immutable facts in the appropriate owner; resolving an absent/expired/revoked/unknown value fails closed. Match the full intent on every method, atomically bind facts once, and prevent alternate request/fence/tenant/expiry from sharing a receipt. `sourceOwners.allocations.read` and `sourceOwners.admission.revoke` remain the current allocation/admission owners. The fact producer reuses existing compilers and trusted current policy; never serialize the raw proxy credential. Deliver a concrete storage/issuer port adapter, failure-state map and persisted restart tests, not another fixture-only implementation.

Acceptance: separate concurrent callers for the same key get one identity; conflicting requests refuse; process restart at claim/generate/material-store/receipt/fact-bind/ACK boundaries preserves issued identity or durable UNKNOWN without redispatch; resolve cannot regenerate; fact mismatch, expiry, revoked grants, unretired source or unproven physical stop refuse. Existing fixture tests remain unchanged and supplement real disposable-store tests. Tests issue only synthetic material within authorized local scope; actual provider/task credential creation remains separately bound.

**S2 - production startup composition.** Existing edit surface: `prepared-candidate.mjs`, its startup/config boundary and focused `test/prepared-candidate-*.test.mjs`; use a small explicit module such as `apps/runtime/prepared-run-bindings.mjs` to construct the concrete S1/admission/policy owners. Supply all three `runIssuance`, `issuanceIntent`, `admissionForBinding` ports through startup, not user-specified callback/module names in config. Reuse `createPreparedNextRunOwner`, registry, canonical next-run journal and admission factory. Closed config may describe reviewed static binding references; it must not instantiate a new authorization system or accept serialized secrets/functions. An explicitly requested multi-run mode with missing owner bindings must fail readiness rather than advertise success on the fixed first-run path. Preserve the separately supported first-run behavior and its existing controls.

Acceptance: the real CLI startup composition reaches these exact owners with explicit synthetic external ports; a genuine two-turn harness exercises issuance, accepted next-run selection, kickoff, checkpoint capture/readback, retirement and actual revocation. Recreate the control owner between turns to prove retained state, then replay the same request and prove no extra capability/RunTask. Refuse partial port injection, changed facts, current-policy denial and UNKNOWN. Do not call a composed harness live-binding evidence; label all external stand-ins.

**S3 - per-run bootstrap files and original transport.** Reuse `task-bootstrap.mjs`, `conversation-runner.mjs`, `prepared-run-registry.mjs`, `readSecret` and the original task verifier. Add a focused loader/materializer such as `apps/runtime/runner-bootstrap-files.mjs` plus independent tests; wire only the minimal startup seam. The plan's encrypted capsule is a proposed transport, not an accepted format. Fable and shipping must freeze the exact delivery/ref-selection interface first: trusted owner supplies an immutable binding to the actual original task/revision, existing issued capability reference, original expiry, versions, file destinations and private TLS/HTTPS receiver. The infrastructure owner supplies the actual capsule/DNS/certificate system; source owns validation, filesystem safety, correlation and lifecycle use.

For per-run routing, propose a narrowly named trusted resolver such as `runnerBindingForRun({binding,original,signal})` returning the exact run's `origin/http` and approved bootstrap reference; this is a **proposed new private port**, not a currently supported assembler/config field. Freeze its validated result into the original-run facts and registry entry through reviewed compiler changes. No arbitrary browser origin, mutable run remapping, cross-tenant lookup or old hostname rebound to a new task. Any effect of new transport fields on fact hashes must be explicit; do not alter independent expected hashes to hide a behavior change.

TaskRoleArn remains absent; no worker AWS SDK/DB/Temporal/provider account credentials. The loader starts no jobs on import, refuses pre-existing/link/foreign-owner targets, writes only fresh owner-only task paths, bounds sizes/deadlines, handles cancellation/partial failure and removes only owned material after required capture/physical retirement. Do not put values in RunTask overrides, evidence or persistent shared environment. If execution-role secret injection is chosen, clear the materialization environment before spawning the native process and prove no child credential inheritance; do not assume the current allocator can select a run-specific reference or grant control RegisterTaskDefinition silently.

Acceptance: wrong binding/task ARN/revision/cert SAN/expiry/version refuses; exact replay retrieves existing material without reminting; distinct next run gets its own immutable transport binding; symlink/overwrite/permissions/partial-write/cancellation/restart cleanup controls run on Linux. Exercise genuine pinned CLI bootstrap with explicit synthetic delivery/TLS ports, including denied trust and late/revoked capability. Live DNS/cert/secret delivery and actual target image remain shipping gates, not mocked passes.

**S4 - Temporal trusted-client authorization.** Existing shared edit surface: `config.mjs`, `control.mjs`, `temporal-worker.mjs`; introduce a focused shared owner such as `apps/runtime/temporal-authorization.mjs` and its tests instead of duplicating credential/metadata handling. S2 and S4 serialize edits to the same files under Fable ownership. Keep `temporalTls`'s mTLS pair and hostname verification. Extend the closed private config deliberately to describe the approved service-specific authorization reference and bounds; do not accept an unvalidated extra field or plaintext credential in ordinary config/logs.

Use the **actual pinned @temporalio client/worker1.24.0 declarations** to choose the supported authentication/metadata and refresh mechanism for both `Connection` and `NativeConnection`; expose one trusted token provider/reader to both. Existing call signatures above establish the missing seam, not a claim that any particular new SDK option is already qualified. Capture the chosen exact SDK API in Fable's design/compile receipt before integration. Bind issued tokens to the intended namespace/audience/issuer and finite expiry, bound refresh lifetime and shutdown, and keep signing authority outside clients. A trusted issuer supplies the token; decoding claims client-side never replaces cryptographic server verification. No retry with missing/old credentials or authorizer disablement on failure.

Acceptance: both actual pinned SDK client types compile and receive the selected authorization metadata with TLS; expire/rotate/revoke/cancel/close scenarios do not leak or prolong credentials. Real server qualification must deny missing/expired/wrong-audience/wrong-issuer/foreign-namespace tokens and exercise poll/complete/heartbeat. Trusted application clients require namespace write under the accepted default-authorizer model; never grant system-admin or route application calls to internal-frontend. The documented stock mapper issuer/required-exp limitations remain a server/ingress qualification dependency; do not claim the client adapter fixes them. Actual server controls remain UNRUN until permitted bindings exist.

# Remote original-task boundary author evidence

Implemented four cohesive modules in `apps/runtime/native-authority/`: `remote-task-boundary.mjs`, `remote-task-client.mjs`, `remote-task-http.mjs`, and `sdk-config-transfer.mjs`. Two focused tests accompany them. No parallel allocation, execution, registration, restoration, or grant ledger was introduced.

The configured controller receives only its pre-supplied control credential. Its standard launch/inspect/retire/readiness/registration/workspace ports return the existing canonical receipts after checking the response's full original tuple. The separate SDK process client receives only its original-task credential; its public stdout is read-only, stdin/stdout frames carry bounded bytes, sequence and SHA256, and it neither holds nor forwards a control credential to the CLI.

Prepared mode reads actual task-local SDK directories, obtains the canonical preparation ACK (original tuple, descriptor/config hashes, preparation UUID, actual task ARN, checked time, original lease), and only then creates the borrowed original IndependentTask. Canonical authorizer.start consumes the existing allocation launch latch and calls broker.start; the nested control launch boots the supervisor. Worker start verifies that original owner and releases its prepared CLI once. Optional authorizer.started records physical start. dispatch:false refuses release. Parked workspace operations require admitted proof before and after the borrowed filesystem operation.

Legacy already-compiled mode remains available. Raw configuration transfer is optional and preserves exact absolute SDK paths and uninterpreted file bytes, directory/file modes and empty directories. It refuses links, overlaps, invalid manifest hashes, overwrites, unsupported files, excessive payloads and observed tree mutations. Reads are fixed-size and final readback covers every observed file, directory and membership. No JSONL decoder or new persistence owner exists here.

`remote-boundary-final.json` pins the tested six source files and command; raw stdout/stderr are adjacent. Tests cover the role split, canonical unwrapped ports, one boot/one release, sequence/hash rejection and lost-ACK byte replay, synthetic canonical preparation ACKs, parked workspace admission, consumed-latch refusal, close-before-start, late-response retirement and raw configuration boundaries. One control uses a genuine separate IndependentTask supervisor and native Node fixture child to establish registration from its actual stdout. Authority responses remain synthetic in this focused suite. This is not actual Claude SDK, PostgreSQL, deployed Fargate, TLS or full-project acceptance.

`mount-config-corrected.*` records a separate fresh nonroot UID1000/network-none container qualification. Caller and physical receiver use the same compiled absolute SDK path while different backing mounts have distinct inodes. Raw bytes/modes/empty-directory readback matches the original tree digest. The owned container and exact fixture root were removed. This proves that raw configuration transfer does not depend on shared caller files or pathname rewriting; it does not qualify a remote native process or deployed isolation.

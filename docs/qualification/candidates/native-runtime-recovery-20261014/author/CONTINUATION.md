# Continuation integration evidence

Base: PR76 `f855af6e1096894909b201603b2f77e5e6230f5f`. Source is an integrated working candidate awaiting root freeze and independent acceptance.

`continuation-runtime.mjs` joins the current canonical verifier's scopes and selected client to `store.read` and `store.lifecycle.execution`. It compares all four runner continuation hints to persisted inputs before dispatching restoration, reuses `buildContinuationOptions`/`assertRestoreReceipt`, pins the restored main SDK key to the persisted resume/fork target, and rechecks authority/persisted facts after the borrowed owner returns. Worker receipt fields/accessors are refused. Fresh persisted targets reject continuation hints; persisted resumed targets reject omitted hints or a missing native restore owner.

The borrowed native restore owner interface is `{restore, registration:{read}}`. `restore` receives a stable `restoreKey` over the canonical target inputs, along with the original binding/version/checkpoint/request/scopes; it must durably deduplicate physical restoration and preserve UNKNOWN after uncertainty. `registration.read` must supply a genuine independent pre-query native observation. The canonical SDK session owner alone validates and persists this observation. The existing non-null SDK-session factory registers before loading/querying; no SDK factory changes or synthetic init events were added.

This adapter integration does **not** implement opaque SessionStore/workspace restoration, native checkpoint object transfer, or the independent pre-query bootstrap observation producer/transport. No current production native owner implements the borrowed interface. Restored bytes and a correlated JSON receipt do not establish native provenance. Continuation remains fail closed without those implementations and qualified bindings.

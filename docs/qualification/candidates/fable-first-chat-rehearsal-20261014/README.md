# First-chat rehearsal, step 1: real SDK launch descriptor against the remote launch gates

Three receipts written by `scripts/qualification/first-chat-rehearsal/capture-sdk-descriptor.mjs` at this slice's head. The tool builds the product SDK options with `buildConversationOptions`, lets the pinned SDK 0.3.295 call its spawn hook once, records the descriptor (command, argv, cwd, env with secret values hashed), and runs it through the remote launch gates without spawning anything: inert JSON (`data()`), presence of the per-task config directories, the presence of a secret inside the env, and `compileNativeLaunch` with directories injected.

- `sdk-descriptor-capture-pr86-options.json`: the PR86 option builder (an exact copy of `apps/worker/conversation/options.mjs` at `c6053e2` was passed with `--options-module`; the receipt's `optionsModule.path` names that origin). The inert-JSON gate fails on `undefined` env entries.
- `sdk-descriptor-capture.json`: the option builder at this head as the committed composition calls it (no directories supplied, `proposedDirectoriesSupplied: false`). The inert-JSON and compile gates pass; the config-directory gates still fail and the proxy credential is still inside the env.
- `sdk-descriptor-capture-with-proposed-directories.json`: the same option builder with `--with-proposed-directories`, which supplies the per-run directory pair in the shape the unapplied runner patch would derive (`<config parent>/sdk-<runId>` and the intent's secure storage directory). Every directory gate passes; the proxy credential observation (gap 3) remains.
- `proposals/gap2-runner-sdk-directories.patch`: the runner-side change for gap 2 and its three-control test, retained unapplied because `apps/runtime/conversation-runner.mjs` is a pinned proof row. Applying it requires dot's proof-row decision; see the finding report.

Reading: see [the finding report](../../../coordination/reports/FABLE-REMOTE-LAUNCH-DESCRIPTOR-FINDING-20261014.md). No process, network, provider, database or credential was involved; the proxy credential in the receipts is a synthetic string recorded only as a hash. The composed end-to-end rehearsal with the real CLI was not run; it is blocked on the runner-side directory injection and the launch-template credential decision.

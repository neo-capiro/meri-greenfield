Root owns canonical preparation SQL/migration, allocation, broker-stack composition and final source freeze. No delegate commits or parallel database/storage owners.

Responsibilities:

- `native-restorer.mjs` reads pinned immutable ObjectReferences through existing `objects.get`, verifies exact byte counts/SHA256, uses the canonical `store.restorations` claim before filesystem effects, and records RESTORED/UNKNOWN. Unacknowledged claims and UNKNOWN never dispatch again. RESTORED replay rechecks original intent and filesystem/object bytes without rewriting and issues a fresh bounded readback receipt.
- `workspace-restore.mjs` maps the existing manifest's constant logical `/workspace/conversation` to the trusted configured task workspace; all paths remain canonical relative file paths. The original workspace must be exclusively owned, quiesced and empty for the first write. Symlinks, unexpected files/directories, hash changes and executable changes refuse. Writes are exclusive, fsynced and read back; failure cleanup removes only newly created matching identities. Caller owns the workspace directory. Limits reuse established native bounds: 256 files, 8MiB per workspace file, 32MiB aggregate workspace data. Filesystem validation does not qualify host isolation or prevent a hostile ancestor owner; the approved trusted/quiesced namespace remains necessary.
- `checkpoint-snapshot.mjs` consumes the **existing** SessionStore snapshot-array representation recognized by `verifySessionStoreSnapshot`: `[{entries},{subpath,entries},...]`. It reuses inert opaque-data copies, canonical scoped keys and readback validation. No native JSONL codec is invented. `meri-native-session-files-v1` bundles are explicitly refused by this SessionStore path. Bounds are 256 streams, 100000 aggregate entries and 32MiB aggregate opaque entries (34MiB envelope bound).
- `continuation-runtime.mjs` keeps the canonical target/scopes/client joins, restores only canonical persisted context, and rechecks authority before writes and afterwards through an internal callback. The snapshot endpoint accepts only the fixed current binding and original task capability; it derives the immutable checkpoint from persisted lifecycle state. Worker-selected checkpoints and keys cannot establish snapshot authority.
- `session-http.mjs`/`session-client.mjs` add a bounded private `/v1/runner/session/snapshot` read without expanding operation vocabulary. Authorization uses the existing canonical `load` operation on the exact binding. Opaque entries use the established SessionStore codec, not ordinary depth64 data decoding.
- `sdk-continuation-session.mjs` returns immutable source `load`/`listSubkeys` before native initialization, resolving pre-query registration circularity. The first supported SDK target append triggers canonical registration and then exact source-history seeding plus current writes, behind the existing registration acknowledgement. Only **actual `tasks.registration`** may supply the independent init/main witness; no restorer or worker JSON fabricates it. Fork source reads preserve the source session identity; all writes use the target session identity. Sequential bounded seeding and ordinary bound-session appends preserve the UNKNOWN barrier. Query lifetime is separate from short preparation lifetime. Root updates the runner to forward `runtimeSignal` for continuation.

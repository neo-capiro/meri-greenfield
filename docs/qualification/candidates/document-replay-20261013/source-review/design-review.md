Trace: the durable producer validates delivery/facts/operation/raw request and stores `owned_<v4 UUID>` plus original deadline before reservation. Its bound reservation atomically claims one invocation. Artifact generation binds full `{request,context,baseVersionId}`, commits an immutable `{version,spec,specSha256,requestSha256,inspection}` record and settles its exact digest/ticket. A completed repeat currently reaches reservation again; the owner refuses a second claim, but no typed artifact result-recovery path exists. The local store publishes a separate head after immutable file creation, so existence of a version file alone cannot prove successful publication. Historical reconciliation can settle UNKNOWN marker accounting and always returns `resultDelivered:false`; it is not current release authority.

Required boundaries for the implementation:

* Keep the new observation private and non-mutating. Validate immutable invocation/facts/request/arguments, reservation and completion lineage under the canonical lock, clipped to the retained original deadline. Do not repurpose historical reconciliation as release authority or silently change its `resultDelivered:false` contract.
* New Word/Excel version identity may derive only from the validated server-owned invocation UUID. Keep per-delivery producer identity; identical request hashes from separate deliveries must not correlate. Validate the original ids() allocation before overriding its version identity; recovery must preserve the retained artifact/object IDs and must not call ids(), newReservationId, executor, put or commit.
* The current journal contains no separately persisted artifact/object allocation. For a pre-marker published record, exact invocation version UUID plus retained full intent/record/publication is the available binding; do not claim an additional independent allocation proof. Root acknowledged this distinction and intends to validate allocation before the new version override, then preserve verified retained IDs on replay.
* Legacy recovery needs unique matching full immutable commit digest from the original completion marker. Validate record filename/version identity, full request/context and exact parent, complete version binding/scopes/evidence, object hash/bytes and inspection. Never find a completion by request hash alone.
* Require actual head or descendant ancestry publication evidence. Reject orphan records, cycles, missing/foreign nodes, wrong artifact identity, conflicting candidates, over-limit scans/bytes/depth and unsupported storage adapters. Use fixed bounded lookup and the original deadline, not a new lease. A descendant head may prove the earlier result remained published without reverting the head or recommitting it.
* Current capability/policy/session and artifact resource authority must be checked before releasing any result, and again after byte inspection/settlement. Preserve original ticket and record/inspection; only the release receipt is refreshed. A smaller current output budget, revocation, scope or source/base change must withhold the result without refunding uncertainty or touching retained artifacts.
* PREPARED with no reservation may use the normal path because the existing reserve-before-generation order prevents a prior effect. Any reservation with no exact published result remains UNKNOWN. For concurrent initial repeats, canonical reservation claiming selects one generator; for concurrent published-result recovery, reuse only canonical same-marker idempotent settlement. Never create a second reservation or derive a new effect from absence observations while another operation may still commit.

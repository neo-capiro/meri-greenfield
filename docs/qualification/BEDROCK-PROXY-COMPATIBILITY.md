# Bedrock proxy compatibility: LiteLLM 1.104.2

Prepared 9 October 2026. **Static compatibility candidate; G1 remains open.** LiteLLM OSS supplies machine virtual keys, Anthropic-to-Bedrock streaming and usable pre-call extension points. It does not, by configuration alone, establish active ECS task/run/fence authorization or the user's hard $10 aggregate ceiling. Qualify the existing upstream budget mechanism before implementing any replacement; retain a trusted durable hold for costs that its estimator/cleanup cannot bound.

This review fetched public source/metadata in memory and read the local frozen contracts/SDK declarations. It launched no proxy, database, Hermes session, cloud resource or model call, and fetched no credentials. No current Capiro implementation was used. Only this finding file was written. D004 remains authoritative: synthetic data, approved US-only Sonnet 4.6 profile, $10 aggregate model-test cap; application services in account 967807252336/us-east-1. Availability/entitlement observations establish no invocation result.

## Admission hooks and current authority

Use an instantiated OSS `litellm.integrations.custom_logger.CustomLogger` subclass registered by `litellm_settings.callbacks: admission.handler_instance`. The exact signature is `async_pre_call_hook(self, user_api_key_dict, cache, data, call_type)`; Anthropic requests arrive with call_type `anthropic_messages`. Registration accepts instances/dotted instance paths without an Enterprise gate. Common processing awaits it before creating the provider task; exceptions re-raise. Raise an explicit denial/error rather than returning a string, which can become a synthetic successful-looking response. [Callback loading](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/common_utils/callback_utils.py#L382), [hook dispatch](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/utils.py#L2497), [pre-call ordering](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/common_request_processing.py#L2189).

The hook can call a trusted broker transaction to check key-to-task/run binding, active membership/policy, current attempt/worker/fence and reserve budget before forwarding. That is a proposed integration, not built-in LiteLLM business authorization. Token metadata and request headers are untrusted attribution. Require independently authenticated task/peer identity from the new transport/broker; possessing a stolen bearer token plus matching JSON must not authorize another task. Fail closed on missing identity, broker/database outage or unknown state. New workers get a new key after binding/fence update and the old key is denied before expiry. The <=30s revocation target remains proposed and must be agreed/measured, including already-running streams.

`async_moderation_hook`/during_call runs concurrently with the provider task, so it cannot safely reserve cost or prevent an unauthorized paid call. Streaming extension points include `async_post_call_streaming_iterator_hook(self, user_api_key_dict, response, request_data)` and per-chunk hooks; cancellation on revoked runs needs a bounded active-state watcher, including silent upstream intervals, not merely checks when chunks arrive. General custom_auth can replace native validation and defaults to skipping common checks unless `general_settings.custom_auth_run_common_checks:true`; prefer native virtual-key auth plus the pre-call extension for this qualification. [During-call/provider concurrency](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/common_request_processing.py#L2578), [stream hook signature](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/integrations/custom_logger.py#L522), [custom-auth default warning](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/proxy_server.py#L6524).

Frozen CapabilityClaims contains no inference action and permits only meri-gateway/meri-broker audiences. A separate broker-to-proxy opaque inference grant must be designed/approved against unchanged RunBinding/Budgets; this finding allocates no shared schema change or new audience/action.

## Budget reservations: adopt, then close the gaps

The OSS module `litellm/proxy/spend_tracking/budget_reservation.py` implements `reserve_budget_for_request(request_body, route, llm_router, valid_token, team_object, user_object, prisma_client, user_api_key_cache, proxy_logging_obj, end_user_id=None, end_user_object=None, apply_user_budget_to_team_keys=False, fail_closed_budget_enforcement=False, raw_body=None) -> dict|None` and `reconcile_budget_reservation(budget_reservation, actual_cost, finalize=True)`. Auth common checks invoke reservation for LLM routes including /v1/messages. It is not merely post-call spend tracking. [Reservation module](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py#L248), [auth integration](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/auth/user_api_key_auth.py#L3013).

Required candidate settings: `general_settings.fail_closed_budget_enforcement:true`; do not set disable_budget_reservation:true. Non-strict defaults can continue on reservation write failure and reduce an over-budget reservation to remaining headroom while still allowing the request. Use one non-resetting qualification team's max_budget=10 covering EVERY task key, with lower per-key limits if needed; never mint an independent $10 allowance per attempt. Global litellm.max_budget is a cached aggregate read check, not one of the atomic reservation scopes. Unknown/nonpositive cost estimates return no reservation even under strict mode: admission must explicitly deny these cases. Native dollar counters use floating-point arithmetic; the authoritative application ceiling remains safe integer 10000000 microUSD. [Strict policy](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py#L165), [unknown-estimate bypass](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py#L294), [global read check](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/auth/auth_checks.py#L778).

Reservation estimates count input and bound requested/default output at the model ceiling, using the higher ordinary/reasoning output rate. They do not apply cache-creation surcharges in this path. The pinned US Sonnet4.6 cost entry includes distinct higher cache-write rates, so ordinary-input estimates are not a worst-case billing bound. Those source prices are evidence of the estimator gap, not accepted current AWS prices. Bound or reject cache creation/other unqualified charged features; freeze actual Bedrock prices and token limits before paid tests. [Estimator](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py#L1310), [model cost entry](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/model_prices_and_context_window.json#L2803).

Counters are cached; shared Redis uses atomic increments, while no-Redis synchronization is in-process only. Postgres holds key/team/accounting state, but an outstanding reservation is not a durable per-request transactional ledger merely because a Prisma database exists. Redis lease renewal refreshes counter TTL at default_ttl/2 while the request remains active, bounded by request_timeout; after task death/abandoned cleanup the plain TTL can expire. Settlement precedes enqueueing this request's spend to the database. Freeze the effective counter/auth TTLs and test replacement/startup/reseed and Redis loss before trusting the cap across processes. Do not add a second proxy process without a proven shared-counter topology. [Lease renewal](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py#L112), [counter implementation](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/proxy_server.py#L3658), [in-process synchronization](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/db/spend_counter_reseed.py#L111), [settlement/DB ordering](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py#L1069).

Cancellation settles to estimated input cost and releases worst-case output; reconciliation converts a missing actual_cost to zero. The release_or_invalidate_budget_reservation failure/refusal cleanup path releases to zero and may invalidate counters when cleanup fails. This is not proof that an ambiguous upstream response produced no billable output/cache write. Preserve a durable broker upper-bound hold when usage/final status is unknown; do not release it merely because LiteLLM refunds a counter, the stream disconnects or its TTL expires. Success, pre-dispatch rejection, provider error, post-dispatch timeout and unknown outcome need distinct reconciliation evidence. No automatic retries or fresh-budget resets. [Reconciliation/cancellation](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py#L380), [failure cleanup](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py#L451).

## Enterprise boundaries relevant to this design

OSS virtual keys, ordinary key/team max_budget, the reservation module and generic CustomLogger hooks have usable source paths without a premium gate. Relevant features that must not be assumed OSS include JWT/OIDC authentication, per-model key model_max_budget, and Enterprise named guardrail callbacks (for example Llama Guard/secret detection). SSO/advanced managed capabilities need their individual license checks; this is not an exhaustive feature/license audit. Generic custom hooks are sufficient for a proposed trusted admission adapter; do not import enterprise modules to obtain them. [JWT feature limit](https://docs.litellm.ai/docs/proxy/token_auth), [per-model budget premium check](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/management_endpoints/key_management_endpoints.py#L7822), [callback premium checks](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/common_utils/callback_utils.py#L203).

## Smallest viable qualification topology and next ticket

Propose one NEW private Fargate proxy task running one process, one NEW Postgres store with separately authorized LiteLLM and trusted-broker state, and the NEW trusted broker/admission function. Inference ingress exposes only the reviewed Messages route over authenticated TLS; management is reachable only by the broker/operator plane. The proxy task alone has the selected Bedrock invoke role. Conversation tasks have no upstream/admin/database role or key and reach only the proxy/broker paths permitted for their own task. Decide/qualify authenticated task identity before invocation; network location or caller headers alone do not bind a bearer token to an executor. A durable broker reservation/unknown-charge hold is required before any paid test. Add NEW shared Redis before multi-process/replica proxy qualification; even then prove failure/reseed/persistence rather than treating cache atomicity as durability. This is a proposal, not deployed infrastructure or production topology acceptance.

Recommended correction to the draft W02-02 task, for Codex to approve: preserve its bounded offline scope, exact paths, frozen contracts and no calls/deployments; inspect/adopt native virtual-key and strict shared-team reservation primitives first. Add deterministic fixtures for unknown-estimate bypass, cache-write underreservation, TTL/process loss, cancellation settlement, semantic stream errors and feature stripping. Keep the local policy model explicitly a reference for missing business checks, not a replacement gateway/ledger. Actual custom-hook integration and durable broker persistence should be separate bounded tickets after interface review. This review did not edit the draft.

Live acceptance still requires actual SDK text/local-tool round trips, exact approved profile invocation, fine-grained tool/usage/cache streaming, unsupported-beta/parameter rejection, semantic errors after HTTP200 and missing terminal events, revocation during quiet streams, key expiry/block/delete across caches/replicas, concurrent caps, disconnect/process-kill/restart with unresolved holds, IAM/network denials and proxy/state outages. The source SSE generator emits errors after streaming has begun; HTTP200 alone cannot establish success. SDK/client error handling, cancellation and retry behavior remain unverified. Current browser/worker findings are separate; no W03 promotion or cutover. [Stream failure path](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/common_request_processing.py#L3941).

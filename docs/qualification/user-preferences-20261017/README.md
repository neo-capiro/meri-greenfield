## Proposed fixture correction — NOT APPLIED

In `apps/control/settings/user-application/test/postgres-qualification-fixture.mjs`, the identity query uses `inet_server_addr()::text AS address`, then requires `identity.address === '127.0.0.1'`. PostgreSQL16 documents that an explicit inet-to-text cast includes the netmask; the host-only address needs `host(inet_server_addr()) AS address`. Retain the exact host, port and database comparison; do not accept arbitrary hosts or remove the guard.

This is a source diagnosis supported by [PostgreSQL16 network-address documentation, Table9.40](https://www.postgresql.org/docs/16/functions-net.html): `text(inet)` includes the mask, while `host(inet)` omits it. The denied diagnostic rerun did not obtain a fresh SQL address row. The before-hook failure is consistent with this definite query/comparison defect, but the original scrubbed diagnostic alone does not distinguish every possible setup failure. Obtain independent review and a new exact source checkpoint before correcting or rerunning it. The portable wrapper detects the known original expression and stops before initdb; it does not fix the test.

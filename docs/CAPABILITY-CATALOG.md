`Catalog.originals` carries the complete native ID, accepted disposition, explicit boundary, replacement reference and mapping state. Selected entries may remain `pending` with `replacement:null`; deferred entries stay `deferred` with `replacement:null`. Mapped entries require an exact registered operation/version. The validator rejects unknown/duplicate IDs, disposition changes, missing replacements, contradictory aliases, canonical-name shadowing and replacement cycles. The 139 count is a preservation obligation, not a target for exposed tools or an operation-count budget.

`OperationDescriptor` supplies stable ID/version, precise when-to-use and positive/negative examples, limitations, source authority/purpose, immutable input/output schema references, aliases, side effects, required grants, approval boundary, handler source identity, availability/qualification, bounded retry taxonomy, replacement and R/REL/RG/fixture mappings. Metadata marked `enabled` must include a qualified handler reference; that consistency check is not evidence that a handler exists or passed policy. The trusted catalog publisher must independently verify the actual closed input/output schemas, handler bytes, fixtures, current availability and description dependencies before exposure. The foundation has no operation invocation API, free-text `query_data`, SQL/table escape hatch, arbitrary loader or lexical router.

Read, proposal, local artifact, application schedule and source-command effects remain distinct. An alias cannot preserve a broad old mutation under a narrow new name. `save_memory` selects sourced proposals only; canonical confirmation/correction/deletion remains deferred. Artifact creation does not authorize Capiro filing. Application Temporal schedule intents do not imply parity with Capiro's schedule store. `update_task` remains selected scope, but the existing 0.1 Command enum does not acquire an update action here; its new typed command and compatibility gate remain required. All commands still need immutable approval, current authority, fencing, idempotency and actual outcome receipts.

For unavailable operations, discovery must return a stable limitation and preserve pending/deferred status. Descriptions and skill manifests must not require absent recipes. Catalog/handler/schema drift, precise domain examples, native SDK deferred-discovery/proxy compatibility and real authorization remain later REL-02/03/05 evidence. Decisions and JEV remain disabled optional experiments; this catalog adds no classifier or agent loop.

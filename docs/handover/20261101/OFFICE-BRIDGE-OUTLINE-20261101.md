# Same-document manual + Meri Office editing bridge — implementation outline (1 November 2026)

Branch `fable/office-bridge-20261101` from `main` 7888a2c5. Frontend twin: `fable/office-bridge-fe-20261101`.

## Admission path (the one owner path a model proposal takes to a new immutable version)

1. **Read** (`propose_office_edit` with `action:'read'`): the run's selected document (`documentRevision` on the submit request) is read through the existing office access owner (`createRuntimeOfficeAccess`, intent `download` for the read, `revise` for a proposal so a user who may only download never holds a proposal whose Apply could only fail; current Core artifact authority, retention, exact bytes). `apps/artifacts/office-units/*` parses the retained OOXML with the existing strict ZIP/OPC/XML readers and returns an addressable outline: `docx` paragraphs (`p:<n>`), `xlsx` cells (`<sheet>!<A1>`), `pptx` slide text shapes (`slide:<n>/shape:<id>`). A management-style read: no journal row, no proposal.
2. **Propose** (`action:'propose'`): the control preparer (`apps/control/intents/office-edit-preparer.mjs`) re-reads the exact selected version, applies the bounded operations to the retained bytes in memory (only the touched units change; every other package part and every byte outside the touched XML element spans is copied unchanged), requires each operation's `before` to equal the current unit text, inspects the result with `inspectOfficeEdit`, and settles a PREPARED proposal `{kind:'office_edit', proposalId, commandSha256, document:{artifactId,versionId,objectSha256,format,title,filename}, summary, operations, result:{partsSha256,parts}}` into the existing intent journal (`meri_intents.preparations`). The pinned digest covers the decompressed parts (name and content, in name order), not the packed bytes, so a zlib or Node change between propose and Apply cannot read a valid proposal as a mismatch. Nothing is written.
3. **Apply** (`POST /api/conversations/intents/decide`, `decision:'approved'`): `approval.mjs` dispatches `office_edit` proposals to the office owner (`apps/artifacts/edit-sessions/apply-proposal.mjs`) under the approver's attended session, with the signed-in principal required and compared to the proposal's actor: current revise authority again, exact parent bytes again, `history` head check (`OFFICE_EDIT_STALE_HEAD` before any write), deterministic re-application whose parts must match the pinned digest (`OFFICE_EDIT_PROPOSAL_MISMATCH`), then `createPostgresArtifactService(...).executeOfficeEdit` with a `meri.office-proposal/1` source (`officeProposalSource`): the same verified-bytes publish, commit CAS on the exact parent head (`ARTIFACT_STALE_PARENT`) and artifact intent journal replay (delivery `office-proposal:<proposalId>`, so a repeated Apply returns the same version and never writes twice; recovery binds to the package digest the publication recorded). `decision:'rejected'` goes through the same owner (`rejectOfficeEdit`) and settles the same journal row `FAILED {code:'REFUSED'}`: a reload or another tab lists `rejected`, a later Apply answers `rejected` without writing, and the opposite decision after a settled one is `APPROVAL_DECISION_REFUSED`.
4. **Reopen**: the FE receives `{status:'office_edit_decided', result:{proposalStatus:'applied', version}}`, reloads library history and opens the returned version.

Refusal codes the UI explains in words (no code, identifier or hash in the person's copy): `OFFICE_EDIT_STALE_HEAD` (document changed since Meri read it), `OFFICE_EDIT_PROPOSAL_MISMATCH`, `INTENT_EXPIRED`, `OFFICE_EDIT_UNIT_UNKNOWN` / `OFFICE_EDIT_UNIT_CHANGED` / `OFFICE_EDIT_UNIT_UNSUPPORTED` at propose time. A private editor draft open elsewhere is not refused server-side (Core has no draft-by-artifact lookup); the real outcome is the later conflict when that draft is published first, and the catalog and UI say so.

`EDITOR_TYPED_REVISION_UNAVAILABLE` stays only for ordinary typed replacement of an office-original/office-edit/office-proposal parent (a regenerated typed body cannot preserve manual OOXML); its message now names `propose_office_edit`.

## Gates removed (lower layer proven)

- `publish-draft.mjs` re-inspected draft bytes and re-checked sha/length and pptx workbook count: the Core draft wire receiver already refuses a byte/sha/length mismatch (`core-draft-wire.mjs savedBytes`), WOPI save is the only writer of draft bytes and refuses a workbook drop before `save` (`wopi-files.mjs`), and `service.generate` inspects the bytes again before any object write. A draft Core retained before the WOPI gate existed could still lack a chart workbook, so the workbook rule now lives once in the artifact owner (`service.generate` compares the parent's inspection with the revision's for every retained revision, editor Publish and proposal alike) and settles the artifact journal row `FAILED {code:'REFUSED'}` instead of unknown.
- `attended.mjs admit()` inspected base and draft bytes on every open/launch/renew for the same workbook rule: same lower layers.

## Tests

- `apps/artifacts/office-units/test/office-units.test.mjs`: outline per format; apply keeps every untouched part and every untouched span byte for byte (the manual edit beside the touched unit survives), determinism, the closed refusals (unknown unit, changed text, unsupported unit or kind, section-break and last-cell-paragraph deletes, formula cells, field shapes); a replacement keeps every run outside the change with its own properties (partial bold/italic, tabs) and a page break stays a page break; a paragraph inserted after a section-ending one carries no `sectPr`; a leading zero stays text; an edited workbook sets `calcPr fullCalcOnLoad` (set on the existing element or placed in schema order) so dependent formula caches are recomputed; a shape kept in both `mc:AlternateContent` branches is one unit whose edit rewrites both copies, and a fallback-only shape refuses.
- `apps/runtime/artifacts/test/office-proposal.test.mjs`: the actual runtime office owners end to end for DOCX, XLSX and PPTX: governed read (no journal row), prepare (same delivery replays), Apply through the approval owner publishes one version whose parts match the pinned digest with a `meri.office-proposal/1` record, a repeated Apply replays without a second write, the item lists `applied`, rejecting an applied proposal is refused, a later typed replacement of that version is refused naming the bridge; a manual Publish in between makes Apply answer `conflict` / `OFFICE_EDIT_STALE_HEAD` without writing; reject settles durably (a fresh owner over the same journal lists `rejected`, Apply from it answers `rejected` without writing, the row outlives a later head change); a tampered digest or foreign actor is refused before any owner call; every prepare refusal keeps its exact code. The composed owner (`createOfficeIntentOwner` over the live transcript and borrowed attended session): no preparer without a selected document, read under download but no proposal under revoked revise authority, a missing or foreign principal and a proposal bound to another conversation refuse `ACCESS_DENIED`, revise authority revoked between propose and Apply answers `EXECUTION_AUTHORITY_REFUSED` without writing, and an expired proposal answers `INTENT_EXPIRED` for both decisions and at the owner.
- `apps/artifacts/edit-sessions/test/publish-draft.test.mjs`: bytes the WOPI gate never admitted are refused by the artifact owner before it claims and settle the Core draft as refused; a legacy draft that dropped a chart workbook is refused by the owner, settles the journal row as a definite refusal and replays that refusal on retry without a second claim or any write.
- Contracts: `retrieval-catalog-current-versions` and bindings at catalog 0.2.32, the public intents distribution admits the `office_edit` item and the `office_edit_decided` answer (`check:generated` clean).
- Frontend (`fable/office-bridge-fe-20261101`): `tests/office-edit-view.test.ts`, `tests/office-ask-meri.test.ts`, browser spec `tests/browser/office-bridge.spec.ts` (entry → proposal → Apply → reopen, and Reject) over scripted owners.

## Live-only

A real Collabora image (the custom cp-26.04.5-2 build is not yet startup-qualified), WOPI save/reopen fidelity of the rewritten packages in that engine, the Core office-drafts routes on the deployed clone, and browser acceptance X02 (manual edit → Save → Release → Publish → Ask Meri → Apply → reopen with both edits) remain live-only. The editor dialog withholds Ask Meri while an editor is open or a saved draft is unpublished; a draft opened in another tab is not refused server-side (Core has no draft-by-artifact lookup), and publishing it first makes the proposal a conflict, which is what the catalog and the card say.

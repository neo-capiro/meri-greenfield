Browser physical-scope successor currentness, 30 October 2026

The browser remains in its original native process/network scope after the old
SDK query is gone. Its old run binding must not recover SDK or Bash authority.
This change derives browser-only continued authority through the existing exact
lifecycle continuation chain to the latest logical run, in the same transaction.
It adds no table, registry, migration, public request field or new authority.

Interface for canonical host routing owner
journal.browserCustody.currentHost(client,{binding,scopes,selectedClientId,
allocation},check). binding is the physical browser's original full RunBinding.
The caller supplies fresh Core-derived conversation/member/client scopes, a
validated canonical host allocation and a bounded acknowledged transaction. The
method takes the existing conversation advisory lock, validates the source APPLIED
hold and pinned checkpoint, reads the latest canonical run, and validates every
intervening takeover.end through the existing readExecution owner. Each edge must
have its exact APPLIED source hold, returned snapshot, same actor, owner instance,
host generation, policy hash and bounded original expiry. No ordinary resume or
next-prompt relationship substitutes for this browser custody chain.

An open source hold returns phase browser-held. A current successor returns phase
browser-successor and browserSuccessor:{binding:logicalTarget}. Both return the
original physical binding, browserCustody and currentUntilMs, with browserAdmitted
true, sdkAdmitted false, bashAdmitted false, capabilityPolicySha256 null. Only
queued/starting/running successors or a valid newer browser takeover hold remain
eligible. Terminal, ordinary-paused or closed current targets refuse. The existing
host-currentness store permits these phases only for browser purpose, validates
the exact resource identity and successor shape, and retains all certificate,
nonce, policy, expiry and acknowledged-COMMIT checks. Source SDK/Bash stays denied.

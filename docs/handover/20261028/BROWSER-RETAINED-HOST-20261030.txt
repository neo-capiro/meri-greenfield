Browser retained host source integration, 30 October 2026

Purpose and outline
Extend the canonical takeover hold through worker drain, actual SDK absence,
retained browser ownership and an exact private filtered return snapshot. The
browser context remains one context; the SDK remains the only model loop.
Use existing control custody, not a second hold journal or a revived SDK query.

Implemented behavior
The worker fences browser calls before interrupting the SDK, drains terminal
usage, closes the query, proves SDK-child absence, records the native checkpoint,
and only then grants the user lease from the exact APPLIED takeover.begin receipt.
The host launcher retires SDK/broker children separately from the browser child;
uncertain absence destroys the host. Browser currentness remains bounded while
SDK and Bash authority are closed. Ordinary pause/approval cleanup is unchanged.

The native host exposes prepareResume(binding,custody). It checks fresh authority,
ends user input, captures one filtered snapshot, retains the exact object privately,
and returns only owner/epoch/digest. Concurrent retries share the capture. It stays
fenced in returning. The viewer controls cannot call an independent resume method.
Browser lease expiry is reported as an absolute time bounded by host/session expiry.

Native integration finding
Actual pinned Playwright MCP schemas carry hidden implementation properties. The
in-process upstream bridge now applies normal bounded MCP JSON wire serialization
before returning those values to the strict model relay. Without this correction
actual SDK discovery connected but returned zero tools. The actual SDK now lists
the browser_snapshot tool through the native authenticated broker.

Context ownership
Ordinary source read/reissue and renewal after expiry/control restart pass while
paused without creating a successor. APPLIED browser custody also preserves exact
ordinary reads. Fresh identity/context transition now accepts takeover.end with
the same target checks as resume; it still cannot select another run. Once the
canonical successor exists the old binding is stale, not evidence of lost tenant
membership. Parent owns the HTTP/frontend handling of that distinction.

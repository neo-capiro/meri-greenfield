## Current authorization remains a separate obligation

The existing Meri Portfolio path requires a nonarchived conversation owned by the current tenant/user and a validated stored scope receipt, then resolves the current portfolio grant. The general Portfolio loader and the review reader's private grant helper are different paths. The existing detail method additionally filters denied client links/events through clientMemoryAllowed. That behavior must not be inferred for every review/snapshot locator: their viewer read does not establish per-evidence source permission, quotation provenance or all-linked-client visibility.

Reuse the accepted standalone `ResearchPortfolioContext` (`RunBinding` plus `ResolvedSubject`) and its canonical subject/binding assertion, requiring exactly one research-portfolio entity and the current conversation. Never let caller review/snapshot IDs choose tenant, actor, portfolio or grants. Current source inclusion, linked-client wall, archive/revocation and underlying locator visibility must be source-owner policy checks at execution/resume. The trusted DTO context records identity correlation; it grants no current access.

A useful concrete API is a new discriminated evidence read over the single resolved Portfolio subject, with named review, retained snapshot and current-continuity variants. Each variant must have exact source identity, bounded selectors/page ownership and truthful per-carrier returned/omitted/unavailable coverage. Raw member and historical carriers must be separately named in its coverage ledger until their read design is established. No review management, assignment, scoring, snapshot creation, continuity refresh, provider retrieval or arbitrary locator execution belongs to this read.

# §6 conversation, stream and recovery coverage map at PR86 (slice 6)

Base `c6053e24b465be677cc5980533009b4aab03beab` (PR86). Author: Fable. Purpose: map every requirement sentence of HANDOFF §6 ("Conversation, stream and recovery work Fable must finish/qualify") to the controls that exist at this base, say what kind of evidence each control is, and list what is missing with a proposed bounded control and its owner. Test names are quoted from the test sources; counts in parentheses are the number of controls in that file. Nothing here is a new acceptance claim: a control listed as "real-PG" ran against the disposable local PostgreSQL 16 clusters of the Fable baseline (`docs/qualification/candidates/fable-local-baseline-20261014/`), and a control listed as "real-CLI" is the composed rehearsal with the unapplied gap 2 proposal (`docs/qualification/candidates/fable-first-chat-rehearsal-20261014/composed/`).

Evidence levels used below:

- `scripted`: in-process controls with scripted SQL, Temporal, identity or native ports.
- `real-PG`: controls that require the local PostgreSQL 16 clusters (`*-pg.test.mjs`, `execution-broker`, `runnable-runtime`, `native-preparation`, `read-optional-pg`, `prepared-execution-claim-pg`).
- `real-process`: controls that fork the actual supervisor, launch an actual child, or bind an actual HTTP listener.
- `real-CLI`: the composed rehearsal with the pinned CLI 2.1.295 and the gap 2 proposal applied to the working tree only.
- `UNRUN`: needs an owner binding (identity, provider, Temporal server, image, live frontend) and is not claimed here.

Classification: `covered` (the sentence has at least one control at the stated level), `partial` (controls exist but a named aspect is unexercised), `missing` (no control found).

## 4. Gaps, proposed bounded controls and owners

1. Concurrent runs and follow-up turns in one conversation. Design gate: the slice 2 proposal (`FABLE-FOLLOWUP-TURNS-PROPOSAL-20261014.md`) must be accepted before code. Proposed control once accepted: two queued runs in one conversation admitted in sequence through the existing opaque session, with the second run's `writerFence` higher and the first run's late publication refused (real-PG).
2. Pause, steer, resume, fork and restore with the real CLI on the composed path. Gaps 2 and 3 are now in source after dot's review, so the composed path runs without a patch; what remains is the parked turn. A zero-turn prompt cannot be paused or steered mid-turn, so these also need a parked model turn: either a qualification-only loopback provider stand-in behind the `https:`-only proxy rule (a task-local CA in the launch template, which is a configuration shape dot must approve) or the real provider route (live gate). Owner: dot for the shape, provider owner for the route.
3. Admitted task dies mid-query. Proposed control on the composed rehearsal: kill the kernel-pinned CLI leader after the first stdout frame and assert a durably `failed` run, `physicalStopProven: true` by `/proc` readback, and refusal of a second dispatch by the journal. With the zero-turn prompt the window between the first frame and the CLI's own exit is a few hundred milliseconds, so the control also needs the parked turn of gap 2 to be deterministic. Owner: Fable once gap 2 is decided.
4. Usage accounting of failed, cancelled and retried model turns. Live gate: needs the provider route and budget pin (HANDOFF §5 item 6). Proposed control: three runs (completed, cancelled after first delta, provider error) and the product budget ledger showing one reservation and one settlement each with no refund on UNKNOWN. Owner: provider/budget owner, then Fable.
5. Replacement admission while the original task is alive. Proposed real-PG control on `meri_conversations.native_allocations`: a second `claim` for the same conversation while the first record is `ADMITTED` with `launchBinding.state = STARTED` must refuse, and succeed only after the first is `RETIRED` with `physicalStopProven: true`. Routine implementation within the approved journal; Fable can add it without an owner decision and will propose it in the next slice if dot agrees the ordering is the intended invariant.
6. Sequence and gap controls of `store.test.mjs` against real PostgreSQL: done in this slice as `apps/control/conversations/test/store-pg.test.mjs` (14 controls, green with the local cluster; `conversations-tests` 147/147). Routine; no owner decision was needed.

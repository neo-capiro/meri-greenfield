## Complete identity binding, without worker authority

Use one immutable trusted registry record per admitted attempt. It binds the public RunBinding fields `tenantId, actorId, conversationId, runId, attemptId, workerId, writerFence` to the exact qualification binding `run_id, attempt, worker_arn, fence, policy_revision`, native session ID/project namespace, source/image/SDK/CLI/contracts/skills/checkpoint versions, original run deadlines, permitted operations/scopes and the current grant. Integer qualification attempt1/2 is not a canonical UUID attemptId; task ARN is not a canonical UUID workerId. A trusted registry supplies this explicit mapping; never cast or infer them from model/header strings.

The driver currently passes exactly `{runUuid,sessionId,attempt,fence,operation,deadlineMs}`. The adapter checks every field against its immutable, owner-supplied phase descriptor; the service then independently resolves the actual peer/grant to the complete registry binding. Do not add authority to this small driver context. Native init must match the registered SDK session identity; bind the actual SDK observation, not a model claim or most-recent session. This proposal creates no IDs or authority record.

Reuse the current grant semantics: current run, active unexpired grant, exact task/attempt/fence/policy, capability hash and current scopes. Canonical capabilities distinguish `meri-gateway` and `meri-broker`; a model inference key does not automatically grant either checkpoint or source access. The new transport must validate its own audience/actions rather than broaden IngressAdmission. `session.persist` and `workspace.persist` already exist; exact read/resume operation semantics need root freeze because the action enum has no separate `session.read`. Do not silently treat persistence permission as unrestricted history access.

Actual peer identity remains a trusted composition prerequisite. Current PeerLease contains private IPv4, observation time, typed qualification binding and grant ID, with30s freshness; constructing it proves no ECS ownership. The server must use verified socket/TLS metadata and a trusted ECS/current-worker observation, reject authority/forwarding headers and duplicate credentials, and refresh current state. No worker receives DB, S3, provider, Temporal or administrator credentials. Task-bound short-lived channel capability is the existing plan boundary, not a new general credential.

## Concrete proposed request/result boundary

The following are draft interface fields, not accepted new schemas or operational routes. Root should freeze them through the canonical contracts owner before dependent source. Fixed authenticated HTTPS POST routes under `/v1/qualification/sdk-interruption/` are an ordinary proposed transport choice; no arbitrary URL, method, SQL, object key or caller-selected loader is exposed. Authorization stays gateway-owned and persistence broker-owned even if a trusted deployment later hosts their routers together.

All requests carry `{channelVersion,requestId,operation,context}` and only the operation-specific payload below. `context` is the exact six-field driver context. requestId is correlation/idempotency data, never authority. A mounted immutable descriptor fixes the exact trusted endpoint, TLS trust/hostname, public/source versions, audience, phase mapping and limits; credential contents stay separately mounted and out of bundles/events/logs. Do not derive endpoint/trust/identity from the model or ambient overrides. Server time, current peer and registry remain authoritative; worker deadline fields cannot extend the original clock.

Success replies must be closed typed records with complete source/version/request bindings. DENIED is content-free and has a finite reason code; UNKNOWN explicitly prevents publication/resume/retry with a new idempotency identity. No arbitrary exception text, credential, storage URL, transcript or workspace content belongs in public status. Raw synthetic/native evidence follows the existing bounded private capture/public exporter boundary. Restored content is delivered only to the authorized worker channel, not the model as an authority token.

The current driver only supplies a partial file bundle. A native entrypoint cannot make the complete commit succeed by returning an ObjectReference. It must compose the canonical SessionStore/workspace/quiescence dependencies first, or keep the experiment on HOLD. A separately labeled diagnostic upload may retain partial evidence, but must use a distinct result type and never enter the complete Checkpoint/verify success path.

The same broker transport must expose these fixed data operations to the thin SDK-facing adapter; these are not model tools. Keep the public SDK signatures unchanged: append(key,entries) resolves void only after a known commit, load(key) returns deep-equal entries or genuinely never-written null, listSubkeys({projectKey,sessionId}) returns the complete bounded subkey set. Wire append adds an explicit batch correlation, expected prior committed ordinal, exact SessionKey and opaque entries; its reply binds that batch/content to the assigned committed ordinal. Wire load/subkeys adds the exact checkpoint read-view identity for resume so concurrent/newer writes cannot silently change the restored snapshot. All keys are constrained to the trusted registry namespace, including session subpaths, and reauthorized server-side. No arbitrary project traversal or generic object listing.

For the existing driver's bundle argument, a fixed `checkpoint.restore-data` operation can privately return the exact authorized immutable native-file bundle plus workspace objects/manifest belonging to the verified Checkpoint. The thin entrypoint obtains these through the broker, validates complete identities/bounds, then supplies the bundle/reference to runInterruptionPhase; it never follows a worker-supplied storage URL. Verification is repeated under current authority immediately before restoration/query. The Checkpoint's single opaqueSession ObjectReference may reference a versioned immutable session snapshot/manifest containing the complete SessionStore/subkey data and required native session files; exact snapshot format/coverage must be root-frozen and compatible with the SDK. Do not infer complete native format coverage by parsing unknown transcript fields or make raw transcript capture a replacement persistence system.

Suggested finite policies for root review, not accepted production limits: retain native-session-files ceilings256 files/512 members/8MiB per file/32MiB total/depth12; bound its base64 JSON transfer to48MiB; bound each SessionStore append/load chunk and explicit page/count/total snapshot coverage separately before allocation. A paged read can only report complete after all fixed-view pages are accounted for; unknown/truncated data refuses restore. Derive request deadlines from remaining original phase/run time, reserve teardown inside C, and never adopt the SDK's60s mirror timeout as permission to exceed the original deadline. Full product corpus/workspace limits and retention still require measured policy; this outline does not shrink them to fixture ceilings.

## Persistence and atomic fence/publication

The trusted broker stages opaque session/workspace bytes into owned immutable versioned objects, verifies exact version/bytes/hash and inherited scopes, and then publishes one canonical Checkpoint in authoritative PostgreSQL. `ObjectReference.objectId` resolves server-side to an owned storage object; workers cannot supply arbitrary S3 keys/buckets. S3 object creation is not the atomic checkpoint commit, and a prepared object left after failure must remain unreachable from a verified checkpoint.

Publication and fence advancement require the same authoritative serialization boundary: acquire current-run lock, evaluate current time/grant/policy/scopes after lock acquisition, verify the exact admitted producer binding and parent checkpoint, then atomically bind the idempotency key to the complete checkpoint digest, durable receipt and event sequence. Advance/revoke/fence and append/publication must use the same lock order. An early `GrantAdmission.check()` followed by an independent write leaves a stale-writer race and is insufficient.

Existing qualification code illustrates this correctly within its own domain: Grants.set_current_run/create_pending/activate/revoke and GrantAdmission.check all acquire PostgresStore.budget's singleton `FOR UPDATE` lock; current time is queried after the lock wait. It does not set SERIALIZABLE isolation and has no checkpoint table. Do not claim an unimplemented checkpoint transaction is already protected. Root must allocate the migration/transaction integration; adding a second current-run table or auth ledger is not proposed. Product W05 authority cannot simply be relabeled from qualification state0001.

Known UUID session entries may deduplicate only with identical content; UUID-less opaque entries must remain ordered and cannot be discarded by hash. Batch identity, committed ordering and ambiguous-ACK reconciliation need a stable transport boundary. The public SDK retries rejected append calls and supplies no batch ID; identical UUID-less batches can be legitimate distinct appends. Do not infer retry identity from content. A wrapper must quarantine ambiguous appends and deny further progress until exact reconciliation; a new ID must not hide uncertainty. The exact SDK retry/drain integration is an implementation prerequisite, not solved by this outline.

SessionStore load must return the full deep-equal opaque entries; compaction/unknown fields survive. listSubkeys is required for full subagent restoration. Unknown-key null is only valid for genuinely never-written keys; a required checkpoint's missing/corrupt/partial state is refusal, not a new empty session. The existing SDK mirror is best-effort after bounded failure (`mirror_error` drops a batch); result/close/process exit and eager mode are not a durable receipt. A trusted complete drain watermark and snapshot coverage check are required before sealing. W05 session listing/summaries/deletion/retention remain in full scope.

Checkpoint preserves original producer binding. Replacement verification checks stable tenant/actor/conversation/run and authorizes the new attempt/worker/fence separately; do not rewrite old provenance to attempt2. Recheck every contributing stored scope and tombstone/restore barrier. Verify exact image/SDK/CLI/contracts/skills/checkpoint compatibility, canonical workspace hash and safe workspace paths before fresh exclusive restoration. DurableReceiptId is backed by a committed authoritative row, not accepted because a caller supplied a UUID.

## Native experiment ordering and limits

The trusted owner admits task A and original D=t0+720000/C=t0+900000. The existing phase bound remains at most60s; no checkpoint/HTTP retry allocates a new run clock. A observes genuine init and active SSE marker, calls real Query.interrupt, closes/drains its native child, and supplies raw session data. Trusted control must establish complete native/subagent/workspace quiescence and SessionStore durability before publishing the complete Checkpoint. Child/connection close alone is not physical task termination or full quiescence.

Before B, positively contain/observe task A STOPPED, revoke its grant/advance the shared fence atomically, and admit a distinct actual task/attempt binding. The driver calling authorize(staleContext) from B is only a stale-context request control: it does not prove a real retired worker credential is denied. Preserve a separately controlled actual old-credential/old-binding request at the real trusted boundary; it must not be granted a fabricated peer identity. Root must freeze the safe evidence method. B verifies the original complete checkpoint under current authority, restores fresh state, reauthorizes, and uses real SDK resume; loopback emits continuity only after exact earlier and resume user blocks appear in actual Messages history. Positively stop/contain both tasks by the original deadlines.

Existing native one-RunTask graph cannot implement this two-task sequence by default. The separately reviewed named profile must retain source/image/definition/version/task/tag/ledger bindings, attempt-before-mutation, no mutation retry, original D/C and UNKNOWN cleanup behavior. No actual graph/IAM/admission is authorized here. The fresh packaging-only image is unscanned/unpushed/runtime-unadmitted;49+5 security findings remain open. No model/provider execution is required to prove synthetic loopback continuity, and none occurred.

## Implementation outline and shared interface

Extend the existing fixed native POST adapters to admit an explicit client UUID without a truthy folder. Keep the actual native ResearchService/Phase8 feature, membership, folder and memory-wall owners; preserve the original flat request and frozen receiving normalizers. The existing bounded native handler continues to own correlated credentials, transport, limits and the five-field private carrier. A selector establishes no current authority.

The legal context module will export `assertLegalSliceRequest(operation, raw)` and `legalSliceContext(operation, raw)`. The latter returns exactly `{clientResolution, citationResolution:null}`. The news context module will export `assertNewsSliceRequest(operation, raw)` and extend `newsSliceContext(operation, raw)` with the selected UUID in `clientResolution` and `effectiveScope.clientId`, keeping the other four context fields unchanged. Existing strict `assertUnscopedLegalRequest`, `assertUnscopedNewsRequest` and `legalLegislationContext` remain compatible.

The two families share pure `captureResearchClientSelection(raw)` and `assertResearchClientSubject(authority, resolution)` exports from the existing legal context module. The capture returns null for no selected client, otherwise `{reference,clientId}` only for an exact UUID after the native trim/clip80/trim passes. It never resolves a name. The subject guard requires exactly one client identity and its matching client resource for a selected UUID; the null branch cannot broaden a client subject. Both source handlers guard the exact request-derived context and subject before transport credentials. Coordinator independently rechecks the actual current native visible-client roster and current run grant through its existing owner before execution and release. No new permission or persistence owner is introduced.

Focused delta tests will exercise UUID case/whitespace and clipping, actual JSON/raw forwarding and proof correlation, exact context/subject coherence, unsupported names/folders/citations, forged resolution/effective scope, receiving substitution and native failure propagation. Fixtures will synthesize the same exact client subject, scopes and visibility interface used by the other native families. Existing tests will change only where UUID behavior intentionally expands; unchanged baseline cases are coordinator-integrated once.

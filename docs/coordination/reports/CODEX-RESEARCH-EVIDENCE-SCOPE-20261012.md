## Concrete API proposal for review

Proposed cohesive module `research-portfolio-evidence.schema.json` / `research-portfolio-evidence-validation.mjs`, URN `urn:meri:retrieval:research-portfolio-evidence:0.2.0`, factory `createResearchPortfolioEvidenceValidators({validateShape,assertSubject,canonicalSha256})`. Reuse canonical inert admission and the existing Portfolio context; root owns loader/registry. Do not edit or duplicate existing Portfolio/BizDev validators.

The proposed caller Request has optional matching `conversationId` and a required named `origin`. Review/snapshot branches select one exact source-record ID; current continuity has no ID/historical/clock selector because the actual read exposes only current defaults. It never supplies portfolio/tenant/actor authority. Normalization derives portfolio identity from the single trusted subject. Review/snapshot exact-record projection is new Meri behavior. Do not invent native pagination: retain whole admitted records or refuse oversized data; current continuity preserves its100-decision guard and current latest-target selection. Returned data is `{binding,subject,data:{origin,records,coverage}}`, with a discriminated, full typed projection for each approved carrier and per-carrier eligibility/continuation/qualification limits. No generic entire-result JSON or union that erases carrier identity; unknown JSON is allowed only in the exact stored locator/evidence/version interiors that are untyped upstream. SourceRevisionId remains an ordinary source string, not an invented UUID.

Three grounded candidate variants are retained review evidence, retained snapshot evidence, and current continuity/decision evidence within the actual authorized selection boundary. The latter is a current read projection and can synthesize `persisted:false` evidence; it is not an immutable history API. Each must retain parent identity/revision/observation fields alongside its evidence so that identical source references from different records cannot be merged or misattributed. Refuse unknown/foreign requested records; do not turn withheld or unsupported carriers into global absence. Coverage is limited to the explicit origin/selection; no whole-portfolio completeness from an empty page. Source dereference, byte fetching, calculations, review decisions, assignments and writes remain outside this read.

**Remaining bounded owner/interface decision:** establish whether the complete selected new read means all already projected retained evidence (reviews, snapshots and the bounded current continuity/decision exposure), or also raw member evidence and older decision/continuity storage. For the latter, the Portfolio source owner must name the exact read projection and current grant/client classification; the existing DTOs do not prove it. This is an exact source-inclusion/exposure decision within the already selected intent, not a request to reapprove all basic Portfolio reads. The independent reviewer should check the census against additional projected carriers before root freezes a complete mapping. A useful partial implementation may follow that review, but the original `get_research_evidence` row stays pending/null until the whole accepted evidence boundary is implemented and independently tested. No coverage narrowing is hidden in this proposal.

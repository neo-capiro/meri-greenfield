## Result for independent source review

The extension is implemented on the isolated branch. Canonical version commits now require a trusted tenant-bound publication owner, the existing raw journal, and the canonical retention gate. Missing owners refuse before SQL. The service passes its already validated receipt and original budget ticket through a third internal commit-port argument; the owned document adapter adds the actual original `owned_<version UUID>` invocation identity. The existing storage envelope, version wire fields, allocation contracts and SQL migrations are unchanged.

`artifact-publication.mjs` validates the full bounded tenant-purpose history and its derived heads. One conditional document write retains the immutable decision and advances the exact expected parent. Original receipts remain immutable on identical replay. Competing children, changed storage bytes, changed original invocation, stale SQL projection, expired authority, terminal barriers and incomplete/conflicting facts refuse. Retained evidence never grants authorization. Durable ACK precedes SQL insertion/head projection. Unknown durable/SQL ACK remains UNKNOWN; these owners contain no renderer, source-object put, allocation remint or autonomous retry. Only a proven native 412 permits another bounded CAS attempt. Owned service recovery continues through the existing canonical budget invocation path.

The native S3 transport is shared with accepted preview evidence while each purpose keeps its own validators, namespace and key. Publication uses `meri.artifact-publication.proposal-1` at `<existing prefix>/artifact-publication/<canonical tenant hash>/index.json`; preview custody retains its accepted separate purpose/key. Full-body checksum, expected account, KMS identity, enabled bucket versioning, native version readback, bounded stream cleanup and delete-marker refusals remain enforced. Defaults remain disabled. The canonical factory is exported by `storage/index.mjs`; no credentials, bucket, policy, key or client is created.

Ordinary reads and publication compare a single joined SQL statement snapshot with CURRENT complete durable facts, including unseen later versions. No local high-water cache or preview history can establish the current head. A valid empty history cannot bless existing SQL: reads/publication refuse unexplained rows, and recovery inventories existing tenant artifacts and refuses unrecorded cutover state. There is no baseline import path in this change. A separately verified explicit cutover remains required for legacy artifacts, otherwise unavailable.

`versions.recoverExclusive(signal)` is one continuation INSIDE the existing raw `journal.exclusive`, after canonical retention recovery and before that owner's serving fence opens. It restores exact retained immutable records and ONLY the durable current head, then checks the current complete facts again. It reuses canonical `journal.readProjection(c,key)` on its existing transaction lease to check suppression before and after restoration. Suppressed conversations/artifacts and durable terminal markers are skipped without restoring purged rows. No deletion or purge permission is added. Unexpected rows, bindings, hashes, lineage, incomplete facts or lost COMMIT refuse. Existing tenant/conversation prerequisites and the canonical retention repair must already be current.

The preview source recovery adapter delegates to that canonical owner and compares historical claim records with recovered decision hashes; it no longer inserts records nominated by preview claims. `versions.readExclusive` is internal metadata validation for that SAME recovery exclusion, still checks current suppression and publication facts, and is not exposed by the user-serving artifact wrapper. Preview projection decoding uses it only during explicit recovery. All ordinary serving uses the normal gate. The concrete preview composition returns the same canonical versions owner and refuses all its methods before IO when disabled.

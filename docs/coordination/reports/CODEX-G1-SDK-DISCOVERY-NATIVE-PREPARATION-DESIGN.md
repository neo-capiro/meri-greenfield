## Findings that determine the next implementation

The accepted `sdk-capture.mjs` is a real, measured native **echo** fixture. `runCapture` at line855 directly constructs the old options and permission callback, expects exactly two requests/one callback/one echo handler, and drops intermediate SDK messages after checking for a result. `createLoopbackServer` at line508 hardwires the echo request classifier and response planner. `buildWireServer` at line790 uses always-load=true. Merely importing the new options cannot change this behavior. The canonical decoder `scripts/sdk-capture/request-validation.mjs` also requires exactly one advertised echo tool and the old prompt. A discovery transcript must have its own versioned semantic validator; changing the old frozen decoder or labelling a new transcript as an accepted echo capture is wrong.

There is a concrete image-import prerequisite: `sdk-discovery-options.mjs:4` reads `../../../../packages/contracts/validate.mjs`. Dockerfile lines146,168–169 copy the qualification package and probes to `/opt/meri-worker`, without that repository-relative contracts tree; qualification package.json has no contracts dependency. That relative import would resolve to `/packages/contracts/validate.mjs` in the image. Rebind through the **existing public** `@capiro/meri-contracts/node` export and an owner-produced, hash-pinned packed package in the reviewed build context. Include its complete runtime dependency closure and new source/archive/inventory pins. Do not copy another validator, fetch an unpinned package, or assume source-tree tests prove image resolution. The private package can be packed and installed as a local reviewed artifact; no public registry publication is necessary.

The pinned SDK declaration supports public `tool(name,description,schema,handler,{searchHint,alwaysLoad})` and `createSdkMcpServer({name,version,tools,alwaysLoad,timeout})`. Server always-load is applied at registration; it is not an extra field on the returned SDK server configuration. Use the two descriptors in `DISCOVERY_FIXTURE` as the sole fixture-description owner. Supply `alwaysLoad:false` at server creation and on both tools, with the existing 5000ms per-tool timeout. SDK runtime DATA shows false is represented by absence of an always-load=true metadata override, whereas searchHint becomes `anthropic/searchHint`. Retain actual registration/list-tools DATA to establish the resulting metadata, not an invented `_meta:false` expectation.

`sdk.d.ts:1636–1644` says `tools:[]` disables all built-in tools. It does **not** identify whether the native search meta-tool is included in that category or inserted independently. The inspected `sdk.mjs` recognizes ENABLE_TOOL_SEARCH but contains neither ToolSearch nor tool_reference; it delegates native behavior.

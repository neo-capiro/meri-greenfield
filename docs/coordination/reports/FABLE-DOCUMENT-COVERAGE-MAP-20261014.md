## 5. Owner inputs and proposed controls

1. Signed URLs. Decide whether downloads stay session-authorized application responses (the PR86 shape, already covered) or whether a presigned-URL surface with expiry and revocation is required. If required, it is a new owner surface in `apps/artifacts/storage` and `apps/control/document-application` and needs a proposal before code. Owner: dot.
2. Deletion and retention. No retention policy or deletion owner exists for published artifact versions, transcripts, events, uploads, browser state, previews, telemetry or backups, and no control proves that an authorized restore cannot revive revoked or deleted access. Proposed: a retention/deletion design proposal (schedule-driven, journaled, never physically deleting an UNKNOWN-liability record) for dot's approval, then real-PG controls on the conversation and artifact schemas and an object-store control through the borrowed S3 adapter. Owner: dot for the design, then Fable.
3. Human quality rubric and benchmark files. The §10 thresholds (100% files open, at least 95% rubric, zero critical corruption/clipping) need the labelled benchmark set and a human review protocol. Fable can produce the structural and render receipts for every benchmark file with the existing local-artifact tooling once the set is supplied. Owner: QA owner for the set and rubric.
4. Real object store. The S3 adapter controls run through an injected handler. One real-bucket run (dedicated bucket, versioning on, KMS key, immutable-version head/get, conditional replay) is needed for the live column and must be performed by the shipping owner with the output grant; Fable prepares the exact command sequence from `s3.test.mjs`. Owner: shipping.
5. Browser and renderer hosts. The dedicated isolated browser host (D005) and the renderer host must be freshly read back and run through the existing probes for this base; the historical G1 receipts qualify nothing here. Owner: shipping for the hosts, then Fable for the probe runs.
6. Executor and library paths in the image. The Python/Office executor paths, LibreOffice and renderer resources inside the admitted image are image-qualified evidence and are UNRUN while the PR86 image is scan-blocked. Owner: shipping (image), then Fable.

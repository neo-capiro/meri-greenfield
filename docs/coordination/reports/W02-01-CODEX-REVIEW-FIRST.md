## Concrete required repairs

Paths and line numbers below refer to the reviewed commit under `apps/worker/qualification`.

1. **Historical apt metadata and CA bootstrap — Dockerfile:30-48.** The fixed September security snapshot is older than its normal Release validity window. Both fixed deb822 sources need source-scoped `Check-Valid-Until: no`, keeping `Signed-By` and normal package/signature verification. [Debian snapshot instructions](https://snapshot.debian.org/) explicitly document expiry handling. The first apt operation also uses HTTPS without explicitly establishing a CA bundle. The [exact upstream Node 24.9.0 Dockerfile](https://raw.githubusercontent.com/nodejs/docker-node/212028f3d223af165e090e0318ca9dee35dc2210/24/bookworm-slim/Dockerfile) installs temporary CA/download tools and subsequently marks/purges unused packages. Do not assume CA availability from the base tag: establish it deterministically, such as a pinned CA package bootstrapped through the fixed signed HTTP snapshot before switching to HTTPS. No TLS or signature bypass.

2. **Sandbox helper preparation — Dockerfile:103-105,119.** `chmod 4755` precedes recursive `chown 10001:10001` of the browser tree. The final helper loses intended root ownership/setuid configuration. Keep the immutable browser install root-owned and assert final helper identity/owner/mode. Pinned Playwright core maps Debian 12 Chromium to CFT `chrome-linux64.zip` (installed `coreBundle.js`:34059,34121); `component-pins.json` instead records the older `chromium-linux.zip` path. [Upstream Chrome automation documentation](https://github.com/puppeteer/puppeteer/blob/main/docs/troubleshooting.md#using-setuid-sandbox) calls the downloaded helper `chrome_sandbox`. Exact archive contents/name and effective installation must be inspected; the current hyphen-only `find` must not be assumed correct. This review did not download/execute the browser archive.

3. **Actual Chromium identity — probes/browser.mjs:65-83,186-189.** The process finder matches any argv element containing `chromium`; the MCP Node server itself qualifies because its argv contains `--browser chromium`. Taking `procs[0]` can label MCP's requested `--sandbox` as effective browser evidence. Identify the real executable and this run's associated browser/renderer process tree; retain every relevant PID/argv and corroborating `/proc` information. Requested config is insufficient.

4. **Pinned MCP framing — probes/browser.mjs:159-183.** Installed pinned Playwright `coreBundle.js` `Response.serialize` (67279-67324) emits Markdown `### Result` sections; the evaluation handler (68119) puts `JSON.stringify(result)` inside that section. `JSON.parse(toolText(...))` over the complete response fails. Falling back to framed/escaped text is not decoding the sandbox page, and config parsing similarly fails. Parse the exact Result payload or use a supported saved/structured result. Reject missing, duplicate, malformed or error sections and wrong decoded types. Preserve raw bounded responses. Regression fixtures must include the actual framing, escaped newlines and code section.

5. **Sandbox rows and final browser verdict — probes/browser.mjs:36-53,198.** The global negative regex rejects a disabled unused SUID alternative even when namespaces and Seccomp-BPF are active. Parse known rows/values independently; require a supported namespace OR SUID layer plus active Chromium Seccomp-BPF, rejecting missing/ambiguous evidence. Also make every required navigation/evaluation/cleanup failure authoritative; the final verdict currently filters only reason strings containing `fixture` or `download`. Capture effective flags across the associated process tree and reject disabling flags.

6. **Office conversion and nested verdicts — probes/artifacts.mjs:65-79,124-137.** XLSX conversion uses the identical source and output pathname and ignores LibreOffice status; reopening that original copy is not proof of successful recalculation. Use distinct input/output directories, require successful conversion and a new output, then verify cached `A4=6`. PDF conversion exit is recorded but not gated; `pdftoppm` status and Python PDF `ok` are ignored, so file/page presence can pass despite failed subprocesses or text inspection. Require status 0, no signal/error and the nested verdict for each stage, preserving diagnostics. Required rendering disabled through `MERI_ARTIFACTS_RENDER=off` must be visibly not passed, rather than qualification `ok:true`.

7. **Failure evidence — probes/browser.mjs:192-214.** MCP stderr collection starts after tool calls, so startup/launch failures can lose their useful diagnostics. `evidence.json` is only written on the successful try path and stores a 500-character sandbox sample. Attach stderr capture before connect, and preserve bounded full responses/process evidence/failure details in `finally` and structured stdout; a path to an ephemeral Fargate volume alone does not preserve evidence after task exit.

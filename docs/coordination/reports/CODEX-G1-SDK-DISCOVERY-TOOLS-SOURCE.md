## Implemented boundary

Public SDK registration factories are invoked only when the function is called. There is no CLI entry point.

The literal schemas are `{messageId:'fixture-message-7'}` and `{subject:'orchard meeting'}`. The full context and parsed arguments are copied/frozen before awaiting any authority callback. Schema-valid foreign identities or old positive fences remain the gateway's decision; shape validation is never access authorization.

The qualification callback seam is deliberately small: `gateway.authorize(request)` resolves **literal true** only when the gateway currently authorizes this request, and every other return or rejection denies. The request contains contractVersion, sessionId, full runBinding, the descriptor's exact operation name and copied arguments. This boolean is not a durable authorization receipt, grant or authenticated identity claim. No product contract/schema was introduced or changed. `gateway.execute(request)` owns the final current-authority recheck and actual side effects; it receives the same frozen request. An earlier canUseTool allow/discovery result is not an adapter input, and each handler invocation performs a new authorization call. The adapter cannot make two separate callbacks atomic or prove their implementation rechecks authority. Mutable gateway-owned state can still revoke authority. Successful gateway MCP results pass through; denial/schema/gateway exceptions produce a fixed content-free isError result. This module does not validate arbitrary successful source content or claim unknown effects can be refunded. Gateway-owned execute must reject revocation before effects and supply supported bounded MCP output; outer canonical SDK/lifetime/usage/accounting owners remain required.

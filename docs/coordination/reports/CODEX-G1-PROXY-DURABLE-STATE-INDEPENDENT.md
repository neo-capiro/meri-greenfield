## Source assessment

The small modules have distinct responsibilities: integer pricing, PostgreSQL connection/transaction handling, current run and capability grants, and ledger reservation/reconciliation. The migration creates a new qualification schema explicitly and refuses an existing one. Existing transport, compiler, lockfiles and contracts are unchanged.

All budget-changing operations serialize on the fixed budget row. Reservation reads database time after its lock, checks the current run/attempt/worker/fence/policy binding and active, unexpired capability, and includes UNKNOWN liability across grants and attempts. Global request uniqueness and one UNKNOWN per grant supplement that lock. A reservation commits UNKNOWN before returning the actual transport receipt. Concurrent threads/processes, lost acknowledgement, cancellation and process death have meaningful real-database tests; no TTL refund or background reset exists.

The ledger re-inspects the native body and binds the raw ingress hash, body bytes, model/profile, count origin and count, output ceiling, pricing revision and original pricing expiry. Trusted complete usage and positive no-dispatch are separate reconciliation methods. Revoked/replaced grants can reconcile their original liability while stale new dispatch remains refused. Contradictory/excess usage is recorded without clamping and quarantines future admission; missing/incomplete/mismatched evidence leaves the hold unresolved. The tests also cover forged NativeBody metadata, expiry after actual lock contention, other unresolved holds during settlement and substitution of renewed pricing expiry.

Typed count/settlement objects and an origin string are adapter inputs, not authentication. The trusted ingress/count/response parser must establish their provenance. The current binding check is a reservation-time database check; it does not authenticate a live peer or implement quiet-stream revocation. The fixed cap is per database. A trusted SQL administrator, replacement database, DDL or fixture reset can bypass it; production must freeze one durable database/schema/role and deny those operations to runtime roles. Explicit test fixture truncation/reset is not a runtime API.

Commit ambiguity stays conservative. An asynchronous caller can time out while its synchronous connection thread later commits; its UNKNOWN must continue to count. A failure during connection close can replace an earlier exception with a sanitized database error, but does not authorize send or establish rollback. These are bounded adapter semantics, not proof of physical network failure or distributed exactly-once behavior.

# Codex G1 trusted proxy completion plan

Status: **DESIGN PROPOSAL ONLY; no proxy/runtime/security/G1 acceptance.** Codex inspected the current source at `d9f31ca5009c28aa72c3026bad65d23223666700` and public primary documentation on 10 October 2026. Only this report is authored in this session. No Hermes, candidate import/test, installation, server, cloud API, model invocation or credential read occurred. The integration owner must allocate and independently review implementation before any deployment or paid request.

The shortest credible path is **one private, non-root Fargate proxy process, upstream LiteLLM, and one new Postgres store for native keys and durable qualification grants/cost holds**. Complete the exact SDK/body/transport proof offline first. Then deploy the isolated boundary and qualify a fixed, small synthetic SDK tool round trip under one non-resetting $10 ledger for paid model inference across qualification sessions. Infrastructure deployment/cost is a separate owner decision. A full product broker, HA and Redis are unnecessary for this deliberately single-process qualification. They cannot be inferred qualified by it.

## Minimal qualification boundary

Use a NEW qualification proxy task and NEW Postgres, separate roles/schemas for LiteLLM and the qualification ledger, private subnets, explicit security groups and original bounded task deadlines. Keep workers roleless: their task definitions omit `taskRoleArn`; the ECS execution role supplies ECR/Logs and, only after separate review, an exact inference-capability secret. The worker receives no AWS/provider, database, master or administrator credential.

For the smallest first transport, propose **direct private TLS from worker to proxy, with actual server-observed peer IP bound to the exact admitted ECS task ENI plus a short-lived opaque native virtual key**. No load balancer or caller-supplied forwarded-IP/run header may supply that peer identity. A thin outer ASGI boundary must obtain the real connection peer, enforce raw request bounds/schema before LiteLLM parsing, and pass a private server-created admission context to the callback. Its source-level composition with the pinned LiteLLM app must be tested; this is not an existing deployed extension. The grant is pending until the trusted owner reconciles the actual task ARN, ENI/private IP, immutable definition/image and run/attempt/worker/fence. Grant activation, revoke and replacement are trusted control-plane transactions. Expiry and authoritative current-state/freshness checks prevent an old grant surviving task termination/IP reuse; stale observations fail closed. A shared security group or matching JSON alone is insufficient.

Use an owner-reviewed per-run capability delivery/readiness mechanism before the SDK starts. An ECS-injected inference-only secret is a candidate, not accepted authority: it changes the definition's currently empty secret surface and execution-role read permissions and needs a distinct reviewed profile. Never weaken the existing loopback capture preflight or silently add credentials to its frozen definition. An optional, tightly scoped non-inference readiness endpoint can wait for trusted activation within the original deadline; it must not authorize a model call or expose management data.

mTLS is supported in current official Claude Code documentation through `CLAUDE_CODE_CLIENT_CERT`, `CLAUDE_CODE_CLIENT_KEY` and `NODE_EXTRA_CA_CERTS`. The installed Windows CLI contains these selectors, but that is not proof for the pinned Linux CLI. If the owner selects mTLS, qualify the exact Linux SDK path first; a pinned ingress such as Envoy may supply verified certificate identity, overwriting client XFCC/XFF instead of trusting it. Do not add that sidecar merely to claim task binding: bind verified identity to authoritative task/ENI/current-run state. Direct TLS/peer binding avoids a new ingress dependency for the first single-task fixture. [Claude network configuration](https://code.claude.com/docs/en/network-config), [Envoy header trust](https://www.envoyproxy.io/docs/envoy/latest/configuration/http/http_conn_man/headers).

Expose only the reviewed inference surface to worker ingress. Keep native key issuance and management accessible solely from the trusted operator plane; do not expose UI, passthrough, arbitrary model discovery, embeddings, uploads, MCP, URL-fetch or direct provider paths. One qualification team has non-resetting `max_budget=10`; every task, retry attempt and resume key belongs to it. Keep `fail_closed_budget_enforcement:true` and `disable_budget_reservation:false`. One process uses upstream's in-process native synchronization as a secondary guard; Postgres remains authoritative across its death/restart. Add and qualify shared Redis before multiple proxy processes/replicas; Redis leases alone cannot replace durable holds.

## Callback and final transport responsibilities

The exact release exposes `CustomLogger.async_pre_call_hook(self,user_api_key_dict,cache,data,call_type)`, `async_post_call_streaming_iterator_hook(self,user_api_key_dict,response,request_data)` and `async_post_call_failure_hook(...)`. Use native auth, then an explicit failing exception for denied admission; a success-looking string is unsuitable. `async_pre_call_deployment_hook(self,kwargs,call_type)` is awaited in `utils.wrapper_async` before the provider function, making it useful for an attempt guard, not proof of final native body identity. [Pinned callback API](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/integrations/custom_logger.py), [actual deployment-hook call site](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/utils.py#L1825).

Split responsibilities into ordinary focused modules: raw Messages admission, trusted binding/current-state lookup, price/count evidence, transactional ledger, upstream callback adapter and streaming validation. Do not import the synthetic Node reference as a runtime service or create a replacement model loop. Preserve contracts `0.1.0`; their CapabilityClaims currently lack an inference action/proxy audience. A private qualification grant can refer to the frozen RunBinding/Budgets fields without claiming an approved product capability extension. Migration IDs and any contract change remain centrally allocated.

There is an additional retry risk beyond the already recorded invalid-thinking-signature retry. In the pinned release, `AsyncHTTPHandler.post` catches `RemoteProtocolError`/`ConnectError` and creates a second POST independently of router `num_retries:0`; its replacement client receives the same event hooks. The handler accepts `event_hooks` and `transport`. A final request hook or equivalent supported client adapter is therefore a credible place to compare the exact native body/URL and atomically consume a single dispatch slot **before each send**. The Bedrock route's actual injection/call path is unproven and must be established using the pinned upstream handler with a fake transport. A logging hook or pre-call callback alone cannot prevent an internal second send. No automatic provider/auth/quota retry is admitted. [Pinned HTTP handler, constructor and retry](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/llms/custom_httpx/http_handler.py#L551).

The stream wrapper must enforce ordered SSE blocks, tool identity and complete input JSON, safe usage, one terminal event and no success after error/truncation/disconnect. No tool result becomes executable from an incomplete stream. Check current grant/fence during quiet streams using a bounded wait/race on the next upstream event and a short authoritative-state poll; per-chunk checks do not revoke a silent stream. A proposed <=30-second revocation target needs owner adoption and measured proof. Keep original absolute deadlines. Cancellation closes the upstream stream but does not establish zero provider charge. Native cleanup can release counters and background success logging is asynchronous; neither is a critical durable settlement transaction. [Pinned common stream processing](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/common_request_processing.py#L3579).

Feed publication was `2026-10-08T23:56:37Z`; decoded feed SHA256 `b21cfc4941e346275d9503700a094dc892f838172c41bc2e14c8284d91b1677a`, 1,706,380 bytes. HTML SHA256 `5fb734865283d8ba3bdc4ecdf093bbbcdf5ed9321d37f114545755434b179002`. These were public HTTPS data reads, not an AWS invocation. An initial compressed-feed decoding failure preceded the corrected gzip decode and is retained in the tool transcript. The page also has a long-context row whose US feed values were absent; no model-wide 1M-context price bound is established. Revalidate at paid admission. [AWS pricing](https://aws.amazon.com/bedrock/pricing/), [official rate feed](https://b0.p.awsstatic.com/pricing/2.0/meteredUnitMaps/bedrockfoundationmodels/USD/current/bedrockfoundationmodels.json).

Start with bounded text and ordinary local tools, thinking/cache/server-compaction disabled, explicit Standard tier, and a small trusted input cap below 200K plus a small hard `max_tokens` ceiling. The exact bound must cover system/tool schemas/history and provider overhead. AWS CountTokens states that the same input/model count matches charged input tokens. Call it inside the trusted proxy on the **complete native InvokeModel body that will actually be sent**, using foundation-model ID `anthropic.claude-sonnet-4-6` in `us-east-1`. The earlier owner free 31-token result establishes only basic availability, not tool/body equivalence. Bind returned count to native body hash, raw request hash, model/profile, pricing revision and output ceiling; reject errors, absent/unsafe counts, transformations after counting and all heuristic fallback. [CountTokens API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_CountTokens.html), [retained pricing/count evidence](../../qualification/BEDROCK-PRICING-IAM-CANDIDATE.md).

The upstream Messages count endpoint and generic token counter are not automatically a safe authority: the pinned proxy can fall back to local counting on provider-counter errors, and its count transformation is a separate path from inference. Use an explicitly non-fallback native count adapter and prove translated-body equality at the actual transport boundary. This is a blocking implementation proof, not an assertion that a suitable adapter is already wired. [Pinned fallback branch](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/proxy_server.py#L12577), [count-body transformation](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/llms/bedrock/count_tokens/transformation.py#L169).

For verified complete input bound I/output ceiling O, conservative cache-tier arithmetic is `ceil((6600*I + 16500*O)/1000)` microUSD, subject to the admitted small-context feature/pricing envelope. I=4096/O=1024 gives 43,930 microUSD; that example is not a verified bound on a real SDK request. Denying cache controls is still required initially; charging the higher cache-write tier gives margin, not permission to admit unqualified cache or long-context features.

Use safe-integer microUSD in a Postgres transaction that locks the one qualification budget row, verifies grant/current fence and `consumed + every outstanding/unresolved hold + newHold <= 10000000`, and records a unique request/dispatch slot before sending. There may be only one in-flight slot per grant. Provider send consumes that slot atomically; duplicate body/retry/attempt callbacks cannot obtain a new one. Every genuine tool-loop request needs a fresh admitted hold; a failed/unknown first call cannot silently advance the grant to the next phase. No rolling duration, daily reset, cached spend or SDK `maxBudgetUsd` supplies the global ceiling.

Crash after reservation, lost commit acknowledgement, lost provider response, timeout, malformed terminal usage and cancellation preserve the hold as UNKNOWN. Do not auto-expire it, infer zero from missing cost, or refund estimated output on disconnect. An explicit trusted reconciliation transaction may replace a hold only with complete bound usage/pricing evidence or affirmative evidence of no dispatch; native zero-cost cleanup alone is not such evidence. If authoritative billing evidence is unavailable, retain the entire hold and block further admission when headroom is exhausted. Record actual liability above a bound without clamping, quarantine all new dispatch and fail qualification. Database outage, ambiguous state or changed pricing likewise denies sends. The pinned native reservation module's unknown-cost/TTL/refund gaps make this small durable extension necessary. [Native reservation implementation](https://github.com/BerriAI/litellm/blob/fc3920bf403124ad075bc04990f999f7e0612e12/litellm/proxy/spend_tracking/budget_reservation.py).

## SDK and image gates that remain

The pinned SDK `0.3.295`/CLI `2.1.295` dry capture has explicit replacement env/settings, local tool-only permission and two-request limits. It deliberately talks to loopback with a synthetic token; native execution is still unrun. Keep that oracle unchanged. First observe actual Linux requests through a no-provider fake service, then the real upstream proxy with a scripted fake Bedrock transport. Resolve `/v1/messages?beta=true`, actual `x-stainless-*`/other headers, betas, caching, tool schema/result framing and compressed bodies explicitly. Current offline policy permits only exact `/v1/messages` and a small header set; it cannot be silently treated as SDK-compatible. Permit only individually reviewed benign wire fields in a new qualification adapter, with negative fixtures; reject unsupported semantic features rather than stripping them.

Use `ANTHROPIC_BASE_URL` plus the inference-only gateway credential in a newly allocated proxy-specific options module. Keep complete inert settings/env, no OAuth/default-provider/model discovery, memory/plugins/hooks/background tasks/updates/telemetry, thinking/cache disabled, local harmless tool only and original abort/deadline/process cleanup. Current docs say TypeScript SDK `env` replaces the child environment. Do not spread parent env. Native mTLS reload can retry a connection; `CLAUDE_CODE_DISABLE_MTLS_RELOAD_ON_STALE_CONNECTION=1` is a current documented candidate if mTLS is selected. Disable request gzip only through a selector verified in the exact Linux runtime, or enforce bounded gzip parsing. Existing selector names/string presence are preparation evidence, not execution proof. [Gateway SDK configuration](https://code.claude.com/docs/en/llm-gateway-connect), [network/mTLS behavior](https://code.claude.com/docs/en/network-config).

Qualify final native body, request attempts, cancellation and terminal semantics under connect loss, response loss, HTTP400 invalid-thinking, HTTP429/5xx, quiet/malformed/truncated/200-error streams and disconnect. The SDK watchdog or internal transport can retry even when router retries are disabled. A final transport guard must prevent unauthorized second sends and preserve unknown liability; observing one happy path is insufficient. Opaque SDK checkpoint/resume and rotating task grants/fences need a separately scoped native recovery scenario; the capture's `persistSession:false` proves no recovery.

The pinned image default is root; force a tested dedicated UID, read-only root, drop ALL caps, no-new-privileges and only explicit writable HOME/tmp/runtime volumes. Bake imports/Prisma binaries/schema preparation at build time; migrations use a trusted separately scoped operation, not every agent-facing startup. `prod_entrypoint.sh` itself only execs LiteLLM/ddtrace; its simplicity does not prove CLI imports/Prisma/UI paths work read-only. The upstream extra dependency list includes psycopg ranges, not proof of installed versions; inspect final inventory and use a precisely pinned existing driver where possible. Record image/lock/dependency/license/signature provenance and scan disposition independently; no root fallback, signature claim or CVE waiver is granted here.

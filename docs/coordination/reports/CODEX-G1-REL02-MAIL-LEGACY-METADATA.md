It pages the canonical deduplicated **messages**, then groups that page into threads in first-seen order. `count` is returned thread groups; `returned`, `totalMatches`, `offset`, `nextOffset` and limit remain message units. One thread can occur on successive message pages. It does not call the separate capped `listMailThreads` UI method. |

Limit 1–10, maxCharacters 1–6000, messageOffset 0–10000, bodyOffset 0–10000000. Positive bodyOffset requires exact messageId. UUID strings are trimmed; optional nonstring clientId/messageId become empty/omitted in this wrapper. |
| Thread message selection | Service loads all active messages in the authorized thread, then wrapper optionally filters exact messageId and slices by messageOffset/limit. ## Body completeness, version and authority boundaries

The thread wrapper uses `message.bodyText ?? ''`; it does not distinguish a null body from stored empty text in the returned body string. It returns metadata.bodyCompleteness when it is a string, otherwise `unknown`. Completing all stored slices cannot turn upstream `preview`, `truncated` or `unknown` into full source evidence. Shared read-outcome metadata marks thread reads partial when hasMore, nonzero messageOffset, returned≠totalMessages, any bodyTruncated, or any bodyCompleteness other than `full`. This classifier is shape interpretation, not authenticated source truth. ([wrapper](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/apps/api/src/meri/meri-tools.service.ts#L7375), [read outcome149–189](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/packages/shared/src/meri-read-outcome.ts#L149))

Provider capture has explicit stored-body provenance. Microsoft uses nonempty Graph body.content, trims text or converts HTML to text, caps at100000 characters and stamps full/truncated; otherwise it falls back to preview. Gmail chooses text/plain before text/html, decodes the inline MIME part and strips HTML when needed, applies its100000-character cap, and stamps full/truncated; unavailable body falls back to snippet/preview. This describes legacy representations, not an approved new normalization implementation. Both initial/backfill windows are365 days. ([Microsoft2354–2395](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/apps/api/src/engagement/microsoft/microsoft-graph-sync.service.ts#L2354), [Gmail1203–1214 and1855–1889](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/apps/api/src/engagement/google/google-sync.service.ts#L1203))

Each selected message returns sourceProof version1, mailbox/thread/message IDs, messageUpdatedAt and SHA256 of the **entire current stored body encoded as UTF-8**, not the returned slice. Thread sourceProof adds mailboxStatus, clientId and threadUpdatedAt. Version1 is the proof schema version, **not an immutable record version or snapshot**. The wrapper accepts no expected body hash/version and re-queries current records on each continuation. List/search asOf excludes later-created/later-dated messages, but does not freeze updates, removals, connection ownership/status or client reassociation. Neither path establishes snapshot-safe pagination. ([wrapper7408–7447](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/apps/api/src/meri/meri-tools.service.ts#L7408))

Active message means `removedAt:null`; active thread means at least one such message. Removal retains the row/body, stamps removal metadata and recomputes the thread from remaining active messages; no active messages clears summary and marks thread metadata.deleted true. The ownership helper requires the connection's createdByUserId; service supplies tenant and optional exact thread clientId. Reads reapply these predicates, so observed removal or changed connection ownership affects later reads. **Connected status is not a read eligibility predicate**: the thread service selects/reports status, and list/search returns stored owned mail across statuses. The coverage helper marks nonconnected mailboxes unavailable; it does not remove their stored records from these reads. Complete gateway client-wall/entitlement/revocation enforcement outside these methods was not established by this bounded discovery. ([state26–38,43–158](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/apps/api/src/engagement/mail-message-state.ts#L26), retained ownership helper67–78, [thread2503–2533](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/apps/api/src/engagement/engagement.service.ts#L2503))

## Coverage and implications for the new contract

Coverage uses mail.syncState.updatedAt, separately reports connection.lastSyncAt and requires captureVersion≥1. Microsoft baseline requires complete folder enumeration, inbox+sentitems entries, and every enumerated folder's valid updatedAt/deltaLink; cursors/next links/pending replay catchup remain incomplete. Gmail baseline requires ALL.backfillDone true, no backfillPageToken and historyId; pending incremental/backfill tokens remain incomplete. Missing replay folders, provider errors, missing folder enumeration, unfinished backfill, future mail timestamp>5minutes and mail freshness>**48hours** degrade coverage. A status other than connected makes it unavailable. Repair is required/in_progress/complete/not_applicable. Its backfillComplete is explicitly **bounded provider backfill**, not all-history completeness; captureVersion is not a source snapshot. The actual48hour constant is retained `index.ts:3968`. ([coverage46–145](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/apps/api/src/engagement/mail-sync-coverage.ts#L46), [constant](https://github.com/neo-capiro/capirov2/blob/fd8765ec01d292013758606204f2c9d886cd31c1/packages/shared/src/index.ts#L3968))

These findings replace the outline's legacy unknowns, not its proposed decisions. New Unicode-scalar offsets/default5/body6000/2million-scalar bound/effective-date+ID order, stricter active-connection policy and snapshot-bound cursors would be **explicit compatibility changes**, not characterized old behavior. Owner must choose and document them before schema freeze. Message-based list paging is confirmed; the legacy grouped-thread envelope/count must be explained separately. New transport-only incomplete-body DTOs must preserve full-read evidence rules and cannot reuse legacy version1 as immutable version authority. No empty page or healthy bounded backfill proves that mail/commitments never existed.

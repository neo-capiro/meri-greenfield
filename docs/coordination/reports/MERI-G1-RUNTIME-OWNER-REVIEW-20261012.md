## Discovery

The accepted standalone `FixtureRegistry.revokeRun` has no non-test caller. `createFixtureControl` is the existing trusted owner composition: it instantiates the real registry, checkpoint store, handlers and ingress, exposes the registry, and owns start/close. Its close operation destroys sockets, waits for tracked promises, then releases owned object resources. It does not invoke grant revocation or provide a run-bound stop operation. The tracked handler promises disappear in `finally`; `Promise.allSettled` in cleanup does not retain a `CommitUncertain` marker for the owner after the ingress correctly reduces worker-facing failures to a bodyless refusal. A cancellation of transport is therefore not durable revocation, and completed cleanup alone cannot establish an unknown transaction outcome.

`scripts/qualification/sdk-native-evidence-owner.mjs` composes a one-shot native observer and evidence publisher. It is not an admitted-run lifecycle owner and does not invoke registry revocation or the control composition. Its existing cancellation tests inject authorization decisions and do not demonstrate durable grant invalidation. `qualification-temporal/workflow.ts` and `activities.ts` are explicitly inert fixtures with no registry/control wiring; their echoed activity outcomes are not runtime cancellation or durability evidence. Production-source search found no caller of the evidence owner or control constructors either, so this work can qualify the existing control entry point's behavior without claiming a launched/native product composition.

The author proposed an owner-only `stopRun` integrated into the existing control, with a cohesive per-binding lifecycle module if allocated by the parent. This is preferable to another unconsumed helper. Exact API and paths await parent approval; the following behavior requirements are frozen before author code.

## Frozen acceptance and negative controls

1. An actual `createFixtureControl` owner call must reach the actual `FixtureRegistry.revokeRun` source and produce an observed one-way grant transition at the scripted transaction boundary. No new worker route, model tool or external authority input. No native-admission or durable-storage claim may be inferred from test doubles.
2. Owner stop input must be inert, detached canonical context plus trusted peer, bound to the complete intended task/grant/session/attempt/fence/policy and original clocks/pins. Caller mutation across an await, proxy/accessor input, foreign actor/tenant/peer/task or stale A must never abort or revoke current B or another run. Reuse the canonical binding owner; do not create a second authorization predicate.
3. Exact stop must synchronously prevent matching new work and request cooperative cancellation of matching tracked operations before awaiting durable revocation. Parked work cannot release success or start another effect when it later resumes. Unrelated runs/current replacement B remain usable. Stop must account for work that was already being resolved/admitted when cancellation began.
4. Stop must preserve registry lock order and database clock, exact expired-current invalidation, idempotent revoked readback and immutable timestamp. There is no resurrection, reset of original deadline, automatic replay/retry, budget refund, grant/credential issuance or checkpoint prerequisite. Repeated/concurrent owner calls cannot create duplicate mutations or broaden the target.
5. Unknown revocation/publication acknowledgement remains explicitly unknown to the trusted owner. Cancellation, timeout, handler completion, ingress bodyless failure, cleanup, read outage and foreign/not-committed readback cannot silently turn it into success or a clean rollback. A later explicit exact-binding readback may resolve only what its authoritative observation proves. Pending operation/unknown status must not be lost when an operation's promise settles.
6. Cancellation timers/listeners/tracking belong to the owner and must be released appropriately. A noncooperative parked port is an unsettled obligation, not evidence of physical stop. Close cannot release borrowed/needed object resources prematurely, swallow unknown liabilities as success, or affect another owner's resources. No new background scheduler.
7. Original positive A commit/B load/verify and stale-A refusal remain canonical. Expired historical A may be lineage for current B; expired request context is not admitted. Accepted cancellation and uncertainty controls remain intact. Original tests, migrations, locks, contracts, catalog and disabled connectivity/admission flags stay byte-identical.
8. Test the actual owner/control path with real registry and handler source plus explicitly scripted database/transport/object boundaries. Observe state, accepted/refused responses, next effects and retained liability, rather than only a mocked helper call. Native PostgreSQL serialization, real TLS/task possession, cloud storage, Temporal replay/durability and physical teardown stay UNRUN/HOLD.

Before execution, the exact approved API will be recorded alongside executable controls. Baseline failures, fixture mistakes and candidate failures will be retained with source refs/hashes.

## Implemented behavior

`ecs-task-binding.mjs` validates the exact admitted original Fargate task: ARN/cluster/revision, original execution/binding/plan/expiry tags, creation time, Linux1.4.0, execute-command disabled, single pinned image/container identity. `ecs-task-owner.mjs` uses actual AWS SDK3.1151.0 command classes with an explicitly borrowed client; it never constructs a client or ambient credential chain. Its launch releases the existing trusted native owner inside an already admitted task, rather than allocating a replacement task. Discovery uses separate bounded startedBy and stopped inventories, preserving pagination/overflow uncertainty. Saved ARN inspection takes precedence on recovery. Contradictory ownership metadata, duplicates, missing/aged-out tasks and incomplete inventory never prove cleanup. Image/platform/execute-command qualification failures block execution while retaining stop responsibility for the positively owned original task. Native registration/readiness/execution replies receive fresh physical task checks after RPC. Unexpected native stop triggers whole original task containment. Stop acknowledgement requires subsequent exact STOPPED task/container readback with exit identity; product outcome remains separate.

`ecs-task-factory.mjs` joins the actual task ARN to existing canonical admitted grant facts before compiling the broker factory. It also composes retirement recovery through the existing conversation-store execution journal. The broker passes its persisted original task ARN into inspect/retire. Constructor acceptance of an expired original lease permits cleanup; start still checks fresh admission before any claim or launch. The local process adapter accepts only its exact persisted PID hint. No second execution registry, migrations or shared contract changes were introduced.

`continuation-runtime.mjs` joins canonical persisted run/lifecycle continuation with current verifier scopes, selected client and policy. Worker envelope/source request/target request/scopes must match those records. Existing continuation options and restore-receipt validators enforce resume/fork pins and original target session identity. A borrowed trusted restorer supplies correlated receipt/key and independently read registration; null witnesses refuse. Facts are rechecked after restore/read, and provider admission rechecks run even on restore failure. Existing protected runner/runtime HTTP accepts the already defined optional continuation fields. Fresh-session behavior and SDK model-loop architecture remain intact.

Actual workspace/opaque restoration, durable restore deduplication/uncertainty handling and genuine pre-query target bootstrap observation are **not implemented by this seam**. The existing eager non-null mirror requires native observation before SDK query/load; restored bytes alone cannot establish that witness. No worker-uploaded observation is accepted. A resumed target without the actual trusted producer fails closed.

## API and ownership

`captureNativeSessionFiles({configDir,cwd,projectKey,sessionId,deadline?,limits?})` returns a frozen opaque DATA inventory: format, exact SDK/CLI labels, binding, directories, files and aggregate bytes. The labels describe the supported preparation profile; they do not inspect or attest the actual runtime binary. `restoreNativeSessionFiles(bundle,{targetConfigDir,cwd,projectKey,sessionId,deadline?,limits?})` validates the entire declared inventory, content hashes/base64, required main, namespace, ancestors and bounds before creating an exclusive fresh config target. It writes only regular files at0600 and directories at0700, fsyncs each file, rereads exact content, and returns DATA counts/path. It does not activate a config, launch a process or discover settings/skills from the bundle. Existing targets are never overwritten or removed.

Limits are fixed ceilings, with optional reductions only:256files,512members,8MiB/file,32MiB aggregate, depth12,128-character portable ASCII segments. Directory enumeration is incremental, file reads use64KiB chunks, and byte/file bounds precede allocation/read. The default monotonic deadline is10seconds; supplied absolute `performance.now()` deadlines cannot extend beyond30seconds. Synchronous OS filesystem calls can still block; the deadline is cooperative and a trusted external whole-operation supervisor remains required.

Capture rejects symlinks/junction aliases, nonregular files, hardlinks, path traversal, ADS/device names, non-NFC/unsupported names, case aliases and ancestor conflicts. It uses lstat/realpath, NOFOLLOW/NONBLOCK where Node exposes them, fd-vs-path identity checks and final observed identity checks. Tests cover Windows junctions. Node does not expose every Windows reparse attribute or atomic openat traversal; this is not an all-reparse or hostile concurrent filesystem proof. The intended Linux/nonhostile trusted filesystem must be qualified separately. No caller boolean establishes exclusivity or quiescence. Trusted ownership of source/target parents and exclusion of concurrent rename/mount/ancestor mutation are required; pre/post checks detect ordinary changes but cannot prevent all races or root-admin tampering.

Restore tracks only objects it created and checks their device/inode/type/owner anchors before cleanup. On partial failure it removes those matching identities in reverse order using unlink/rmdir, never recursive wildcard deletion. A replaced/unknown identity is retained and marks `cleanupComplete=false`. That field concerns only attempted removal of this restore operation's files; it is not a physical-resource, durability or authorization receipt. Successful file fsync is not a parent-directory fsync/atomic multi-file durable commit. The bundle's self-contained hashes detect content inconsistency, not authenticity or omitted-but-consistently-redeclared files: trusted orchestration must bind the whole immutable bundle hash/inventory to `Checkpoint.opaqueSession` before restore.

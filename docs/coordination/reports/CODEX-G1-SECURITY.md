## Concrete SDK admission blocker

The current native definition source is incompatible with the proposed credential-free SDK preflight. `infra/native-qualification/app.mjs` sets `taskRoleArn: WORKER_ROLE_ARN` for both definitions. Its empty-policy role is still a task role: ECS vends task-role credentials through the container credential interface. `sdk-capture-options.mjs` rejects `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` by its AWS/credential-name selectors; it is absent from the harmless metadata allowlist. `runCapture` returns a failed preflight before native spawn. This is source-plus-documented-behavior evidence, not a new live observation. [AWS task roles](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task-iam-roles.html), [AWS ECS environment variables](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs-environment-variables.html).

Before SDK admission the owner must reconcile a role-free exact task definition and its enforcement binding, or separately review an equally strict credential-isolation mechanism. Do not weaken the sensitive-selector preflight, call an empty policy “no credentials,” or merely hide the endpoint variable while leaving credential access available. The existing validator expects the worker role, so omission is a separately scoped definition/compiler change, not an unreviewed launch override. Canary/Office also must disclose actual credential delivery if retaining that empty role; the zero-credential condition above is prospective until resolved. This report supplies no authority to change IAM, definitions or the accepted compiler.

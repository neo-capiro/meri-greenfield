## Collector and evidence limits

The collector requires Linux, CodeBuild source-root identity, the external manifest pin, fixed source/version/result environment and 2 GiB free disk before output allocation/importing the pinned assembler. GNU timeout bounds the unchanged assembler to 45 seconds/5-second kill grace. The collector uses one original monotonic 1500-second end, Docker build at most 1200 seconds, per-command captures at most 60 seconds, with a 300-second reserve before each artifact copy for five cleanup/readback calls. A create also requires its own call plus that cleanup reserve. This narrows the proposed 1800/1500 limits to leave time within the existing 30-minute build ceiling for failure packaging/upload; it is not a guarantee that every build duration fits or that blocked filesystem operations terminate. An operation that exhausts the budget fails rather than resetting time.

Streaming capture drains fast-exiting processes to EOF, writes bounded prefixes (stdout default32 MiB, artifact tar at most33 MiB; stderr32 MiB), and records UTC/elapsed time, observed/retained sizes and raw hashes. Image/container JSON has an 8 MiB bound. Truncation, timeout or incomplete child cleanup refuses. Linux process-group kill does not prove Docker daemon build work stopped; source-only Windows tests did not qualify actual Linux selector/process behavior.

The collector binds an exact SHA256 image IID, Linux/amd64 config, UID10001:10001, expected entrypoint/workdir/env, exactly `/workspace` and `/tmp` volumes and immutable RootFS diff IDs. One UUID-named/labeled container is created with an inert entrypoint, no network, read-only root, dropped capabilities and NNP. Ownership readback requires exact IID/name/labels/user/entrypoint, never-started state and exactly two anonymous volumes without host binds. Lost ACK may reconcile only that exact identity. Foreign/unknown ownership never triggers removal. Fixed tar members must be single regular nonsparse entries, exact names and finite lengths; no host extraction or links occur.

Finally it rechecks ownership before removing only that container with `-v`, positively checks container absence and **both** recorded volume absences. A missing volume observation or removal failure cannot pass. The unique built image and daemon cache are retained; no image/cache absence is claimed. Failure bundles prioritize JSON, reserve their 128 MiB budget before copies, retain/disclose prefixes or post-copy metadata failures, cap128 files/33 MiB per member, and enumerate excluded members. Bounded finally packaging and result upload can still fail; an absent/partial bundle is failure. Root acceptance must require terminal input/build/version binding, complete required streams/bundle, `result.captureComplete`, `source-post.sourceStable`, canonical inventory and positive owned cleanup.

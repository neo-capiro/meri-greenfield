# Finding: the real SDK launch descriptor cannot pass the remote launch gates at PR86 (slice 3)

Base `c6053e24b465be677cc5980533009b4aab03beab`. Author: Fable. Evidence: `docs/qualification/candidates/fable-first-chat-rehearsal-20261014/` (three machine-written receipts from `scripts/qualification/first-chat-rehearsal/capture-sdk-descriptor.mjs`, no process spawned, no network, secret values hashed; one unapplied patch proposal).

## What was attempted

Slice 3 set out to run the composed first-chat path locally with the real pinned CLI 2.1.295 inside the existing remote task composition (real PostgreSQL 16, real supervisor process, synthetic ECS/identity, zero model turns), extending `apps/runtime/native-authority/test/prepared-runtime-pg.test.mjs`, whose native child is a Node stand-in. The first step is to feed the real SDK's launch descriptor, produced from the product option builder (`apps/worker/conversation/options.mjs`), through the same gates the remote task applies to a descriptor: `prepareNativeSdkQuery` (inert JSON), `matchPreparedDescriptor`/`remote-task-http` (per-task config directories under the approved parent, exact env equality with the configured launch template) and `compileNativeLaunch` (string-only env, forbidden keys). That step fails at PR86 for three distinct reasons, so the full rehearsal was not run and no passing end-to-end receipt is claimed.

## What the receipts show

The SDK hands its spawn hook exactly `options.env` plus three SDK constants (`CLAUDE_CODE_ENTRYPOINT=sdk-ts`, `CLAUDE_AGENT_SDK_VERSION=0.3.295`, `CLAUDE_CODE_SDK_READS_SESSION_STATE=1`); it does not merge the host environment and it adds no config directory. The argv for the product option set is deterministic and recorded in the receipt (`--output-format stream-json --verbose --input-format stream-json --max-turns=1 --max-budget-usd=… --model=… --permission-prompt-tool=stdio --tools= --setting-sources= --permission-mode=default --include-partial-messages --session-mirror --settings {"autoMemoryEnabled":false}`).

Earlier Codex receipts did not meet these gates because they bypassed them: the single-query component probe built its own env (both config directories, loopback proxy, two disable flags) and derived the launch configuration from the SDK request itself; the composed PostgreSQL tests use a Node child with a fixed descriptor. Neither exercised the product option builder against the configured-template path.

## Reconciliations made in this slice (routine, worker side only)

1. `buildConversationOptions` no longer places `undefined` entries in `env`. Node drops `undefined` env values at spawn, so the entries only ever served as "unset if inherited" for the SDK's default spawner; the remote path hands `env` verbatim to the launch plan, which admits only strings. Account keys stay out by omission, and the runner's existing `assertRunnerEnvironment` refuses any task process that inherits them. The existing option control now also asserts that every env value is a string and that neither account key is present.
2. `buildConversationOptions` accepts the optional pair `sdkConfigDirectory`/`sdkSecureStorageDirectory` in its closed runtime object (both or neither; each absolute, no `/../`, no trailing slash, not equal, not nested in each other) and places them in the env as `CLAUDE_CONFIG_DIR`/`CLAUDE_SECURESTORAGE_CONFIG_DIR`. Without them the options are identical to reconciliation 1, so no committed caller changes behavior. The option control covers the accepted pair and four refusals.

Worker suite 135/135 after both changes (`checks/RESULTS-touched-suites-worker-directories.json`: `source-proof` 3/3, `runtime-typecheck`, `runtime-tests` 111/112 with only the Docker control failing, `gateway-selected-skills` 36/36, `scripts-local` 27/27).

## Gaps 2 and 3 after dot's source review (implemented in source)

Dot's review at `7f7ee02` held the retained gap 2 patch as written (the canonical runner is the correct injection point, but ownership, private permissions and symlink safety must be verified before SDK initialization), accepted separate credential verification for gap 3, and approved a revised candidate manifest with explicitly changed proof rows for review. Both are now in source:

- Gap 2 (revised): `apps/runtime/conversation-runner.mjs` derives `configParentDirectory/sdk-<runId>` and the intent's secure storage directory, creates the config directory fresh (an existing one refuses) and the secure directory if absent, and verifies each directory and its parent with `lstat`: a real directory, owned by the task uid, mode without group or other bits, and `realpath` equal to the path (no symlink anywhere). Any failure refuses before the SDK is initialized. Controls: `apps/runtime/test/sdk-configuration-directories.test.mjs` (8: derivation, creation, reused config directory, permissive parent, permissive existing secure directory, symlinked secure directory and symlinked parent, foreign ownership, initialization failures).
- Gap 3: `preparation-intent.mjs` refuses a template that carries `ANTHROPIC_AUTH_TOKEN` (as it already refused `CLAUDE_CONFIG_DIR`); `matchPreparedDescriptor(descriptor, intent, proxyCredential)` excludes only that key from static equality and verifies it against the issuer's exact task credential (constant-time digest comparison; missing, empty, malformed, wrong or changed values refuse); `matchPreparedDescriptorShape` is the untrusted task-side pre-check (well-formed value present, every other check intact). Callers: `prepared-runtime.mjs` preparation and reconciliation (recovery recomputes the descriptor with the issued credential, so a changed credential fails closed), `broker-stack.mjs` compilation, `remote-composition.mjs` worker. The SDK options pin (`sdk-option-projection.mjs`) records the credential's presence as a marker, never its value, so a configured pin cannot carry the secret either. Controls: `apps/runtime/native-authority/test/preparation-intent.test.mjs` (4).
- Proof rows changed: `apps/runtime/conversation-runner.mjs`, `apps/runtime/native-authority/prepared-runtime.mjs`, `apps/runtime/native-authority/remote-composition.mjs`, `apps/runtime/native-authority/test/broker-pg-fixture.mjs`, enumerated with historical and current hashes, reasons and decisions in `scripts/qualification/assembled-image/candidate-manifest-fable-20261014.json`; the historical manifest and its pins are preserved and the proof control proves the other 41 rows unchanged (and fails closed on an unenumerated change, verified).
- Composed rehearsal at this head without any patch: `composed/source-gap2-gap3.json` and `composed/source-gap2-gap3-cancellation.json`, both PASSED, with `carriesProxyCredential: false` in the launch template. Suites: `native-authority` 309/309, `runtime-tests` 119/120 (Docker control only), `worker-conversation` 135/135, `scripts-local` 27/27, `source-proof` 4/4 (`checks/RESULTS-gap2-gap3-source.json`).

## What this does and does not establish

It establishes, with reproducible receipts, that the product option builder and the remote launch gates disagreed at PR86 and exactly how, and that with gaps 1 to 3 in source the composed path (controller, remote task, supervisor, real CLI, durable session, product runner) completes and cancels one zero-turn conversation locally with physical stop proven and no secret in any static template or pin. The changed proof rows are enumerated for dot's review in the candidate manifest; nothing here uses a provider, image, Temporal server, cloud resource or real credential, and nothing claims native, image, Temporal, provider or live behavior.

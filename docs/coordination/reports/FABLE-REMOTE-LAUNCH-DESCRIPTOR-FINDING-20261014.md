# Finding: the real SDK launch descriptor cannot pass the remote launch gates at PR86 (slice 3)

Base `c6053e24b465be677cc5980533009b4aab03beab`. Author: Fable. Evidence: `docs/qualification/candidates/fable-first-chat-rehearsal-20261014/` (three machine-written receipts from `scripts/qualification/first-chat-rehearsal/capture-sdk-descriptor.mjs`, no process spawned, no network, secret values hashed; one unapplied patch proposal).

## What was attempted

Slice 3 set out to run the composed first-chat path locally with the real pinned CLI 2.1.295 inside the existing remote task composition (real PostgreSQL 16, real supervisor process, synthetic ECS/identity, zero model turns), extending `apps/runtime/native-authority/test/prepared-runtime-pg.test.mjs`, whose native child is a Node stand-in. The first step is to feed the real SDK's launch descriptor, produced from the product option builder (`apps/worker/conversation/options.mjs`), through the same gates the remote task applies to a descriptor: `prepareNativeSdkQuery` (inert JSON), `matchPreparedDescriptor`/`remote-task-http` (per-task config directories under the approved parent, exact env equality with the configured launch template) and `compileNativeLaunch` (string-only env, forbidden keys). That step fails at PR86 for three distinct reasons, so the full rehearsal was not run and no passing end-to-end receipt is claimed.

## What the receipts show

The argv for the product option set is deterministic and recorded in the receipt (`--output-format stream-json --verbose --input-format stream-json --max-turns=1 --max-budget-usd=… --model=… --permission-prompt-tool=stdio --tools= --setting-sources= --permission-mode=default --include-partial-messages --session-mirror --settings {"autoMemoryEnabled":false}`).

Earlier Codex receipts did not meet these gates because they bypassed them: the single-query component probe built its own env (both config directories, loopback proxy, two disable flags) and derived the launch configuration from the SDK request itself; the composed PostgreSQL tests use a Node child with a fixed descriptor. Neither exercised the product option builder against the configured-template path.

## Reconciliations made in this slice (routine, worker side only)

1. `buildConversationOptions` no longer places `undefined` entries in `env`. Node drops `undefined` env values at spawn, so the entries only ever served as "unset if inherited" for the SDK's default spawner; the remote path hands `env` verbatim to the launch plan, which admits only strings. Account keys stay out by omission, and the runner's existing `assertRunnerEnvironment` refuses any task process that inherits them. The existing option control now also asserts that every env value is a string and that neither account key is present.
2. `buildConversationOptions` accepts the optional pair `sdkConfigDirectory`/`sdkSecureStorageDirectory` in its closed runtime object (both or neither; each absolute, no `/../`, no trailing slash, not equal, not nested in each other) and places them in the env as `CLAUDE_CONFIG_DIR`/`CLAUDE_SECURESTORAGE_CONFIG_DIR`. Without them the options are identical to reconciliation 1, so no committed caller changes behavior. The option control covers the accepted pair and four refusals.

Worker suite 135/135 after both changes (`checks/RESULTS-touched-suites-worker-directories.json`: `source-proof` 3/3, `runtime-typecheck`, `runtime-tests` 111/112 with only the Docker control failing, `gateway-selected-skills` 36/36, `scripts-local` 27/27).

## Remaining gaps, owner and proposed shape

- Gap 2 (bounded composition; worker side done above, runner side written but unapplied, blocked by the proof control): the runner's `prepareRuntime` must derive `configParentDirectory/sdk-<runId>` and `secureStorageDirectory` from the compiled preparation intent of the admitted remote task, create both with mode 0700 owned by the task UID (refusing a reused config directory), and hand them to the option builder so the SDK materializes its configuration there before launch and the task's `captureSdkConfiguration` can pin it. That change (two small exported functions in `apps/runtime/conversation-runner.mjs`, one line in `prepareRuntime`, a new three-control test file) was implemented and passed its controls, but `apps/runtime/conversation-runner.mjs` is one of the 44 non-recipe rows whose exact hashes `scripts/qualification/assembled-image/source-proof.test.mjs` pins, and the handoff keeps those rows unchanged. It was therefore reverted to its PR86 bytes and is retained unapplied as `proposals/gap2-runner-sdk-directories.patch` in the candidate directory; receipt 3 shows that with exactly that shape every directory gate passes. Decision for dot: (a) approve a proof-row change for the runner, which also requires a fresh candidate source manifest and a new 44-row pin in the proof control (a proof-control change, called out as such), or (b) name a non-proof injection point for the directories (none exists at this head: `prepareRuntime` lives in the runner and the remote runner module is also a proof row; `apps/worker/conversation/activity.mjs` is not a proof row but does not see the preparation intent).
- Gap 3 (owner decision, `native-authority/preparation-intent.mjs`, `remote-task-http.mjs`, `prepared-candidate-config.mjs`): the configured `launchTemplate.env` is compared for exact equality after stripping only `CLAUDE_CONFIG_DIR`. The SDK places the per-task proxy credential in the env, so either the template must contain that secret (contradicting the secret-file configuration design) or the matcher must treat `ANTHROPIC_AUTH_TOKEN` like `CLAUDE_CONFIG_DIR`: stripped from the equality check and verified separately against the task's issued proxy credential. The second shape keeps secrets out of configuration and keeps the exact-argv guarantee; it changes a closed matcher and therefore needs dot's decision before code. The receipt's argv and env key set give the owner the exact approved template to configure.
- Not a gap: the CLI runs without `PATH`/`HOME` (the earlier Codex probe launched it with only the keys above), so no host environment needs to leak into the template.

## What this does and does not establish

It establishes, with reproducible receipts, that the product option builder and the remote launch gates disagree at PR86 and exactly how, that the worker side now accepts the per-task directories, and that the proposed runner derivation would close gap 2. It does not run the real CLI through the composed path, does not change any gate or proof row, and claims nothing about native, image, Temporal, provider or live behavior.

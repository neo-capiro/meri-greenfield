Held work retains its overlap position until actual completion or proven retirement. Cancellation targets the actual effect. Partial or UNKNOWN model effects are never automatically retried. Each occurrence is delivered to its deterministic new Meri conversation/inbox item, with no external delivery or arbitrary existing-thread destination.

## Implemented source behavior

The existing model/tool liability journal now accepts a private sealed `occurrenceCostScope`. Its canonical group key is the tenant and immutable occurrence key; neither a different cap nor a different allocation hash creates a new allowance. Admission, reservation and settlement inspect both model and tool liability under the existing shared budget lock. UNKNOWN holds retain their charge, known consumption remains charged and conflicting scope/allocation evidence refuses. No new table, DDL, allocator, public Run field or manifest budget is introduced. Allocations without this scope retain their existing path.

The native job monitor reads original admission and verified same-work resume lineage from the existing conversation store. A wrapper start returns internal ACTIVE and keeps the OPEN occurrence occupied through running, paused, approval-waiting and uncertain work. Actual terminal state plus proven native retirement is required for settlement. A retired original worker paused for approval is not completion of the logical job. The SDK wrapper has one attempt, including when the human requests a larger retry limit; partial or UNKNOWN model work is never automatically restarted.

Cancellation proposals resolve the actual native workflow execution references on the server. Caller-supplied references are rejected. The original raw request remains the preparation journal identity; the immutable proposal and approved execution use the server-expanded references. Execution rechecks those references, the full canonical lineage and the captured current binding before the canonical run-control effect. A concurrent resume cannot redirect an old approval to the new target. Retirement is limited to the approved lineage, and an uncertain stop retains the OPEN barrier. If an actual provider execution cannot be observed, request-cancel refuses; pause/delete with `running: leave` can still fence future firing.

Every occurrence already owns a deterministic new Meri conversation. The added history composition accepts only a positively identified canonical schedule origin, rechecks native membership/client permissions before and after the read, and returns existing canonical run events through the current history contract. Confirmed absence follows the existing Core path; a failed Core read is not evidence of local schedule origin. The only permitted destination is `meri-inbox`. No email, Slack, arbitrary existing conversation, duplicate output text or new frontend wire shape is added. Cancelling/updating a routine does not erase its retained history.

The actual feature worker composes these job owners from four mandatory trusted ports: authority, native admission, run control and retirement. Enabled startup validates these ports before secrets and requires the existing allocation/checkpoint/next-run relations. History/readiness wiring stays on this feature stack. No primary CLI, config, Temporal startup, prepared-run compiler, whole-facts reconstructor, image or infrastructure source was edited.

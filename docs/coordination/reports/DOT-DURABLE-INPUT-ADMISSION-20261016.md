## Implementation outline

- `apps/control/conversations/service.mjs` owns one shared acceptance helper behind `submit` and `admitInput`. Existing session/current-state, retention and skill owners remain authoritative. Existing `store.accept`/`nextRuns.accept` persist the immutable request/run and one queued event. Admission invokes no dispatcher. Exact request lookup precedes relative-window normalization; replay returns the stored normalization and pin.
- `apps/control/conversations/input/http.mjs` owns only the fixed POST mount, bounded native Request parsing, cancellation/deadline and error/response release. Startup owns the tiny `apps/runtime/control.mjs` composition using the already assembled lifecycle service, and all package.json/export metadata.
- `packages/contracts/conversation-input/` and `generate-input.mjs` own only the additive public request/receipt boundary. Canonical SubmitRequest, StoredRequest and Run schemas and existing public receiving semantics are reused. The accepted history 0.1.6 output and old submit wire bytes remain unchanged. Startup/Qualification own successor package metadata/artifact publication.
- Positive receipt is exactly `{run,request,lastSequence,replayed}`. It proves durable input acceptance, never absence of dispatch. Current-run history and paged transcript recover stored input after lost response. Empty/404/RESERVED/unknown never establish unsent state or permission for another identity. Fresh session recovery cannot replace the target or refresh the original runtime deadline.
- Focused controls cover zero-dispatch admission, exact/conflicting concurrent replays, commit/start uncertainty, original relative windows, next-run reservations, terminal/delayed recovery, current auth before persistence and final release, transport bounds and canonical request/response provenance. One process, 128 MiB V8, <=120 seconds hard wall, no services/child tests. Generation/compiler stages are serialized by Qualification.

## Exact integration interfaces

`createConversationInputApplication({service,now,maxRequestBytes,maxResponseBytes,maxRequestMs})` is exported by `apps/control/conversations/input/http.mjs`. Pass the already assembled lifecycle service; it preserves `admitInput` by spreading its base service. Mount only `/api/conversations/input/admit` without a second store/session owner. Limits default to and cannot exceed 131072 request bytes / 2097152 response bytes; maxRequestMs cannot exceed 30000.

Public source exports `receiveConversationInputRequest(bytes)`, `receiveConversationInputResponse(status,bytes,request,expectedContext,currentView?)`, `conversationInputView(receipt)`, `conversationInputMetadata`, `conversationInputVersion`, `conversationInputPath`, and `ConversationInputResponseError`. Expected context is mandatory closed `{tenantId,actorId,conversationId,runId,clientId}`, supplied independently by authenticated BFF context. `currentView` accepts a genuine old canonical submit/history view or genuine input receipt; serialized clones are refused. `conversationInputView` exposes the genuine canonical history view for ordinary submit/history receivers, without asserting that synthetic validation-tail events were rendered. Metadata route is `conversationInputMetadata.routes.admit`.

Startup owns additive package exports `./conversation-input` -> `dist/conversation-input.{mjs,d.ts}` and `./conversation-input/schema` -> `dist/conversation-input.schema.json`, and adding the new generator/public tests/type control to appropriate scripts without regenerating the old distribution. The new browser file must retain its exact sibling import `./conversation-application.mjs`; bundling a second copy would clone canonical WeakMaps and invalidate interoperability. Declaration type imports use the public package export to resolve the existing `.d.ts` correctly.

## CAS and preservation semantics

Allocation stores only immutable input/request digests and context/identity facts, not duplicate prompt text. Before creation the canonical public input/admission validators correlate the raw intent with the prepared StoredRequest. The full prepared request hash pins original prompt, selected skill assets, normalized window and original window request; acceptance must match it exactly. Normalization uses the original allocatedAt reference. A retry must reuse that reference and immutable intent, never recompute a new prompt/window. The row cannot refresh its original expiry; later current-authority checks can only shorten the operation deadline.

One row per server-derived tenant/conversation and globally unique requestId, per Qualification's exact0016/table allocation (local reservation5c83c015ee6fe8ab9fa07228e7caa23e19c34999, source authority relayed directly; its denied remote push is not retried or re-exported). The original writer fence must be1. New claim checks there is no conversation, run or next-run journal. A preexisting claim is decoded and integrity/correlation checked; only an exact identity/input/request/context retry may return it, always created:false. RESERVED with a run or ACCEPTED without its exact matching original run is corruption, not permission to create. A different requested identity never overwrites the row. An unacknowledged COMMIT is STORE_COMMIT_UNKNOWN and returns no positive receipt; reconstruction reads the same row but never re-labels it new.

`initialInputs.accept` checks the claimed binding/scopes/versions, requestId and full prepared request hash while holding the same conversation lock. It changes RESERVED to ACCEPTED in the transaction containing the original run and queued event. Any mismatch, expiry or integrity error rolls back all three. Exact accepted retry returns the stored original request/event, without creating a second run, event or dispatch. Allocation itself never dispatches. The existing Temporal workflow identity remains the sole dispatch/recovery identity after durable admission.

Service/session/HTTP/public-generation integration follows exact narrow wire review. Current authorization is checked before the claim and before receipt release; a revoked or shortened session cannot release a fresh receipt. A hard reload without immutable local intent or positive stored-input recovery remains blocked, even if a RESERVED receipt is read. Existing history/admission does not fabricate this proof.

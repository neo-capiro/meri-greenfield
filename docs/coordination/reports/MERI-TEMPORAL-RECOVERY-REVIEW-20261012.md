## Independent discovery

`apps/control/qualification-temporal/workflow.ts` currently performs a finite synthetic approval/checkpoint/publication sequence. Its activities echo a checkpoint/object reference and return a fixed approval. No non-test Temporal caller consumes the canonical registry/control owner or SDK interruption/resume path. Thus the existing compatibility fixture proves types/control flow, not recovery of task A into task B.

`FixtureRegistry` owns database currentness, fences, original committed checkpoint and replacement. `replaceRun` requires the previous grant ACTIVE, verifies the committed checkpoint, then revokes A and inserts B atomically. Normal recovery must NOT first call `stopRun`/`revokeRun`: doing so makes canonical replacement fail. An early reviewer suggestion of a separate revoke-before-replace sequence was corrected immediately after exact-source inspection, before implementation. Explicit cancellation is a separate operation. Logical revocation does not establish native process exit.

`createRunStop` retains pending operations and uncertain publication/revocation only in the current process; it is explicitly not restart reconciliation. `createNativeEvidenceOwner` owns a one-shot bounded publication. Existing worker resume admission depends on actual fresh B admission and a trusted stale-A challenge. None of these may be bypassed by Temporal activity history, retry attempt or heartbeat payload.

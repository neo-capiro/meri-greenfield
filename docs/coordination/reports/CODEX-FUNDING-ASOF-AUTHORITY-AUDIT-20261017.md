## Findings that constrain implementation

1. **All five frozen inputs require an explicit client UUID.** There is no optional-client/global branch in this funding family, including refusal, requirements and landscape paths. Require the current exact one-client task subject/resource and fresh native visible-client membership before releasing credentials or starting source HTTP. Native feature/role/profile-wall gates remain decisive; do not infer them from task scope or add an invented profile-status grant to the generic membership receipt.
2. **The original request hash and normalized arguments hash are distinct.** Preserve the flat original request body and hash it canonically for the observation. Its omitted defaults, query whitespace, UUID casing and page value must not be replaced with normalized input. The existing normalized `argumentsSha256` remains a separate proof. In particular, `asOf` is normalization metadata, not part of that normalized input hash, so the pinned context must also be joined explicitly.
3. **The five native methods already consume an optional third `asOf`; the b525 tool dispatch never supplies it.** Forwarding the reviewed observation into that parameter is the only required clock bridge. Never add a model/body `asOf`, alter public retrieval schemas, repurpose an execution deadline, rewrite result timestamps or pin unrelated SQL clocks.
4. **An old server ignoring the header is unsupported.** Matching result `asOf` is necessary receiving validation but does not prove the server consumed the observation; coincidental equality is possible. No additional acknowledgement schema is allocated by this audit. Require the reviewed Core bridge and exact server/source qualification before installation; do not claim old-server support or retry the legacy path after a refusal/mismatch. Source-only fixtures cannot qualify this external dependency.

## Clock capture, proof joins and receiving

The existing CONTROL owner can capture a canonical ISO instant from its injected clock **once per invocation**, pin it with the original request/delivery, and reuse it unchanged on all fresh authority observations. Original task/native/source expiry still bounds the call; clock capture must not refresh a grant. Existing current task/run/allocation, native tenant/actor, client membership revision, closed subject/resource, operation/version, origin, raw `requestSha256`, normalized `argumentsSha256` and exact `{asOf}` context must remain correlated before credentials and on release. No selector, timestamp or observation header grants authority by itself.

The [b525 dispatch at L2747-L2792](https://github.com/neo-capiro/capiro-backend/blob/b525032222515d636b0dae2d46e40c7c3d8b5528/apps/api/src/meri/meri-tools.service.ts#L2747) currently forwards only actor/input. The allocated finite observation carrier supplies the unmodified body's canonical hash and exact operation/context; the Core bridge must validate route/operation/version/body correlation, decoded size, canonical instant and an **actually verified** internal-service identity before producer I/O. [ToolServiceSecretGuard](https://github.com/neo-capiro/capiro-backend/blob/b525032222515d636b0dae2d46e40c7c3d8b5528/apps/api/src/meri/tool-service-secret.guard.ts#L20) observe-mode success in development/test does not establish that a secret matched. Preserve ordinary native JWT/current principal checks and legacy behavior for unrelated calls.

`x-meri-deadline-at` only shortens execution; it is not the deadline-calculation instant. Envelope `asOf` must equal the trusted context for available and refusal states alike. Requirement-page `generatedAt` must equal it too. Search/client-context structured deadline days/status and scoped counts use it when native mode emits that projection; the frozen funding receiver accepts the native mode variants and needs no new evidence-mode context. SQL lifecycle/current-health and nested search generation retain their actual independent clocks. No global snapshot, byte-determinism or all-clocks-equal claim follows.

Missing/malformed/foreign observation, unverified service identity, operation/hash/context substitution, cancellation, expiry or current-client/task drift must withhold the complete result. Old-server unsupported behavior is a deployment/source qualification HOLD: the old dispatch may execute before a receiving mismatch is detected, and equality alone is not proof of bridge support. Do not add an unallocated acknowledgement contract or runtime startup/installation workaround. Installation must be restricted to the explicitly verified Core implementation and exact server configuration; no fallback request is authorized.

# Fable runtime slices S1–S4: implementation outline (returned before implementation, as the supplement requires)

Base: `fable/meri-complete-20261015` after integrating dot's provenance commits (602d8d4, c83b7cf, b11a6c9 in order; no path overlap with Fable's lanes). Supplement: `docs/deployment/runtime-preview-20261015/FABLE-SOURCE-SLICES.md` at `3e1e76b`. Inspected runtime source as listed there; findings below were rechecked against this branch. No credential, issuer, binding or Temporal policy is created by this outline; every live binding stays an explicit port.

## Selected owners and APIs (the three questions the supplement asks first)

1. **Durable storage and opaque-material owner for S1.** No approved issuer is supplied, and the supplement forbids issuer state in memory, in the next-run mapping or in a second budget ledger, and forbids consuming 0009, 0010 or artifacts 0002 for it. Decision: the issuer adapter is written against an explicit durable **issuance store port** with linearizable `claim`, immutable `bindFacts` compare-or-set and protected `material` retrieval, plus a **capability-material authority port** (the approved capability-generation owner, which exists today only as `sourceOwners.admission` and the task-verifier digest conventions). The port contract is proven by a disposable-store adapter in tests and by a PostgreSQL adapter whose schema requires **a separate central allocation** (proposed `apps/control/conversations/migrations/0011_run_issuance.sql` or a new `meri_issuance` namespace; requested in section 4, not taken). Opaque material is stored by reference only: the store holds `materialRef` (an opaque id) and the hash of the capability; the material itself lives with the capability authority (today the control's secret file owner; in product the shipping-owned secret store), never in receipts or logs.
2. **Per-run transport and capsule delivery owner for S3.** The exact delivery interface is frozen as a private port `runnerBindingForRun({binding,original,signal})` → `{origin, http, bootstrapRef, taskArn, taskRevision, expiresAtMs, versions, tls:{caSha256, serverNameHint}}`, supplied by the trusted owner (registry entry compiled by the control) and consumed by the runner's bootstrap-file materializer. The capsule format is **not accepted**; the materializer accepts a plain owner-only directory of files delivered by the infrastructure owner (capability, config, TLS CA) and validates ownership, mode, no-follow, size, deadline and correlation. Shipping owns the actual capsule, DNS and certificate system.
3. **Exact pinned Temporal SDK API for S4** (inspected `@temporalio/client` and `@temporalio/worker` 1.24.0 declarations in `apps/control/qualification-temporal/node_modules`): client `ConnectionOptions.apiKey?: string | (() => string)` (becomes the `Authorization: Bearer` header; mutually exclusive with an `authorization` key in `metadata`), `Connection.withApiKey`, `Connection.setApiKey`, `Connection.withMetadata`; worker `NativeConnectionOptions.apiKey?: string`, `NativeConnectionOptions.metadata?: Metadata`, `NativeConnection.setApiKey(apiKey)`, `NativeConnection.setMetadata(metadata)`. Selected mechanism: one trusted token provider exposed to both; the client receives the `apiKey` callback (fresh token per call), the worker receives the initial `apiKey` at connect and `setApiKey` on refresh. TLS stays `temporalTls` (mTLS pair plus server root), unchanged.

## Modules and interfaces

| Slice | Module (new unless noted) | Public interface | Notes |
|---|---|---|---|
| S4 | `apps/runtime/temporal-authorization.mjs` | `createTemporalAuthorization({reader, namespace, audience, issuer, now, refreshMs, maxLifetimeMs})` → `{apiKey(): string, current(), refresh({signal}), attach(connection), close()}`; `parseTemporalAuthorizationConfiguration(value)` | `reader` is a trusted token reader port (file with `readSecret` semantics or an issuer client); the module validates finite expiry, bound refresh lifetime, namespace/audience/issuer claims **as a client-side consistency check only**, never as verification; no retry with a missing or expired token; close stops refresh |
| S4 | `config.mjs` (shared, serialized with S2) | `temporal.authorization` closed object: `{tokenFile, namespace, audience, issuer, refreshMs, maxLifetimeMs}` | optional; when absent the current TLS-only behavior is preserved; plaintext tokens in config are refused |
| S4 | `control.mjs`, `temporal-worker.mjs` (shared) | pass `apiKey` to `Connection.connect` and `NativeConnection.connect`; attach refresh | call signatures otherwise unchanged |
| S1 | `apps/runtime/prepared-run-issuer.mjs` | `createPreparedRunIssuer({store, authority, now, maxRequestMs})` → the issuer port of `prepared-run-issuance.mjs` (`read`, `issue`, `bindFacts`, `resolve`) | failure map: claim UNKNOWN on store timeout or ack loss; `issue` claims the exact key before calling `authority.generate`; replay returns the issued identity; `resolve` reads material by reference and fails closed on absent, expired, revoked or UNKNOWN |
| S1 | `apps/runtime/prepared-run-issuance-store.mjs` | store port contract and the disposable in-process adapter used by tests; PostgreSQL adapter follows the allocation | separate module because persistence is its own responsibility |
| S2 | `apps/runtime/prepared-run-bindings.mjs` | `createPreparedRunBindings({configuration, pool, issuer, policy, now})` → `{runIssuance, issuanceIntent, admissionForBinding}` | constructs the three ports from reviewed static references; refuses partial configuration; `multiRun: true` with missing bindings fails readiness |
| S2 | `prepared-candidate.mjs` startup seam | `startPreparedCandidate` passes the three ports when `nativeCandidate.multiRun` is configured | first-run behavior unchanged |
| S3 | `apps/runtime/runner-bootstrap-files.mjs` | `materializeRunnerBootstrap({directory, delivery, expected, now, signal})` → validated `{capabilityFile, configFile, caFile}`; `releaseRunnerBootstrap({directory})` | refuses pre-existing, link or foreign-owner targets; owner-only fresh files; bounded sizes and deadline; removes only owned material |
| S3 | `prepared-run-registry.mjs` (existing) | per-entry `transport` from `runnerBindingForRun` instead of the shared `taskOrigin`/`taskHttp` | fact-hash effect made explicit in the compiler change |

Dependency direction: S4 and S1 independent; S2 consumes S1 and S4's config; S3's port is frozen here and wired through S2 last. Reuse: `readSecret`, `createOperationLifetime`, `compilePreparedRunFacts`, `createPreparedNextRunOwner`, `createPreparedRunRegistry`, `createNativeAllocationAdmission`, existing fixtures.

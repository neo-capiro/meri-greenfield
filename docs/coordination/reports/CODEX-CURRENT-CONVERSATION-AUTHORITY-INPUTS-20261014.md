## Later continuation and approval inputs

This slice wires **borrowed compiled owners** into existing control composition. It does not implement an independent target-admission/decision authority. Supplied `nativeAdmission:{admit,retire}` and `approvals:{read,readDecision}` are inertly captured through existing runtime ports; prepared startup retains them while keeping mandatory candidate identity. Existing private native transport remains the default when none is supplied. The standard CLI without real owners still fails closed for these later calls.

`nativeAdmission.admit` receives `{controlId,mode,sourceBinding,checkpoint,checkpointSha256,request,scopes,selectedClientId,versions,signal}` and returns `{binding,scopes,selectedClientId,admissionReceiptId,targetSessionId,expiresAtMs}`. The receipt must be a genuine independent target authorization. Resume preserves conversation and advances fence with fresh run/attempt/worker; fork creates a fresh conversation/run/session. Task capability/grants and runtime recipe must be fresh, not source-token reuse. Existing lifecycle journal alone persists target/lineage before Temporal dispatch. Full actual target identity/runtime/bootstrap selection remains source integration work beyond this mount.

`nativeAdmission.retire` receives `{controlId,binding,checkpoint,signal}` and returns `{binding,retirementReceiptId,expiresAtMs}` only after genuine original physical stop and authority retirement. Resume calls it before target admission; fork retains the source. No scripted receipt proves retirement. Ordering still matters: lifecycle admission precedes target-row insertion, whereas actual RunTask allocation requires an existing queued target row. A genuine preallocation authorization owner or a separately reviewed canonical pending-target ordering implementation is required; directly attaching RunTask here would be invalid. Do not manufacture a target row, ARN or successful receipt to bypass it.

`approvals.read` receives `{proposalId,binding,scopes,signal}` and returns integrity-checked immutable CommandProposal. `readDecision` receives `{proposalId,commandSha256,binding,signal}` and returns the existing closed ApprovalDecision `{proposalId,commandSha256,decision,decidedAt,expiresAt,approver,policyRevision}`. Resume from approval wait requires the unchanged retained proposal, approved exact command/approver/current policy and nonexpired/nonfuture decision; actual command execution separately requires fresh existing `{decision,checkedAtMs,revoked:false}` authority. Approval metadata persistence is not decision issuance. No such independent owner identifier/reference is supplied by PR17 identity/context. Binding its actual owner is a later required decision/input, not a first-chat blocker.

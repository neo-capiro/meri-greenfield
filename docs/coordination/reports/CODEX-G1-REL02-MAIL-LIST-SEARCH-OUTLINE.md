Proposed interfaces are `assertMailListInput`, `assertMailSearchInput` and `assertMailCandidateSourcePage(page,input,operation)` with fixed operation enum, backed by closed `MailListInput`, `MailSearchInput` and shared `MailCandidateSourcePage` definitions. Reuse personal/client `SubjectRequest`, resolved subject, canonical window and source-inventory eligibility checks; obtain tenant/actor/authorization from canonical context, never caller filters. Preserve numeric defaults/ranges and literal AND search semantics, while deliberately using strict finite integer/string JSON types and rejecting accessors, hidden keys, coercion, null numeric arguments, unknown list search fields and oversized search terms rather than silently coercing/truncating. Normalize optional absent terms and folder without inventing a required keyword. `clientId` becomes the accepted explicit client subject representation, retaining personal subject when omitted; selecting a client elsewhere must not inject a mail filter. ## Clarifications to settle before implementation

1. **Time bounds:** legacy query asOf is inclusive, canonical NormalizedWindow ends exclusive. Recommend keeping explicit `queryScope.effectiveStartInclusive/asOfInclusive` and storedCreatedAt<=asOf in the candidate transport, while retaining the canonical requester window as separately declared context. Never claim those windows equivalent or synthesize endExclusive by adding1ms. If the owner instead selects canonical exclusive query semantics, record that intentional compatibility change before coding. Missing dates also need an explicit declared query rule, not a fabricated timestamp.
2. **Preview unit:** retain preview as incomplete text without body offsets or known full size. An exact public preview bound must name its unit and be checked consistently with the future adapter; the inspected PostgreSQL slice is not a proven UTF-16 400 bound. Avoid silently imposing the thread's UTF-16 contract or changing/removing content. Recipient cap8 requires disclosure, never complete-recipient assertion.
3. **Counts and versions:** keep stored deduplicated totalMatches separate from canonical evidence completeness. Query asOf and messageUpdatedAt must not populate immutable snapshot/recordVersion IDs. Unknown versions force unknown enumeration; even known transport counts and exhausted pages confer no absence/full-read result. Offset ceiling and concurrent update/delete/dedup changes remain explicit partial-view limits. No snapshot service is allocated.

These are bounded representation decisions, not missing permission to read legacy source or implement an adapter. The discovery does not resolve runtime isolation/current revocation, provider completeness, immutability, cross-transaction snapshot behavior or Unicode database behavior; those need future adapter evidence.

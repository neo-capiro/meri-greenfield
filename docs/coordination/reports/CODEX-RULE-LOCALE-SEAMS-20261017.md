## Rule stage and comment clocks

The existing [rule lookup](https://github.com/neo-capiro/capiro-backend/blob/b525032222515d636b0dae2d46e40c7c3d8b5528/apps/api/src/meri/meri-tools.service.ts#L6118-L6201) owns exact-id and bounded state/federal title/abstract selection, ambiguity and no-match honesty. Found rows flow through [formatRuleStatus](https://github.com/neo-capiro/capiro-backend/blob/b525032222515d636b0dae2d46e40c7c3d8b5528/apps/api/src/meri/meri-tools.service.ts#L6204-L6271), which calls both shared predicates without supplying their optional `today`. It creates `generatedAt` later. That envelope time cannot establish either predicate's evaluation time.

The actual [stage helper](https://github.com/neo-capiro/capiro-backend/blob/b525032222515d636b0dae2d46e40c7c3d8b5528/packages/shared/src/index.ts#L1825-L1857) already accepts `today?: Date` and otherwise evaluates `new Date()`. Proposed-rule comment closure uses strict `end < today`; final-rule effectiveness uses `effective <= today`. The separate [comment helper](https://github.com/neo-capiro/capiro-backend/blob/b525032222515d636b0dae2d46e40c7c3d8b5528/packages/shared/src/index.ts#L1867-L1890) also accepts `today?: Date`; for comment-accepting stages it uses its own default clock, strict `end > today` and inclusive `start <= today`. It returns false before reading that clock for other stages. These clocks cannot be silently collapsed or inferred from lifecycle labels, deadline dates or a false `isOpen` flag.

The frozen [Meri rule normalizer/receiver](../../../packages/contracts/retrieval-0.2/rule-status-validation.mjs) requires canonical `stageAsOf` and `commentAsOf` strings even on no-query/no-match branches. The closed caller Request accepts only query/state. The required clocks have no nullable-unused branch. A request-only partial path cannot truthfully manufacture those required observations. No shared source-context owner currently emits them.

Minimal additive proposal for a separately allocated backend/bridge owner:

1. Keep the fixed native operation and model Request unchanged. Add an optional **trusted private** rule-observation argument to the private tool/formatter chain, with exactly `{stageAsOf: Date, commentAsOf: Date}` for retained calls. Existing ordinary callers that omit it retain their current default helper behavior.
2. In the retained path, obtain the two values through the current authenticated CONTROL observation/credential owner and a reviewed backend transport carrier, bound to tenant/user, operation, original request hash, policy/source grants and expiry. The existing fixed tool route has no such carrier at this pin; it must be implemented and reviewed by its owner. Do not add these fields to model arguments or infer them from tool output.
3. Pass the first value only as `deriveRuleLifecycleStage({...existingInputs,today:stageAsOf})`, and the second only as `isRuleCommentOpen({...existingInputs,today:commentAsOf})`. Propagate them through every found-row formatter branch; do not recompute stage or openness in Meri. Preserve existing dates, lookup order, labels, caveats and generatedAt semantics.
4. Return/recheck the matching private context proof to Meri without changing the frozen public rule DTO. Keep both observations stable through the existing call lifetime/rechecks. Require direct boundary tests at equal/end/start instants, distinct clock values, default legacy calls, ambiguity/no-match, expired/mismatched receipts and caller-supplied clock rejection before enabling the adapter.

This proposal uses existing pure helper injection seams and requires no new clock policy or shared-contract schema change. The missing pieces are private caller plumbing and an authenticated carrier/current-context owner, not a new date algorithm. Backend and bridge ownership must be allocated before implementation. Alternative response-captured observations would need a coordinated receiving/context protocol; they cannot be passed off as an already available pre-call context.

## Certification comparison locale

The actual [certification presenter](https://github.com/neo-capiro/capiro-backend/blob/b525032222515d636b0dae2d46e40c7c3d8b5528/apps/api/src/meri/meri-tools.service.ts#L3774-L3825) trims the query, applies no-argument `toLocaleLowerCase()` to the query, product IDs and both product/CSP names, prefers exact product-ID matches, and otherwise keeps name matches in source order, capped at ten with the full candidate count. It does not select or expose an explicit comparison locale. Host default casing is therefore a source-process dependency, not a user preference or a gateway locale.

The frozen [Meri certification receiver](../../../packages/contracts/retrieval-0.2/certification-status-validation.mjs) requires a canonical, supported `comparisonLocale` and uses it for matching checks. ICU support and canonical spelling are only input admission; neither proves the remote presenter used that locale. Current [native authority observations](../../../apps/runtime/native-authority/native-read-credentials/core-client.mjs) contain principal/role/member/visible-client revisions and lifetime fields, with no source locale or rule clock. The existing source-context module has no rule/certification branch. A gateway-local default, hardcoded `en-US`, locale inferred from result names, or a model-supplied value would not establish actual source matching semantics.

The existing [FedRAMP client](https://github.com/neo-capiro/capiro-backend/blob/b525032222515d636b0dae2d46e40c7c3d8b5528/apps/api/src/external/fedramp/fedramp.client.ts#L111-L122) has injectable fetch and observation-time dependencies but no casing-locale responsibility. The presenter calls it without options; it performs bounded live public source fetches with one retry on eligible failures. Its returned observation timestamp is source provenance, not a comparison-locale receipt. No such fetch ran in this audit.

Minimal additive proposal for a separately allocated backend/bridge owner:

1. Keep the Request/DTO and fixed tool route unchanged. Add an optional trusted private presenter option `{comparisonLocale: string}`. For retained calls, use one canonical locale explicitly for **every** query/product-ID/name lowercase comparison; ordinary callers that omit it retain their existing no-argument behavior.
2. Add a same-source-process locale observation through a reviewed native authority/private read-context seam. The owner must establish the actual default-locale semantics and ICU behavior of the process that executes matching, then bind the selected locale to the current request/actor/operation/source grants and expiry. Merely reading a locale in the gateway, identity service or a different backend instance is insufficient. The observation must be checked against the process or explicitly injected value that performs the comparisons.
3. Thread the observed locale through the authenticated private carrier proposed above and the current Meri `comparisonLocale` context. Recheck the same locale on credential acquisition/result release, refusing missing, drifted, unsupported or mismatched values. Do not add a caller locale knob or mutate the central frozen contract in this lane.
4. Qualify this seam with non-ASCII casing (including Turkish dotted/dotless I), exact-ID preference, source-order ambiguity/cap/count, complete-dataset miss provenance, Unicode canonical locale validation, process-locale drift and existing legacy behavior. Preserve official source parsing, bounded fetch/retry, rights/status vocabulary and source observation provenance.

No existing trusted seam identified in the inspected caller can satisfy these observations today. The exact blocked action is implementing/enabling `get_state_rule_status` and `get_certification_status` as faithfully received native reads; the missing owner contract is the private observation carrier and its formatter/comparison injection. This is a source dependency HOLD, not a denied action or an uncertain external outcome. No implementation attempt or source call was made for these two operations. Their remaining counts and SDK availability are unchanged.

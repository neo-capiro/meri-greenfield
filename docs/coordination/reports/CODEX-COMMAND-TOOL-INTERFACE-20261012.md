`prepare(raw,{signal})` uses the actual canonical domain normalization before a trusted metadata preparation port, validates the exact raw/input hashes, original binding, tenant/domain scopes, server IDs, required approver and finite current dates, and returns `{status:'approval_required',proposal}`. No executor, journal or source effect occurs. No dummy execution/approval decision, new approval engine, local proposal cache or additional durable store is introduced. The existing approved administrator self-review exception is unchanged.

The mandatory metadata owner has `prepare({operation,action,binding,request,input,inputSha256,deadlineMs,signal})` and `read({proposalId,commandSha256,operation,action,binding,deadlineMs,signal})`. Both return the closed record `operation,action,binding,request,inputSha256,commandId,idempotencyKey,proposalId,scopes,createdAt,expiresAt,requiredApprover,checkedAtMs`. The external canonical owner is responsible for durable stable metadata and current preparation policy; freshness/identity checks do not independently establish that policy. Its adapter remains unqualified. A late acknowledgement may have persisted metadata; cancellation is not rollback proof.

`executeApproved(proposal,execution,credential,signal)` requires a fresh metadata read and exact reconstruction of the retained raw request/proposal, then calls the existing guarded executor with the original signal. Current approval/revocation, fresh executor authority, durable intent claims, canonical budget accounting and source effects stay in that accepted executor. Original producer provenance is retained; fresh executor attempt/fence semantics stay with the canonical execution validator. Every returned value passes the root `assertCommandToolOutput(action,outputShape,result,retainedRaw,{commandContext,command})`; its existing intent/domain/receipt checks are the sole result correlator. `observed` is an exact correlated receipt/result, `indeterminate` is the closed null-outcome variant. `absent`, forged digests and a new pending proposal are not executor results. Returned values are detached/frozen inert data.

Metadata preparation/read has its original bounded lifetime. It completes before delegation; execution uses the existing executor's separate current-authority/expiry/lifetime. The original caller signal is checked before delegation, after executor await and after canonical output validation. There is no combined request deadline claim or second execution timer. A cancelled release can coexist with a durable OUTCOME and does not reset that outcome, retry or refund an effect.

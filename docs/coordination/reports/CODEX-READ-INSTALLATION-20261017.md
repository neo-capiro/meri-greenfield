## Existing owners and actual missing seam

`createGeneralReadFamilyHandlers` owns canonical family constructors and ordered, deduplicated source manifests. `registerMeasuredHandlers` and `createGeneralReadInstallationOwner` verify those exact bytes against a fresh, externally trusted current installation. Measured source, catalog state and qualification UUID syntax do not establish qualification. The current receipt producer is injected through `readCurrentInstallation`; no replacement issuer is allocated.

The general current-installation request is `{binding,scopes,policyRevision,signal}`. Its closed result is `{binding,scopes,policyRevision,baseCatalogSha256,installationId,executionCatalogSha256,operations:[{operation,descriptorSha256,handlerSourceSha256,qualificationReceiptId}],checkedAtMs,expiresAtMs}`. The existing owner checks full binding/scope/policy and descriptor/source hashes, fresh observation/expiry, unique operations, exact execution-catalog hash, then remeasures every installed file within a bounded lifetime. The gateway and native reads owner independently recheck installation/discovery/task authority before releasing output.

`createPreparedRunRegistry`, immutable issuance facts, `createPreparedReadEntry`, `createReadTaskVerifier` and `createPreparedNativeReads` already bind approved read configuration to the actual admitted run, grant, capability digest, task ARN, persisted request, allocation, scopes, policy and original expiry. `remote-composition.mjs` already supplies the full task tuple to `createReadsRuntime`. That hook is synchronous. The canonical family integration currently performs asynchronous file reads and has no production composition with `createNativeReadCredentialOwner`. The bounded implementation supplies that composition without changing the hook or startup.

Selected skills retain their separate existing `createSelectedSkillInstallationOwner`: request/selection/skill pins plus current scopes/selected client and its own trusted `readCurrentContext` and `readCurrentInstallation` ports. A general receipt must never be relabeled as a selected-skill receipt. Both paths can reuse the same canonical prepared handler manifests and fresh per-task handler construction.

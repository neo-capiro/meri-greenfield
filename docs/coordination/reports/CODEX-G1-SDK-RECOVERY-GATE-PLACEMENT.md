## Finite trusted qualification receipt and channel proposal

Prefer a distinctly named `FixtureCheckpointReceipt` in a centrally reviewed qualification envelope, **not** a product `Checkpoint` with a misleading durableReceiptId. Reuse canonical RunBinding/ObjectReference/WorkspaceManifest shapes where their fields really match; their validation still grants no authority. Keep `profile:'sdk-interruption-fixture-v1'`, `completeRecoveryCheckpoint:false`, `sessionStoreQualified:false`, and an explicit declared-subset coverage label mandatory and immutable. Product checkpoint/resume endpoints must reject this type.

The closed receipt binds: original run/session/project namespace; admitted producer task ARN, attempt/fence and policy; explicit mapping to canonical tenant/actor/conversation/run/UUID attempt/worker identities if used; original D/C; exact source/image/SDK/CLI/contracts/skills versions; whole native bundle size/hash and exact immutable object version; declared fixture-file inventory/hash/reference; original native init/interrupt/exit/drain evidence references; trusted storage-commit identity; and the current-fence publication outcome. Do not allocate any of those operational IDs/clocks here. A worker boolean, bundle's self-hash or fsync alone cannot establish storage durability or authority.

Use one small fixed trusted gateway/broker qualification channel in the adopted trusted control/gateway placement. Workers retain only short-lived task-bound channel capabilities, never S3/DB/provider/Temporal/admin credentials. The channel resolves actual peer plus current grant, complete admitted task/run/fence/policy mapping and permitted operation; driver context remains a request. Do not overload `/v1/messages`, accept arbitrary URL/object keys or create a second auth ledger.

Proposed fixed operations and adapter mapping:

1. `authorizeFixturePhase(context)` backs gateway.authorize. Only a fully validated current decision becomes true; explicit validated stale-binding denial becomes the stale-witness false. Network/parse/timeout ambiguity throws, rather than falsely proving stale fencing.
2. `commitFixtureCheckpoint({context,bundle,fixtureFiles})` backs checkpoint.commit through a thin adapter that obtains the fixed fixtureFiles from trusted composition. The broker validates declared layout/coverage and admitted ownership, persists exact immutable objects, positively rereads their versions/hash/bytes, then records the complete receipt under current authority/fence. Reply is the typed receipt/reference, not a full Checkpoint. It must remain recoverable after A is physically stopped.
3. `loadFixtureCheckpoint({currentContext,receiptIdentity})` authorizes the new task against the original producer receipt and delivers the exact immutable bundle and declared file data privately through the fixed channel. No storage URL supplied by the worker is followed. Original producer provenance is not rewritten to attempt2.
4. `verifyFixtureCheckpoint({currentContext,bundle,reference})` backs checkpoint.verify. It returns true only after authentic receipt lookup, independently measured bytes, exact fixture profile/version/namespace, compatible pins and current replacement authority. That true means verified **fixture** recovery inputs only; completeRecoveryCheckpoint remains false. A fabricated, partial-upload, expired, foreign, altered, revoked or unknown receipt refuses.

Durable storage and fencing are still real requirements at this smaller boundary. Stage immutable versioned objects, then serialize current-grant/fence checks and fixture-receipt publication with the same trusted qualification authority lock. Existing Grants methods acquire PostgresStore.budget's FOR UPDATE lock before current state/time checks; that is a reusable canonical pattern, not an implemented fixture-checkpoint table. Root must centrally allocate any required qualification migration/transaction seam. Do not introduce an independent current-run ledger or claim a pre-check followed by an unrelated write is atomic. Ambiguous writes stay UNKNOWN with the original identity until exact read-only reconciliation; no new ID/retry hides uncertainty. This finite fixture transaction does not implement all W05 product persistence semantics.

For a files continuity observation, add one explicitly declared synthetic workspace sentinel using existing canonical path/manifest checks and fixed owned regular-file capture/restore; do not expand native-session-files into a general workspace copier. A single sentinel proves only that declared file, not complete workspace restoration. If root elects transcript-only scope for one experiment, record file continuity UNTESTED and do not mark the corresponding checkpoint/files spike row complete.

The current driver can keep its injected callback interface and local persistence options. Its nonboolean reference plus verify callback supports this explicit fixture receipt without changing completeRecoveryCheckpoint=false. Full SessionStore injection is a separate W05 allocation. Native quiescence required here is the closed fixture's actual writer/process set; unknown additional native state or unresolved child/subagent activity must HOLD. Complete product quiescence is not silently declared from this narrower evidence.

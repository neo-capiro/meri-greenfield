## Existing owners and their actual limits

- The [ordinary native authority client](../../../apps/runtime/native-authority/native-read-credentials/core-client.mjs) observes current principal, role, identity/membership revisions and visible client UUIDs. The roster contains no names, folder relationship, parser observation, producer clock or comparison locale. A selected UUID and membership grant cannot establish a name-to-UUID association.
- The [application authority wire](../../../packages/contracts/action-authority-0.2/validate.mjs) accepts only an identity-receipt hash plus explicit canonical conversation/client UUIDs. Its real [HTTP client](../../../apps/control/action-host/application-adapters/authority-http.mjs) can recheck those existing resources; it is not a general selector resolver.
- The [retained resource wire](../../../packages/contracts/runtime-0.2/retained-reads.mjs) can carry Florida effective scope and client resolution, but its closed operation set and fixed routes are the three retained research-portfolio/Florida reads. A usable producer for those operations does not automatically allocate a general resolver for other families.
- The [current business-authority composition](../../../apps/gateway/authorization/current-tool-authority.mjs) checks fresh decisions through its configured policy owner. It does not resolve names by itself. Native dispatch currently authorizes raw requests before preparing native context; a future name-resolution implementation must preserve this ordering's authority guarantees instead of loosening an early business gate in a fixture.

No additional fake context port is accepted. Any extension must identify its actual native producer and preserve original request hashing, current task/tenant/user/client grants, bounded expiry, stable resource revision and before-use/release rechecks.

Direct inspection used Core `b525032222515d636b0dae2d46e40c7c3d8b5528`. The unchanged [canonical receiver](../../../packages/contracts/retrieval-0.2/client-knowledge-search-validation.mjs) requires canonical `context.asOf` and exact equality between it and output `generatedAt`. The closed raw request admits no `asOf`. A local clock, HTTP Date header, missing-client note, provider outage or guessed timestamp does not supply that producer-owned observation. Simply assigning the returned timestamp to a context after HTTP would not satisfy the existing dispatch/credential lifecycle, which normalizes and pins the complete context before source execution. Input hash independence from the timestamp does not remove that context binding.

The smallest actual producer change is to capture/consume that same source-owned observation in an authenticated, request-bound execution context, or provide an explicitly coordinated prebound observation consumed by this exact wrapper. A response/context protocol change would require its own allocation and review. Adding an unused Meri `asOf` callback while the native producer still creates a separate timestamp does not close the gap. No such change is implemented by this review, and the graph operation does not confer semantic-search completeness.

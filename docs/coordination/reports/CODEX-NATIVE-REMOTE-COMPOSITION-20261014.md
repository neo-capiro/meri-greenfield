## Implemented owners and runnable composition

`allocateRemoteNativeController` compiles the preparation intent before existing canonical allocation/admission, constructs parked task authority without fabricating a CLI descriptor, and defaults to the concrete borrowed ECS read-only task/image proof. `createRemoteNativeController` composes actual canonical session, restoration/snapshot, runtime/execution, preparation and checkpoint HTTP owners. `createRemoteNativeWorker` mounts task-resident workspace restoration, one deferred independent supervisor/CLI, role-separated bounded stdin/stdout, one retained SDK Query facade and task capture. The existing conversation-runner CLI now accepts an explicit closed remoteTask configuration and invokes runRemoteConversation, which mounts the private HTTP receiver, supplies the same one-Query facade to the existing activity and binds a concrete same-mirror checkpoint factory. Factories are inert; the allocated entry performs only the existing original allocation effect after task-access preflight. A rejected/unknown start cannot allocate a replacement or release a second CLI.

The existing allocation row owns the once-latched `{preparationId,descriptorSha256,configTreeSha256,state}` resource extension. Migration0008 adds no table. The existing run row/fence, original tuple, ARN, lease, budgets and prepared facts remain immutable. PREPARED→CLAIMED is consumed durably before the existing execution broker boots the supervisor; actual CLI release follows that ACK. STARTED/UNKNOWN cannot redispatch. Generic allocation updates preserve the launch binding, including UNKNOWN replay and retirement. Configuration bytes are checked against the actual descriptor before/after release. No parallel authority/session/object journal was introduced.

Before a descriptor exists, runtime reads require the current admitted task, immutable authority scope/client/policy, image/runner configuration and original budgets. CLAIMED/UNKNOWN cannot yield a parked runtime. STARTED reads require the existing broker's genuine CLI liveness and recheck current authority. A running task with an exited CLI cannot release runtime/proxy configuration.

Checkpoint capture freezes/drains the existing mirror, reads and verifies the supported SDK SessionStore snapshot before native exit, proves original native group absence, captures actual workspace bytes and publishes immutable object references through the existing canonical lifecycle owner. The producer intentionally caps opaque transcript JSON at8MiB, each object/file at8MiB, aggregate workspace at32MiB and256files; oversized snapshots, empty workspace directories, aliases/nonregular files and native-JSONL bundles are refused. Restoration's larger supported snapshot-array bound is not a capture-size acceptance claim. Read/replay remains original-task lease scoped; future long-lived inspection needs a current control identity owner, not an expired task capability.

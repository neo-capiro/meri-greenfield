## Connector settings and failure semantics

In the retained raw connector, lines 334–405 parse SSL settings; 122–130 load the CA; 549 sets the effective host; 602–622 construct TLS. Defaults permit plaintext negotiation and invalid certificates. Only `disable`, `prefer`, `require` are recognized SSL modes. Unsupported values retain the preceding mode, initially `prefer`; therefore a lone `verify-full` silently weakens the requested guarantee. `sslaccept=strict` enables certificate validation. `sslcert` reads a PEM certificate and adds it as a root. `sslidentity`/`sslpassword` optionally load a PKCS12 client identity; they are unnecessary for server-authenticated password/SCRAM fixtures. Unknown keys, including `sslrootcert`, are ignored. Repeated keys are processed in order; `host` can override the URL host, including a Unix socket. Use one closed, unambiguous set of parameters and an absolute CA path. [Pinned connector](https://raw.githubusercontent.com/prisma/prisma-engines/ac9d7041ed77bcc8a8dbd2ab6616b39013829574/quaint/src/connector/postgres.rs).

Current official v6 documentation corroborates the mode/accept keys but additionally lists `sslrootcert`; it is not an exact 5.4.2 snapshot and cannot override the pinned parser. Its relative-path description is avoided by the absolute-path fixture. The original unversioned documentation URL redirects to v7, whose driver-adapter model must not be adopted for this engine. [Official v6 PostgreSQL documentation](https://www.prisma.io/docs/orm/v6/overview/databases/postgresql#configuring-an-ssl-connection).

The exact rust-postgres fork passes its TCP host into the native-TLS connector, which retains that domain for the handshake. Its PostgreSQL SSL negotiation explicitly fails when the server refuses TLS in Require mode; Prefer permits plaintext. This is PostgreSQL's negotiated TLS protocol, not an ordinary HTTPS socket. [Fork connect source](https://raw.githubusercontent.com/prisma/rust-postgres/a1a2dc6d9584deaf70a14293c428e7b6ca614d98/tokio-postgres/src/connect.rs), [TLS negotiation](https://raw.githubusercontent.com/prisma/rust-postgres/a1a2dc6d9584deaf70a14293c428e7b6ca614d98/tokio-postgres/src/connect_tls.rs), [domain handoff](https://raw.githubusercontent.com/prisma/rust-postgres/a1a2dc6d9584deaf70a14293c428e7b6ca614d98/postgres-native-tls/src/lib.rs).

## Hostname, SAN and trust-store limits

The exact native-tls crate defaults to hostname verification and built-in roots. The Prisma connector does not disable either. Its insecure certificate mode changes OpenSSL verification to NONE; strict mode leaves peer validation enabled. The supplied PEM adds trust alongside system roots, rather than exclusively pinning that CA. The API reads a certificate, not a demonstrated arbitrary CA-bundle implementation. Use a single fixture CA PEM, explicit file/ownership binding, and no ambient trust overrides. The builder's protocol minimum defaults to TLS 1.0; no corresponding Prisma URL override was found. Enforce the approved minimum on the PostgreSQL server and measure the negotiated protocol. [Versioned native-tls API](https://raw.githubusercontent.com/sfackler/rust-native-tls/v0.2.11/src/lib.rs), [Linux implementation](https://raw.githubusercontent.com/sfackler/rust-native-tls/v0.2.11/src/imp/openssl.rs).

Rust OpenSSL's modern verification path sets expected IP for an IP literal, otherwise expected DNS name, with partial-label wildcards forbidden. DNS SNI is enabled; IP literals do not receive DNS SNI. This is hostname verification, not a SAN-only policy: standard OpenSSL behavior may use DNS CommonName if a corresponding SAN is absent. IP matching requires an IP-address SAN, not an IP string in DNS SAN/CN. Issue explicit matching DNS/IP SANs in the qualification certificate. OpenSSL 3.0.16 documentation was retained as explanatory DATA, not a claim that the engine's loaded library has that exact version. [Pinned Rust OpenSSL connector](https://docs.rs/crate/openssl/0.10.56/source/src/ssl/connector.rs), [OpenSSL hostname/IP rules](https://docs.openssl.org/3.0/man3/X509_check_host/).

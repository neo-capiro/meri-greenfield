## Acceptance sequence

1. Close/test broker/runtime code against canonical interfaces and independently review one integrated source candidate. Avoid broad baseline repeats without a changed surface.
2. Read back owner-provided real bindings and verify exact source/image/authority/allocation/isolation/Temporal relationships. Missing bindings stay configuration blockers; do not fabricate readiness.
3. If separately authorized, perform one bounded actual SDK zero-provider mechanics check through the integrated native stack, with original expiry/hash/storage/physical cleanup evidence. It does not substitute for a model turn.
4. Perform the approved authenticated conversation once; prove current authorization, native session registration, durable transcript/events, proxy budget/accounting and physical retirement. Only this closes the first-conversation gate.
5. After separate output approval, perform one editable DOCX run and verify artifact/storage/renderer/output plus cleanup. Keep wider W05 recovery, source/browser/output/parity and release gates visible; first conversation is not whole-project completion.

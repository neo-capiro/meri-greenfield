1. One cohesive `catalog-validation.mjs` owns operation-to-input/output
   definition bindings and catalog preservation, alias, replacement, byte-pin
   and availability consistency. The existing canonical loader compiles the
   same schemas and injects their exact hashes/metadata; `validate.mjs` retains
   its existing `assertCatalog` interface through thin composition. Synthetic
   foundation DTO fixtures remain supported; they prove no handler availability.
2. Extend the actual `meri.retrieval` catalog by ten producer-informed typed
   intents: three meeting operations, query_tasks, search_capiro_data and five
   federal market operations. Retain the three mail descriptors byte-exact.
   The concrete catalog has 13 mappings, 83 selected pending unmapped IDs and
   43 deferred IDs. Preserve every original ID/disposition/boundary. All
   descriptors remain null-handler, unimplemented, pending and zero-retry.
3. Do not map query_action_items as complete coverage: its unscoped legacy mode
   remains unclosed. Preserve its pending map and explicit qualification gap.
   Discovery/execution is absent; descriptors do not authenticate, normalize a
   live producer, make evidence ready or establish source coverage/freshness.
4. Verify exact known operation/schema definitions and hashes, wrong/foreign
   definitions, version drift, aliases/replacements, missing mappings,
   unavailable-handler behavior and unavailable skills. Preserve existing
   domain assertions and public distribution. No generic SQL or lexical router.
5. Run focused and existing contract/Hermes checks plus public generated bytes,
   typechecking and package tests, using physical copies of the accepted local
   dependency trees and bounded owned process/temp resources. Retain raw
   failures/rerun reasons, source preservation and exact evidence hashes.

## Approved private resolver and characterization extensions

The parent additionally assigned `operation-contracts.mjs` to own inert JSON
admission, an immutable source-catalog snapshot and private callback composition.
`catalog-validation.mjs` remains the sole operation/schema/callback registry;
existing family factories remain semantic owners. The private loader exports
`resolveOperationContract({id,version})`, returning `{descriptor,binding,
normalizeInput,assertOutput}`. Input normalization returns `{request,input,
metadata,argumentsSha256}`, with canonical defaults applied before hashing.
Output validation receives `{request,...context}` using the owned original
request. Explicit context keys are `nowMs`, `actorId`, `previousPage`; only the
relevant family keys are delegated. This is not trusted source authorization.

The parent also approved exactly four stale registration assertion migrations
in data-search, federal-market, meeting-source and operational-reads test
bodies. Their other semantic assertions and unavailable-skill manifest/assertion
suffixes are retained; original full files and failed 194/198 receipts are
preserved. Public exports and live availability remain absent. Private catalog
version intentionally advances to 0.2.1; operation/contract versions stay 0.2.0.

Private resolver admission adds conservative ceilings of 100,000 JSON nodes,
64 levels and 16 MiB of encoded data (syntax accounting may refuse just below
16 MiB). Plain JSON below those limits retains original domain semantics.
These new private ceilings apply before recursive serialization/freezing and
are not a promise of backend or producer response support. Accessor, proxy,
non-plain, cyclic, sparse or non-JSON values refuse without caller code execution.

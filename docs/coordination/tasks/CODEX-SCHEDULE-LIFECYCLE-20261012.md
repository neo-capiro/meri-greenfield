# Application schedule lifecycle source outline

Exact base PR37 `e5fb3963de787bbd7b7663316c368f15814897da`; branch `task/meri-schedule-lifecycle-20261012`; dedicated sparse worktree. Root allocation `7754f1d4` covers four selected operations: `schedule_task`, `list_scheduled_tasks`, `cancel_scheduled_task`, `update_scheduled_task`. Public0.1, existing Temporal inspector/shared lifetime, canonical registry and source activation are immutable in this lane.

Proposed cohesive modules: new private `lifecycle.schema.json`/`lifecycle-validation.mjs`; new control `schedule-lifecycle.mjs` (authorization, durable intent/generation ownership and operation composition), `temporal-schedule-mutations.mjs` (explicit SDK create/update/pause/delete/cancel translation), and `temporal-run-history.mjs` (bounded exact-run metadata/history projection). Reuse canonical inert snapshot, public ScheduleProjection/Identity/Scope, existing inspector and shared operation lifetime. No alternate model loop, scheduler or provider implementation.

`createScheduleLifecycle({scheduleClient, workflowClient, scheduleOwner, authorize, clock})` is inert and borrows SDK clients/connections. `execute({intent,callerIdentity,deadlineMs,signal})` handles the three mutations; `list({selection,callerIdentity,deadlineMs,signal})` consumes an authorized application projection page and inspects known IDs, never treating a namespace-wide Temporal scan as tenant authorization. Durable application persistence allocation is being coordinated with root; an unimplemented injected owner is not claimed as durable integration.

An immutable private intent binds operation/intent ID, expected and next generation, public projection, current caller and server-owned pinned task/template identity. Explicit operator policy inputs include complete calendar/interval/cron specification, timezone, overlap, catchup window, pause-on-failure, remaining actions, initial pause and immediate-run choice. Temporal create's immediate trigger uses ALLOW_ALL: that cannot be silently replaced with the regular overlap choice. Cancel explicitly chooses pause/delete and leave/request-cancel for specifically bound running executions. Cancellation acknowledgement is not physical stop. No new public Command enum or approval semantics are introduced; current authorization callback owns policy and exact intent approval requirements.

Current authority is checked before durable admission, before every SDK effect and before result release. Receipts bind exact intent/projection/caller, expire monotonically and expose `limitDeadline` so a newly known deadline is published before another port can park. The application owner durably reserves stable intent identity and generation before effects, prevents repeat dispatch and retains unknown outcomes after possible effects. Settlement/reconciliation cannot authorize redispatch. Shared runtime limits bound one local call, not the future schedule execution budget. Future workflow execution must separately enforce the public projection's current scopes, cost/runtime/retry limits and task manifest.

SDK1.24.0 source is inspected directly from the allocated installed donor. `update()` internally describes then replaces without server conflictToken; application serialization cannot prove safety against external writers. `create()`/`update()` use random SDK request IDs, not stable application replay IDs. `fetchHistory()` accumulates all pages, so bounded history uses the actual exposed workflowService paging API with fixed exact run identity and capped pages/events/tokens. Only safe event IDs/types/times and execution metadata may leave the adapter; workflow inputs, memo, event attributes and credentials must not. Missing or truncated pages never claim complete history. Schedule original firstExecutionRunId is not silently used as the current retry identity.

Verification: local scripted-port tests through actual new adapters, immutable input/context substitutions, generation/replay denial, post-effect unknown state, revocation and shortened deadlines at each parked boundary, no late nested callback effects, explicit SDK options, exact-run/cursor/history caps, filtered output and borrowed-resource preservation. Independent memory reviewer freezes separate controls. Preserve every failure/preimage and owned process cleanup. No Temporal server, database, SQL, native/provider/model/cloud/network/security action; no installs or large dependency copies. Source-only checks cannot close G1.

Approved implementation amendments: root allocated `postgres-schedule-owner.mjs` and product `migrations/0001_schedule_owner.sql` under this lane; no shared command journal. `createPostgresScheduleLifecycle` concretely composes the owner with the adapter, while the injected-owner constructor remains a test/application seam. The application owner persists projection generations and stable intent states CLAIMED/DISPATCHING/ACKNOWLEDGED/UNKNOWN. No migration is executed automatically. The selected history surface is bounded original-execution summaries through exact run-ID `getHandle().describe()`, not raw event history; reviewer explicitly accepted this scope. Overall history is always partial and current retry identity unverified. Listing preserves authorized application rows when actual Temporal inspection is unavailable, after fresh row authority; cancellation state alone never establishes absence.

The private schema exposes all policy choices explicitly: complete calendar fields, interval every/offset, cron strings, exclusions, timezone, start/end bounds, jitter, overlap, catchup, pause-on-failure, remaining actions, paused/note, immediate execution, pinned task and workflow template. Calendar and cron/IANA interpretation remains the SDK/server's responsibility. Intent dates use canonical `Date.toISOString()` wire spelling; per-call deadline is at most60 seconds. Numeric local resource ceilings are documented input admissions, not permission or spending authority. Private approval uses public ApprovalDecision field shapes only, with intent digest correlation; it is never sent through the public Command validator.

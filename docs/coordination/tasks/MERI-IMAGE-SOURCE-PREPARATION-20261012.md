## Acceptance defined before source changes

1. Preserve the exact held image and its 47 current findings, five older carried
   findings and two older krb5 findings: 54 distinct unresolved obligations.
   A finding disappearing from a scan is not remediation. Preserve source,
   archive, context and scan identities separately.
2. A patched recipe requires supported, released, coherent distribution and
   dependency fixes, authoritative applicability evidence, exact reproducible
   inputs and relevant compatibility checks. Do not mix unstable packages into
   Debian stable, remove required packages, invent not-affected dispositions or
   update guard pins merely to obtain a pass. Embedded copies remain in scope.
3. Source preparation acceptance requires independent reproduction of the
   canonical context, exact pin/lock agreement, retained failures and precise
   statements of unverified binary, signature, license and runtime properties.
   Reuse the existing context assembler, manifest format and guard implementations.
4. License evidence must distinguish registry metadata, notices actually shipped
   in exact artifacts, source-level notice recovery and unresolved embedded or
   commercial agreement scope. It is not legal or redistribution approval.
5. A source manifest does not prove reproducible OCI layers or installed package
   closure. Fresh installed inventory, complete current vulnerability scan,
   applicability review and native functional/sandbox checks remain separate.
6. If no coherent supported patch set exists, publish an independently reviewed
   preparation packet with explicit HOLD. Do not label unchanged recipe bytes a
   patched candidate. Any concrete unrelated defect needs its own justified scope.

The buildspec invokes only that collector, then uploads the already-created archive in `post_build`. A standalone new script would be outside the source ZIP and never invoked, or would publish without the canonical verified static/cleanup result. Post-collector publication would also leave the immutable result bundle without publication evidence. Reimplementing the builder/collector's bindings in the new script would create a parallel authority path.

A publication module needs a narrowly scoped private stdin credential flow and positive `clear-qualification-docker-config.py` readback. The fixed buildspec's `AWS_MAX_ATTEMPTS=1` and `autoRetryLimitOverride=0` are useful but do not by themselves resolve an ambiguous Docker push.

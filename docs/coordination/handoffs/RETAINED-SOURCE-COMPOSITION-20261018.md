# Retained read source composition, 18 October 2026

## Implementation outline and ownership

- The 76 operations in the canonical catalog remain the desired inventory. An operation becomes installed only through an explicitly reviewed active P2 measurement after its production port and source qualification exist. A partial receipt neither revokes nor changes the other catalog operations.
- The build measures the active operation refs and the full 76-row source inventory separately. Runtime values remeasure both against the source tree. The render requires the same explicit active refs and pins the active measurement. The worker's fixed G3 profile registers only those refs, preserving its run-invariant SDK options hash. The control composer derives its families from the pinned P2 rows and keeps the `omittedMeasuredFamilies` refusal for any explicit narrower override.
- The control CLI supplies the existing task-bound signed relay to the five selected-client retained families only when the reviewed receipt names no other retained owner and Option B delegation is enabled. It borrows the existing Core origin, current gateway authority, reservation, selected-client scope and approved per-task request/response limits. The relay is constructed at the first signed source call so an unrelated task can initialize without client-only facts.
- Other retained families require their own genuine ports and current source facts. Memory remains the separate memory lane. The eight v1 adapters remain with the active A8 owner on `codex/meri-a8-v1-adapters-20261018`. Shared receiving changes need review by their assigned owner before integration.

- Mail needs mailbox-scoped credential and retention owners. Monday needs a current versioned board mapping. Memory needs its separately owned eligibility and continuation context. An enabled P2 installation with either side absent or mismatched refuses.

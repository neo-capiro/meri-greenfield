- The 76 operations in the canonical catalog remain the desired inventory. An operation becomes installed only through an explicitly reviewed active P2 measurement after its production port and source qualification exist. A partial receipt neither revokes nor changes the other catalog operations.
- The build measures the active operation refs and the full 76-row source inventory separately. Runtime values remeasure both against the source tree. The render requires the same explicit active refs and pins the active measurement. The worker's fixed G3 profile registers only those refs, preserving its run-invariant SDK options hash. It borrows the existing Core origin, current gateway authority, reservation, selected-client scope and approved per-task request/response limits. The relay is constructed at the first signed source call so an unrelated task can initialize without client-only facts.
- The existing `datasetMetadataTaskPort`, `createOperationalTaskPorts`, and `createResearchEvidenceTaskPorts` are genuine source slices but are not yet composed by this CLI branch. A later reviewed subset needs their exact task-local aggregation and P2 source-path measurement; `query_tasks` still has separate portfolio-wide authority. Memory remains the separate memory lane. The eight v1 adapters have a published PR159 checkpoint at `cdb5c2e7`; this read lane is preparing a separate A8 successor after verifying no current local writer. Shared receiving changes need review by their assigned owner before integration.

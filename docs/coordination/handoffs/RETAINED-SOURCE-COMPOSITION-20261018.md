# Retained source composition, 18 October 2026

## Implementation outline

- Control's existing reads composer owns current authority, P1/P2 installation, reservation, budget, and the Option B run delegation. Core owns the current selected client and each source result. The source composition borrows those ports; it never issues a grant.
- Add a small task-port composition beside the existing retained-read factories. It derives exact `POST /api/clio/tools/<operation id>` endpoints from the already validated Core candidate origin and returns only the seven client-scoped signed operations' five family transports. The `getCredentials` port is the composer's `getSignedSourceCredentials`, which binds the exact body, correlation, run, client, and invocation before Fetch. Clamp request time and response bytes to the accepted per-task read limits.
- Control CLI can pass this task callback to `createControlReadsComposer` only through an honest full-family composition supplied by the existing owners. The current all-family receiving contract requires all 15 retained family transports and mail/memory/retained context owners. A client-only callback cannot satisfy it. The CLI remains unchanged in this slice; no selected operation is removed or silently revoked to make the installation pass.
- Reuse `createOperationalTaskPorts`, `createResearchEvidenceTaskPorts`, `datasetMetadataTaskPort`, and `createCoreRetainedTaskPorts` for their respective owners when their required facts are available. Portfolio issuer/recipient trust is not inferred from a Core origin. Memory eligibility and continuation custody belong to the memory lane. Mailbox entitlement and Monday's current versioned board mapping need authority successors, not generic tokens or placeholder context ports.
- The P2 manifest must cover every new source module loaded by the control receiver, the signed relay, and Monday's adapter/handler. Verify exact endpoint groups, bounds, client scope, Option B refusal, and source-measurement coverage with focused synthetic tests. No live Core, SQL, AWS, credential, paid, or model calls.

## Current integration limits

The 76-operation receipt is preserved. The seven genuine selected-client source transport configurations construct seven canonical family handlers, use the task's approved read limits, and borrow the exact `getSignedSourceCredentials` callback. The full production runtime is still unavailable because the CLI cannot supply a truthful 15-family callback: memory eligibility/continuation is separately owned, Portfolio trust has no configured issuer/recipient pins, mail lacks mailbox scope/retention, and Monday lacks a versioned board mapping. The current composer also constructs a client-only relay and two restrictive factories eagerly for unrelated tasks. An unavailable callback advertised as installed would risk a budget reservation before failing, so none is installed.

Core PR87/92 prepares signed admission and ten receiver branches, but the preview routes are not live; `read_client_documents` explicitly returns 503. These source configurations therefore establish the exact production port shape, not deployment or authenticated readback. A later CLI receiver must import this slice, merge only genuine owner ports, and complete the existing composer under the unchanged 76-operation measurement.

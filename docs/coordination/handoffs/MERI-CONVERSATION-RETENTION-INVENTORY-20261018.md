# Conversation-owned retention inventory — source outline, 18 October 2026

This bounded slice adds a read-only producer for the rows owned by the conversation store: the conversation, runs, events, controls, lifecycle checkpoints, completion checkpoints, next-run reservations and memory-proposal continuation rows. The canonical retention planner and purge switch remain separate owners. No missing class is represented as absent.

## Ownership and interface

`apps/control/conversations/retention-inventory.mjs` owns one production PostgreSQL read-only `REPEATABLE READ` snapshot for an exact trusted `{tenantId,conversationId,ownerActorId}`. It scans each relation in bounded keyset pages and refuses overflow, cancellation, timeout and any incomplete or inconsistent row. `retention-inventory-decode.mjs` validates stored hashes, canonical DTOs, tenant/conversation/actor bindings and row links, then returns explicit row identities plus the exact object-version references already present in checkpoint and continuation records. The existing memory-proposal journal exports its validated same-client scanner so its rows share this snapshot. The caller owns the pool; this producer releases only its borrowed client.

The producer neither supplies policy, cross-subject holds, liabilities, row deletion targets nor a complete `facts.inventoryFor` implementation. Its output is a conversation-owner slice for a later coordinated planner contract: `subject`, `conversation`, `runs`, `eventRows`, `artifactVersionRefs`, `controls`, `checkpoints`, `completionCheckpoints`, `nextRuns`, `memoryContinuations`, `objectVersions`, and a canonical `inventorySha256`. Controls and every event row have explicit identities. `artifactVersionRefs` preserve validated `artifact.available` event lineage separately from storage object references. Unpublished `CAPTURING`/`UNKNOWN` completion rows remain present with a null checkpoint; their possible orphan capture bytes require a separate liability decision. Object references from a fork's retained continuation belong to the target conversation even if the checkpoint source binding names its original conversation.

The producer refuses beyond 4096 total rows, 16 MiB of scanned or returned JSON, or a 5000 ms deadline. A timed-out pool lease is retired on late arrival; a timed-out statement retires its uncertain connection without racing a rollback. Each of the eight tables is scanned under the same PostgreSQL read-only repeatable-read snapshot. Rows must match stored hashes, owner actor, run binding and scopes, event sequence, control/checkpoint/completion links and next-run reservations. Migration 0009 can backfill older run ranges without `next_runs` records; existing reservations are still validated, but no absent historical reservation is fabricated.

## Verification

Focused journal and lifetime checks passed 15/15. A disposable network-disabled PostgreSQL 16 control applied conversation migrations 0001, 0002, 0009, 0010 and 0019 to an empty private socket database; its final run passed 1/1. It used canonical conversation, completion, lifecycle and next-run owners, then verified the event and memory page boundaries, a concurrent post-snapshot memory insert, actor/tenant/conversation refusal, object-version enumeration and a corrupted stored run hash. The container, socket and temporary dependency links were removed. `node --check` and `git diff --check` passed. These checks establish local source behavior only; no live SQL, AWS, provider or deployment action occurred.

SDK sessions, artifacts/uploads, Core memory, budgets, receipts, schedules, logs/telemetry, cross-subject object holders and legal holds need their own authoritative producers and policy before purge can be considered. Existing inventory planning cannot yet consume the newly explicit control/event identities or nullable unpublished completion checkpoint; that shared contract requires its own owner review. This standalone source factory is deliberately not wired into the production retention `facts` composer or shared family-source manifest because no complete all-class snapshot/policy exists. The eventual composer owner must import `createConversationRetentionInventory` and coordinate its source-manifest entry; the conversation store's existing per-run `tx` must not be reused because it is READ COMMITTED and takes a writer-blocking conversation lock.

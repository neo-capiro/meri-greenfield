## Connected reader reconciliation (1 November 2026, M32 and M33)

Source-level reconciliation of every read family in the 31 October handoff domain appendix against the current admitted catalog (`packages/contracts/retrieval-0.3/catalog.json`, 0.2.30), the gateway family modules and source handlers, the worker mount (`apps/worker/conversation/reads/families.mjs`) and the tool descriptions the model sees. The table is derived by `scripts/retrieval-audit.mjs` and `scripts/retrieval-audit.test.mjs` fails when this document drifts from the derivation. Registration is not activation: a row here says the source path exists and is tested with synthetic Core, not that the deployed installation, serving data or live acceptance exists.

How the four result states are kept apart, for every family:

- **Denied scope** is the closed failure `ACCESS_DENIED` (gateway admission, Core 401/403 on the source route, or current-authority loss during the read). It carries no source detail and is never rendered as an empty page.
- **Unsupported operation** is `UNAVAILABLE`: the read is not mounted, installed or served for this conversation, or Core answered 404/410/501 on its fixed tool route (a client, folder, feature or membership Core will not serve for this request).
- **Unanswered source** is the new closed failure `SOURCE_UNAVAILABLE`: Core answered 408/425/429 or any 5xx; the read is supported, the source did not answer this call. Previously these collapsed into `INVALID_RESULT` ("a result that failed validation"). `apps/gateway/sources/json-response.mjs#sourceStatusCode` owns the mapping; the code crosses control to the worker in the closed native-read set (`packages/contracts/runtime-0.2/reads.mjs`, `apps/runtime/reads-client.mjs`, `apps/runtime/reads-http.mjs`) and renders as its own text in `apps/worker/conversation/reads/results.mjs`.
- **Absent data** is only ever a successful result with an empty collection, inside the coverage the result declares (page, window, source set). **Stale or partial** coverage is declared by the result fields each family names in the table (coverage, truncated, hasMore, nextCursor/nextPage, limitations, freshness, asOf, sourceFreshness). The server instructions state this vocabulary once (`RESULT_STATE_GUIDANCE`) and each tool description names the family's own fields.

Tool descriptions: preserved catalog descriptors keep their published bytes (the current catalog must carry every 0.2 descriptor unchanged), so the model-facing text is composed in `apps/worker/conversation/reads/tools.mjs` from the descriptor plus the reviewed family guidance in `family-guidance.mjs` (what the family covers, what it returns with its freshness/version fields, how its result declares absent/partial/stale data). Registration-era limitations that are false for a mounted read ("null handler", "no enabled source", "remains unqualified") are filtered out. Structured families carry the SQL-first sentence when both `describe_capiro_data` and `query_capiro_data` are mounted in the run, and an explicit "text-to-SQL is not enabled here" sentence otherwise. The five 0.3-only descriptors of graph-paths, buyer-workspace and funding-analysis were rewritten in the catalog itself (they are not preserved rows) and the installation catalog pin in `packages/skills/index.mjs` follows.

"Tests referencing each operation" counts test and fixture files that name the operation id. Many of those suites failed on untouched `main` on this host because their fixtures predate the slimmed gateway read context (`assertReadContext`) and the profile mount (`activeReadOperations`); this change repairs the fixtures of the twenty families built on the bill-text fixture and the worker read fixture, and modernizes the authority-mutation tests that became vacuous. ### M33 graph, buyer, funding and procurement analysis

- `find_path_to` (graph-paths): every edge carries `basis` (direct/thematic/derived), `origin` and canonical `sources`; the validator binds edge sources to their basis, path continuity, depth and `coverage.state`/`reasons`; `observedAt` and `temporalCoverage: current_only` are explicit.

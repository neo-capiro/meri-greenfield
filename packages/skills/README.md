# Original Meri skill assets

`selectSkill(skillId, skillVersion)` returns a frozen `{manifest, prose, pin}` from a finite immutable index. The caller must supply an exact version; there is no latest-version or fuzzy fallback. The pin retains skill/version, canonical manifest SHA256, exact UTF-8 prose SHA256 and the canonical retrieval catalog SHA256. `listSkills()` lists asset identities and hashes without exposing a runtime grant.

Thirteen previously absent original recipes now have substantive steps, allowed operations, required evidence sources, output/completion rubrics and immutable 1.0.0 assets. Their native SKILL.md frontmatter describes each recipe and disables autonomous model invocation; the trusted request owner selects the workflow explicitly. The existing Congressional sourced brief for Bill Watch 1.0.0 is read byte for byte from `apps/control/document-application/research-brief/`. Its manifest, prose and bounded intent are unchanged; it remains one Bill Watch output rather than the full federal/state workflow promise.

Control must use the existing `assertSkillManifest(manifest, catalog)` and `assertSkillPin` before execution. The loader checks asset shape, original hashes and source/operation catalog binding without changing operation availability. All current operations remain unavailable, and the canonical runtime validator refuses every selected asset. Loading a recipe is not authorization or runtime acceptance. Budgets reuse the existing brief's conservative 12-turn, 24-tool, 60-second ceilings with zero recovery attempts; these are unqualified upper bounds, never spending authority. A larger admitted workflow needs a separately reviewed new version rather than silently changing these assets.

The manifest source inventory covers every source/purpose required by its declared operations. Where broad discovery describes a source as authoritative but a specific domain operation describes it as derived, the manifest retains the lower-authority legal requirement. Every read retains its actual authority; the asset does not upgrade the domain projection. A trusted portfolio roster/version is required independently of discovery; search candidates cannot prove the roster is complete.

`compileCommitmentsAudit(input, {context, reads})`, exported from `commitments/index.mjs`, produces a read-only ledger from canonical current decisive-read envelopes and explicitly extracted observations. It binds exact passages to source/record/version, content and passage hashes, authorized scope and decision, and current run/attempt/fence. It separates suggestions, deduplicates only identical original promise passages, exposes unknown/conflicting owners/dates, retains proposed tracking links and delivery claims, and shows all six required source coverage cells. Monday evidence additionally binds the trusted client-board IDs via the existing applied-filter hash. Missing mapping, missing reads and provider disconnection remain visible. It makes no calls or mutations and grants no authority.

This is a bounded evidence/extraction implementation. Extracted semantic classifications, owner/date interpretations and cross-record links still require verification. Native task completion does not establish delivery or acceptance under the existing contracts, so the projection never marks a commitment completed and never asserts absence. A qualified source adapter and complete semantic/held-out evaluation remain necessary for the full Commitments workflow. Existing action-followthrough owns a separately requested immutable task proposal; this package does not duplicate it.

Targeted verification: `node --test packages/skills/test/assets.test.mjs packages/skills/test/commitments.test.mjs`. It checks all original identities, source/rubric coverage, exact Bill Watch preservation, fixed hash pins including coordinated prose/self-hash tampering, immutable explicit selection, unavailable runtime refusal and Commitments isolation/evidence/Monday/semantic counterexamples. Synthetic local evidence only; no provider, native database, cloud, credentials or private artifacts.

`plugin.mjs` projects the same originals as one native SDK plugin. `describeSkillPlugin()` derives each plugin skill name from the immutable index and the SKILL.md frontmatter (assets without SDK frontmatter are listed as excluded), and `materializeSkillPlugin({directory})` writes `.claude-plugin/plugin.json` plus byte-exact `skills/<name>/SKILL.md` files into a fresh owner-only directory for the runtime image; it refuses an existing target and removes what it created on failure. No prose is duplicated in Git and model invocation stays disabled by the original frontmatter. Verification: `node --test packages/skills/test/plugin.test.mjs`.

Native skill format reference: [Claude Agent SDK skills documentation](https://code.claude.com/docs/en/agent-sdk/skills), checked 2026-10-13. No upstream skill implementation was copied and no dependencies were added.

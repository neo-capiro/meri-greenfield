# Public conversation receiving boundary (package0.1.3)

The additive `@capiro/meri-contracts/conversation-application` export and `/conversation-application/schema` use canonical Run, RunBinding, Scope and UIEvent wire0.1.0 references. Window and selected-skill schema fragments are build-time projections from their existing private0.2 owners; the published browser bundle imports no private source, Node builtin or external package. All prior root/browser/action/document generated bytes stay unchanged, including document metadata0.1.2 and action metadata0.1.1. Receiving validation supplies integrity checks only; it cannot establish current identity, source truth, revocation, authorization or an executable grant.

`receiveConversationRequest(route,utf8Bytes)` takes native Uint8Array bytes and admits closed requests: submit `{requestId,prompt,windowRequest?,skill?:{skillId,skillVersion}}`, history `{after?,limit?}`, cancel `{}`, events `{command:{conversationId,intent:'view.subscribe'}}`. Scope, session credentials, tenant/fence/worker authority and arbitrary commands are absent. Requests are capped at131,072bytes. JSON responses/events are capped at2,097,152bytes; these limits apply to buffered receiving input. The authenticated network client must bound network/body allocation too. Existing upstream AI SDK remains the SSE parser; this export adds no streaming parser or agent loop.

`receiveConversationResponse(route,status,utf8Bytes,admittedRequest,currentView?)` is asynchronous and returns a deeply frozen actual JSON success/error. HTTP200 alone carries success. Exact canonical error/status pairs are listed in `conversationApplicationMetadata.errorStatuses`; no private error text or credential is admitted. Events success is an AI SDK stream, so its JSON200 receiving path raises `STREAM_RESPONSE_REQUIRED`.

Successful submit `{run,requestId,lastSequence,replayed}` and history `{run,request,events,nextSequence,hasMore,lastSequence}` become locally admitted views. The caller must select the exact current view when already known. Binding includes tenant/actor/conversation/run/attempt/worker/fence and scopes must agree exactly. A history page must begin at requested after+1, be contiguous and complete up to its continuation boundary, never exceed lastSequence, and preserve immutable request identity/input. Stored prompt, selected skill, original window specification and subsequent stored request cannot be substituted. Explicit timestamps, relative anchor/elapsed duration, fiscal year/calendar/stage/revision/timezone and week policy correlate with the original specification. These checks do not prove the underlying sources or authorize their release.

`createConversationCursor(view,after?)` admits an acknowledged offset only from observed provenance. Submit defaults to0 and admits only0: lastSequence does not mean event bytes were observed. History defaults to its received nextSequence; an explicit offset must be between that page's requested after and contiguous nextSequence. A partial page's unobserved lastSequence cannot be selected. `receiveConversationEvent(utf8Bytes,cursor)` validates one canonical event against exact view binding/scopes, requires after+1 and an unused immutable event ID, consumes that cursor and returns frozen `{event,cursor:next}`. Consumed/shape-only cursors fail. Retained event IDs are capped at10,000 per cursor chain; `CURSOR_CHECKPOINT_REQUIRED` preserves the old cursor and requires fetching/admitting a fresh history page before further receiving. An acknowledged history page seeds known IDs; deliberately rewinding within its observed range is allowed. A new current view requires a fresh cursor; server current authority is rechecked separately.

`conversationReconnect(cursor)` returns `{method:'GET',path:'/api/conversations/events/{conversationId}/stream',headers:{'x-meri-resume-sequence':decimalAfter}}`. Use that header with AI SDK7.0.137 `DefaultChatTransport({api:'/api/conversations/events',headers:currentAuthHeaders})` and `reconnectToStream({chatId:cursor.conversationId,headers:reconnect.headers})`. No custom reconnect URL hook is needed. The actual existing server mount validates the selector against authenticated history before exposing any stream and rechecks current session/scopes on every event page. Query cursors, Last-Event-ID, noncanonical/unsafe sequence headers and GET body/content conflicts are refused. Public POST subscribe has no cursor field; legacy POST `{after?,limit?}` is documented separately on the server.

An ended subscription/AI SDK finish is not proof of durable run completion. Only the received run.status event or authenticated history provides the run state. Aborting/cancelling a stream reader closes that subscription, with no durable cancellation. POST cancel `{}` invokes the existing durable cancellation service and returns its terminal state (`completed`, `failed` or `cancelled`). Current authenticated session remains the server authority for every route.

Generation is offline: `node packages/contracts/generate-conversations.mjs [--check|--help]`; invalid arguments/drift exit1 before any network activity. New dist metadata pins the canonical schema and application/receiving sources. `npm run check --prefix packages/contracts` includes deterministic generation, typechecking and old/new public checks. Targeted executable fixtures compose the real Fetch mount/session owner/SQL store/service/event source and pinned upstream AI SDK client/producer, with synthetic SQL and identity. No native DB/provider/source call or deployment occurs.

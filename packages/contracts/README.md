# Meri shared contracts 0.1.0

Public distribution candidate for D014: `@capiro/meri-contracts` exports generated UI-event types at the package root, browser validation at `/browser`, immutable schema metadata at `/metadata`, the exact frozen JSON at `/schema`, and existing Node checks at `/node`. The package version does not change the frozen wire protocol. R2 additive candidates are intentionally absent from these exports until separately reviewed/frozen.

Run `npm ci --ignore-scripts --prefix packages/contracts`, then `npm run check:contracts:distribution`. Regenerate only with `npm run build --prefix packages/contracts`; `generate.mjs --check` compares deterministic generated bytes without writing. The generator refuses any drift from the accepted 50043-byte schema hash. Pack with `npm pack ./packages/contracts --ignore-scripts` at the repository root; consumers use the resulting versioned public tarball, never private source imports. Generated types describe shape and cannot express every format/bound; runtime validation remains required. Validation grants no authorization.

Owner: Codex integration. Status: prepared for independent review; freeze requires review acceptance and a pinned integration commit. `meri.schema.json` uses JSON Schema 2020-12, stable ID `urn:meri:contracts:0.1.0`, closed records, UTC timestamps, safe integers and explicit protocol versions. These independent definitions import no Capiro implementation. Subordinate tool argument/result schemas must be approved with each new connector; the generic `arguments` and `data` envelopes are deliberately opaque and are never permission grants.

`npm ci` followed by `npm run check:contracts` validates the contract boundary fixtures. Ajv handles shapes, formats and unknown fields. `canonicalize` supplies the RFC 8785 JSON encoding for SHA-256 over the complete `Command`, including its identity binding, operation, arguments, immutable attachments, lineage and idempotency key. Approval metadata and decisions are excluded from that preimage. A changed command always requires a new proposal and approval. Strict schemas mean added fields can break old readers; bump the contract version and qualify an adapter before dependent work.

## Required service semantics

- Resolve identity with the official Clerk backend SDK, then current authoritative local user and active tenant membership. Capability claims are server-verified metadata, never model-supplied authority. Validate signature/opaque grant lookup, issuer, audience, expiry, actions, actor, tenant, conversation, run, attempt, worker, budgets, current policy revision and writer fence at the trusted gateway/broker. No bearer keys belong in events, files, checkpoints or logs.
- Enforce all client walls, mailbox ownership and private-memory grants independently of tenant identity. Check current access to every protected contributing scope for tool reads, resume, publication, event replay, thread history, citations, previews, downloads and exports. Losing authority cancels affected live work and blocks historical content. A scope list alone proves no access.
- Every derived object inherits the union of contributing source scopes. Reject mismatched tenant bindings and dropped lineage. A public source does not erase private lineage. Citation IDs resolve through the gateway after authorization, rather than exposing raw storage URLs.
- Sequence events once per conversation in durable application storage. Immutable event IDs deduplicate delivery; reconnect requests events after an acknowledged sequence. Enforce ordering across runs/attempts and fence stale writers. UI events are separate from opaque SDK transcripts and do not expose private model reasoning.
- Bind opaque pagination cursors to the actor, current authorization revision, scopes, source, normalized query and continuation. Do not interpret a bounded empty scan as complete coverage. Truncated results cannot claim complete coverage; unsupported history and counts remain explicit.
- Execute approved commands only after current authorization, matching proposal/hash/approver/expiry and live fence checks. Atomically bind the tenant-scoped idempotency key to the exact command hash and outcome. Same key with a different hash conflicts. Reconcile indeterminate external outcomes before retrying; an SDK/Temporal retry alone cannot guarantee no duplicate side effects.
- `Command.binding` is immutable producer provenance. `CommandExecutionRequest.executorBinding` and capability identify the current trusted executor; compare stable tenant/actor/conversation/run identity with the approved intent, then authorize the current attempt/worker/fence independently. Approval-wait recovery may replace the executor without modifying approved intent or its idempotency identity. Source receipts bind the actual executor.
- A checkpoint requires independently verified durable SDK state AND workspace bytes/manifest, exact runtime/image/contract/skill versions, a trusted durable receipt and fencing. `durableReceiptId` in untrusted JSON does not prove durability. Verify all bytes/hashes/object permissions and compatibility before resume; unsupported links and traversal are rejected. Detect filesystem ancestor/descendant conflicts during restoration. Uploaded `.claude`, instructions, plugins and config remain inert data outside runtime discovery.
- Lifecycle tombstones and restore barriers must survive backup restoration. Apply deletion/retention to transcripts, events, uploads, browser state, snapshots, previews, artifacts, caches and exports. Legal holds need explicit policy; do not silently resurrect deleted material.
- Record measured usage for every run/attempt including failures, retries, cancellation and SDK subagents. Reconcile provider records and enforce budgets outside the agent. Temporal owns orchestration/schedules; nondeterministic execution belongs in activities or broker workers.

## Initial evidence boundary

The fixtures prove only local structural and immutable-payload/path checks. They do not prove authentication, current authorization, durable storage, cursor security, deletion, idempotent external execution, network isolation, browser sandboxing or Fargate compatibility. Those remain W02–W09 deployment evidence.

The revocation deadline is proposed at no more than 30 seconds and must be agreed before G3. Per-task and tenant cost caps must be chosen from qualification measurements. Production source reads/writes, schedules and authenticated browsing are disabled until their gates pass.

## Additive action application receiver (package 0.1.1)

`@capiro/meri-contracts/action-application` exports async `receiveActionResponse(route, httpStatus, jsonText)` and `ActionResponseError`, plus route-specific receiving TypeScript types. Use `await receiveActionResponse('query', response.status, await response.text())`. The input must be primitive JSON text: arbitrary objects, accessors and Proxies are rejected without inspection. A successful return is a detached, deeply frozen actual wire value (success or `{error:{code,outcome}}`). Only HTTP200 carries success. Other statuses must match the canonical content-free error code; errors throw content-free `ActionResponseError` codes. No endpoint, credential, approval or retry capability is exported.

The receiver requires browser WebCrypto SHA-256 and TextEncoder. It bounds UTF-8 text to16MiB, nesting to64 and parsed nodes to100,000; these last two are deliberate receiving limits. Nested contracts are generated from their canonical owners, including original public0.1 UIEvent/RunBinding/ApprovalProposal/CommandReceipt and the selected private read/task result definitions. Only the receiving projection is published: importing does not import any private server source. The new `/action-application/schema` export contains that projection; source hashes are in `dist/action-application.metadata.json`. Existing public0.1 schema and root/browser generated bytes are unchanged.

Hash equality and internal correlations do not authenticate source truth, transport or current access. Prepared means `approval_required`, never approved. An observed receipt is not a fresh grant or safe retry instruction. Execute responses omit the original proposal, so consumers must retain and separately correlate the trusted originating proposal/command when needed; this receiver cannot infer that missing fact. Recovered current attempts may differ from draft source provenance while stable tenant/actor/conversation/run identities remain correlated. UNKNOWN/RESULT_NOT_RELEASED/STORED_NOT_RELEASED/NOT_STORED/READ_UNAVAILABLE never imply rollback or retry permission.

Build/check includes `generate-actions.mjs`; it reads schemas and application error vocabulary at build time only. No runtime/API/model/provider/database activity occurs. Isolated installation uses the package tarball; no npm publication is authorized.

## Additive document application receiver (package 0.1.2)

`@capiro/meri-contracts/document-application` adds the DOCX/TXT and XLSX wire projection. `/document-application/schema` exports its JSON Schema; `dist/document-application.metadata.json` pins the canonical schema and application sources. All older exports, generated bytes and the frozen public0.1 schema remain unchanged. PDF, presentations, general analysis, private context, credentials and authority are outside this export.

```ts
import {
  receiveDocumentRequest, receiveDocumentResponse, receiveDocumentDownload,
} from '@capiro/meri-contracts/document-application';

const request = receiveDocumentRequest('create', new TextEncoder().encode(JSON.stringify({
  deliveryId: 'document-1',
  request: { operation: 'create_word', format: 'txt', title: 'Draft', content: { text: 'Hello' } },
})));
// Send JSON.stringify(request) using the application's existing authenticated client.
// Its bounded JSON transport supplies strict UTF-8 bytes and the actual status.
const receipt = await receiveDocumentResponse('create', status, boundedJsonBytes, request);
if (!('error' in receipt)) {
  // downloadResponse is the actual authenticated /api/documents/download Response.
  const download = await receiveDocumentDownload(downloadResponse, receipt.version);
  const blob = new Blob([download.bytes], { type: download.version.mimeType });
  // The UI owns any object URL it creates and must revoke that URL when finished.
}
```

The exact request envelopes are create `{deliveryId,request}`, revise `{deliveryId,baseVersionId,request}`, and inspect/download `{versionId}`. `receiveDocumentRequest` is synchronous; both response functions return promises. JSON receivers require a native `Uint8Array`, not arbitrary objects or text. They snapshot before parsing, reject malformed UTF-8, unpaired Unicode, prototype-control keys, depth over64 and over100,000 nodes. Requests are capped at2MiB and JSON responses at16MiB. These receiving functions bound already-buffered input; the calling JSON transport must also enforce its network-body cap before allocating an unbounded response. The server remains the owner of content semantics such as permitted formula functions, sheet uniqueness, chart relationships and asset admission.

Requests and successful receipt versions are deeply frozen and locally branded. Pass the exact returned request to the response receiver and the exact returned version to the binary receiver. A stored/cloned version must be readmitted by a fresh validated inspect receipt; the consumer cannot manufacture an admitted version by matching its TypeScript shape. Branding only records local validation provenance. It does not authenticate the server, establish current authorization, validate stored content or grant access. No storage URL or credential is exported.

A created receipt correlates filename/format, parent version, object bytes/hash, scopes and inspection with the admitted request. An inspect receipt additionally requires the requested version ID and `currentBytesVerified:true`. This boundary cannot recompute the execution fingerprint without the private trusted context, authenticate receipt IDs, infer original artifact identity from a parent UUID, or establish current access. Those remain server responsibilities. Draft/pending and native-opened/rendered/recalculated false are preserved, including XLSX's explicit unverified formula-cache status. Error receipts preserve uncertainty and never recommend an automatic retry.

`receiveDocumentDownload(response, version, {maxBytes?,timeoutMs?,signal?})` reads the native Response stream and returns `{version,bytes}` only after genuine EOF, exact length and SHA-256 verification. It rejects responses with the native redirected flag; callers must also use fetch redirect:`error` to prevent the network from following a redirect before this receiver sees it. It requires HTTP200, exact MIME, quoted attachment filename, canonical content-length, `cache-control:no-store`, `x-content-type-options:nosniff`, and no content-encoding. It refuses unsupported formats and filesystem-like filenames through the admitted receipt. Options are trusted consumer configuration: default/max16MiB; default30 seconds, maximum60 seconds, optional native AbortSignal. Native getters bypass response/typed-array own-property overrides. Timeout, cancellation, read errors, truncation, overflow and hash mismatch release no bytes; reader cancellation is best effort and does not prove physical network termination. Returned bytes are a detached mutable Uint8Array owned by the caller; the metadata is frozen. WebCrypto is required. The standalone browser ESM has no Node globals, runtime imports, fetch side effects or authority callbacks.

`generate-documents.mjs [--check|--help]` is the offline deterministic generator (exit0 success/help, exit1 invalid arguments/drift). Package build/check/typecheck/public tests include this additive surface. Validation and synthetic consumer tests are source evidence only, not Office, rendering, production security or runtime admission.

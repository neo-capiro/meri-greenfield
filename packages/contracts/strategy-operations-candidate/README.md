## Envelope and operation semantics

Each closed request carries operation, request/job identity, tenant/actor/client/owner, actual Objective revision/version/snapshot and all five intent fields (or an explicit manual source), context packet and coverage hashes, original deadline and an opaque delegation reference/revision. Edit/document requests also pin the exact Strategy/version/hash and complete existing dependency graph. `inputSha256` is canonical SHA256 of the whole request excluding only `inputSha256`; it is not a hash of the nested `input` alone. Hashes detect mismatches; a trusted owner must supply the expected identities and snapshots.

`strategy.draft` carries an optional existing Strategy type hint. The model proposes one of the seven existing types and rationale from evidence; Objective ask type is a separate enum. No extra mandatory user picker is added. The whole graph must have 1–60 nodes, valid kinds/subjects/statuses, supported ownership/evidence, required real start dates, valid ranges and known acyclic edges. Unknown required dates produce typed `needs-information`; nothing fabricates a date, truncates nodes/titles or drops edges.

Draft dependencies use stable source node keys. `draftDependencyIndices` validates the entire graph and maps edges exactly to the current draft DTO's numeric indexes. It is not an implemented backend adapter. The backend must re-run its existing verifiers. Legacy draft owner selection is only `dto.ownerUserId?.trim() || clerkUserId`; it is not evidence of current membership validation. Objective's authoritative owner binding remains separately Core-owned. Assistant ownerNames uses the current active native member directory; do not conflate these paths.

Draft input now explicitly preserves `goal` (4000), `meriContext` (8000), raw `ownerUserId` (120), nullable real `targetDate`, and all supplied `attachmentIds` (10 strings of200), beside typeHint. Omitted/null optional DTO fields normalize with the existing `??null`/`??[]` behavior; strings, duplicate IDs and empty ID strings are preserved without trimming/filtering. `context.draft` is a closed typed packet carrying these exact fields, client and separately selected owner. `contextSha256` hashes the entire context excluding itself. `assertLegacyDraftMapping` compares that packet against the trusted original DTO and actual separately observed filename/text bundle. The current Strategy resolver filters blank/whitespace texts, but drops document IDs/status/truncation/reason and unavailable IDs: legacy observations explicitly say unattributed and coverage unproven. No index/filename/hash is promoted into a document ID.

Core `resolveAttachmentText` already returns actual `{id,filename,kind,text,status,truncated,reason}` and unavailable IDs under tenant/native-user lookup. `assertCoreDraftMapping` preserves this richer authorized response by actual document ID, independent of response ordering. Each observed prompt excerpt gets a raw UTF-8 text hash/byte count and canonical content-snapshot digest over the exact returned representation; content-addressed `versionRef` is not a database row version or proof that a snapshot was durably stored.

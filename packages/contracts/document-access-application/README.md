# Document access application contract (inspect, download, immutable history and library)

Unpublished `urn:meri:document-access-application:0.2.0` browser boundary for document inspect, download, history and library discovery. The history/list routes are additive; existing inspect/download request and success shapes remain unchanged from document-access 0.1.0. The frozen `document-application` 0.1.x distribution and published package archives stay byte-identical. This document-access version is separate from the frozen root wire and `RuntimeVersions.contracts` 0.1.0; neither changes. Validation grants no authority, qualifies no renderer and is not deployment, composition or runtime-mount evidence.

## Immutable history

`POST /api/documents/history` accepts exactly `{versionId, limit, cursor}`: an anchor UUID, an integer limit from 1 to 100, and a null or lowercase 64-hex opaque cursor. The producer verifies that the anchor belongs to the complete authorized immutable chain before slicing. Its response is exactly `{anchorVersionId, artifactId, headVersionId, versions, nextCursor}`. The anchor echoes the request; versions run newest to oldest along exact parents. The first page starts at the head and a terminal page ends at a null parent. A continuation is bound to the current tenant/actor/conversation/scopes, anchor, limit and head snapshot. Changing any of them invalidates the continuation. A cursor is a page selector, never authorization: every page requires current Core access and retention checks before metadata release.

History carries original version/provenance metadata only. It does not read or verify object bytes, report native opening/preview, or brand versions for download. The consumer must inspect an exact selected version before using the existing byte receiver. History receives only generated versions; native workspace files retain their separate inspection branch and no synthesized version chain. Archive, delete, share, comments and rename are not admitted by this route.

## Current library discovery

`POST /api/documents/list` accepts exactly `{scope, limit, cursor}`. Scope is `conversation`, `client` (the currently selected client), or `owner` (the authenticated actor across their own eligible origins); limit is an integer from 1 to 100 and cursor is null or lowercase 64-hex. The response is exactly `{scope, versions, nextCursor}` with zero to limit original current-head versions. It never discovers colleagues' private conversations. Each origin requires fresh same-user Core authorization and current retention before admission and again before release. A current-conversation grant cannot authorize another origin implicitly, and original bindings/scopes are never rewritten.

Each page scans a bounded candidate window. Denied or suppressed heads are omitted without exposing counts; an empty visible page can still have `nextCursor`. Only a null cursor ends the retained candidate snapshot. Continuations bind the original caller context, query and candidate-head snapshot; a changed snapshot/query is refused with `ARTIFACT_LIBRARY_CURSOR`. The cursor is neither a bearer nor a cached access grant. Unknown authority or storage outcomes fail the page rather than silently hiding them as denials.

List versions are metadata, without a download admission brand or byte/preview claims. Select the original conversation through its normal session owner, then use the existing inspect/history/download boundaries. Their conversation fences remain unchanged. Native workspace files keep their separate inspection branch; this library does not invent generated-version records for them. The public receiver validates correlation and closed shapes; it never replaces server authorization.

The strict-contract policy in `packages/contracts/README.md` requires a version change when extending a closed public surface. This unpublished sibling version preserves old operation shapes; existing 0.1.22 consumers continue using their old inspect/download boundary. A new npm package allocation, generated-source review and matching consumer reception are separate from this source change. Existing 0.1.22/UI 0.1.9 archives are immutable.

## Why it exists

The frozen document receiver is a build-time projection of the canonical artifact contract that keeps only `docx`, `txt` and `xlsx` (`admitted` in `document-application/schema.mjs`). The canonical `artifacts-0.2` schema, the artifact producers and the server's format admission (`apps/control/document-application/format-admission.mjs`) also carry `pptx`, `zip` and `pdf`. A PPTX, ZIP or PDF version therefore cannot be inspected by that receiver, and because download is admitted only for a version the receiver admitted from an inspect answer, it cannot be downloaded either. This contract projects every canonical inspection variant (`docx`, `txt`, `xlsx`, `pptx`, `pdf`, `zip`) onto the two read routes. Create and revise stay in the frozen contract.

## Compatibility with the frozen receiver

The public names are the same so a consumer swaps one import path: `receiveDocumentRequest`, `receiveDocumentResponse`, `receiveDocumentDownload`, `DocumentResponseError`, and the types `AdmittedDocumentRequest`, `AdmittedDocumentVersion`, `DocumentReceipt`, `DocumentResponse`, `DocumentDownload`, `DocumentDownloadOptions`. Existing routes `inspect` and `download` retain their request and response shapes. The checks for an inspect answer are the frozen receiver's, unchanged (scope and size, evidence scopes, hash, bytes, MIME type and file extension agree with the inspection, exact version id), over all six formats. Download reuses the frozen `receiveDocumentDownload` source: the version must have been admitted from an inspect answer (module-local provenance), headers and bytes are verified against that exact version, and the caller cannot bypass inspection. The error vocabulary is derived from the same document owners and preserves all prior codes/statuses; only the new history/library cursor codes belong exclusively to this access contract. `DocumentResponseError` is a distinct class from the frozen bundle's.

## What a variant says (and does not)

Inspection is structural. Every variant has `nativeOpened`, `rendered` and `recalculated` fixed to `false`; `pptx` carries `visualInspection:'pending'`, `pdf` carries `renderInspection:'pending'` and the source DOCX hash, `zip` carries row/column/chart facts. No inspection describes a rendered or visually checked file, and the receiver refuses any that claims it.

`version.previewStatus` is `pending` and `generationStatus` is `draft`, because the document application releases nothing else (`index.mjs version()`); a status the producer never emits is not admitted. Preview support is therefore not learnable from the version. The metadata carries what the preview owner does (`previewFormats`: `docx`, `xlsx`, `pptx`, `pdf`; every other format answers `ARTIFACT_PREVIEW_UNSUPPORTED`; each except `pdf` also needs a qualified converter or answers `ARTIFACT_RENDERER_UNAVAILABLE`). This contract has no preview route and says nothing about whether a renderer is qualified in any deployment.

## Derived, not copied

`generate-document-access.mjs` reads the canonical artifact schema, the MIME vocabulary, the catalog, the real `admitDocumentDescriptor` for each operation (to publish `operationFormats`), the preview owner's `PREVIEW_FORMATS`, and the document HTTP owners' status table, and records the SHA-256 of every source (including the preview service text). A change to any of them without regeneration fails `--check`. Output is independent of the checkout layout (symlinks preserved; layout paths refused). Canonical esbuild/json-schema-to-typescript backend only.

## Known producer limits (documented, not papered over)

See `docs/integration/MERI-DOCUMENT-ACCESS-CONTRACT-B2-20261019.md`: one operation descriptor per document-application instance, no preview route contract, no status other than draft/pending, PDF composition gated by a renderer switch, and the unverified end-to-end composition for mixed-format conversations.

Native workspace files use the explicit `kind: native-file` inspect branch. Metadata identifies the committed manifest, exact path and immutable object; `integrity.currentBytesVerified` records the current byte/hash check, without generation, format or rendering claims. Download remains inspect-first and uses `application/octet-stream`, with the exact basename conveyed by the shared ASCII/RFC5987 disposition convention. The native file byte cap is 8 MiB; generated versions retain their existing format and inspection contracts.

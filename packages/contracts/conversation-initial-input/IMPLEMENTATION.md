Public API:

- `receiveConversationInitialInputRequest(utf8Bytes)` returns the SAME genuine frozen request returned by accepted `receiveConversationInputRequest`; an additional private WeakMap records allocation provenance.
- `receiveConversationInitialInputResponse(status, utf8Bytes, request, expectedContext)` returns the closed `{allocation, state, created}` envelope or the new closed allocation error envelope. Positive receipt proof is tied to the exact original request object and independent five-key context values. No Conversation view is minted. The private record pins all allocation facts, including both original timestamps, across repeated responses; a later positive reply must use `created:false`, and ACCEPTED cannot revert to RESERVED.
- `receiveAllocatedConversationInputResponse(status, utf8Bytes, request, expectedContext, allocationReceipt)` requires that exact allocation proof, delegates bytes unchanged to the accepted input receiver, verifies binding/scopes/versions and the full JCS StoredRequest digest, and returns the SAME genuine input receipt. The existing `conversationInputView` remains its sole view owner. The bridge uses the existing 2 MiB input response limit; the new allocation route's response cap is 131072 bytes.

`expectedContext` is the independently authenticated closed `{tenantId,actorId,conversationId,runId,clientId}` value. Validation grants no current membership, creation, effect or dispatch authority. The server owns current authorization and the immutable original deadline; client receipt validation also rejects inactive allocation times. `created:false`, UNKNOWN, errors, absent rows and digest-only reloads never establish a new input identity. Exact retained intent with a genuine `created:false` receipt remains recoverable.

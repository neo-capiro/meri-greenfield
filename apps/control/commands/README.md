# Guarded command source composition

`createPostgresCommandExecutor` in `durable-executor.mjs` is the concrete control owner. It imports the public gateway budget composition, uses the existing owned invocation producer and conservative fixed-charge accounting, and executes `createCommandExecutor` with the supplied canonical current `command.execute` authority. Construction is inert. `sourceEnabled` defaults to false; no production catalog, listener or runtime wiring is enabled here.

Trusted construction requires a borrowed budget pool and immutable allocation, a `producerContext` containing exact retained grant facts and producer identity, a command journal, current authority/approval ports, the fixed-route HTTP source, domain contracts, descriptor, original producer context, clock, UUID supplier and limits. The descriptor separates command action from the selected original operation at version 0.2.0. Trusted configured executor factories exist only inside application composition; no request or returned facade exposes executable callbacks, private producer ports or completion submission. This is not confinement against malicious host application code or a pool operator.

The owner accepts `{proposal, execution}`. It derives stable delivery identity from the command ID, durably binds hashes of the entire immutable command/proposal/context, and preserves the separate original command and fresh executor bindings. `execute` returns an observed exact receipt/result or an indeterminate observation; `readOutcome` may also return a point-in-time absent observation. Absent never authorizes redispatch. Replays of a journaled command do not repeat source effects. Recovered executor attempts can read the original outcome through fresh authority; budget reconciliation retains the original producer/grant facts and does not mint replacement authority.

`prepareInvocation` and `reconcileInvocation` concern canonical budget intent/accounting only. A recoverable completion marker permits the existing fixed hold to settle once; it never reconstructs missing source results or proves delivery. An unknown source/claim/final acknowledgement is not rollback. No refund, automatic retry, stale claim takeover or source transaction ID is invented. Final source output, receipt and authority checks precede accounting; all live ports retain the shortest original/current deadline. Cleanup checks prevent a late pool acquisition starting new SQL after its original cleanup cutoff, but cannot physically interrupt a database or socket operation.

`createCommandHttpSource` calls only governed `/clio/tools/create_task`, `/clio/tools/update_task`, `/clio/tools/save_chat_attachments` and the compatible shared-scope `/clio/tools/save_memory` branch. Credentials and immutable attachment mappings come from trusted host brokers. Broker facts must attest the actual authenticated backend identity, including Clerk/backend user mappings, and actual source attachment bytes/version/destination; equality checks are not attestation. Middleware provisioning/healing, audit, extraction and indexing effects remain native qualification obligations. No HTTP request is made by the local source tests.

Personal memory remains `PENDING_PRODUCER_UNAVAILABLE` before intent/source effects: the legacy producer auto-commits personal memory. Firm/client success means pending candidate creation only. The approved administrator self-review exception is unchanged. Task update is an explicit private 0.2 unconditional patch, without compare-and-swap or nullable clearing through this wrapper. Date-only/UTC-midnight admission is deliberate. Filing preserves saved reasons and all per-object observations: only all-saved is a succeeded aggregate; all other sets remain indeterminate.

Migration source consists of existing qualification state 0001→0002→0003 for the canonical budget owner plus this command-owned `migrations/0001_commands.sql`. There is no automatic migration or engine execution. Existing Aurora selection is retained. Current rights/approval brokers, native journal durability/concurrency, atomic attachment identity, actual credential/transport behavior and supported patched runtime remain unqualified.

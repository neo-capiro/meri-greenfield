# Action recommendation lookup control

Use the supported `index.mjs` exports to compose `createTaskLookupDelivery({gateway,store,authorize,clock})` with `createPostgresTaskLookupStore({pool})`. Importing opens no connections. The gateway must be the current-authorized durable execution owner exposing `executeOwned(requestJson,credential,deliveryJson,signal)`; the control invokes it once. This module does not allocate tool budgets or own model orchestration.

`lookup({request,context,credential,signal})` accepts only canonical action selectors (actionItemId/status/sort/limit/cursor); the already selected client UUID comes from trusted context. Context carries lookup/result/request IDs, original public RunBinding/scopes, the immutable trusted gateway delivery JSON, two pre-reserved public event slots and deadline. The independent upstream event owner must reserve globally collision-free sequences. Local SQL checks collisions only among records retained here; this is not a global event allocator or proof of an upstream reservation.

The store claims the exact original binding, commits a dispatch marker, and then the control invokes the gateway. Neither ambiguous commit nor repeated claim dispatches automatically. Result and completion event persist atomically. A successful call returns `{lookupId,resultReference,resultSha256,classification:'recommendations',acceptedTasks:false,events}`. The result hash covers the complete governed envelope. `read({resultReference,context:{currentBinding,scopes,deadlineMs},signal})` returns the same fields plus `observation`. It retains original event/observation provenance; fresh policy decides whether the separate current reader may access it. UUID-equivalent result-reference spellings identify the same result without rewriting stored bytes.

`authorize({phase,binding,signal,limitDeadline})` must be an application-owned current policy adapter. Its closed receipt is `{authorized:true,bindingSha256,expiresAtMs}`. Its binding is `{original,current,scopes,resultReference,resultSha256,bindingSha256}` where `original` is the full prepared retained binding, or null before a read; the digest excludes its own field. The callback must publish any shorter known expiry through limitDeadline before awaiting later work. Lookup phases: before_claim, before_dispatch, before_store, before_release; error observation uses before_error_release. Read phases: before_read then before_release, with exact retained result digest. Structural validation and DB existence confer no authority. `assertTaskLookupStoredBinding` exports only this structural validation for server composition/evaluation.

Journal states are CLAIMED, DISPATCHING, RESULT, ERROR. CLAIMED/DISPATCHING left by interrupted or ambiguous work stay unavailable to automatic replay; they are not proof of no effect. UNKNOWN is the caller disposition for ambiguous durable work, including lost claim or dispatch acknowledgement. RESULT_NOT_RELEASED preserves a known retained result when later release fails. An ERROR row is a delivery observation only: it neither resolves gateway budget liability nor establishes failed/completed run status. A known RESULT cannot be overwritten with ERROR. Recovery/reconciliation still needs the separate authoritative owner; no reconciliation mutation is implemented here.

Only existing public0.1 tool.started/tool.completed/run.error events are returned, as a bounded batch for the existing application transport. No live progress stream, SSE implementation, run.completed, task acceptance or task mutation is produced. Canonical source coverage, pagination, evidence and absence limitations remain untouched. All97 production descriptors remain unavailable.

The borrowed pg8.23.1-compatible pool owner must configure finite connectionTimeoutMillis and query_timeout. Transactions set statement_timeout5s and lock_timeout2s. The shared operation lifetime bounds caller waiting (maximum60s); pending DB work can finish after cancellation. Unknown BEGIN/failed rollback/ambiguous commit evict the client; a secondary release error does not erase primary uncertainty. Do not terminate a borrowed pool. Migration0001 is explicit source only and has not been applied.

`fixtures.mjs` and `postgres-fixture.mjs` are test-only inert ports. The latter recognizes only this store's fixed SQL and supports one transaction at a time; it does not emulate PostgreSQL concurrency, locking, permissions, crash durability or native execution. Real pool/migration/gateway source credentials, current policy and event reservation producers remain qualification prerequisites. No tool is activated by this composition.

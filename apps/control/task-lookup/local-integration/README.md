# Existing local PostgreSQL action durability cases

`runLocalActionPersistence({descriptor,pool,openFreshPool,createCase})` is an explicit test runner. It uses `createPostgresTaskLookupStore` and `createTaskLookupDelivery`, plus the trusted case producer's actual durable gateway and current-read authorizer. Import does not connect, launch, migrate or seed. It requires an already isolated local PostgreSQL fixture; a descriptor is correlation data, not permission to run.

The root CLI owns the existing `parseNativeAdmission/openNativePool/verifyDatabase` boundary and exact pg8.23.1 driver. It supplies the nonsecret descriptor shown in the task outline, a borrowed pool, and `openFreshPool() -> {pool,close}`. Pool owners must set finite connection/query timeouts and at least two concurrent connections. Every schema must already exist: qualification0001, budget0002, invocation0003 and task-lookup0001. Migration hashes bind current source bytes. Live probes check cluster identity, fsync/synchronous_commit and required projected columns separately; they do not prove migration installation provenance or full schema equivalence.

`createCase({pool,name,deadlineMs})` supplies `{gateway,authorize,lookup:{request,context,credential},readContext,sourceCalls,revokeRead,expectedChargeMicroUsd}`. It creates fresh synthetic run/grant and event/delivery IDs, and binds the gateway allocation through its real owner. Only explicit fresh synthetic rows may be inserted. This is the separate identity owner's code, not a constant allow receipt. Source is synthetic and in-process; no provider or customer access. Each case must have its own run and lookup. No background caller may mutate the fixture while counts/accounting are observed.

Six cases check reconnection/reconstruction, simultaneous duplicate claims, lost claim/dispatch/result COMMIT acknowledgments and current-read revocation. The fault wrapper passes every statement to real pg and throws once *after* a selected lookup COMMIT succeeds. Other gateway/budget statements use the original pool. A retained ERROR is a delivery observation; it is not an accounting resolution. Retained RESULT cannot be rewritten by the error fallback. Completion hashes, two exact reserved events, original binding, invocation/reservation identity and settled fixed charge are checked through SQL and a fresh authorized read.

The initial pool is borrowed and never ended. The single fresh pool is closed once, including late acquisition after timeout; pending or failed cleanup remains HOLD and cannot prove physical termination. The global deadline uses the accepted shared operation lifetime. Cancellation bounds caller waiting and cannot cancel every native query. The fixture owner must ensure all pending SQL and pool work is gone before teardown. Rows are retained: output includes every case's run/grant/lookup/result/event IDs; this runner issues no delete, truncate, drop or migration. Do not delete accounting rows while retaining their consumed global budget. The fixture owner tears down only its fully isolated fixture.

Reconstruction means new control/store objects and a new pool. It does **not** test a database crash/restart or power-loss durability. Real cases are UNRUN in the saved environment: no PostgreSQL server, cached image or exact driver is available. Offline tests only verify admission refusals and real-call forwarding semantics with small port spies; they cannot establish database locking/durability. All production tools remain unavailable; this runner does not change the catalog.

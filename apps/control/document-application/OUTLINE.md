# Document application source outline

The Fetch boundary admits the exact configured canonical create_word (docx/txt) or create_excel (xlsx) operation. It does not interpret prose, create authority, generate approvals, or implement rendering. Existing session issuance remains independently mounted. HTTP bearer credentials are opaque sessions; the configured artifact capability never comes from the body.

`createDocumentApplication({sessions,selectedClientId,artifactOptions,credential,now,limits,enabled=false})` returns `{handle}`. Limits are maxRequestMs/maxRequestBytes/maxResponseBytes. The original canonical artifact context is snapshotted once; its deadline, evidence, assets, scopes and binding are never rewritten to produce a different delivery hash.

Modules: http.mjs owns native Request admission and content-free responses; current.mjs composes createRequestCurrent and captures trusted configuration; format-admission.mjs admits only the two exact canonical descriptor projections and their bounded application formats; index.mjs dispatches to actual artifact owners and validates release. Canonical artifact validators and format helpers own shapes/filenames/MIME. PostgresArtifactService owns all write accounting and replay; ArtifactService owns read verification without budget reservation. Every authority boundary and final release rechecks current sessions and exact configured binding/scopes/client. Session and authority expiries synchronously narrow one outer lifetime before another port can run.

Routes: POST /api/documents/create {deliveryId,request}; revise {deliveryId,baseVersionId,request}; inspect/download {versionId}. JSON results are existing artifact results. Download returns exact verified bytes with attachment filename and MIME. Errors contain only a finite code and disposition; write calls with uncertain completion remain UNKNOWN, and acknowledged output denied at release remains RESULT_NOT_RELEASED. There is no automatic retry, reconciliation mutation, resource disposal, or production catalog activation.

Workbook continuation base bc8b65cc7186e449cf20b4956e4cd88684b35325: trusted configuration selects exactly one operation. Each request must match it before authorization/accounting, and every create/revise/inspect/download response must belong to the same format family. Excel uses the existing canonical ExcelRequest/Workbook, XlsxWriter generator and openpyxl revision owner; no generator, schema or policy changes. Word/TXT defaults and all original tests remain. PDF, slides and analysis remain outside this narrow application admission.

Tests use actual canonical artifact services and budget ledger with explicitly scripted ports. Root owns the compatible local fixture operation option, actual workbook content/render qualification and CLI. Test bounds are240 seconds. No native database, provider, customer data or source activation is used by this author lane. Failed captures and exact owned-process cleanup are retained.

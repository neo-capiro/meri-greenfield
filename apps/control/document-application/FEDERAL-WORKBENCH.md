# Retained federal drafting review

The existing document application accepts `federal-import`, `federal-prepare`, `federal-load`, `federal-publish`, `federal-approve` and `federal-history` under `/api/documents/`. Core's existing artifact authority owner admits the corresponding read or publication operations. The public request carries no identity, scopes, authorization or legal approval. The public receiver is `@capiro/meri-contracts/federal-workbench` 1.3.0.

Import reads the exact five-pin official selection through the current Core reader and retains the projected envelope as an immutable TXT artifact; a retained USLM extraction becomes a `federal-uslm-xml/1` source with its identifier tree, plain text stays flat ([compiler](../../artifacts/federal-drafting/README.md)). Preparation reads an exact immutable TXT source version/hash through current artifact authority and retention, then runs the deterministic compiler. Save (`output: draft`) writes the review record through the ordinary artifact delivery journal; a revision is a child version of its exact previous review version (`baseVersionId` plus `baseRevisionSha256`). Load reads both record and original source again and recompiles, comparing the complete compiled revision and holding the record's approval to the store rule.

Approve (`{versionId, expectedArtifactSha256, revisionSha256, deliveryId}`) loads that saved review exactly as load does, requires the recompiled revision hash to equal the one named, and publishes a child version carrying the same compiled revision plus `approval: {revisionSha256, reviewVersionId}`. Approving a version that already is an approval refuses (`DRAFT_REVIEW_ALREADY_APPROVED`, 409). A later revision is a new version with a new revision hash and `approval: null`; the earlier approval cannot be cited for it. A retained record whose approval names another revision or another parent is `DRAFT_REVIEW_INVALID` (422) on load, approve and history.

Export requires the reviewed revision hash and one selected output: `operative`, `consolidated`, `redline` (TXT) or `docx` (the review dossier rendered by the canonical Word owner). An export may cite `reviewVersionId`, the saved review it comes from; it is `approved` only when that exact version carries an approval for that exact revision, otherwise `confirmed-for-export`. The response carries the `approval` it relied on. Source access is checked at write authorization and after publication. The immutable request title contains the complete revision hash, so same-byte output from another revision cannot alias an existing delivery. An uncertain effect uses its original delivery ID; no new delivery is generated for recovery.

History (`{versionId, limit, cursor}`) pages the ordinary immutable version chain of a review artifact newest first and releases, for each version, its retained revision hash, source artifact pins and approval state under current custody; it recompiles nothing, and `federal-load` remains the path that re-establishes a revision from its source.

Refusals keep their exact reason as the error `code` (`DRAFT_SCOPE_INVALIDATED`, `DRAFT_SOURCE_FORMAT_UNSUPPORTED`, `DRAFT_WHOLE_SOURCE_REPEAL_UNSUPPORTED`, `DRAFT_XML_RESULT_MALFORMED`, …) with status 422 and `operationId` when the compiler named the refused operation; stale official source is `DRAFT_SOURCE_STALE` 409 and an absent reader `UNAVAILABLE` 503. The complete table is in [the scope record](../../../docs/legislative-workbench-20261101/FEDERAL-WORKBENCH-SCOPE.md).

The additive public receiver validates canonical shapes, source/output/revision digests, exact request correlation, version scopes/evidence, approval binding and published bytes (rendered DOCX bytes are correlated through their inspection, not recomputed). It grants no authority. Generated contract source is under `packages/contracts/federal-workbench`; `generate-federal-workbench.mjs` supports an `outDir` for isolated contract checks. Parent owns public package exports, versions, archives and frontend pins; the frontend proxy must admit the two new routes before they are reachable from the application.

This is the retained-source workbench. Publisher/URL text inside a retained envelope is a claim. Partial coverage, source limitations, unresolved numbering/cross-references/arithmetic/substantive law and absent legal currency verification must stay visible. Approving or confirming export records an exact user selection; it is not approval that text is legally correct or enacted.

Source checks use isolated SQL/object/native-identity ports, a synthetic Word renderer port and actual mounted public HTTP routes. They do not qualify native Linux, production database admission, browser-host credential confidentiality, Office fidelity or deployment. No app/image build, deployment, provider/model call, activation or independent review occurred.

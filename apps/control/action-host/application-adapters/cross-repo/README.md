# Pinned Capiro endpoint source integration

Implementation outline: a qualification-only loader reads exact Git blobs from the separately supplied Capiro repository, verifies PR2449 commit/tree and source hashes, and transpiles the actual accepted TypeScript into memory. Private implementation bodies and emitted JavaScript never enter Meri Git. Full middleware, Clerk and client-scope owners are executed; the large Meri controller/service are restricted to exact AST-selected endpoint and lookup methods, preserving their bodies and selected helper dependencies. A bounded in-process Fetch shim executes middleware provenance and RolesGuard before the actual controller method, then the canonical Meri authority HTTP client/context/session adapter receives the serialized response.

External Clerk verification/session reads and Prisma are explicitly synthetic, with tenant predicates evaluated against records (including foreign-tenant wall grants). Decorator metadata is captured by a fixture adapter; no Nest bootstrap, live HTTP server, RLS database, current Clerk qualification, deployment, or native worker observation is claimed. Missing/changed source, import, compiler or method fails closed. Existing Meri production owners remain unchanged. Planned controls cover principal/revision mismatches, missing/foreign/revoked wall grants, native session revocation, membership/role changes, conversation/client mismatch, original expiry and currentRun substitution.

Modules: source.mjs owns pinned source admission and AST compilation; endpoint.mjs composes exact owners/metadata and the fixed two-route Fetch shim; fixture.mjs owns synthetic external records/ports; integration.test.mjs connects them to canonical Meri receivers. Source/test imports are inert. Explicit fixture construction performs local Git reads only; no credentials, network access or database connections are allocated.

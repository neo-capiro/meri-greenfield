# Synthetic host recovery over loopback HTTP

Run `node scripts/local-followthrough/host-run.mjs --run` from this checkout. `--help` is inert; invalid arguments exit 2. A successful run exits 0, a handled failed run exits 1. No native database, provider or production credential is used. The CLI sets `MERI_REVIEW_SOURCE_ROOT` to its own checkout, refuses an incompatible existing value, and restores the previous environment afterward.

`createLocalActionHostFixture({mode:'synthetic-local'})` returns `openHost`, `approve`, `revoke`, `stats`, and `close`. `openHost` reconstructs the accepted host, durable lookup/approval-metadata/command owners over retained scripted SQL maps with the same grant/allocation/producer identity. The synthetic identity/current-policy ports supply server-owned facts. Its approval fact port returns null until explicit synthetic approval; the existing canonical guard refuses it without dispatch. This is not an approval endpoint or policy replacement.

`runLocalHostRecovery({mode,openHost,approve,revoke,stats})` owns three sequential ephemeral `127.0.0.1` HTTP listeners. The first queries and reads a recommendation, creates an editable draft and immutable pending proposal, and confirms an unapproved execution has zero effects. The second rereads the retained result and executes that same proposal after explicit fixture approval. The third replays the same proposal without another effect, then verifies fresh revocation. Existing operation lifetime bounds the complete runner, including approval/revocation callbacks, to 30 seconds; each listener is also bounded and closed in `finally`. The caller owns fixture disposal; the CLI closes it.

Success reports only fixed outcomes, counts/accounting, and listener closure. `stats.closed` is sampled before CLI teardown; top-level `fixtureClosed` reports final disposal. Failure reports fixed code `LOCAL_HOST_RECOVERY_REFUSED` and a fixed phase such as `HOST1_UNAPPROVED`, never the rejected error's message, stack, proposal, bearer token, or source body. `localHostRecoveryFailurePhase(error)` reads an internal association without inspecting caller data; the runner preserves the original rejection for direct callers.

These are real Fetch/Node HTTP and canonical owner calls over synthetic source and SQL ports in one process. Reconstructing objects over retained maps does not prove PostgreSQL persistence, process restart, native authentication, provider behavior or production activation. Source connectivity remains disabled. The task proposal does not cryptographically bind its supporting recommendation snapshot as approval provenance.

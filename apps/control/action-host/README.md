# Trusted host application binding

`createActionHostApplication` from `./index.mjs` returns the unchanged Fetch application `{handle(Request)}`. Construction is inert and borrows every service. No fixture, native authentication implementation, pool opening, migration, source activation, approval decision or ID cache is imported into this production graph.

Pass exactly `{services,authenticateSession,readCurrentState,reserveLookup,issueLookupCredential,issueExecution,now,limits}`. `services` is the durable composition's `{lookup,commandOptions,commandExecutor}`; only its lookup and commandOptions execute path are used by requests. commandExecutor remains the caller's explicit durable grant/invocation admission surface. The same `now` function must be supplied to commandOptions. limits are the accepted app's `{maxRequestMs,maxRequestBytes,maxResponseBytes}`. The original command producer binding comes from commandOptions.commandContext; current executor binding comes from the host current-state receipt. Their tenant/actor/conversation/run must match, while explicit execution can use a fresh current attempt/fence.

All ports receive an AbortSignal and the same shrink-only absolute deadline; receipt timestamps must be finite safe integers. checkedAtMs must be within that particular port call's start and return time, and expiresAtMs must be later than return time. New expiry can only shorten the original request cutoff. Every result is inert closed own-data, admitted by existing canonical snapshots; accessors/Proxies are refused.

- `authenticateSession({credential,signal,deadlineMs})` returns `{principal:{sessionId,tenantId,actorId,conversationId,runId},sessionRevision,checkedAtMs,expiresAtMs}`. All principal/revision fields are nonempty strings. credential is the opaque application session, not a tool capability. The native authentication owner must authenticate its actual identity and current revocation; a returned string is not self-attestation.
- `readCurrentState({authentication,signal,deadlineMs})` returns `{authenticationSha256,binding,scopes,selectedClientId,checkedAtMs,expiresAtMs}`. authenticationSha256 is canonicalSha256 of the exact fresh full authentication receipt. binding is the current full public RunBinding; scopes are current public Scope values in the same tenant and include the selected lowercase client UUID. That UUID must equal the prebound command context's resolved client. This structural correlation does not create current rights; the external current-state owner supplies them, and canonical lookup/gateway/command owners still authorize execution/release.
- `reserveLookup({authentication,current,signal,deadlineMs})` returns `{authenticationSha256,binding,lookupId,resultReference,requestId,deliveryJson,slots,checkedAtMs,expiresAtMs}`. The host allocator must supply fresh globally reserved UUIDs and run event slots, with the existing canonical delivery JSON and full current binding. The existing lookup context validator checks their shape/correlation. It is called for every resolved intent because the unchanged application receives a complete lookupContext; unused event reservations are allocator-owned, never fabricated completion events. Allocation ACK loss does not authorize duplicate reuse. Native durable allocation remains external/unqualified.
- `issueLookupCredential({authentication,current,signal,deadlineMs})` returns `{authenticationSha256,binding,credential,checkedAtMs,expiresAtMs}`. The broker owns actual short-lived capability identity; matching the binding receipt alone does not prove token claims. Existing canonical capability/current authority checks remain mandatory.
- `issueExecution({authentication,current,proposal,signal,deadlineMs})` returns `{authenticationSha256,binding,execution,credential,checkedAtMs,expiresAtMs}`. execution is the public CommandExecutionRequest, with exact proposal ID/full command digest/idempotency key and current executor binding. The broker must issue the capability it describes; this creates no approval. Current approval remains with the unchanged executor.

The latter three receipts hash the exact authentication input and match the complete current binding. Each request rechecks stable principal/sessionRevision/binding/client/scopes before and after actual lookup, metadata and executor ports, as well as around reservation and credential acquisition. Fresh timestamps may advance; they are not new identity. A changed selection requires a new request instead of silently substituting scope mid-operation.

After acknowledged owner success, host release refusal preserves RESULT_NOT_RELEASED for retained lookup or observed command results, STORED_NOT_RELEASED for newly prepared metadata, READ_UNAVAILABLE for metadata reads, and UNKNOWN for indeterminate command results. Rejected owner calls retain their original uncertainty; no retry/refund/rollback is inferred. Cancellation is cooperative and does not prove physical external I/O stopped. Source/native session, policy, credential, allocator, persistence and provider qualification remain separate; the canonical production catalog stays unavailable.

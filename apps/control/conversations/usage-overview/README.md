# Current tenant usage overview

`POST /api/conversations/usage-overview` uses the existing native membership gate and its final membership recheck. The closed request selects no tenant, actor, client, conversation or run. A General member can read the current tenant's aggregate numbers without starting a conversation or admitting model execution. The response contains no member, client or run identities, prompts, tool arguments or transcript data. This accounting view is not a conversation inventory; per-run discovery and exact usage remain under their existing Core/currentness/retention release fences.

The existing `meri_conversations.runs` ledger supplies every number. One borrowed read-only, repeatable-read transaction reads UTC day, ISO Monday week and calendar month cohorts by canonical `createdAt`, the monthly admission basis by `sdk_usage_recorded_at`, current durable states, and the existing tenant SDK policy. No new table, writer, budget reservation, admission logic or scheduler is introduced. The public observation has an explicit timestamp; a later accounting record or policy change appears on a later read.

Each period separately counts failed, cancelled and other attempts, recorded/unavailable/not-recorded accounting, known SDK estimated charges, and completed attempts with recorded accounting. Attempts are not complete jobs. Missing/unavailable cost is not zero; provider billing and complete-job economics remain unavailable. The admission-month sum can differ from the creation-month sum when an earlier attempt records usage this month. The remaining amount is based only on known charges; concurrent admitted work can exceed the cap. Absent configured policy stays unavailable.

Queue counts describe recorded durable states. They do not observe physical work, worker health, provider quotas, available capacity or fair tenant allocation. Those remaining MO10/ST15 requirements are not closed by this source slice.

The independent `meri.usage-overview/1` receiver is generated into the existing public `conversation-usage` export. Its own schema and branded request do not widen the closed `meri.conversation-usage/1` receiver or grant execution authority. Frozen contracts0.1.24/UI0.1.11 archives remain immutable and contain no overview exports; a centrally reviewed successor package is required before frontend adoption. RuntimeVersions.contracts stays0.1.0. Local source generation is not a new package release.

Focused tests cover boundaries, membership revocation/change, ordinary receiver parity, unavailable/unknown read failures and actual runtime mounting. Opt-in `test/postgres.test.mjs` requires the marked disposable local M7 container configuration, refuses an inherited DATABASE_URL, creates a uniquely marked database, applies exact existing DDL, runs the production store's SELECT queries under a SELECT role, and drops only that database. Its role/transaction evidence is local qualification, not a claim about deployed grants or acceptance.

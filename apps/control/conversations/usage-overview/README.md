# Current tenant usage overview

`POST /api/conversations/usage-overview` uses the existing native membership gate and its final membership recheck. The closed request selects no tenant, actor, client, conversation or run. A General member can read the current tenant's aggregate numbers without starting a conversation or admitting model execution. The response contains no member, client or run identities, prompts, tool arguments or transcript data. This accounting view is not a conversation inventory; per-run discovery and exact usage remain under their existing Core/currentness/retention release fences.

The existing `meri_conversations.runs` ledger supplies every number. One borrowed read-only, repeatable-read transaction reads UTC day, ISO Monday week and calendar month cohorts by canonical `createdAt`, the monthly admission basis by `sdk_usage_recorded_at`, current durable states, and the existing tenant SDK policy. No new table, writer, budget reservation, admission logic or scheduler is introduced. The public observation has an explicit timestamp; a later accounting record or policy change appears on a later read.

Each period separately counts failed, cancelled and other attempts, recorded/unavailable/not-recorded accounting, known SDK estimated charges, and completed attempts with recorded accounting. Attempts are not complete jobs. Missing/unavailable cost is not zero; provider billing remains unavailable. The admission-month sum can differ from the creation-month sum when an earlier attempt records usage this month. The remaining amount is based only on known charges; concurrent admitted work can exceed the cap. Absent configured policy stays unavailable.

The same transaction now serves the successor source version `meri.usage-overview/2` on this same route: the store's single `read` is the production reader and the HTTP owner returns its value. Each period reports attempts (run rows), conversation threads (distinct `conversation_id`, a separate period-level row set that is not additive with attempt cohorts), recorded/unavailable/not-recorded coverage, root/fork/resume lineage derived from `sdk_usage.parentRunId` plus the run binding `writerFence`, partial/failed/cancelled attempts kept separate, every recorded attempt as an explicit liability view, measured counter sums, and a per-category basis map in which the charge is an SDK list-price estimate. A completed run is not a complete job, and no job is inferred from one: `wholeJobs` reports the canonical ROOT Work/Delegate objectives — the runs whose stored request carries `request.work`, joined to the runs their persisted continuation custody continues — separated into successful, partial, failed, cancelled and unclosed. The closure decision is the existing completion producer's own rule over that lineage: a completed revision is settled only by its PUBLISHED `native-session` completion capture whose identity pins that revision, a failed/cancelled revision is settled by its own fenced terminal state, and a capture that began and never published leaves the objective unclosed. An unresolved continuation control or an unsettled child receipt keeps the objective unclosed, never successful; `jobIdentity` publishes that rule, the goal-revision basis and the exact statement the reader consumes. A category with no counter stays `unresolved`; a configured activity ceiling is not reported as measured capacity. Only the run `delta` is summed, never `cumulative`, so resumed/forked and subagent/compaction spend is not double counted. The writerFence guard is bounded to nine digits before any integer cast, so huge malformed numeric text stays `unknown-lineage` instead of aborting the read.

Queue counts describe recorded durable states. They do not observe physical work, worker health, provider quotas, available capacity or fair tenant allocation. Those remaining MO10/ST15 requirements are not closed by this source slice.

The closed overview family is extended explicitly rather than mutated: the `/1`-named document is the EXACT document physically published by the immutable `0.1.25`/`0.1.26` packages (two defs, `sha256 4598cc03…1e52e`), and the successor shapes live only in the separately resolvable `usage-overview-v2.schema.json` under its own advertised `urn:meri:usage-overview:2.0.0` `$id`, so a published file's digest is never silently changed. `meri.usage-overview/2` adds `UsageOverviewRequest2`/`UsageOverviewResponse2` with their own validators, semantics and branded request set. A request admitted for one wire version can never be settled by the other, so the frozen `0.1.25` physical receiver keeps ordinary `/1` parity and refuses the `/2` body, while `/2` refuses `/1`. Both versions remain the same public `conversation-usage` export, so no frontend import bypasses the package. Frozen `0.1.24`/`0.1.25`/UI `0.1.11` archives remain immutable and unchanged; producing the generated `/2` browser union stays with the owning package release. `RuntimeVersions.contracts` stays `0.1.0`. Local source generation is not a new package release.

Focused tests cover boundaries, membership revocation/change, ordinary receiver parity plus new-version refusal, unavailable/unknown read failures, the real production transaction (five statements for `/1`, six for `/2` including the bounded whole-job objective statement) and its stored counter shape, strict `/2` receiving of the real HTTP response, the completion producer's closure rule (successful/partial/failed/cancelled/unclosed, unresolved successor, unsettled child receipt, an outside-window root excluded and counted, and refusal of a continuation cycle, a duplicated revision or a malformed closure), and (when its dependency graph resolves) the runtime mount. Opt-in `test/postgres.test.mjs` requires the marked disposable local M7 container configuration, refuses an inherited DATABASE_URL, creates a uniquely marked database, applies exact existing DDL, runs the production store's SELECT queries under a SELECT role, and drops only that database. Its role/transaction evidence is local qualification, not a claim about deployed grants or acceptance.

# Native correction feedback

The existing authenticated conversation application accepts `POST /api/conversations/feedback` and reads a run's receipts with `POST /api/conversations/feedback-read`. The public shapes and receiver belong to the existing `@capiro/meri-contracts/conversation-application` subpath. Integration/Release regenerate and qualify its physical distribution; this source change does not modify manifests, lockfiles or generated artifacts.

The request selects a terminal run's exact last event sequence and either a message or a published artifact/version. The server derives the message revision from its ordered persisted deltas, or pins the artifact publication event. An optional source event selector binds the exact retained source revision by its immutable event hash. Missing targets, stale sequences, foreign sources and changed scope are refused. Task revision is explicitly inapplicable because these native targets do not publish a typed task revision. The receipt never invents a document, task or artifact ID.

The existing SDK accounting projection supplies the actual model names with positive counters in this run's delta and its persisted session reference. This is run-level evidence including subagents; it does not claim a particular model authored an individual sentence. Missing result or unavailable delta stays unavailable. The selected model in the request/preferences is never substituted.

Preference, factual correction and recommendation are separate closed signal shapes. An immutable receipt reports `recorded / not_reviewed / none`. Existing approval-request and checkpoint events are linked by ID and hash only. Recording feedback cannot approve an action, apply a correction, mark a task complete or promote memory/training. No event pipeline or generic ledger is introduced.

Receipts live in bounded `runs.feedback` JSON (50 per run), serialized by the existing conversation transaction and protected by the matching digest and append-only database guard. Same request ID and identical payload replay the receipt; a conflicting payload is refused. A lost commit/release acknowledgement is `FEEDBACK_WRITE_UNKNOWN`; authenticated readback and exact replay recover the immutable request. Current session and retention checks apply to writes and reads, including historical turns in the same conversation.

`feedback-migration.sql` is forward migration source awaiting a numeric slot from the orchestrator. It adds only run-owned columns/grants/guards and extends the existing terminal retention tombstone guard. The existing erasure route clears both feedback columns with the other conversation bodies, preserving accounting and consumed request identity. Release must qualify the real migration, runtime grants, append-only/conflict behavior and authenticated terminal erasure on isolated PostgreSQL before integration acceptance.

Focused source checks: `node --test --test-concurrency=1 apps/control/conversations/test/feedback.test.mjs packages/contracts/test/conversation-feedback.test.mjs`; affected erasure check: `node --test --test-name-pattern='^run erasure' apps/control/retention/test/conversation-purge-rows.test.mjs`. Scripted SQL is not native database proof.

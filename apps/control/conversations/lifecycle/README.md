# Opt-in durable conversation controls

Compose `createConversationLifecycleService({service,store,dispatcher,checkpoints,nativeAdmission,approvals,sessions})` around the existing conversation service and product PostgreSQL store. Mount with `createConversationLifecycleApplication({service})`; legacy submit/history/events/cancel delegate to the frozen HTTP owner. Configure `createTemporalConversationDispatcher({client,taskQueue,lifecycle:true})` only with the lifecycle activity owner. Default dispatcher starts the original workflow and has no lifecycle signal methods. Register the additive `meriConversationLifecycleWorkflow` exported from the existing workflow bundle; original workflow function/imports remain unchanged.

Private authenticated `POST /api/conversations/control` accepts exactly the root-owned `assertLifecycleCommand` variants. No selectors establish authority. Supply the SAME existing opaque session owner through required sessions.authenticateSession/readCurrentState; the facade validates their correlated current receipts against service history and pins actual selectedClientId. Native target subject must exactly equal that selected subject, including when scopes contain multiple clients. Target execution load also checks its fresh session subject against the persisted source/admission subject. Every operation obtains current full binding/scopes/request/pins through the existing authenticated session service before and after trusted effects and release. Public contracts/package0.1.3 and its generated bytes remain unchanged; a public lifecycle client/export is a separate coordination gate.

The transaction journal stores immutable controlId/input/source request/context/runtime/command hashes before effects. A PENDING worker command can be durably claimed once into DISPATCHING. `nextControls` omits DISPATCHING and UNKNOWN; retries/restarts cannot send those commands to the SDK again. APPLIED steer requires an observed SDK user-message UUID equal to controlId. Ambiguous delivery remains UNKNOWN until an explicit trusted confirmation; no timeout lease or process-local deduplication grants replay.

Credential-bound worker ports are `nextControls({binding,after,signal})`, `claimControl({binding,input:{controlId,commandSha256},signal})`, `ackControl({binding,input:{controlId,commandSha256,outcome,sdkUserMessageId?},signal})`, and `recordCheckpoint({binding,input:{controlId,checkpointId,checkpointSha256},signal})`. The trusted task/session owner supplies the credential outside the DTO. Only `claimControl(...).claimed===true` releases a command. Pause/approval.wait immediately hold worker publication; exact trusted checkpoint readback publishes paused or waiting-for-approval from the immutable intent. Authenticated legacy cancellation uses a private store capability; ordinary worker append cannot forge USER_CANCELLED to cross the hold.

`checkpoints.read` returns exactly `{checkpoint,checkpointSha256,sourceRequestSha256,contextSha256,resumeSessionAt,readReceiptId}`. This trusted native-owner port must read/hash the immutable opaque session/workspace; structural validation alone is not native proof. Persisted rows bind redundant tenant/conversation/run/checkpoint/control selectors, original pins and APPLIED originating controls. Fork may use a separately trusted immutable checkpoint while the original continues running; it does not retire or hold that source.

Resume requires paused/approval-wait source plus exact native retirement and a new admitted run/attempt/worker/higher fence in the same conversation. Fork needs a new conversation/run/attempt/worker and a distinct native SDK session with an independent positive fence. Native ports are idempotent by controlId: `retire` returns `{binding,retirementReceiptId,expiresAtMs}` and `admit` returns `{binding,scopes,selectedClientId,admissionReceiptId,targetSessionId,expiresAtMs}`. These remain unqualified live gates, not local physical-stop proof. No target credential is minted or returned; acquire a fresh session through the existing trusted session owner.

Target execution load exposes root-validated `continuation` plus the exact `sourceRequest`; current target request only changes requestId. Default skill/window/windowRequest/scope/runtime/checkpoint content is preserved; explicit skill migration is unsupported and closed commands reject it. New source workflow durably waits with upstream Temporal `condition` after the activity returns paused/waiting. Resume signals `meriLifecycleContinued` only after exact retirement and target persistence/start; fork never signals/stops the origin. Cancellation uses upstream workflow cancellation. There is no second activity/model loop in the workflow.

Approval wait binds an original immutable ApprovalProposal and the existing current ApprovalDecision owner. Approved resume preserves read-only context. It does not execute an inherited proposal or alias a grant to a new run: target mutation requires a fresh immutable proposal/current approval through the existing owner. Cross-run approval execution is a remaining source protocol capability gap, not a live qualification claim.

Synthetic SQL protocol, actual Fetch and installed Temporal1.24.0 Activator checks are retained under `test/lifecycle-evidence`. Initial failures and rerun reasons remain visible. No PostgreSQL server, Temporal server, native task/provider/cloud/credential/private data calls were made. Live transaction durability, native capture/retirement/admission/restore, task-bound refresh, deployment and public lifecycle export are unqualified. Root performs independent integrated review.

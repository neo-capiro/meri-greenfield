# Existing HTTPS staging probes with separate data ownership

`createStagingE2EClient` composes the frozen public0.1.3 receiving contracts and the existing conversation/document HTTP applications. It supplies bounded authenticated requests for submit/history/cancel and create/revise/inspect/download. Canonical download receiving verifies actual bytes, immutable version hash and response headers. Imports and construction allocate no network connection or resources.

Shipping must supply the actual existing DNS-enabled HTTPS staging origin and exact deployed source/image verification port. A syntactically valid hostname is not a DNS/TLS or deployment qualification. No hostname was guessed, created, enabled or contacted in this batch. `verifyCandidate` must use the existing shipping owner to read the actual immutable candidate; a caller-supplied synthetic proof is only a local fixture. The expected source commit must be the approved deployed candidate.

Before using this factory, the existing authorized data/session owners must supply two separate clients and disjoint conversation IDs: automation-owned synthetic data and Neo's manual data. `target.automation` includes the exact tenant, actor, client and preallocated conversation IDs. `target.manual` supplies the excluded manual client and conversation IDs. The current session port authenticates through the existing opaque session owner, reads current binding/scopes/selectedClientId and returns fresh checkedAtMs/expiresAtMs. These configuration IDs select allowed test data; they never grant access. The actual application rechecks the same existing session. Any other client scope, manual conversation, changed authority or expired/revoked context refuses before effect or response release.

`authenticatedFetch` is borrowed from the already authorized staging session. This module stores no credential, issues no token, activates no connector and changes no auth/network settings. No cleanup or arbitrary source mutation routes exist. Inspect/revise/download only select immutable versions admitted earlier by this client; unknown/manual versions refuse. Version tracking is capped at64 and requests at30seconds. `close()` cancels owned request lifetimes and clears local version tracking; it never disposes borrowed ports or deletes persistent data. Transport cancellation is dispatched without awaiting an unbounded external promise; this is not evidence of physical remote stop.

Local tests invoke the actual Fetch conversation application and opaque session, and the actual document/artifact/storage owners with scripted accounting and real TXT generation. They verify both immutable versions, inspect/download/hash checks, post-revocation refusal, unowned-version exclusion, bounded response cleanup and parked-request cancellation. Those passes do not establish live DNS/TLS, deployed model/Temporal/native execution, frontend/browser behavior or manual acceptance.

The new conversation lifecycle route remains private and unexported. Public0.1.3 clients continue the existing routes. Frontend lifecycle controls require separately coordinated public export/UI work before live manual testing. Existing staging hostnames/candidate proof and authorized automation/manual fixtures remain external shipping dependencies; this factory creates none.

# Claude Agent SDK conversation activity

`createConversationActivity({runOwner,prepareRuntime,query?,heartbeat?})` returns `executeConversation`. Production defaults to Claude Agent SDK0.3.295 `query`; tests supply scripted SDK messages without a model call. The runtime owner supplies exact RunBinding/RuntimeVersions, isolated conversation workspace, trusted proxy task capability, bounded turns/cost/output/deadline, and a durable SDK SessionStore. Upstream options are checked against the installed SDK declarations. SDK SessionStore mirror errors, missing/duplicate/error results, output limits, revocation and deadlines prevent completion. SDK Query is closed and the heartbeat/deadline resources are cleaned up.

The activity claims starting/running before calling query once. Durable starting admission serializes competing deliveries; a second activity sees a non-queued run and cannot query again. Temporal retries are disabled. Recovery after a lost worker/ambiguous result needs the existing verified checkpoint/attempt owner and later resume integration; no automatic paid retry is invented.

Only supported top-level public text is projected. Streamed blocks are not repeated when final assistant frames arrive. Thinking, subagent content, raw tool arguments, provider diagnostics and session-store errors are withheld. No institutional tools are activated in this slice; the default instructions disclose unavailable evidence. Selected original prose is injected only after exact pins and canonical manifest availability succeed. Gateway/tool/artifact owners remain responsible for authorized effects and receipts.

No worker is started and no account/provider credential is loaded on import. Worker registration, Temporal heartbeat/cancellation binding, isolated launch, durable SessionStore/workspace owner, native model-proxy admission and allowed gateway tool wiring require the live owner. This source adapter does not establish those runtime gates. The SDK0.3.295/CLI2.1.295 pins remain consistent with the existing native qualification owner; no native fixture source/configuration was edited.

Only an acknowledged starting claimant may observe a terminal failure. A competing or unknown-ack activity leaves the winner/original admission intact. On failure, Query is closed before a separate bounded30ms status-observation wait; that observation reuses current control authority and may fail, leaving persisted state for explicit reconciliation. It does not grant another model attempt or result release.

The saved normalized window/scopes/selected pin reach the SDK as explicitly labelled request data. Query cleanup errors are translated to `SDK_CLEANUP_UNKNOWN`; they retain completed provenance and never disclose raw provider diagnostics or invent rollback/retry.

## Optional SDK capabilities (default off)

`capabilities/` turns supported Claude Agent SDK features on per run, only when the execution record loaded by the run owner carries a sibling `capabilities` policy beside the closed `Run` contract. Without it `buildConversationOptions` returns exactly the previous options and the activity behaves as before. `policy.mjs` validates the policy (every flag false by default, bounded allowlists, idempotent); `index.mjs` `createSdkCapabilities(policy, {runOwner, binding, cwd, skillPluginDirectory?, now, newId})` composes an additive Options fragment from `workspace-tools.mjs` (built-in Read/Write/Edit/Glob/Grep/Bash confined to the conversation cwd by a PreToolUse gate and `canUseTool`; every other built-in is in `disallowedTools`), `subagents.mjs` (SDK `agents` for research, analysis, artifact_production and verification, plus an Agent admission gate for declared type, inherited model, foreground execution and bounded parallelism), `skill-plugin.mjs` (SDK `plugins`/`skills` bound to the immutable image directory produced by `packages/skills/plugin.mjs`, never cwd; `settingSources` stays `[]`) and `hooks.mjs` (`tool.audit`, `compaction.boundary`, `subagent.lifecycle` events carrying names, SHA-256 digests, sizes and timings only). `fragment.mjs` owns the fragment shape and merges it into the options with own-key validation, `allowedTools` union, hooks by event name and chained permission callbacks. `progress.mjs` displays only SDK `task_progress` one-line summaries when the policy admits them; subagent content keeps `parent_tool_use_id` filtering.

A refused capability event denies the tool or stops the SDK loop and fails the run at the result frame. The control service currently admits only `run.status` and `message.delta`, so audit, compaction and subagent lifecycle hooks fail closed until the contract and control owners admit those event types. The workspace gate is a textual path rule, not a sandbox; the SDK sandbox, network-confined Bash and credential-free tool environment remain unqualified separate gates.

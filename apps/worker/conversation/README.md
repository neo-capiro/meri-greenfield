# Claude Agent SDK conversation activity

`createConversationActivity({runOwner,prepareRuntime,query?,heartbeat?})` returns `executeConversation`. Production defaults to Claude Agent SDK0.3.295 `query`; tests supply scripted SDK messages without a model call. The runtime owner supplies exact RunBinding/RuntimeVersions, isolated conversation workspace, trusted proxy task capability, bounded turns/cost/output/deadline, and a durable SDK SessionStore. Upstream options are checked against the installed SDK declarations. SDK SessionStore mirror errors, missing/duplicate/error results, output limits, revocation and deadlines prevent completion. SDK Query is closed and the heartbeat/deadline resources are cleaned up.

The activity claims starting/running before calling query once. Durable starting admission serializes competing deliveries; a second activity sees a non-queued run and cannot query again. Temporal retries are disabled. Recovery after a lost worker/ambiguous result needs the existing verified checkpoint/attempt owner and later resume integration; no automatic paid retry is invented.

Only supported top-level public text is projected. Streamed blocks are not repeated when final assistant frames arrive. Consecutive text deltas of one content block fold into one `message.delta` publication: the deltas the SDK produced while the previous publication was in flight, plus those it produces within the fold window (`DELTA_FOLD_WINDOW_MS`, 200 ms on the injected clock, `deltaFoldWindowMs` 0-1000), up to `DELTA_FOLD_MAX_BYTES`; a block boundary, a non-text frame, a hold or the result ends a fold at once, and every delta is durable before the result is handled. Thinking, subagent content, raw tool arguments, provider diagnostics and session-store errors are withheld. No institutional tools are activated in this slice; the default instructions disclose unavailable evidence. Selected original prose is injected only after exact pins and canonical manifest availability succeed. Gateway/tool/artifact owners remain responsible for authorized effects and receipts.

No worker is started and no account/provider credential is loaded on import. Worker registration, Temporal heartbeat/cancellation binding, isolated launch, durable SessionStore/workspace owner, native model-proxy admission and allowed gateway tool wiring require the live owner. This source adapter does not establish those runtime gates. The SDK0.3.295/CLI2.1.295 pins remain consistent with the existing native qualification owner; no native fixture source/configuration was edited.

Only an acknowledged starting claimant may observe a terminal failure. A competing or unknown-ack activity leaves the winner/original admission intact. On failure, Query is closed before a separate bounded30ms status-observation wait; that observation reuses current control authority and may fail, leaving persisted state for explicit reconciliation. It does not grant another model attempt or result release.

The saved normalized window/scopes/selected pin reach the SDK as explicitly labelled request data. Query cleanup errors are translated to `SDK_CLEANUP_UNKNOWN`; they retain completed provenance and never disclose raw provider diagnostics or invent rollback/retry.

## Optional SDK capabilities (default off)

`capabilities/` turns supported Claude Agent SDK features on per run, only when the execution record loaded by the run owner carries a sibling `capabilities` policy beside the closed `Run` contract. Without it `buildConversationOptions` returns exactly the previous options and the activity behaves as before. `policy-resolution.mjs` computes that effective policy for the control owner (platform maximum ∧ tenant settings ∧ role ceiling ∧ optional tenant role narrowing; widening refused with stable codes). `policy.mjs` validates it (every flag false by default, bounded allowlists, idempotent; `bash` is explicit eligibility, never implied by `workspaceTools`). `index.mjs` `createSdkCapabilities(policy, {runOwner, binding, cwd, skillPluginDirectory?, bashSandbox?, sdkConfigDirectory?, sdkSecureStorageDirectory?, now, newId})` composes an additive Options fragment from `workspace-tools.mjs` (Read/Write/Edit/Glob/Grep confined by SDK permission rules: `blockReadsOutsideWorkingDirectories` plus `Read(//cwd/**)`/`Edit(//cwd/**)` allow rules), `bash-sandbox.mjs` (Bash only with policy eligibility and the runtime-preparation attestation, inside the SDK `sandbox` with `failIfUnavailable`, no unsandboxed escape, strict network allowlist, cwd-only writes, credential env deny and `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`, mirrored as parent policy-tier locks), `subagents.mjs` (SDK `agents` for research, analysis, artifact_production and verification, never Bash, plus an Agent admission gate), `skill-plugin.mjs` (SDK `plugins`/`skills` bound to the canonical, symlink-free image directory produced by `packages/skills/plugin.mjs`, never cwd; `settingSources` stays `[]`) and `hooks.mjs` (`tool.audit`, `compaction.boundary`, `subagent.lifecycle` events carrying names, SHA-256 digests, sizes and timings only). `fragment.mjs` owns the fragment shape and merges it into the options. `progress.mjs` displays only SDK `task_progress` one-line summaries when the policy admits them.

Native clarifying questions (`userQuestions`): `capabilities/questions.mjs` gates `AskUserQuestion`, `questions/registry.mjs` is the durable pending-question owner and `questions/events.mjs` records each question as the run's own `question.pending`/`question.answered` events. One claimed `answer` control resolves the suspended call exactly once (`questions/dispatch.mjs`: the answer record is durable before the call resumes, the control is acknowledged APPLIED, and a repeated or stale answer is acknowledged UNKNOWN and never re-applied). The run's abort signal reaches the gate, so a Stop or deadline ends the wait without an answer; the activity closes the registry before its terminal event so every question still pending has a durable cancelled outcome, and the control store settles any question a user Stop left pending inside the cancellation transaction.

Any hook validation, projection or publication failure denies or stops inside the SDK and latches: the activity then refuses further output, checkpoint capture and completion. The control service currently admits only `run.status` and `message.delta`, so audit, compaction and subagent lifecycle hooks fail closed until the contract and control owners admit a telemetry receiver. `sandbox-readiness/cli.mjs` is the worker-host readiness check for SDK-sandboxed Bash (no model request); it is local readiness, not sandbox qualification.

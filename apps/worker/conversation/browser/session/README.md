# Browser session composition source

createBrowserSessionHost binds an owned browser context and Playwright MCP 0.0.83 createConnection to one session owner, then binds separate native model and user-control relay ports. The activity-facing prepareBrowserRun now refuses an open browser without this owner and checks the returned descriptor against the original native shim. Held activation never creates the session or grants egress. Teardown closes both relay channels, fences/drains, closes the context, requires actual process-absence proof, then disposes profile/HOME/output through the existing host filesystem owner.

The session owner composes the existing S1 fence, S2 filter and S3 destruction owner. It serializes page effects and snapshot release. Unknown dispatched calls close the session instead of admitting a replay. Takeover requires the canonical lifecycle hold's APPLIED receipt after drain; the hold port must recover the original command, never allocate another after a lost answer. Hand-back requires explicit resume and a new snapshot masking all observed field values. Timers destroy the session at the earlier run deadline or selected workflow TTL. There is no cross-run authenticated profile reuse.

For a configured website task, the host requires the canonical siteWorkflows.resolve port and independently binds the exact manifest version/hash through the existing prepareCurrentSiteWorkflow owner. A missing resolver or policy wider than that task refuses before context creation. Model calls, takeover, user input and hand-back resume all recheck the selected task; current-authority refusal starts destruction. Model dispatch rechecks after its preflight snapshot, and resume has the same bounded, cancellable lifetime as other session operations. This covers host-side controls as well as the worker's existing permission hook; the native resolver/relay providers still require real integration.

The model receives newly captured ARIA page snapshots and field metadata from the same owned Playwright context. Raw upstream tool prose, console text, dialogs, errors, metadata and images are discarded. Current values and field metadata are sampled before and after capture; changes refuse release. Observed credential values remain masked in reflected text after their fields disappear. Sign-in/IdP pages and valued sensitive fields withhold content. Screenshot calls are refused before dispatch; image release remains unqualified. Failure to inspect a page/frame refuses release. This is not a proof against every hostile DOM, browser extension, native widget or credential echo.

The native model stream adapter now uses the pinned MCP SDK 1.32.1 server and stdio transport. It accepts one binding from authenticated host-broker streams, forwards only calls through the existing session owner, preserves each RPC request identity for replay fencing, and releases only bounded filtered text. It exposes no takeover/user-control method. Native private errors and images are withheld. Stream loss cancels pending work and enters host destruction; a disconnect during viewer attachment closes the late relay instead of returning a closed session. The dependency is installed for production by the canonical worker package owner. This adapter does not authenticate socket peers.

Native context creation, authenticated broker stream attachment, the user viewer relay, canonical current authority/hold recovery, process observations and filesystem disposal still require host integration. This change does not install a D005 host or change the direct supervisor command. The runtime gate refuses the missing session owner; production must connect the authenticated broker to this adapter before activation. The session owner must remain outside the browser child process group so it can observe absence before issuing destruction receipts. No worker-supplied policy, lease epoch or parser result establishes native authority.

Author implementation assessment: connection owns only the pinned upstream transport; snapshot owns only page inspection/redaction; owner composes session transitions and bounded effects; host owns binding and relay teardown. No new policy, lifecycle ledger, credential vault, model loop or browser-state export is introduced. Existing browser option composition now preserves the current Claude Code preset instead of treating it as an obsolete array. This assessment is not an independent review.

Validation: scripted mounted composition checks cover request gating, exact shim descriptor, held activation, current refusal, unknown effects, teardown failure, hold/lease behavior and credential canaries. Actual MCP client/stdio checks additionally cover transport framing, request replay, private error/image refusal, stream cancellation and late viewer attachment. The exact downloaded 0.0.83 API was also initialized/listed/closed with a synthetic context and without launching a browser. Native sandbox/egress, actual relay isolation, real IdP canaries, hostile DOM coverage, revocation propagation and destruction qualification remain open. No app/image build, deploy, browser activation, provider/model call or independent review occurred.

Network submission gate (2 November 2026): `submission-gate.mjs` routes the session's browser context so that, during an agent action, every request the page sends with POST, PUT, PATCH or DELETE is held until the run's canonical approval owner answers (`permissions.mjs` `submissions`), at most three distinct questions (method and destination host) per action; refused, expired or withdrawn (takeover, session end) requests are aborted, requests outside an action are aborted, the user's own takeover traffic continues. Any other method, a denied or private destination, a request without a public page to ask about, and questions past the limit are refused by policy without asking, and the model is told so (not that the user declined). A browser-level DevTools session watches responses: a 307/308 redirect of a sending request to another host (which would re-send the body) fails before the browser follows it, for fetch, form navigation, workers, iframes and popups; a same-host redirect stays inside the approval. The structural classifier stays the first, cheaper layer: it asks before any click on a submit control whatever the form's method, and its approval covers the page's own host for that SDK tool use only (`toolUseId`), until that approval expires. Not held: GET, HEAD and OPTIONS requests, including a GET form submitted by script (`requestSubmit()` on `method=get`) or a script navigation with a query string, since a site that changes state on GET is indistinguishable from reading; WebSocket messages after the handshake. The egress policy still bounds their destinations.

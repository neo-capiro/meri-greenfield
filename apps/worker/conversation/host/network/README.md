# D005 network confinement source outline

- `plan.mjs` owns exact run-derived namespace/interface names and route validation. Browser routes terminate at their own host-loopback egress proxy. SDK routes terminate at named, pinned private model/control endpoints and, only when networked Bash is admitted, at the two exact host-loopback Bash proxy ports. This module grants no authority.
- `firewall.mjs` builds transactional nftables JSON and verifies the exact installed table, chains and ordered rules. The tool namespace has default-drop input/output/forward chains. The host drops every packet arriving on that run's veth except TCP from the tool peer to the pinned relay ports, and drops forwarding from that veth.
- `relay.mjs` owns bounded TCP byte relays with fixed listener and target addresses and immediate socket destruction on close. A local relay must be started by the native launcher **inside** the namespace under an unprivileged identity. Its only reachable host destination is the matching host veth relay; the host relay is bound to the veth peer and forwards only to a run-bound loopback proxy or a pinned private endpoint.
- `confinement.mjs` is the trusted privileged setup/readback adapter. It creates the namespace and veth before untrusted exec, installs the nft rules before starting any tool process, verifies namespace NSFS identity, interfaces, addresses, global host subnet uniqueness, routes and rules, and returns a pinned namespace dev/inode for the native pre-exec helper. Every failure attempts teardown; an uncertain cleanup is explicitly unknown.
- `launcher-adapter.mjs` binds the fixed `local-relay-entry.mjs` to the native launcher's credential-free, pinned-namespace relay process. `confinement.mjs` reads the actual `127.0.0.1` listeners with `ss` and requires their PID to match that helper before returning readiness. It revokes host relays synchronously before bounded child cleanup.
- For networked Bash, create the SDK namespace with model/control routes, run the canonical no-model readiness probe **inside that exact confined SDK context**, and observe its SDK child cgroup empty under a held launch lock. After the Bash proxy is prepared, `extendBashRoutes` closes the old local relay, adds only the paired Bash HTTP/SOCKS routes in atomic nft rule batches, restarts the local relay with four exact listeners in the **same namespace**, and rechecks all kernel readbacks before conversation GO. The real Bash command remains in the SDK's nested bubblewrap sandbox.

The SDK parent has a separate compartment with only its exact model/control routes and optional Bash proxy bridge ports. The actual Bash command is in the SDK's own nested bubblewrap sandbox; the source's separate `bash` plan is not an active enforcement claim until the pinned CLI bridge placement is verified. The browser namespace has no default route, DNS route, UDP path, metadata path or trusted-control path. The launcher must move the child into the verified namespace before exec, drop UID/GID and all capabilities, set no-new-privileges, hide cgroupfs and credentials, and reverify immediately before exec. These source checks are not a real-host qualification; the image must supply pinned `ip`/`nft` binaries and the D005 host must prove native direct-bypass denial.

`public-egress.mjs` is a source contract for a future public proxy mode, not an activation path. It requires a separately confined proxy UID/cgroup/PID, a distinct host-relay UID/cgroup/PID, exact host OUTPUT nft readback, one IPv4 default route over the pinned ENI and no IPv6 default. The proxy UID has only exact resolver/metadata/private-service exceptions and IPv4 TCP 80/443 on the pinned ENI; its other output drops on every interface, including an alternate specific route. Only established loopback replies are allowed. The current host-veth relay runs in the privileged setup process, so this guard cannot match the current stack. A future `relay-host` native path must pin the host namespace, dedicated unprivileged UID/cgroup, target authorization, listener PID, teardown and live readback; public SG/NAT/routes and a production qualification run must be reviewed separately. Until then the enabled stack remains closed-network.

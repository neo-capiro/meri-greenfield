# D005 network confinement source outline

- `plan.mjs` owns exact run-derived namespace/interface names and route validation. Browser routes terminate at their own host-loopback egress proxy. SDK routes terminate at named, pinned private model/control endpoints and, only when networked Bash is admitted, at the two exact host-loopback Bash proxy ports. This module grants no authority.
- `firewall.mjs` builds transactional nftables JSON and verifies the exact installed table, chains and ordered rules. The tool namespace has default-drop input/output/forward chains. The host accepts only TCP from the tool peer on the run's veth to the pinned relay ports, drops other ingress to the host-veth address even if it arrives on another interface, and drops forwarding from the veth. Its UID-wide host OUTPUT deny is installed and read back **before** the host relay starts; exact target dials and established veth replies become available only after listener and process proof.
- `relay.mjs` owns bounded TCP byte relays with fixed listener and target addresses and immediate socket destruction on close. A local relay must be started by the native launcher **inside** the namespace under an unprivileged identity. Its only reachable host destination is the matching host veth relay; the host relay is bound to the veth peer and forwards only to a run-bound loopback proxy or a pinned private endpoint.
- `host-launcher-adapter.mjs`, `host-relay-entry.mjs`, and `native/meri-host-relay-launcher.c` run the host-veth relay as a separate unprivileged process. The root-only helper pins the original host network namespace before dropping privileges; afterward it compares a fresh self-namespace handle with that pin and closes the pin before READY, without reopening PID 1's protected proc link. It also pins root-owned Node/script paths, the exact run cgroup and a distinct UID/GID, then drops capabilities, hides cgroupfs, clears its environment, and execs from `/`. The adapter pins the relay's PID, UID/GID, cgroup, namespace and listener ports; `cgroup.kill` revokes the entire process tree. SDK and browser host relays require separate identities because each run-owned nft table ends with a UID-wide drop.
- `confinement.mjs` is the trusted privileged setup/readback adapter. It creates the namespace and veth before untrusted exec, installs and verifies the host deny before starting the unprivileged relay, then verifies namespace NSFS identity, interfaces, addresses, global host subnet uniqueness, routes, exact host-relay process and listener ownership, and rules. It returns a pinned namespace dev/inode for the native pre-exec helper. Teardown keeps the UID-wide deny installed unless relay cgroup exit, veth removal and namespace removal are positively observed. A rejected initial or Bash replacement relay launch has no returned handle and therefore retains the deny as UNKNOWN.
- `launcher-adapter.mjs` binds the fixed `local-relay-entry.mjs` to the native launcher's credential-free, pinned-namespace relay process. `confinement.mjs` reads the actual `127.0.0.1` listeners with `ss` and requires their PID to match that helper before returning readiness. It revokes host relays synchronously before bounded child cleanup.
- For networked Bash, create the SDK namespace with model/control routes, run the canonical no-model readiness probe **inside that exact confined SDK context**, and observe its SDK child cgroup empty under a held launch lock. After the Bash proxy is prepared, `extendBashRoutes` closes the old local relay, adds only the paired Bash HTTP/SOCKS routes in atomic nft rule batches, restarts the local relay with four exact listeners in the **same namespace**, and rechecks all kernel readbacks before conversation GO. The real Bash command remains in the SDK's nested bubblewrap sandbox.

The SDK parent has a separate compartment with only its exact model/control routes and optional Bash proxy bridge ports. The actual Bash command is in the SDK's own nested bubblewrap sandbox; the source's separate `bash` plan is not an active enforcement claim until the pinned CLI bridge placement is verified. The browser namespace has no default route, DNS route, UDP path, metadata path or trusted-control path. The launcher must move the child into the verified namespace before exec, drop UID/GID and all capabilities, set no-new-privileges, hide cgroupfs and credentials, and reverify immediately before exec. These source checks are not a real-host qualification; the image must supply pinned `ip`/`nft` binaries and the D005 host must prove native direct-bypass denial.

`public-egress.mjs` is a source contract for a future public proxy mode, not an activation path. It requires a separately confined proxy UID/cgroup/PID, a distinct host-relay UID/cgroup/PID, exact host OUTPUT nft readback, one IPv4 default route over the pinned ENI and no IPv6 default. The proxy UID has only exact resolver/metadata/private-service exceptions and IPv4 TCP 80/443 on the pinned ENI; its other output drops on every interface, including an alternate specific route. Only established loopback replies are allowed. The host-veth relay now has a separate native process and UID/cgroup proof, but the browser egress proxy still runs in the trusted supervisor process. The public guard's ENI-wide drop also needs reviewed exact SDK relay private-service exceptions in the combined host rules. Public SG/NAT/routes, a separate proxy process, live kernel/network readback, and production qualification remain activation requirements. Until then the enabled stack remains closed-network.

`native/meri-host-relay-namespace-test.c` is a focused nonroot permission regression. Compile it locally with `cc -std=c11 -Wall -Wextra -Werror -O2` and run it as a nonroot user. It forks a process that becomes non-dumpable, proves that a fresh open of its proc namespace is denied, then calls the launcher's actual post-drop check with a previously pinned nsfs FD; a wrong inode must exit 111. This does not execute the root/cgroup launcher or qualify the host image.

# D005 guest run composition

## Source outline

This folder owns the trusted guest bootstrap for one control-owned host allocation and full RunBinding. It composes existing policy, egress, currentness, network, native launch and process-observation modules; it does not create an SDK query or change the shared runtime composer. The shared integration owner must pass its one-use `processClientFactory` into `createPreparedRunnerQuery`, which captures the SDK's actual launch descriptor. A separate conversation SDK process is forbidden.

The entry point requires an authenticated, durable host currentness client pinned to the exact host identity. It starts an SDK run monitor for every run, including browser-only and offline Bash. The model and control routes must match trusted private endpoints exactly; the conversation SDK descriptor must use the model relay's HTTPS loopback port and pinned CA path. The SDK and browser host-veth relays each require a separate native helper, UID/GID and cgroup; all six SDK, browser and relay identities must be distinct. The reviewed private interface is an exact input, and the SDK relay is authorized against currentness before launch. Bash facts require a trusted outer-isolation verifier and a no-model readiness probe executed through a separate native readiness launcher in the same SDK pre-exec path, namespace and launch gate as the eventual conversation process. A reviewed image manifest must supply the actual SDK CLI descriptor validator. The SDK network compartment starts with only the pinned model/control relays and, for networked Bash, extends to the exact Bash proxy relays after the readiness SDK child is positively absent under a frozen launch gate. No unconfined probe attests Bash.

The shipped browser activation record is hard-held. While held, or when the effective tenant browser policy is disabled, bootstrap starts no browser currentness client, egress proxy, namespace, broker or process observer and returns no browser runtime port. This keeps an ordinary SDK run available; no `components` or runtime parameter opens the browser gate. When a reviewed source change opens the record, browser launch still requires the host/browser-workspace readback on the paused browser child before GO, a run-bound proxy route, exact network proof and the existing browser approval controls.

The launcher receives the one-use SDK process descriptor and a one-shot, prebound Playwright broker descriptor. Its pre-GO callbacks reverify network and currentness and arm the host-wide SDK observer and browser observer while the corresponding leader is live in its exact cgroup. No callback acknowledgement means no GO. The browser command comes from `playwrightHostCommand` and the SDK-facing MCP config contains only the per-run shim path, socket path and nonce.

The returned host service owns every client, monitor, proxy, network compartment, broker, launcher and observer it creates. A currentness loss immediately cuts local relays and proxy tunnels, then schedules host teardown. On any failure it closes launchers, revokes proxies, closes network compartments and requests host teardown with exact process and cloud absence readback. An uncertain operation reports `HOST_BOOTSTRAP_UNKNOWN` or `HOST_TEARDOWN_UNKNOWN` and leaves the allocation quarantined. A resource cleanup error cannot be hidden behind the startup error. Borrowed policy, approval, artifact, receipt, cloud and native verifier ports are not closed here.

`native-verifier.mjs` provides read-only procfs and namespace facts for one SDK PID. It intentionally refuses a host-wide confinement receipt: one snapshot cannot prove all untrusted entrypoints are constrained, future cgroup migration is impossible, or the image contains no alternate launcher. It also refuses the Bash outer-isolation receipt because local procfs cannot establish the EC2 allocation, physical host identity or no-Fargate placement. The host/image owner must provide measured native/image evidence and a trusted verifier that satisfies `host-wide-process-observer.mjs` and `bash-runtime-facts.mjs` before activation. The browser workspace preparer and native private mount view are source complete; the image owner must qualify their actual behavior on the candidate. The model proxy must present an IP-SAN certificate valid for `127.0.0.1` through the pinned CA, or an equally exact reviewed SNI scheme. Cloud absence still needs the trusted destroy and independent instance/volume/ENI readback owner. No production activation follows from these source tests.

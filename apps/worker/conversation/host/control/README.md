# D005 host currentness control port

Implementation outline: keep the on-host client, mTLS server, wire checks and durable read adapter separate. The client presents the exact allocation, full RunBinding, host identity, fixed `sdk`, `browser` or `bash` purpose, policy digest and a cryptographic request nonce. The server derives the peer fingerprint from its verified TLS socket and checks the host-specific DNS SAN. The store consumes the nonce in the same acknowledged transaction that reads the host credential/allocation row and canonical run state under locks. It issues only a short active receipt. Every mismatch, replay, expiry, revocation, transport loss or uncertain transaction refuses. Each purpose-specific host client exposes only `readCurrent({allocation,binding,policySha256,signal})`; certificate material stays in trusted supervisor memory. The SDK client is required for every isolated-host run, including browser-only. Browser and Bash have separate canonical admission checks.

Source ownership here excludes the product migration, certificate issuer, canonical run persistence, deployment routes and shared runtime composer. The actual application must supply the exact same-transaction `readCanonicalRun` port and a PostgreSQL transaction owner; neither a response body nor a worker claim is authority. Focused tests cover protocol and transaction refusal with synthetic SQL, plus a local mTLS handshake. They do not prove database engine durability, live credential issuance, DNS routing, host confinement or revocation latency.

The private control endpoint uses TLS 1.3 and mutual certificates; it has one fixed POST route and a bounded JSON body. Handshakes and HTTP handlers each have a configured finite deadline; `maxSockets` caps pre-TLS and HTTP sockets together. No URL, host, credential, role or origin comes from a tool request. The server certificate must chain to the configured CA, carry the configured DNS SAN, match the configured SHA-256 DER fingerprint and be within its configured short lifetime. The client certificate must similarly chain to the server's CA, carry the per-host DNS SAN `h-<host UUID without hyphens>-g<generation>.host.meri.internal`, match the current fingerprint in the durable host row, and expire no later than the host allocation. Tool namespaces cannot reach this endpoint or read these credentials.

The control owner must allocate and review the schema name and migration before deploying the adapter. The exact proposed SQL is in `SCHEMA-PROPOSAL.md`. No migration or live apply occurs here.

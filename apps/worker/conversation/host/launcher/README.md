# D005 native launch boundary

## Implementation outline

The trusted host supervisor owns one immutable allocation, complete RunBinding, host identity, currentness reader, exact SDK and Playwright command descriptors, per-run Linux users, and prepared network namespaces. `supervisor.mjs` validates those pins, verifies the prepared network immediately before every launch, and waits for authenticated currentness. It starts the root-only native launcher with no model data or credentials in arguments. The native launcher moves itself or its forked browser child to the derived cgroup before any untrusted exec, enters the pinned network namespace, hides cgroupfs in a private mount namespace, drops to a distinct nonroot UID/GID with no capabilities, and pauses. The supervisor calls the matching process-observer arm callback while the child is live but paused, repeats currentness and network checks, then releases the child. A failure never sends GO.

The SDK's stdio MCP command is the unprivileged `meri-mcp-shim` binary. Its arguments contain only one single-use socket path and nonce. The root-owned broker checks `SO_PEERCRED` against the one SDK UID/GID, the shim's pinned executable inode, the exact SDK child cgroup and the **one SDK leader PID** supplied over a supervisor-only pipe. A pidfd pins that leader alive at accept and browser GO. It accepts only a shim directly spawned by that leader, consumes the nonce once, receives only the shim's three anonymous stdio FDs, and launches a **prebound** Playwright command. The request cannot select a command, cgroup, namespace, UID or environment. The exact installed SDK must be qualified to spawn this shim directly; an intermediate process causes refusal. The socket lives at `/run/meri-launch/<full RunBinding SHA>.sock` in a boot-owned root:sdkGid `0710` directory; Bash must not see that directory or the shim executable. A second connection is refused. The supervisor kills and reaps its leaders; host-wide process absence is required before cleanup can be reported as proven.

`readiness-ports.mjs` sends the SDK Bash namespace probes and the real no-model SDK startup through the same native SDK path. It prepares only root-owned `0710` temporary parent directories with private sdkUid-owned `0700` workspace/config children. `readiness-descriptor.mjs` requires an image-measured SDK executable hash and normalized no-model CLI argv hash. The SDK launch gate and `sdk-quiescence.mjs` then prove the readiness SDK child cgroup empty while network routes are extended. Conversation SDK launch requires the exact `https://127.0.0.1:<model-proxy local port>/` URL and the canonical CA path. The model proxy certificate must have IP SAN `127.0.0.1` and pass normal TLS verification.

`native/meri-host-launcher.c` and `native/meri-mcp-shim.c` are executable source, not a qualified image. The image owner must compile and pin both binaries, keep the launcher root-owned and inaccessible to tool UIDs, verify their hashes at bootstrap, and pin the readiness CLI binary/argv. The host must prove cgroup v2, namespace, UID separation, firewall/relay, SDK Bash sandbox and Chromium/renderer sandbox on the exact image. The concrete browser workspace plan is in `../browser-workspace/README.md` and its paused-child readback in `../browser-workspace/readback.mjs`: root:sdkGid sticky `01770` cwd, browser-owned private state, a private tmpfs overlay masking cwd, and only `.browser` bound into that view. The native browser child now installs that view before dropping its UID and signaling READY; it derives the conversation cwd from the exact browser HOME suffix, pins root-owned ancestors and the original `.browser` inode with no-follow FDs, and verifies the mounted inode and flags. A search-only ACL is insufficient because known `0644` SDK files would remain readable. This source does not establish the real image mount and Chromium/renderer behavior: the pre-start workspace preparer, paused-child readback, and host qualification must all succeed before browser activation can open. The current in-process host-veth relay needs a separate unprivileged host relay UID/cgroup before proxy-web mode can qualify. The control owner supplies authenticated, durable currentness; no receipt shape alone grants authority. These modules make no live host or cloud changes and do not open the browser activation gate.

Focused checks: validate command/identity refusal with synthetic ports, compile both native sources with warnings as errors, and exercise the stdio broker/observer handshake using isolated test ports. A real host qualification remains mandatory.

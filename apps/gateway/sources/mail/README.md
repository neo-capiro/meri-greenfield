# Canonical mail source-page adapter

This implements the mail read source port for `mail.list_messages@0.2.0`, `mail.search_messages@0.2.0` and `mail.read_thread@0.2.0`. It does not enable the production source catalog. The canonical dispatcher remains the consumer and owns current authorization, budget reservations, retained candidate history, final output validation and release.

Configure all three HTTPS endpoints explicitly with a trusted producer of the existing canonical mail source-page schemas. There is no default endpoint and no translation of an undocumented native response. Endpoint configuration cannot include credentials, a query or a fragment. Each request is one POST with redirects refused, ambient cookies omitted and no retries. The body is `{input,metadata}` from the existing canonical operation normalizer. Mail metadata is null; `input` preserves exact normalized subject, offsets, filters and query anchor. No actor, tenant, authority object or credential is placed in that JSON body.

`createMailHttpAdapter({endpoints,getCredentials,fetchImpl?,now,maxRequestMs?,maxResponseBytes?})` returns `{read}`. `read({operation,input,request,authority,signal?})` admits the original request again and derives the exact metadata; it accepts no caller-authored metadata. Default bounds are 15 seconds and 1 MiB, additionally shortened by the inherited authority deadline and credential expiry. `fetchImpl` is borrowed, never disposed by the adapter. The adapter owns only its lifetime/controller and acquired response body; it cancels them on all exits, including a response that arrives after cancellation. Physical socket retirement remains a native transport qualification check.

The trusted `getCredentials` port receives frozen `{operation,input,metadata,argumentsSha256,requestSha256,binding,subject,policyRevision,sourceIds,deadlineMs,signal}`. `argumentsSha256` is the canonical selection digest; `requestSha256` is `canonicalSha256({input,metadata})`. Its inert receipt must contain exactly `{operation,argumentsSha256,metadata,requestSha256,binding,subject,policyRevision,sourceIds,bearerToken,serviceSecret,expiresAtMs}`. All pins must match before either token is used. Credentials come only from this trusted port. The adapter neither authenticates a caller nor replaces that port's current source admission responsibilities.

`createMailReadHandler({operation,adapter,now})` returns the existing `execute(call)` handler signature. It captures the admitted read method and preserves its original adapter receiver. It returns the canonical source-page JSON directly. Binding, full subject, operation, normalized selection, digest and declared source authority are correlated. Before source effects, both the adapter and handler require the canonical authority shape and check that its supplied gateway/read capability and allowed AuthorizationDecision agree on operation, actor, policy, decision ID and scopes. This is internal fact correlation; the dispatcher still authenticates and rechecks current authorization. The canonical validators check thread semantics and first candidate pages at the source boundary. Later candidate pages retain exact data until the dispatcher validates them against its privately retained previous page; this handler never invents or rewrites that history. Do not invoke the handler as a public release endpoint.

Candidate previews keep unknown immutable versions and unresolved decisive reads. Thread sections preserve the source's record version, citation and content hash, exact UTF-16 code-unit offsets and explicit body completeness. Neither body text nor a citation marks a free-form claim verified: the existing transport keeps `evidenceReady:false` and `negativeAssertion:{kind:'none'}`. Empty or terminal pages do not establish absence. Coverage, versions and hashes are never generated or upgraded by this adapter.

Source-only checks cover actual local Fetch/byte decoding, all three handler operations, the late decisive body, offsets/anchor/provenance and scope/refusal/lifetime controls. Native source producer compatibility, real identity/permissions, live worker activation, socket retirement and quantitative retrieval qualification remain unverified. No live account, private source, model call, database, artifact transfer or cloud action is used.

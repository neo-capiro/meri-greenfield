# Passive client-knowledge source reads

This implements only the existing `search_memory@0.2.0` and `read_monday_client_boards@0.2.0` read source ports. The production catalog remains pending/null; there is no default endpoint or activation. No memory proposal, approval, extraction, refresh, Monday MCP write or model loop is added. The canonical gateway owns current actor/source authorization, budget reservation, normalized argument digest and final release.

`createClientKnowledgeHttpAdapter({endpoints,getCredentials,readMemoryEligibility,fetchImpl?,now,maxRequestMs?,maxResponseBytes?})` returns a frozen `{read}`. Both endpoints must be explicitly configured HTTPS URLs keyed by the exact operation IDs, without credentials, query or fragment. They must implement the committed canonical source projection protocol; undocumented native URLs/payloads are not projected. Each read makes one POST, refuses redirects and ambient cookies, and has no retry. Default bounds are15 seconds and1 MiB, shortened by the inherited authority and credential/eligibility expiry. The adapter owns only its request lifetime and acquired response body. Borrowed transport/clock/ports are not disposed. Physical socket retirement is a separate native transport qualification dependency.

`read({operation,input,request,authority,normalizationContext,signal?})` validates the closed supplied authority and its binding/subject/claim/allowed decision coherence. It rederives input/metadata with the existing canonical normalizer. The root gateway derives normalizationContext from trusted facts: `{tenantId,userId}` exactly matches binding tenant/actor for memory; Monday requires `{}`. Model arguments cannot provide this context. Personal and exact selected-client scope remain separate. `createClientKnowledgeReadHandler({operation,adapter,now})` captures the ordinary read method with its original adapter receiver, admits the existing dispatcher call plus required normalizationContext, and emits exactly `{binding,subject,operation,argumentsSha256,result}`. Canonical validators own the raw result DTO. This handler is internal and is not a public release endpoint.

HTTP body is exactly `{input,metadata}` serialized by the already adopted canonicalize5.1.0 (Apache-2.0), so the actual UTF-8 byte SHA equals `requestSha256`. Metadata is preserved in full. Context/claims/credentials are not added to the JSON body. `getCredentials` receives frozen `{operation,input,metadata,normalizationContext,argumentsSha256,requestSha256,binding,subject,policyRevision,sourceIds,deadlineMs,signal}`. The inert receipt contains exactly `{operation,argumentsSha256,metadata,normalizationContext,requestSha256,binding,subject,policyRevision,sourceIds,bearerToken,serviceSecret,expiresAtMs}`; Monday additionally requires `managedBoardMapping`. The operation, scope, context, metadata and digests must all match before Fetch. The credential broker remains responsible for current native access.

Monday's `managedBoardMapping` is exactly `{tenantId,userId,clientId,mappingVersionId,boardIds}` from that current broker. Tenant, actor and selected client must match; version must be present and numeric board IDs unique. Each returned record's board, client and sourceActorUserId must match it. Item/subitem/provider fields are retained as inert data. `boardContext` remains a selector and grants no access; a requested board cannot escape the managed mapping. The mapping's currentness and native producer compatibility remain broker qualification duties.

The frozen memory projection cannot prove current recall eligibility. Its governance observations omit private-owner/wall/sensitivity/review facts, and the private memory-review-policy file is explanatory only. The existing external native eligibility owner therefore supplies the specific passive `readMemoryEligibility` receipt after canonical source decoding. Its request is the credential request pins plus `{resultSha256,records,deadlineMs,signal}`, where records are exact `{memoryItemId,recordSha256}` of the unmodified source page. Its closed receipt is the credential receipt pins without tokens, plus `{resultSha256,checkedAtMs,expiresAtMs,records}`. Each receipt record is exactly `{memoryItemId,recordSha256,eligibleForRecall:true}`. Checked time must lie within the current call; expiry cannot extend its bounded deadline. Missing/unknown/ineligible, stale, duplicate, additional, omitted or mismatched receipts refuse the whole page. No records are filtered/recounted and no proposal becomes approved content. The adapter does not copy or implement the native lifecycle predicate. Native current eligibility enforcement and revocation remain external qualification dependencies.

Memory excerpts and exact nextRead content keep their canonical UTF-16 offsets, item/actor/client cursor correlation, hash and source version. Metadata-only learning-event content retains the explicit limitation that approval of an event does not verify the underlying fact. Null TTL/review/provenance observations stay null; sourceStatus or instructionsAllowed is not approval. Native eligibility receipt acceptance does not verify a free-form claim or replace original source evidence.

Coverage and observability remain the existing reported source metadata. These flags do not establish verified completeness, native snapshots, cursor authentication or authoritative absence. An empty result remains bounded by disclosed partial/unavailable coverage and the original governance limitations. No coverage derivation, verified/negative assertion, live source acceptance or whole-plan closure is implied by the local checks.

Synthetic fixtures are exported from `test/fixtures.mjs` for root's real dispatcher integration. Source-only tests exercise actual loopback Fetch/bytes, exact body SHA, passive domain receipts, source scope/refusal controls and cleanup; they access no real account, private source, provider/model, database, cloud or artifact transfer. Root independently reviews, integrates and qualifies the candidate.

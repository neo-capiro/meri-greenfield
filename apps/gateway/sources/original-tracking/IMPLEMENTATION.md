`request-context.mjs` binds the exact original operation, descriptor source requirement, full current decision/subject/capability, original request normalization and immutable clock. `http-adapter.mjs` handles bounded POSTs to the existing `/clio/tools/query_tasks` and `/clio/tools/query_action_items` routes, with request-bound injected credentials and shared Fetch Response decoding. `projection.mjs` preserves native rows, proofs, scope, coverage and cursor disclosure and adds only partial/null/unknown receipt lineage. `handler.mjs` is the thin canonical output handler. `mount.mjs` composes actual adapter and handler, exposing source-implemented/pending metadata and the precise live gate; it performs no registration or activation.

The configured `sourceIdentity` is exactly the original contract's `{sourceId,authority,purpose}`. `tasks/authoritative/enumeration` and `action_recommendation/authoritative/enumeration` are accepted only under their corresponding original operation. `actions.query`, `action_items_complete`, derived authority, another source or arbitrary routes are refused during inert construction. This is configuration correlation, not authentication of the native service.

The credential provider receives `{operation,sourceIdentity,binding,subject,policyRevision,sourceIds,argumentsSha256,deadlineMs,signal}`. It must return the same immutable pins plus `{bearerToken,serviceSecret,expiresAtMs}`. The adapter supplies no ambient credential provider and never forwards the worker capability. Existing gateway dispatch must authorize current source and business scope and reserve budget before this provider is called. Source read credentials expire no later than the authority deadline. No retries are introduced.

Handler calls retain existing `{input,request,authority,argumentsSha256,signal?}` and accept optional `normalizationContext`. Tasks require the original canonical `{nowMs,actorId}` when supplied. Actions use `{actorId}` and accept a bounded `{nowMs,actorId}` gateway context while retaining only actorId for their canonical validator. The root owns freezing and carrying that clock in shared dispatch; clocks are never decoded from native opaque cursors. Without pinned context, a changed default-overdue clock can cause safe admission refusal. Portfolio-native overdue flags are checked against the contract's trusted clock, so a native clock crossing a due date can also refuse until real clock semantics are qualified.

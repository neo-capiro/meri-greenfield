The selected skill mount uses existing `createDurableToolDispatch.executeOwned` for every SDK or compiler delivery, against the same pool, immutable original allocation, grant facts and producer identity. It creates no grant, allocation, budget counter or model loop. The original preservation catalog remains pending and byte-identical; a separate execution installation view resolves those same descriptors only after a configured trusted installation owner returns current qualification.

`createSelectedSkillInstallationOwner` accepts the exact server-selected request, selection, scopes and current client. `readCurrentContext({binding,signal})` projects the existing opaque session owner's current result to `{binding,scopes,selectedClientId,checkedAtMs,expiresAtMs}`. `readCurrentInstallation` is a trusted native qualification-owner port, never caller/model supplied. It receives the pinned SDK input plus scopes/client/policy and must verify native qualification and authorization before returning the canonical installation receipt plus `{scopes,selectedClientId,policyRevision}`. Qualification UUIDs and handler availability metadata cannot substitute for this owner. No such production owner or live qualification is claimed by source protocol fixtures.

Handler registrations are a Map keyed by `id@version`, with `{execute,sourceSha256,sourceFiles:[{label,sha256}]}`. Labels are paths relative to the configured Meri source root, and `sourceSha256` hashes that ordered code-file manifest. Every current installation read measures those file bytes, with regular-file/no-symlink and byte limits, before releasing the receipt. The native qualification owner is responsible for completeness of the source/dependency manifest and authentic source/policy qualification; local file hashes alone do not establish it. The catalog contract port is the closed `{resolveOperationContract}` adapter over the canonical contracts package.

The gateway mount has `sourceEnabled:false` by default. Partial installations refuse absent operations before creating an invocation or acquiring source credentials. `producerContext` is the existing canonical tool-grant facts, `producer` is the stable trusted `{namespace,executionId}`, and `deliveryId` is the actual supported SDK tool-use ID or pinned compiler delivery identity. Reusing a claimed delivery follows the canonical refusal/UNKNOWN behavior; this mount never redispatches a settled or unknown effect.

The admission owner adds `admitSelection` before persistence, replay and release. It rechecks opaque current context, server-selected client/window/scopes, measured current installation, and `createPostgresAdmittedRunOwner.currentAllocation`; the latter performs the same original run/grant/allocation SQL checks. It does not alter the original read-only manifest or add `create_word`. Editable output remains a separate approved run with explicit provenance.

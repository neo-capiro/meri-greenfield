# Explicit isolated preview runtime

The executable commands compose the existing product owners. This is a source checkpoint for an isolated preview, **not production or native runtime acceptance**. Configuration permits `profile: "isolated-preview"`, one control replica, process-local opaque sessions, and `sourceEnabled: false` only. Production profiles, unknown fields and source activation are rejected before allocation. No legacy Meri proxy or arbitrary JavaScript factory is loaded.

The native-flow successor mounts the existing document POST routes, four private selected-task routes and four private SDK-session routes through `product-applications.mjs`. Trusted callers can supply captured compiled identity/context, document-options, selected-controller, SDK-session, original selection-admission and governed output-publication owners to `assembleControl`/`startControl`. These ports are borrowed, cannot be installed by request/configuration JSON, and retain their original method receiver. CLI installs no substitute when an owner is absent: identity/context issuance and document/session operations refuse; selected source operations remain inactive. The identity port must use `createNativeIdentityContext` over the existing Capiro authority client and canonical current-run join. A raw native context body does not satisfy the opaque Meri session contract.

The default conversation CLI requires an exact native-observed `sdkSessionKey` from its trusted runtime owner and re-registers it against actual task/SDK observation before querying. No project-key algorithm or first-session observer is invented. The private selector is stripped before SDK Options; mirror writes settle before durable completed status. Owned mirrors acquired after cancellation are retired exactly once. Cleanup uses validated `limits.shutdownMs` (1000ms for existing assembly callers without limits), reports `RUNNER_CLEANUP_UNKNOWN` if its callback remains unsettled, and never equates a bounded promise with physical task shutdown. The pure canonical session codecs/adapter are the only included files from the historical qualification directory. Product budget and SDK/read migrations remain unapplied. Actual native task verification, first-key observation, approved output/source/renderer bindings, process isolation, selected continuation/completion recovery and deployment are still qualification gates.

| Role | Executable | Authority and resources |
| --- | --- | --- |
| Trusted control | `node apps/runtime/cli.mjs control --config /run/meri/control.json` | PostgreSQL pool, Temporal client, fixed native capability provider; canonical opaque session/service/store/HTTP owners |
| Trusted Temporal poller | `node apps/runtime/cli.mjs temporal-worker --config /run/meri/worker.json` | NativeConnection and Worker.create, exact canonical workflow definitions, execution-broker activity; no model loop |
| Fresh isolated conversation task | `node apps/runtime/cli.mjs conversation-runner --config /run/meri/task.json` | One exact RunBinding, private workspace, short-lived task capability; canonical Claude Agent SDK activity; no database, provider-account or Temporal service credentials |

`--help` lists usage and exit codes. Exit 0 means graceful completion, 2 configuration/startup timeout, 3 runtime failure/shutdown timeout. Imports are inert. CLI SIGTERM/SIGINT aborts work, marks the listener unavailable, drains bounded HTTP streams, closes owned resources and exits. The native task-launch broker must launch a **fresh task per conversation**; the trusted Temporal process never calls the SDK locally. Physical task isolation is not proved here.

The selected source path is Claude Agent SDK0.3.295/CLI2.1.295 through the configured HTTPS trusted proxy. Existing canonical SDK options set `ANTHROPIC_BASE_URL`, a task-scoped `ANTHROPIC_AUTH_TOKEN`, and `model` from the trusted runtime owner, with account API/OAuth keys excluded. The runner compares configured immutable runtime versions against both durable run and returned runtime before the single query, and rejects ambient Bedrock/Vertex/Foundry/Anthropic AWS provider flags. The approved plan does not name a concrete real upstream provider/model ID; that exact supported model/proxy/provider pin remains **UNRESOLVED/HOLD**. Synthetic test model names do not establish it. A question about SDK Bedrock support does not authorize changing providers, IAM or paid qualification.

## HTTP and durable registration

Control listens on the explicitly configured address/port; container planning should assign control 8080 and poller health 8081 in separate services. `GET /health/live` is process liveness; `GET /health/ready` checks dependencies and returns 503 when unavailable. A successful ready response says `profile: isolated-preview`, `releaseAcceptance: held`; it does not assert native qualification. Incoming browser Origin must equal the configured frontend origin. Reverse-proxy/TLS and network policy remain deployment configuration responsibilities. The poller listener serves health only.

The control assembly mounts canonical routes:

- `POST /api/action-followthrough/session` reuses the existing opaque issuance owner. This is the existing session route, not a new Quicklog UI.
- `POST /api/conversations/submit`, `/history`, `/cancel`, `/events`.
- `GET /api/conversations/events/{conversationId}/stream`, with `x-meri-resume-sequence` as a selector. Current session/scopes are checked again.
- `POST /api/conversations/control` and `/api/conversations/checkpoints/inspect` through the existing lifecycle facade.
- Private task routes `POST /internal/conversations/{load,publish,next-controls,claim-control,ack-control,record-checkpoint}`. Closed envelopes reuse the canonical binding/worker-owner arguments. Worker publish permits only `run.status` and `message.delta`; artifact publication remains the trusted output owner.

Temporal namespace and task queue have no implicit default. The dispatcher uses exact workflow ID `meri:<tenant>:<conversation>:<run>` and starts `meriConversationLifecycleWorkflow`; the canonical workflow module also registers `meriConversationWorkflow` for compatibility. Activity name is `executeConversation`, with the existing 30-minute timeout, 30-second heartbeat timeout and maximumAttempts 1. The broker activity uses an immutable binding hash for launch correlation, polls the same execution ID, rejects changed binding/fence and reports heartbeat. It never retries an uncertain launch.

The control PostgreSQL pool requires an explicit connection file with exactly one query parameter, `sslmode=verify-full`. Duplicate modes, other query overrides and fragments are refused before Pool or Temporal allocation. Startup checks the required conversation tables are present; it does not verify exact migration hashes/columns or native durability. Temporal GetSystemInfo checks service connectivity, not configured namespace/task-queue authorization or fresh isolated broker launch. Exact product migrations0001/0002/0003, native namespace/queue and durability remain qualification gates. The entrypoint never runs migrations. No protected `meri_qualification` fixture is provisioned, renamed or modified. There is no additional queue implementation alongside Temporal.

## Configuration and native boundaries

The JSON file is at most 32 KiB. All fields are closed. `version: 1`, `profile: isolated-preview`, `sourceEnabled: false`, `limits: {startupMs,shutdownMs,requestMs,requestBytes}` and `native: {origin,capabilityFile,loopback,maxResponseBytes}` are required. Origins have no trailing slash, query, credentials or fragment. HTTPS is required; explicitly enabled loopback HTTP is accepted only for local synthetic fixtures. Limits cap startup/shutdown at 30 seconds, request at 3 seconds, browser bytes at 128 KiB and native response at 2 MiB.

Control additionally requires `http: {hostname,port,frontendOrigin}`, `database: {connectionFile}`, `temporal: {address,namespace,taskQueue,tls: {caFile,certFile,keyFile}}`, `sessions: {mode: process-local,replicas: 1,maxSessions,maxTtlMs}`, and exact canonical `RuntimeVersions`. The poller needs http/temporal but no database or browser session configuration. A runner needs exact `binding`, `versions`, `workspace` ending in its conversation UUID and `proxyOrigin`; it cannot receive database or Temporal fields. Secret/certificate files are absolute, regular, non-symlink files owned by the running UID, with no group/other permission bits. Values are never printed.

The fixed native provider URL receives closed POST JSON under `/v1/`, with the configured server/task capability as Bearer credential. No provider adapter implementation or private native schema is imported from Capiro. These are **required provider contracts, not evidence that the provider already exists**:

| Provider operations | Required owner behavior |
| --- | --- |
| `identity/verify`, `context/resolve` | Existing canonical identity/current-context receipts, native policy and selected client. Current scope is checked before and after every browser operation by the opaque owner. |
| `worker/authorize` | Current signed task capability bound to exact binding/operation/input hash, actor/tenant/client/scopes/policy/expiry and native decision ID. It supplies native identity only to the trusted control process. The private route issues a temporary opaque session, compares current state, invokes the canonical service, rechecks native authority, then revokes that session. |
| `checkpoint/read`, `continuation/admit`, `continuation/retire`, `approval/read`, `approval/decision` | Existing canonical lifecycle owners verify exact retained checkpoints, independent approval, current target admission and source retirement. JSON data alone grants no rights. |
| `execution/start`, `execution/poll` | Durable idempotent launch correlation, fresh physical SDK task, current full binding and lease, same execution identity. Native task/broker failures are not release acceptance. |
| `runner/load`, `runner/publish`, `runner/runtime` | Broker forwards through the current task-authorized control routes; runtime result pins binding/versions/proxy origin, budget, workspace ownership and deadline. Never release browser opaque session or native identity/provider/DB credentials to the task. |
| `runner/next-controls`, `runner/claim-control`, `runner/ack-control`, `runner/record-checkpoint`, `runner/checkpoint/capture` | Actual CLI reuses canonical lifecycle run owner and activity lifecycle over the task-capability transport. Credential is stripped from JSON; the fixed client header and native current-task owner remain authoritative. Steer requires exact UUID echo/claim; pause/approval wait require native capture/readback before canonical checkpoint persistence. Native capture absence/refusal fails explicitly. |
| `runner/session/load`, `runner/session/append` | Durable SDK SessionStore bytes under native tenant/conversation/run/SDK-session ownership. Bind actual SDK session/key/subpath; never authorize from caller projectKey alone. Ordered append/idempotence and revocation/restart remain provider qualification requirements. |
| `readiness` | Connectivity contract `{service: "meri-native-capability-provider/1", ready: true}`; this health result cannot authorize any operation. |

Actual CLI ordinary controls are wired to existing activity lifecycle; continuation forwards the immutable envelope/sourceRequest/request/scopes to the trusted runtime owner and accepts a restoreReceipt only for that actual continuation. Existing canonical native capture/restore validators enforce exact checkpoint/source/context/workspace/opaque-session/scopes/version hashes and expiry before execution. Basic helper composition without a credential transport is retained for characterization; it does not establish lifecycle acceptance.

Artifact DOCX/XLSX routes are not mounted by this bootstrap because native artifact/runtime options and source admission are not yet assembled here. The parallel S3/PostgreSQL storage adapters must be wired through the existing document/artifact service, with the reviewed product version migration, dedicated bucket/versioning/KMS and current output grant. FS storage and callback booleans are not substituted. Original selected skills likewise fail closed until their canonical selected runtime/compiler/output and current native allocation/installation owners are connected over the approved private boundary. Process-local opaque sessions do not satisfy replica/restart durability. These, native capability provider/launch broker, durable SessionStore, protected-budget-to-product schema mapping, real provider qualification and browser sandbox remain release blockers.

## Dependencies, build and evidence

Own lockfile pins `@hono/node-server` 2.1.5, pg 8.23.1 and Temporal 1.24.0 (MIT). Claude SDK remains the existing 0.3.295/CLI 2.1.295 owner; TypeScript is 5.9.3. No root/shared lock changed. The Node server adapter deliberately sets `overrideGlobalObjects: false` and materializes a native Fetch Request because canonical owners validate native brands. Upstream references: [Node adapter](https://github.com/honojs/node-server), [Temporal workers](https://docs.temporal.io/develop/typescript/workers), [pg pool](https://node-postgres.com/apis/pool).

Build from repository root using `docker build -f apps/runtime/Dockerfile --build-arg NODE_IMAGE=<reviewed-node24-image@sha256:digest> .`. No floating image default exists. ENTRYPOINT is the actual CLI, USER is node, and role/config are explicit container arguments. Mount only each role's secret files and writable task workspace; apply read-only root/network/sandbox controls in the separately reviewed deployment. `.dockerignore` excludes host dependencies, secrets, private fixture artifacts and evidence while retaining source schemas, locks and original skill assets. A build is not browser/isolation qualification.

Run `npm ci --prefix apps/runtime --ignore-scripts --no-audit --no-fund`, then `npm test --prefix apps/runtime` and `npm run typecheck --prefix apps/runtime`. Existing application package dependencies must also be installed from their locks. Tests exercise real HTTP listener/IPC/SIGTERM plus canonical service/SDK and upstream workflow bundling; native/SQL/Temporal-server/provider inputs remain explicitly synthetic. Every check uses `evidence/capture-reaped.py`, preserving failures and physical process-group cleanup. The executor sandbox's mapped ancestry caused an SWC native-cache failure; the automatic reviewer allowed a narrow unsandboxed **local bundle test**, which passed with no native DB/provider/cloud calls. Earlier untracked-source captures had a zero diff hash; later staged/committed captures bind the source and this limitation remains visible.

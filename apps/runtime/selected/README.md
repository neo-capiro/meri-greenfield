# Native selected recipes

`createNativeSelectedComposition` composes the two original selected recipes into control using the existing run, execution, typed-read, selected-output retention, intent journal and immutable approval metadata owners. `assembleControl` mounts its ports when source reads and the existing default Congress are configured, and closes its owned runtimes during shutdown. The AgentCore candidate forwards only the four private `selected/prepare`, `selected/read`, `selected/finish` and `selected/publish` operations to that composition.

The isolated SDK process exposes the existing original MCP server. Private requests carry the run-scoped execution credential, full binding and opaque selection/completion identifiers. Core remains responsible for business-data admission. Control verifies the current run, request, scopes, selected client and immutable expiry, then sends reads through the same native reads HTTP owner used by ordinary tools. Source results retain SDK tool-use correlation and the existing call, byte and runtime caps. There is no allocation or financial reservation ledger on this path. Applied `selected_reads` SQL remains immutable history.

The actual deterministic compiler runs inside control. It retains the source preparation and observed reads in the existing `selected_outputs` owner. Publication creates a real `document.draft` proposal through the existing intent preparations journal and immutable metadata writer, then publishes `approval.required` through the ordinary conversation service. Repeated publication returns the same proposal/event. Unknown metadata or journal outcomes do not permit a new proposal dispatch. The source preparation, evidence binding and request hashes are preserved; no synthetic access/session receipt UUID establishes authority.

The private wire contains no compiler object, retained source body, approval decision, artifact options, Core service secret or database credential. Controller handles remain process-local and capped at 64. Lost preparation/compilation handles fail closed; this is not a claim of compiler recovery after a control restart. The stored proposal and selected output have their existing durable ownership, while approved output generation still requires the separately composed real decision and artifact publication owner.

Closed controls exercise the actual assembled control routes, SDK MCP/read transport, source adapters, both compilers, SQL adapters, retained output and approval event; SQL, provider and Core transport fixtures remain synthetic. They prove refusal on changed credentials/current scope and cleanup of pending reads. They do not qualify native PostgreSQL, a model invocation, a rendered approved DOCX or live deployment. Selected pause/fork continuation and the final approved-publication mount remain explicit paired work until their native owners are connected and tested.

# Admitted task verifier and supervisor binding

`createAdmittedSessionSupervisor` in `admitted-supervisor.mjs` composes one existing product admission owner, canonical native identity/context adapter, task verifier, protected receiving application and durable SDK-session owner. It allocates no process/network/database resources at construction and creates no capability, grant, schema or parallel registry. Borrowed pool and transport remain with their runtime owner.

Supply existing `allocationJson`, `grantFactsJsons`, selected `grantId`, trusted `operations` (canonical run-owner keys and `runner/session/*`), original PR74 `launchConfiguration`, limits, clock and explicit `enabled:true`. `identity` contains the existing HTTPS origin-only `origin`, original `commandContext`, `fetchImpl` and existing native bearer `credential`. `callerCapabilitySha256` is the hash of an independently owned existing trusted-control caller capability; it must differ from every configured task grant. No token is issued or activated by this factory. The original launcher must also be explicitly enabled.

The task token is matched by raw SHA256 against the selected canonical grant. Before and after fresh native authority checks, the canonical product admission owner's new `currentTaskRun` performs a **separate** repeatable-read read-only transaction using the same grant/run/fence/policy/allocation/quarantine/deadline predicates as existing admission. It has no row locks or effects. This matters because the durable SDK owner calls verification while holding its write-side admission lease. The existing `currentRun`, allocation and leased effect methods retain their original locking semantics.

Fresh native identity/context uses the same read-only currentTaskRun path. Receipts retain the full original task binding, trusted operation/input digest, current selected client/scopes/policy, original native identity credential and minimum original grant/native/launcher expiry. A decision digest binds the checked facts; it is not a substitute for a native decision. A request deadline bounds verification but does not replace the authority lease. Each subsequent operation must reverify; receipt/identity/context are not authorization caches.

Mount `supervisor.application` only in the **trusted-control** native service composition. Its existing POST `/v1/worker/authorize` body is `{capability,binding,operation,inputSha256}`; the HTTP bearer is the distinct trusted-control caller capability, not the task capability. It returns the existing private WorkerAuthorization shape, including native identity credential, solely to trusted control. Do not expose this application as an unauthenticated or worker-token-authorized endpoint. Physical network isolation remains deployment-owned. The existing native client/authority adapter consumes it without a wire change.

Mount `supervisor.productPorts` through the existing control `productPorts` binding (or return that object from its compiled factory). The identity/context and SDK-session persistence ports share this same admission/verification owner; do not instantiate a second first-run admission mount for this run. The stable `supervisor.registration` port refuses until an actual launcher exists and actual init/main frames have been read.

The genuine broker may call `await supervisor.prepareLaunch({capability,signal})` once with its existing task capability. This checks the exact task's current read authority, then constructs PR74's pinned one-use launcher with a lease no longer than the original plan/current receipt. It does **not** allocate/admit a new task or replace `execution/start`. Use the returned launcher's `spawnClaudeCodeProcess` in the approved independent supervisor transport. No worker may compile the original plan, install observations or access the native identity credential. Always await `supervisor.close()`; it aborts parked preparation/new verifier calls and closes only its owned launcher, never the borrowed pool/listener. Late borrowed SQL/native responses remain governed by canonical deadlines and their owners; bounded cancellation is not physical database-query shutdown.

Backend PR6 `1f2655fe964cb2a01343d3bcb560de60fa5f69be` preserves the exact `/api/clio/application-authority/identity` and `/context` contracts, mounted once through Core. Pass an HTTPS origin without `/api`; the canonical transport appends the fixed prefix. Actual serving image/source/origin and current native identity/owned conversation/client still need the backend/runtime owner. No backend implementation is copied here.

Missing production integration remains the actual durable broker, native task allocation/isolation and `runner/runtime` model/proxy/executable/image binding. This factory closes current-verifier and admitted-source composition gaps; real local fixtures do not establish that independent deployed trust boundary, actual product database or a successful SDK/model turn.

# Trusted native launcher binding

`createNativeSessionLauncher` is the trusted supervisor's one-use adapter for the existing SDK `spawnClaudeCodeProcess` transport. Import from `./session-launcher.mjs`. It does not establish task admission or deploy a supervisor.

Compile original `binding`, normalized `workspace` and `configDirectory`, `versions:{sdk:'0.3.295',cli:'2.1.295'}`, original `expiresAtMs`, executable SHA256 and `launch:{command,args,env}` in trusted supervisor code. Supply `enabled:true`, optional cancellation signal, clock, observer limits and `shutdownMs` (10–10000, default1000). Command must be a real absolute executable path. Environment is explicit, without inherited ambient variables, and includes both `CLAUDE_CONFIG_DIR` and `CLAUDE_SECURESTORAGE_CONFIG_DIR` equal to the compiled directory. Provider/account/database/cloud/control credentials are refused; an existing task-scoped model proxy token remains the runtime owner's responsibility.

Before allocation, the hook matches the entire SDK command/args/cwd/env to the compiled plan, checks workspace/config real directories and executable SHA256, then rechecks cancellation and the original lease. It spawns a detached Linux process group and installs the existing registration reader against original kernel stdout. The executable must remain immutable between readback and exec; a local digest is not deployed-image attestation. The supplied SDK version is a trusted original input; CLI2.1.295 is additionally verified from native init by the existing reader.

Pass only `launcher.registration` into `createNativeFirstRunMount({registration,...})` in trusted control. Use `launcher.spawnClaudeCodeProcess` as the supported SDK option for this exact planned launch. The SDK receives a real ChildProcess whose stdout is a readable facade over the observer, never its writable witness Transform. The supervisor retains the launcher and registration port. A mismatched request does not consume the launch slot; successful allocation does, even on subsequent initialization failure. No worker-supplied child, stdout, observation or renewal is accepted. Reads before spawn fail unavailable; existing session registration starts after the actual native main/init frames.

Always `await launcher.close()` in the launch owner's `finally`. Cancellation, lease expiry, malformed observer stream and initialization failure start physical retirement. Only the owned group is signaled, first SIGTERM then SIGKILL within the configured cleanup bound. Child close plus positive Linux group absence proves physical cleanup; permission errors/timeouts remain unknown and `close()` throws `NATIVE_LAUNCH_CLEANUP_UNKNOWN`. `completion()` resolves the physical outcome, and `status()` reports the reader/process state. Natural process completion preserves buffered stdout until transport consumption; explicit retirement destroys owned transport and drains the original pipes. Stderr consumption/diagnostic bounds remain the SDK transport consumer's responsibility.

This source adapter does not install an independent supervisor into the current worker-owned SDK CLI. The genuine admitted broker must compile this plan and bind process transport across its approved supervisor/worker isolation boundary. The existing task verifier, broker execution/runtime/model proxy, product database/admission, Temporal and physical deployment isolation still require real owners/resources. Never use a worker-owned hook or these synthetic fixtures as independently deployed authority. No new contract, route, durable owner or SDK model loop is introduced.

# Exact-text federal draft preparation

`createArtifactService().prepareFederalDraft(selection, context, options)` is the private receiving path. It reads the selected immutable source using the artifact owner's existing current-authority, retention and byte-verification checks, then runs the deterministic compiler. Preparation writes nothing. The source selection includes `versionId`, `expectedArtifactSha256` and ordered `operations`.

The retained TXT source envelope is JSON with `documentId`, `publisher`, `sourceVersion`, `sourceUrl`, `publishedAt` (an exact calendar date or explicit null when unreported), `parserVersion`, exact UTF-8 `text`/`sha256`, `coverage: {complete, limitations}`, and ordered `scopes: [{id,label,start,end,sha256}]`. Offsets are UTF-16 string offsets, with Unicode scalar boundaries validated; source text is not normalized. Scope hashes cover the exact original slices. The source importer is responsible for accurate publisher/version attribution. Storing a claimed publisher in an artifact is not official-source verification.

Each operation has a unique `id`, `kind: replace|insert|delete`, `scopeId`, `expectedScopeSha256`, nonempty `expectedText` and its SHA-256, and `dependsOn`. Replace adds `text`; insert adds `text` and `position: before|after`; delete permits neither. Dependencies must reference earlier operations, and a subsequent operation on a changed scope must name the previous operation on that scope. The expected scope hash is the exact intermediate text hash. A missing or repeated anchor, changed scope, invalid dependency, successful no-op or empty final source is refused. No fuzzy anchor, inferred ancestor or fallback search exists. Every intermediate change occurs on copies; a failed operation returns no partial package. Each refusal is a `DRAFT_*` code with the refused `operationId` when the compiler identified one; the public routes release that code as the error reason ([scope record](../../../docs/legislative-workbench-20261101/FEDERAL-WORKBENCH-SCOPE.md)).

## Parser identities

- `federal-plain-text/1`: flat non-overlapping scopes. Official plain-text imports use one `document` scope. A source that begins with markup is refused (`DRAFT_SOURCE_FORMAT_UNSUPPORTED`).
- `federal-scoped-text/2`: the same fields plus a required `ancestorPath` on every scope. Scopes are in preorder; exact ranges are disjoint siblings or contained descendants and the declared path equals the enclosing scope IDs. No legal structure is inferred from headings.
- `federal-uslm-xml/1`: raw USLM XML text. Scopes are derived by `uslm-source.mjs` through the strict `saxes` parser the artifact structure reader already uses: the root element as `document`, then every USLM-namespace element carrying an `identifier`, as nested element spans (from the start tag's `<` through the end tag's `>`) with the identifier mapped to the scope id (`/us/bill/119/hr/1/s1/a` is `us:bill:119:hr:1:s1:a`) and kept verbatim in the label. Declared scopes must equal that derivation exactly (`DRAFT_USLM_SCOPES_MISMATCH`). Edits are exact markup edits inside those spans; the compiled result is re-read as one well-formed document with the original root (`DRAFT_XML_RESULT_MALFORMED` otherwise). Well-formedness, the declared namespace (`http://xml.house.gov/schemas/uslm/1.0` or `http://schemas.gpo.gov/xml/uslm`) and identifier uniqueness are checked; USLM schema validity is not. A DOCTYPE, a non-UTF-8 declaration, a foreign root namespace, a duplicate or unmappable identifier and plain text labelled USLM are explicit refusals.

For nested parsers, edits update the working document and all surviving scope locations. A target's hash always covers its current intermediate text. Every operation that changed that text must be present in the dependency closure: independent sibling edits require both branches before editing their ancestor. Transitive dependencies are accepted. Insertion at a descendant's start/end by an ancestor belongs outside the descendant; insertion through that descendant belongs inside it and its ancestors. An ancestor edit wholly consuming a descendant or crossing its boundary invalidates that old identity. Subsequent use of that scope or any target whose declared ancestor path contains it returns `DRAFT_SCOPE_INVALIDATED`, even if child text survives or replacement text happens to recreate a similar heading. Matching hashes and explicit dependencies cannot restore an invalidated path; unrelated subtrees with valid ancestors remain usable. An edit wholly within a descendant preserves its identity and adds a dependency. Invalidated scopes are never fuzzy-rematched. The original source/operations remain unchanged on any failure.

## Outputs

The result contains three distinct outputs: ordered operative instructions, exact consolidated text, and a legal text comparison expressed as typed unchanged/delete/insert JSON segments. Literal marker characters cannot be mistaken for changes. Adjacent segments of one kind are merged, so the comparison is a function of the exact source and operations alone, never of how scopes partition the text; the same input yields identical segments, bytes and hashes on every run and regardless of request key order (`test/redline.test.mjs` pins nested sections, overlapping ranges and whole-section repeal). Removing insert segments reconstructs the original source; removing delete segments reconstructs the consolidated source. Output and revision hashes bind the exact text and source custody. The compiled `approval` field is always `unapproved`; review approval lives in the retained review record below. Numbering, cross-reference, arithmetic and substantive-law findings explicitly remain unresolved.

Whole-section repeal is an ordinary delete of the section's exact text (flat) or of the element's exact span through its parent (nested/USLM): one delete segment, the consumed identity invalidated, siblings still usable. Whole-source repeal (an operation that leaves no consolidated text, or removes a USLM root element) is refused with `DRAFT_WHOLE_SOURCE_REPEAL_UNSUPPORTED`: a proposed repeal is not a text amendment, and no empty document or placeholder bytes are produced.

`federalDraftExportRequests(prepared, expectedRevisionSha256)` converts those exact outputs into the existing three `create_word`/TXT requests. The expected hash prevents an accidental stale export; it is not authorization or approval. `federalDraftDossier(prepared, approval)` builds the existing typed `create_word`/DOCX request: provenance (document, publisher, version, source locator, source SHA-256, retained source artifact version/object/spec hashes, revision SHA-256, approval state, source limitations, unresolved findings), the operative instructions, the consolidated text one paragraph per line, and the comparison with struck runs italic and inserted runs bold. The canonical renderer owns the DOCX bytes; a revision beyond the Word contract refuses the dossier (`DRAFT_OUTPUT_UNEXPORTABLE`) without affecting the TXT exports. Exported USLM consolidated text is the exact XML bytes in a TXT artifact; the artifact contract has no XML format.

## Review record and approval

`review-record.mjs` owns the retained review bundle `{schema: meri.federal-review.v1, prepared, approval?}` and its store rule. A saved revision always carries `approval: null` and keeps the pre-existing byte shape. Approval is a separate immutable child version of the exact review version it approves, carrying the same compiled revision and `approval: {revisionSha256, reviewVersionId}`. On every read the approval must name the recompiled revision hash and the record's own parent version; otherwise the record is invalid (`DRAFT_REVIEW_INVALID`), never silently unapproved. A revision therefore invalidates any prior approval by construction: it is a new version with a new revision hash and no approval, and the old approval cannot be cited for it. See [the control-plane note](../../control/document-application/FEDERAL-WORKBENCH.md).

## Official sources

The attended native `prepare_federal_draft` operation connects the canonical Core federal evidence read to this compiler through `native-source.mjs`. Its exact selection comes from `read_bill_text`; Core verifies current retained content and text hashes. The SDK tool keeps the frozen flat contract: a USLM or other markup extraction is refused there (`DRAFT_SOURCE_FORMAT_UNSUPPORTED`). The document application's `federal-import` route projects the same Core read with `structured: true`, so a retained USLM extraction imports as a `federal-uslm-xml/1` source with its identifier tree; plain text still imports flat. `source-custody.mjs` stores `{schema: meri.federal-source.v1, selection, source}` as an ordinary immutable TXT artifact using the existing delivery journal. Every prepare/load/approve/export/history of an official envelope re-reads Core's exact selection and compares the complete projected snapshot. Stale source returns `DRAFT_SOURCE_STALE`; an absent reader refuses. Core remains the source custodian; no second source store is introduced. Core's read returns extracted text only; whether a retained extraction is USLM depends on the retained evidence, and the live fetch itself is outside this repository.

The additive public source contract is workbench version 1.3.0 ([routes](../../control/document-application/FEDERAL-WORKBENCH.md)). The four federal-workbench distribution files are generated with the source change. Package manifest version/archive publication and the frontend dependency pin remain with the coordinated package owner.

Current bounds are 128 KiB source text, 128 scopes (1024 for USLM), 64 operations and 16 KiB per instruction text; the existing artifact request bounds also apply. Author tests exercise exact scoped replace/insert/delete, rollback after a later failure, ambiguous/missing anchors, intermediate hashes/dependencies, Unicode/CRLF, original/final reconstruction, deterministic comparison fixtures, USLM identity/edits/refusals, the review record rule, the dossier request, immutable source custody, foreign actor/revocation/suppression, prior-revision refusal, and byte-exact publication/download through the existing artifact owners. SQL/publication ports are isolated scripted fixtures; no live database, model/provider, browser, Office renderer or legal review is represented by them. This is not completed A5 acceptance.

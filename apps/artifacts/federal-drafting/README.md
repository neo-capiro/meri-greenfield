# Exact-text federal draft preparation

`createArtifactService().prepareFederalDraft(selection, context, options)` is the private receiving path. It reads the selected immutable source using the artifact owner's existing current-authority, retention and byte-verification checks, then runs the deterministic compiler. Preparation writes nothing. The source selection includes `versionId`, `expectedArtifactSha256` and ordered `operations`.

The retained TXT source envelope is JSON with `documentId`, `publisher`, `sourceVersion`, `sourceUrl`, `publishedAt` (an exact calendar date or explicit null when unreported), `parserVersion: federal-plain-text/1`, exact UTF-8 `text`/`sha256`, `coverage: {complete, limitations}`, and ordered non-overlapping `scopes: [{id,label,start,end,sha256}]`. Offsets are UTF-16 string offsets, with Unicode scalar boundaries validated; source text is not normalized. Scope hashes cover the exact original slices. The source importer is responsible for accurate publisher/version attribution. Storing a claimed publisher in an artifact is not official-source verification.

Each operation has a unique `id`, `kind: replace|insert|delete`, `scopeId`, `expectedScopeSha256`, nonempty `expectedText` and its SHA-256, and `dependsOn`. Replace adds `text`; insert adds `text` and `position: before|after`; delete permits neither. Dependencies must reference earlier operations, and a subsequent operation on a changed scope must name the previous operation on that scope. The expected scope hash is the exact intermediate text hash. A missing or repeated anchor, changed scope, invalid dependency, successful no-op or empty final source is refused. No fuzzy anchor, inferred ancestor or fallback search exists. Every intermediate change occurs on copies; a failed operation returns no partial package.

The additional retained parser `federal-scoped-text/2` uses the same source fields and adds a required `ancestorPath` to every scope. Scopes are in preorder; their exact ranges must be disjoint siblings or contained descendants. The declared path must equal the enclosing scope IDs in order. No legal structure is inferred from headings. Flat `federal-plain-text/1` remains non-overlapping and its accepted output/revision bytes stay unchanged.

For v2, edits update the working document and all surviving scope locations. A target's hash always covers its current intermediate text. Every operation that changed that text must be present in the dependency closure: independent sibling edits require both branches before editing their ancestor. Transitive dependencies are accepted. Insertion at a descendant's start/end by an ancestor belongs outside the descendant; insertion through that descendant belongs inside it and its ancestors. An ancestor edit wholly consuming a descendant or crossing its boundary invalidates that old identity. Subsequent use returns `DRAFT_SCOPE_INVALIDATED`, even if replacement text happens to recreate a similar heading. An edit wholly within a descendant preserves its identity and adds a dependency. Invalidated scopes are never fuzzy-rematched. The original source/operations remain unchanged on any failure.

The result contains three distinct outputs: ordered operative instructions, exact consolidated text, and a legal text comparison expressed as typed unchanged/delete/insert JSON segments. Literal marker characters cannot be mistaken for changes. The nested engine tracks surviving original ranges; unchanged text between separate edits remains unchanged in the redline, including CRLF and Unicode. Removing insert segments reconstructs the original source; removing delete segments reconstructs the consolidated source. Output and revision hashes bind the exact text and source custody. All revisions are unapproved. Numbering, cross-reference, arithmetic and substantive-law findings explicitly remain unresolved.

`federalDraftExportRequests(prepared, expectedRevisionSha256)` converts those exact outputs into the existing three `create_word`/TXT requests. The expected hash prevents an accidental stale export; it is not authorization or approval. The existing delivery owner must publish and retain each exact request and reconcile its original outcome after an interrupted write. Preparation verifies that all three outputs fit that existing contract before returning. No publication loop, approval ledger or persistence schema is added.

The attended native `prepare_federal_draft` operation now connects the canonical Core federal evidence read to this compiler through `native-source.mjs`. Its exact selection comes from `read_bill_text`; Core verifies current retained content and text hashes. The converter preserves separate source dates and unknown extraction/legal semantics. See [the native source boundary](../../gateway/sources/federal-draft-source/README.md). Core remains the source custodian; no second source store is introduced.

The document application's `federal-import` route accepts only the exact native five-pin selection and an original delivery ID. The current Core source reader shares the artifact authority client's bounded transport and live native credential owner. `source-custody.mjs` stores `{schema: meri.federal-source.v1, selection, source}` as an ordinary immutable TXT artifact using the existing delivery journal. The native projection is shared with `prepare_federal_draft`; no second compiler, source ledger or authority receipt is added. The title binds the complete envelope hash, so changed metadata cannot reuse a delivery as if it were the old import.

Every prepare/load/export of an official envelope re-reads Core's exact selection and compares the complete projected snapshot. Stale source returns `DRAFT_SOURCE_STALE`; an absent reader refuses. The JSON marker grants no trust. Legacy bare source envelopes still contain unverified publisher claims. Publication checks source currentness before effects and release. A committed result withheld at release can recover its original version; an effect interrupted before commitment remains UNKNOWN in the canonical journal and cannot be repeated by retry. This does not prove enactment, current law or legal fidelity.

The additive public source contract is workbench version 1.2.0. The four federal-workbench distribution files are generated with the source change. Package manifest version/archive publication and the frontend dependency pin remain with the coordinated package owner. Existing flat imports/prepare/load/save/export stay compatible. Official native imports remain the frozen flat v1 projection; a nested retained envelope does not acquire official-source trust. The existing frontend can review/export loaded multi-operation drafts but only authors one operation at a time; the wider authoring UI remains a separate gap.

Current bounds are 128 KiB source text, 128 scopes, 64 operations and 16 KiB per instruction text; the existing artifact request bounds also apply. XML/USLM/HTML markup detected at the start of an alleged plain-text source now refuses with `DRAFT_SOURCE_FORMAT_UNSUPPORTED`, including native import before publication. This is a refusal guard, not an XML validator. XML/USLM parsing, whole-source repeal, richer authoring and production qualification remain outstanding. See [proposed remaining contracts](CONTRACT-EXTENSIONS.md). This is not completed A5 acceptance.

Author tests exercise exact scoped replace/insert/delete, rollback after a later failure, ambiguous/missing anchors, intermediate hashes/dependencies, Unicode/CRLF, original/final reconstruction, immutable source custody, foreign actor/revocation/suppression, prior-revision refusal, and byte-exact publication/download of all three outputs through the existing artifact owners. SQL/publication ports are isolated scripted fixtures; no live database, model/provider, browser, Office renderer or legal review is represented by them.

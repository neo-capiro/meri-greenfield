# Remaining drafting contracts — proposed, not implemented

The retained requirements are Core `docs/meri/implementation/02-Meri-Coworker-and-Congressional-Drafting.md` §8.6 and DR-09–16/24–26, program plan §5.7, and the 7 October finish-plan §3.8. They require pinned original formats, reversible locations, explicit intermediate dependencies, atomic preview and useful unsupported outcomes. The retained 7 October plan explicitly leaves the XML validation implementation choice open. The newer Wave 6 readiness record still lists USLM/hierarchy as unfinished. These proposals do not certify legal effect or narrow that scope.

## XML/USLM and House DTD

The current Core source response provides `extracted_text`, hashes and parser metadata, but does not return the retained raw content or a declared XML schema. Some retained extractions are XML themselves. Labelling those bytes plain text and editing markup is not a structural application engine. The new refusal guard contains that defect; it does not complete XML support.

Proposed owner contract:

1. Extend the canonical Core source read with a versioned raw-format projection. Bind the same exact selection, raw content hash, retained raw bytes, declared format, namespace/schema version and parser identity. Do not invent original-HTTP-byte verification. Keep currentness/authorization in the existing owner. No external URL fetch at import or replay.
2. Choose and qualify the local XML validator path before accepting XML. The retained approved-schema acquisition pins are USLM `100338992150c276aae5544d01d9b821a27eb383` and bill DTD `18a68dad697ea7447881e0c10dd96dcecbdeb508`; their assets and notices are not vendored by this change. USLM 2.1.1 is not an implicit default. Match the actual declared supported schema, reject unknown versions, and resolve dependencies only through the pinned local catalog. Disable arbitrary external DTD/entity/schema access. A well-formed SAX parse alone must not report full XSD/DTD validation.
3. Preserve the order and original lexical spans of elements, text, entities, quotes, tables, strike/underline marks and source page/line metadata. Store decoded text runs with reversible UTF-8 byte and UTF-16 display offsets. Distinct runs separated by markup cannot silently become one replacement anchor. Do not invent spaces during normalization.
4. Initially support unique exact text replacement/insertion within one admitted text run and complete supported non-root unit deletion. Plain inserted text is XML-escaped; user text is never interpreted as markup. Preserve original bytes outside the edited spans and revalidate the output tree. Node replacement, renumbering, cross-run replacement, tables and page-line/OCR application require separate source-bound fixtures; return localized unsupported outcomes until then.
5. Keep the current source/operation/revision hashes, atomicity and artifact history. Add explicit XML structural output and comparisons; do not route flattened text through a TXT export and call it XML fidelity. Real DOCX/PDF semantic-format preservation remains a separate artifact/renderer qualification.

Concrete fixtures to implement: a declared supported USLM section with a nested paragraph containing `Pay &amp; report.` may replace the decoded `report` with `record`; resulting raw bytes change only that lexical span. An expected `Pay & report.` crossing an intervening `<ref>` must refuse until a multi-run operation is defined. External entity declarations, unknown schema versions, wrong raw hashes, duplicate IDs, an ambiguous ancestor path and any malformed resulting tree refuse with zero publication. Tests must use the pinned schema's actual valid examples; the illustrative text here is not a schema-validity fixture.

Required coordination: canonical Core raw-format contract and package owner; local validator/schema qualification; frontend structural review and faithful artifact export. No source import, schema download, provider/model call or live mutation was performed for this proposal.

## Whole-source removal / proposed repeal

The existing instruction grammar can delete an exact nonempty text anchor, but rejects an empty final result (`DRAFT_EMPTY_RESULT`). The existing artifact request requires nonempty document content. A placeholder such as `[repealed]` would falsify consolidated source bytes. The requirements also distinguish amendment-to-bill text from hypothetical effects on existing statutes; a mechanically empty string cannot establish enactment, effective date or legal repeal.

Proposed explicit operation `remove_source_text` binds a complete full-document scope, original source snapshot/hash, target layer and dependencies. It is not an inferred synonym for deleting a section. Example: a complete selected source `SEC. 1. Example.\n` produces `consolidated: ""`, its real empty-string SHA-256 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`, and one delete redline containing every original byte. Operative output says that removal is a proposal against the named snapshot; substantive-law findings stay unresolved. No enacted/repealed status is written to the source owner.

Before implementation, coordinate a versioned empty-output artifact contract: permit an explicitly typed empty consolidated TXT result, its zero-byte object/inspection/download, public receiver and history; keep ordinary blank-document refusals. Preserve operation identity and avoid repeating up to 128 KiB as an anchor subject to the 16 KiB instruction limit. Reject partial coverage, non-document scopes, wrong source/layer pins and undefined follow-on edits after removal. Save/load/replay/download must reproduce zero bytes without adding whitespace or markers. Existing v1 requests continue to refuse empty results until that contract and its consumers are reviewed together.

## Source-ready portion in this change

`federal-scoped-text/2` implements declared text ancestry and overlapping, explicitly dependent exact edits. It updates surviving locations, rejects consumed descendant identities and preserves unchanged redline spans. Tests traverse the existing retained source → preparation → save/load → parent revision → operative/consolidated/redline export → idempotent replay and suppression boundaries using offline synthetic storage ports. It does not parse XML, import new government records, qualify live behavior, or supply multi-operation frontend authoring.

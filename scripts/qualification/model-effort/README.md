## Cases and bounds

The only original requests, in order, are Sonnet high, Sonnet max, Opus null, Opus high and Opus max. Exact request IDs are `us.anthropic.claude-sonnet-4-6` and `us.anthropic.claude-opus-4-6-v1`. Every case uses the fixed prompt in `plan.mjs`. Null means omit SDK effort, not assert a particular provider default.

Each case permits one original allocate/admit/submit sequence, one native SDK query, at most 2 SDK turns and a $0.25 SDK estimated-cost budget. The batch permits at most 5 queries / 10 SDK turns / $1.25 SDK estimated cost. The SDK's monetary budget is an estimate/stop threshold, not a hard provider invoice ceiling; a single in-flight request can exceed it. An observed overrun fails qualification and stops the driver. Provider-billed cost remains unknown.

Each driver case has 180 seconds, each HTTP operation 10 seconds and at most 24 history reads. The allocation lasts at most 900 seconds; new work stops 30 seconds before expiry. The runtime aborts a case after at most 180 seconds and shuts down at allocation expiry with a 30-second cleanup deadline. These are cancellation deadlines, not proof that remote billing stopped. Any unknown outcome or cleanup requires Release to reconcile the existing run; never resend, copy an allocation to bypass its claim, restart a used runtime, or create a replacement request. Existing native idempotent accounting/event-write retries retain their existing owner and semantics.

The SDK keeps its Claude Code presets, tools, sandbox, session store and ordinary runner lifecycle. A qualification-only additive `PreToolUse` hook denies every tool, including delegation, and aborts on any attempt. A read-only Stop hook records the SDK's active post-downgrade effort level. An explicit-level mismatch fails, absence stays UNKNOWN. The hook is an intentional qualification restriction; this method does not qualify tools, skills, delegation or multi-turn behavior.

Run from the bound repository source with its existing dependencies and trust environment. No command below performs catalog activation or tenant writes. `--help` is safe offline.

```sh
node scripts/qualification/model-effort/runtime.mjs /private/allocation.json

node scripts/qualification/model-effort/review.mjs /private/allocation.json /private/new-driver.jsonl /private/combined-runtime.jsonl /private/new-review.json
```

The runtime keeps the native AgentCore `/invocations` and `/ping` protocol on port 8080, authenticated control transport, canonical runner, real workspace/session factory, actual pinned `sdkQuery`, durable usage writer, execution settlement and cleanup. It adds no provider endpoint. The driver uses the canonical initial-input/conversation/usage receivers over existing product routes. An exclusive, fsynced `.attempted` file is created before effects; preserve it even after failure. Process exit 2 is refused/setup failure; exit 3 is unknown/failure; driver exit 0 is only product completion pending runtime review.

Collect namespaced runtime JSON lines only from the actual five candidate sessions (ordinary native diagnostic lines are separate). Retain raw private logs unchanged plus the extracted JSONL. Review joins allocation SHA, case ID, full binding, request ID, declared image/source/method/Release binding, actual SDK options, init/result session/profile, Stop effort, tool attempts, native settlement and persisted usage. SDK init/result names may be the exact requested US profile, its base `anthropic.*` name or its corresponding `claude-*` name; this evidence mapping never changes a submitted or stored ID. Unexpected mappings remain UNKNOWN. SDK `provider: bedrock` is evidence of the SDK path, not AWS invoice acknowledgement.

The reviewer must independently verify custody, successful native cleanup, per-case and aggregate usage, no missing/duplicate requests, candidate routing and deployment readbacks.

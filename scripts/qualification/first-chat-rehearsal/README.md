# First-chat rehearsal tools

`capture-sdk-descriptor.mjs --out FILE [--options-module PATH] [--with-proposed-directories]` captures the launch descriptor the pinned Claude Agent SDK produces for the product option set (`apps/worker/conversation/options.mjs`, or an alternative copy of it) by interrupting the SDK at its spawn hook, and reports each remote launch gate's outcome on that descriptor: inert JSON, per-task config directories, secret-in-env observation, and `compileNativeLaunch` with directories injected. It spawns no process, performs no network or provider access, and hashes secret-shaped env values before writing. `--with-proposed-directories` supplies the per-run SDK directory pair in the shape the proposed (unapplied) runner change would derive from the admitted preparation intent; by default the capture passes exactly what the committed composition passes. Exit 0 with the receipt written (gate outcomes are inside, not an exit code), 2 usage, 3 if the SDK produced no descriptor. Tests: `node --test scripts/qualification/first-chat-rehearsal/capture-sdk-descriptor.test.mjs`.

`composed-rehearsal.mjs` is the composed rehearsal: real PostgreSQL 16 (the local broker cluster), the real remote controller, remote task application, independent supervisor process and the real pinned CLI 2.1.295, driven by the product runner (`assembleConversationRunner`), the product option builder and the durable SDK session path, for the accepted zero-turn request `/status`. ECS, identity, authority and proxy facts are synthetic and the proxy credential is a synthetic string. It is not collected by the suite globs because it needs the gap 2 runner derivation applied (`apps/runtime/conversation-runner.mjs` is a pinned proof row, so the patch is applied and reverted around the run) and a launch template that carries the synthetic credential (gap 3). Run it explicitly as a non-root user with the clusters started:

```sh
MERI_REVIEW_SOURCE_ROOT="$PWD" MERI_REHEARSAL_RECEIPT=/path/receipt.json node --test scripts/qualification/first-chat-rehearsal/composed-rehearsal.mjs
```

The receipt records head/tree, whether the runner module carries the patch, the CLI hash, the redacted descriptor, every route reached, the durable conversation events, the registered SDK session rows, the launch binding state and the physical-stop receipts; a failed run records the refusal code and the same facts. Without the patch the run fails at the SDK options pin before any native-task route, which is the retained PR86 control.

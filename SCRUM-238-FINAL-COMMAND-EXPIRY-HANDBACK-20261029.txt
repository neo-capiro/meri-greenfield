2. CORRECTION 1 — NESTED UNKNOWN AND TRANSPORT UNKNOWN (useRunQuestion.ts)
   The control route answers either a receipt with `state` or, for 502, {error:{code:'LIFECYCLE_EFFECT_UNKNOWN',outcome:'UNKNOWN'}}.
   controlOutcome(receipt) now reads both shapes and returns PENDING / UNKNOWN / NOT_DISPATCHED; anything unreadable is UNKNOWN.
   answerCommand maps: APPLIED/PENDING/DISPATCHING -> waiting; NOT_DISPATCHED -> rejected (the only correctable refusal);
   UNKNOWN -> unknown (latched; the card cannot resend, and no new random controlId is minted); a thrown ConversationUnavailable
   (superseded / no longer current) -> error, which the card now locks; any other throw after dispatch (fetch TypeError, lost
   response) -> unknown, never a refusal. QuestionCard's `disabled` now includes "error", so a superseded conversation is no
   longer an editable send state. No new ledger, queue or receiver change.

3. CORRECTION 2 — SUBMIT-TIME CURRENTNESS AND DEADLINE (useRunQuestion.ts)
   The submit path is now the exported answerCommand, used by the hook: it re-reads port.getSnapshot() and re-derives the
   pending question immediately before sending, and sends nothing unless the question is still the same one, the run is not
   settled (isSettled, so paused / waiting-for-approval / terminal all refuse), and the deadline has not passed. A question that
   quietly crosses expiresAt is bounded by a scheduled timer in the effect, so it becomes unavailable without another event, and
   the timer is cleared on effect cleanup. A late completion from a previous question or port is discarded by comparing the
   capturing port/question against the card's current pair (`showing` ref); the same-live-run durable reload, the paused/terminal
   refusal and the question-change selection reset are unchanged.
